# 6. 이미지 생성 프롬프트 점검 및 교정 지침

## 목적

이 문서는 이미지 생성 모듈 내부 1~8번 기능에서 요구사항 확인서와 최종 영어 프롬프트를 마스터에게 공개하기 직전에 수행하는 공통 사전 점검의 정본이다.

프롬프트가 자연스럽거나 그럴듯한지만 평가하지 않는다. 기능 계약, 참고 자료, 스타일 계약과 고정 영어 블록이 실제 문안에 정확히 반영되었는지를 `통과` 또는 `실패`로 판정하고, 실패한 문안은 승인 요청 전에 바로잡는다.

## 적용 시점과 하드 게이트

1. 필요한 자료와 실제 이미지 픽셀을 확인한다.
2. 요구사항 확인서 초안과 최종 영어 프롬프트 초안을 작성한다.
3. 이 지침의 점검을 수행한다.
4. 실패 항목이 있으면 자동 교정하고 처음부터 다시 점검한다.
5. 모든 필수 항목이 통과한 뒤에만 요구사항 확인서와 최종 영어 프롬프트를 공개하고 생성을 승인받는다.

점검 결과가 `실패`이거나 확인할 수 없는 필수 항목이 남아 있으면 프롬프트를 확정하지 않는다. 해당 상태에서 `생성`, `진행`, `승인`, `이대로 생성`, `다음`을 요청하거나 이미지 생성 도구를 호출하지 않는다.

이미 실패한 문안을 공개한 뒤 마스터가 생성을 승인했더라도 그 승인을 사용하지 않는다. 문안을 교정하여 다시 공개하고 새 승인을 받는다.

## 점검 전 기준 분류

먼저 그림체 적용 방식을 다음 중 하나로 확정한다.

### A. 제공 이미지 그림체 보존

- 별도 스타일 변경 지시가 없는 캐릭터 레퍼런스 V1·V2와 세션 하이라이트 등에 적용한다.
- 제공 이미지의 디자인과 그림체·마감을 기준으로 사용한다.
- 정식 스타일의 고정 영어 그림체 블록과 공통 고정 영어 마감 블록을 자동 삽입하지 않는다.

### B. 정식 스타일 적용

- `애니 페인팅` 또는 `붓터치 반실사`가 선택된 경우에 적용한다.
- 선택 스타일의 정식 앵커를 실제 픽셀로 확인한다.
- 선택 스타일의 고정 영어 그림체 블록과 공통 고정 영어 마감 블록을 원문 그대로 삽입한다.

### C. 사용자 지정 스타일 또는 기능성 예외

- 사용자가 다른 화풍을 명시했거나 배틀맵·게임 아이콘·양피지 지도처럼 기능 계약이 스타일보다 우선하는 경우에 적용한다.
- 적용하거나 제외한 스타일·마감 규칙과 그 근거를 요구사항 확인서에 적는다.
- 정식 스타일을 선택하지 않았다면 정식 스타일 블록을 임의로 혼합하지 않는다.

그림체 적용 방식이 둘 이상으로 충돌하면 임의로 혼합하지 않는다. 현재 대화와 참고 자료만으로 기준을 확정할 수 없으면 마스터에게 한 가지 결정만 질문한다.

## 필수 점검표

각 항목은 증거를 확인한 경우에만 `통과`로 판정한다.

### P01. 기능과 산출물 계약

- 선택된 내부 기능이 사용자 목적과 일치한다.
- 생성 수량, 캔버스 비율, 파일 형식, 투명 배경, 레이아웃과 필수 패널이 기능 계약과 일치한다.
- 요구사항 확인서와 영어 프롬프트가 같은 산출물을 가리킨다.

### P02. 대상과 가변 요구사항

- 대상 수, 종족, 성별, 연령, 체형, 핵심 외형, 의상, 무기, 행동과 감정이 사용자 지시와 일치한다.
- 사용자가 맡긴 자동 보정 요소는 실제로 고정한 해석 또는 `모델 재량으로 미고정`임을 `추정한 요소`에 기록한다. 모델 재량 항목을 사용자 확정 사항처럼 표현하지 않는다.
- 포즈·카메라·배경이 미지정이면 모델 재량으로 둘 수 있으며, 자유 결정 영역과 기능상 필수 제한을 구분한다.

### P03. 참고 자료와 디자인 기준

- 사용자 제공 이미지, 프로젝트 공식 이미지, 캐릭터 레퍼런스와 설정 자료의 사용 여부가 기록되어 있다.
- 디자인 기준 이미지가 있으면 어떤 이미지를 우선하는지 명확하다.
- 제공 이미지의 그림체를 보존할지 정식 스타일로 변경할지 명확하다.
- 기준 이미지가 충돌하거나 대상 동일성이 불명확하면 임의로 선택하지 않는다.

### P04. 정식 앵커 실제 확인

정식 스타일 적용 방식 B에서만 필수다.

- `라이브러리/스타일/정식 스타일 호출 규칙.md`와 선택 스타일 계약에서 선택 스타일의 전체 활성 앵커 매니페스트를 확인했다.
- 요구사항 확인서의 산출물 구도 분류가 실제 산출물의 주 프레이밍과 일치한다.
- 중앙 호출 규칙이 해당 구도에 반환하는 예상 앵커 조합과 실제 사용할 스타일 앵커가 일치한다.
- 실제 불러온 모든 앵커의 전체 파일명이 요구사항 확인서에 기록되어 있다.
- 제외한 활성 앵커의 전체 파일명과 제외 사유가 기록되어 있다. 도구 참조 한도 때문에 제외한 앵커를 `해당 없음`으로 처리하지 않는다.
- 파일명·메타데이터·과거 기억이 아니라 실제 이미지 픽셀을 확인했다.
- 사용자 제공·프로젝트 공식 디자인 기준 이미지가 있으면 중앙 호출 규칙의 참조 예산 우선순위에 따라 스타일 앵커보다 먼저 배정했다.
- 앵커에서는 그림체·채색·재질 표현·마감만 참조하며 인물·의상·팔레트·포즈·카메라·배경·장면 구성을 가져오지 않는다.

### P05. 고정 영어 그림체 블록

정식 스타일 적용 방식 B에서만 필수다.

- 선택 스타일 계약의 코드 블록 전체가 최종 영어 프롬프트에 한 번만 들어 있다.
- 문장, 단어, 구두점과 순서를 요약·번역·변형하지 않았다.
- `painterly semi-realistic style`, `anime painting style` 같은 일반적인 한두 문장은 고정 영어 그림체 블록을 대체하지 못한다.
- 가변 프롬프트가 고정 블록과 다른 얼굴 구조·해부학·선 처리·형태 단순화 방식을 요구하지 않는다.

### P06. 공통 고정 영어 마감 블록

정식 스타일 적용 방식 B에서만 필수다.

- `공통 붓터치 마감 규칙.md`의 코드 블록 전체가 최종 영어 프롬프트에 한 번만 들어 있다.
- 문장, 단어, 구두점과 순서를 요약·확장·변형하지 않았다.
- 고정 영어 그림체 블록 바로 뒤에 배치되어 있다.
- 가변 프롬프트는 통제된 저수분 수채·과슈 영향을 허용하되, 묽은 투명 워시, 젖은 안료 번짐, 물감이 고인 가장자리, 색이 빠진 안개, 거친 임파스토, 플라스틱 CGI, 균일 텍스처 오버레이처럼 고정 마감 블록과 충돌하는 표현을 요구하지 않는다.

### P07. 스타일과 가변 내용의 분리

- 기능별 가변 프롬프트는 대상·디자인·행동·포즈·카메라·배경·출력 규격만 담당한다.
- 캐릭터의 중요도나 디자인 밀도를 특정 문화권 장식, 금장, 모피, 고딕 장식처럼 사용자가 요구하지 않은 고정 도상으로 치환하지 않는다.
- 스타일 앵커의 콘텐츠나 구도를 긍정 조건으로 복제하지 않는다.
- 같은 스타일을 서로 다른 표현으로 중복 지시하여 고정 블록의 영향력을 흐리지 않는다.

### P08. 신체·장비·구도 안정성

- 단일 대상 계약에서 추가 인물, 분할 화면, 콜라주와 인셋을 요구하지 않는다.
- 머리, 손, 발과 핵심 장비의 잘림 여부가 기능 계약과 맞는다.
- 손가락, 그립, 장비 접촉과 장착 위치가 물리적으로 읽힌다.
- 무기와 방패처럼 동시에 운용하기 어려운 장비가 있으면 어느 손에 들고 어디에 장착하는지 정한다.
- 전신 실루엣과 주요 장비가 서로 가리지 않도록 한다.

### P09. 금지 조건과 내부 충돌

- 사용자 금지 요소, 기능별 금지 조건과 선택 스타일의 금지 조건이 반영되어 있다.
- 긍정 지시와 금지 지시가 같은 요소를 동시에 요구하지 않는다.
- 포토리얼 금지와 사실적인 사진 묘사처럼 서로 충돌하는 표현이 없다.
- 미지정 사항을 확정 설정처럼 추가하지 않는다.

### P10. 공개본 일치와 승인 가능 상태

- 공개할 요구사항 확인서와 최종 영어 프롬프트가 점검한 초안과 동일하다.
- 요구사항 확인서에 실제 점검 결과와 자동 교정 내역이 있다.
- 모든 필수 항목이 통과했다.
- 이 생성 배치만을 대상으로 새 승인을 요청한다.

## 판정 규칙

- `통과`: 적용 방식에 해당하는 모든 필수 항목이 증거와 함께 충족되었다.
- `실패`: 하나 이상의 필수 항목이 누락되었거나 계약과 충돌한다.
- `확인 필요`: 자료 부재나 사용자 결정이 필요하여 자동 교정할 수 없다. `통과`로 간주하지 않는다.

부분 통과나 점수제는 사용하지 않는다. 적용 대상이 아닌 항목은 `해당 없음`으로 기록할 수 있으나, 확인하지 않은 항목을 `해당 없음`으로 처리하지 않는다.

## 자동 교정 절차

실패가 발견되면 다음 순서로 처리한다.

1. 실패한 항목 번호와 원인을 내부적으로 기록한다.
2. 기능 마스터, 디자인 기준, 선택 스타일 계약과 공통 마감 계약을 다시 읽는다.
3. 사용자 지시와 기능별 가변 내용은 유지한다.
4. 잘못 요약하거나 변형한 스타일·마감 문장을 제거한다.
5. 필요한 고정 영어 블록을 정본에서 그대로 다시 삽입한다.
6. 누락된 앵커 확인, 장비 배치, 보존·금지 조건과 출력 계약을 보완한다.
7. 요구사항 확인서와 최종 영어 프롬프트를 함께 갱신한다.
8. P01부터 P10까지 처음부터 다시 검사한다.

자동 교정 과정에서 새로운 캐릭터 설정이나 제품 판단이 필요하면 추측하지 않는다. 해당 항목을 `확인 필요`로 두고 마스터에게 한 가지 결정만 질문한다.

## 요구사항 확인서 표시 형식

요구사항 확인서의 `스타일 통제` 아래에 다음 항목을 반드시 표시한다.

```text
- 그림체 적용 방식:
- 선택 정식 스타일:
- 산출물 구도 분류:
- 디자인 기준 이미지:
- 스타일별 전체 활성 앵커:
- 실제 사용할 스타일 앵커:
- 제외한 스타일 앵커와 사유:
- 앵커 실제 픽셀 확인: 완료 / 해당 없음
- 고정 영어 그림체 블록: 원문 적용 / 미적용 사유
- 공통 고정 영어 마감 블록: 원문 적용 / 미적용 사유
- 프롬프트 점검 결과: 통과
- 자동 교정 내역: 없음 / <실제 교정 내용>
```

도구 참조 한도 때문에 앵커를 제외한 경우 `제외한 스타일 앵커와 사유`에 해당 파일명과 참조 예산 축소 사유를 적는다. 이 경우 제외된 앵커를 `해당 없음`으로 표시하지 않는다.

점검 결과가 `실패` 또는 `확인 필요`인 문안에는 승인 요청 문구를 붙이지 않는다.

## 실패 사례

다음과 같은 시작 문장은 그 자체로 붓터치 반실사 고정 영어 그림체 블록과 공통 마감 블록을 적용한 것으로 인정하지 않는다.

```text
Create a single full-body character portrait in a painterly semi-realistic style with visible brushwork and refined rendering.
```

이 문장은 가변 프롬프트의 짧은 스타일 설명일 뿐이다. `붓터치 반실사.md`의 고정 영어 그림체 블록 전체와 `공통 붓터치 마감 규칙.md`의 고정 영어 마감 블록 전체가 원문 그대로 들어가야 정식 스타일 적용으로 통과한다.

## 생성 직전 최종 확인

사용자가 승인한 뒤 이미지 생성 도구를 호출하기 직전에 다음 네 가지를 다시 확인한다.

1. 승인받은 요구사항 확인서의 `프롬프트 점검 결과`가 `통과`인가
2. 실행할 최종 영어 프롬프트가 공개·승인된 문안과 동일한가
3. 승인 이후 대상·수량·스타일·참고 이미지·출력 계약이 바뀌지 않았는가
4. 승인 상태가 이전 생성에서 이미 소모되지 않았는가
