# 요구사항 확인서 작성 규칙

## 기본 필드

- 기능
- 대상
- 출력 계약
- 스타일
- 공통 붓터치 마감 적용 여부
- 레이아웃
- 배경/환경
- 포즈/상태
- 보존 요소
- 금지 요소
- 참고 자료
- 생성 수량
- 스타일 통제

사용하지 않는 필드는 생략할 수 있다. 기능의 고정 계약은 선택 사항처럼 표현하지 않는다.

`프롬프트 점검 결과`와 `자동 교정 내역`은 생략할 수 없다. 점검 결과는 `6. 이미지 생성 프롬프트 점검 및 교정 지침.md`의 P01~P10을 모두 확인한 뒤에만 `통과`로 기록한다.

## 스타일 통제 필수 필드

```text
- 그림체 적용 방식:
- 선택 정식 스타일:
- 산출물 구도 분류:
- 디자인 기준 이미지:
- 스타일별 전체 활성 앵커:
- 실제 사용할 스타일 앵커:
- 제외한 스타일 앵커와 사유:
- 앵커 실제 픽셀 확인: 완료 / 해당 없음
- 고정 영어 그림체 블록: 원문 적용 / 미적용 사유
- 공통 고정 영어 마감 블록: 원문 적용 / 미적용 사유
- 프롬프트 점검 결과: 통과
- 자동 교정 내역: 없음 / <실제 교정 내용>
```

도구 참조 한도 때문에 앵커를 제외한 경우 `제외한 스타일 앵커와 사유`에 해당 파일명과 참조 예산 축소 사유를 적는다. 이 경우 제외된 앵커를 `해당 없음`으로 표시하지 않는다.

## 완성형 토큰 추가 필드

- 기준 이미지 유형: 포트레이트 전신 확정본 / 사용자 업로드 이미지
- 대상 유형
- 자동 적용 토큰 계열과 판단 근거
- 적용 등급: 일반 / 엘리트 / 보스
- 자동 프레임: 색상·재질·문양·장식 밀도·보스 표적성 요약
- 산출물: 캐릭터가 포함된 1:1 투명 PNG 1장

## 공통 붓터치 마감 표기

- 포트레이트, 완성형 토큰, 캐릭터 레퍼런스, 풍경, 세션 하이라이트, 아이템, 비공정·건축·기계 등 설정화·컨셉 아트에는 `적용: 은은한 붓터치 기반의 고급 디지털 페인팅 마감`으로 기록한다.
- true top-down 배틀맵, 게임 아이콘, 양피지 지도에는 `예외: 기능성·판독성 우선 계약`으로 기록한다.
- 사용자가 특정 화풍을 지정한 경우에는 그 지시와 공통 마감의 적용·대체 관계를 명시한다.
