# 캠페인 이벤트 원장 아이디어

## 목적

캠페인 이벤트 원장(Campaign Event Ledger)은 세션 로그에 남아 있는 실제 플레이 결과를 구조화된 사건 데이터로 승격하여, 이후 세계 상태·NPC 기억·지식 그래프·스토리 스레드·다음 세션 설계가 같은 사건 정본을 참조하도록 만드는 공통 캠페인 데이터 계층이다.

핵심 역할은 다음 세 층을 분리하는 것이다.

1. 설정: 세계가 원래 어떠한가.
2. 사건: 실제 플레이에서 무엇이 일어났는가.
3. 현재 상태: 누적된 사건 결과로 지금 세계가 어떠한가.

## 핵심 가치

- 같은 로그를 여러 기능이 반복 해석하는 문제를 줄인다.
- NPC·장소·아이템·단체가 플레이를 통해 어떤 역사를 가졌는지 추적할 수 있다.
- 현재 상태가 왜 그렇게 되었는지 사건 단위로 역추적할 수 있다.
- 설정 원본과 캠페인 플레이 결과를 분리하여 같은 설정을 다른 캠페인에서도 재사용할 수 있다.
- 장기 캠페인에서 전체 로그를 다시 읽지 않고 관련 사건만 검색하여 맥락을 복원할 수 있다.

## 기본 흐름

```text
세션 설계
  ↓
실제 플레이
  ↓
로그
  ↓
로그 분석
  ↓
캠페인 이벤트 원장
  ↓
├─ World State
├─ NPC Memory
├─ Knowledge Graph
├─ Story Thread
└─ 다음 세션 설계
```

## 사건 기본 구조

초기 MVP는 다음 필드를 기준으로 한다.

- `event_id`: 사건 고유 ID
- `session_id`: 발생 세션
- `scene_id`: 연결된 장면
- `type`: 사건 유형
- `actors`: 행동 주체
- `targets`: 영향을 받은 대상
- `location`: 발생 장소
- `summary`: 사건 요약
- `result`: 실제 결과
- `source_log`: 원본 로그 근거
- `importance`: 중요도

확장 시 다음 필드를 추가할 수 있다.

- `sequence`: 실제 발생 순서
- `assets`: 획득·분실·파괴된 아이템
- `witnesses`: 목격자
- `knowledge_scope`: 누가 알고 있는가
- `certainty`: 확정 사실 / 추정
- `effects`: 후속 상태 변화 후보
- `world_time`: 세계관 내부 시간
- `caused_by`: 선행 사건
- `correction_of`: 정정 대상 사건

## 사실·추론·효과 분리

사건 내부에서는 반드시 세 층을 구분한다.

- `facts`: 로그로 확정할 수 있는 사실
- `inferences`: 분석을 통해 추정한 해석
- `effects`: 후속 시스템에 적용할 상태 변화 후보

예를 들어 NPC가 PC를 노려본 경우, 사실은 "노려봄"이고 "증오함"은 추론이며, `suspicion +1`은 상태 변화 후보다.

- `minor`
- `normal`

중요도는 캠페인 요약, 하이라이트, 장기 로그 압축에 활용한다.

## 운영 원칙

- 사건은 가능하면 append-only 방식으로 보존한다.
- 잘못된 사건은 삭제보다 정정 사건을 추가하여 변경 이력을 남긴다.
- 모든 사건은 가능한 경우 원본 로그 근거를 가진다.
- 설정 문서 자체를 사건 기록으로 덮어쓰지 않는다.
- 파생 상태는 사건을 근거로 별도 World State 계층에서 관리하는 구조를 우선한다.
