# 스타일 개발 템플릿

새 스타일 분석을 시작할 때 이 폴더의 내부 구조를 복제해 `TRPG 데이터/20. 그림 스타일 분석/<스타일명>/` 개발 패키지를 만든다.

스타일 최상위 폴더에는 `dev_` 접두사를 붙이지 않는다. `dev_`는 내부 개발 하위 폴더와 개발 단계 자산에만 사용한다.

## 개발 중

- `dev_문서/`: 최종 정식 계약으로 승격할 문서 초안
- `dev_분석/`: 스타일 분석과 시안 판정 이력
- `dev_프롬프트 블록/`: 역할별 독립 프롬프트 블록
- `dev_앵커/`: 현재 승격 후보로 살아 있는 앵커만 보관
- `dev_견본 레퍼런스/`: 사용자 제공·수집 견본
- `dev_시안 레퍼런스/`: 생성 테스트와 실패·교정 시안

## 확정 시

1. `dev_문서/dev_스타일 계약.md`를 `<스타일명>.md`로 정규화하여 `라이브러리/스타일/`에 복사한다.
2. `dev_앵커/`의 확정 파일을 `라이브러리/견본/<스타일명>/`에 복사한다.
3. `dev_문서/dev_앵커 매니페스트.md`를 근거로 중앙 `정식 스타일 호출 규칙.md`에 역할과 최소 조합을 등록한다.
4. 이미지 모듈 AGENTS·마스터에는 스타일명과 라우팅만 연결한다.
5. `dev_분석`, `dev_프롬프트 블록`, `dev_시안 레퍼런스`는 개발 기록으로 `TRPG 데이터/20. 그림 스타일 분석/<스타일명>/`에 보존하며 런타임에는 연결하지 않는다.

개발 패키지는 정식 승격 전 이미지 생성 런타임에서 자동 호출하지 않는다.
