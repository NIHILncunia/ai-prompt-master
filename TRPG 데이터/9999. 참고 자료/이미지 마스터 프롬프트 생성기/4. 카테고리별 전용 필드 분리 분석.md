# 4. 카테고리별 전용 필드 분리 분석

## 1. 분석 목적

3번 단계에서는 2.1부터 2.11까지의 전체 카테고리를 묶는 공통 필드를 추출했다.

이번 4번 단계에서는 그중 `detailDesign` 내부를 카테고리별 전용 필드로 분리한다.

즉, 공통 구조는 유지하되 실제 입력 항목은 각 카테고리의 성격에 맞게 독립 스키마로 나누는 것이 목적이다.

---

## 2. 기본 원칙

전체 구조는 다음처럼 유지한다.

```text
공통 필드
- category
- usageTarget
- worldContext
- mainSubjectType
- outputPurpose
- detailDesign
- styleDirection
- mood
- backgroundSetting
- layout
- referenceImages
- textPolicy
- includeRequests
- excludeRequests
- additionalRequests
- automationPolicy
```

이 중 `detailDesign`만 카테고리별로 갈라진다.

```text
detailDesign

- characterSpecification
- creatureSpecification
- placeSpecification
- architectureSpecification
- sceneSpecification
- itemSpecification
- costumeSpecification
- machineSpecification
- symbolSpecification
- mapSpecification
- effectSpecification
```

내부 필드명은 카테고리별 의미가 분명해야 한다.

예를 들어 캐릭터에는 `appearance`가 필요하지만, 지도에는 필요하지 않다.

지도에는 `spatialStructure`와 `mapView`가 필요하지만, 캐릭터에는 필요하지 않다.

---

## 3. 분리 기준

카테고리별 전용 필드는 다음 기준으로 나눈다.

```text
1. 해당 카테고리에서만 의미가 있는가?
2. 다른 카테고리와 공유하면 의미가 흐려지는가?
3. 마스터 프롬프트 생성 시 반드시 다른 방식으로 문장화해야 하는가?
4. UI에서 독립 섹션으로 열고 닫을 필요가 있는가?
5. JSON 구조상 다른 카테고리와 충돌 가능성이 있는가?
```

이 기준에 따라 공통 필드와 전용 필드를 분리한다.

예를 들어 `색상`은 여러 카테고리에서 쓰이지만, 의미가 다르다.

캐릭터의 색상은 머리카락, 눈, 피부, 의상 색상일 수 있다.

효과의 색상은 발광, 에너지, 속성 표현의 색상이다.

지도 색상은 지형, 세력권, 바다, 경계선의 색상이다.

따라서 단순히 `color` 하나로 통합하지 않고, 카테고리별 상세 구조 안에 두는 것이 안전하다.

# 4.1 캐릭터 / 인물 전용 필드

## 필드명

```text
characterSpecification
```

## 역할

캐릭터 또는 인간형 존재의 외형, 인상, 의상, 특징 요소, 포즈, 표정, 레퍼런스 시트 여부를 담는다.

캐릭터는 생물 구조보다 **인물성, 외형, 실루엣, 표정, 의상, 분위기**가 중요하다.

## 권장 구조

```text
characterSpecification

- characterFocus
- numberOfCharacters
- roleArchetype
- ageRange
- bodyType
- heightImpression
- faceImpression
- expression
- gaze
- pose
- hair
- eyes
- skin
- distinctiveFeatures
- nonHumanTraits
- outfitSummary
- equipmentSummary
- characterMood
- referenceSheetOptions
```

## 세부 설명

```text
characterFocus
- 인물 자체, 얼굴, 전신, 의상, 포즈, 전투 자세 등 강조점을 담는다.

numberOfCharacters
- 인물 1명, 2명, 여러 명 여부를 담는다.

roleArchetype
- 주인공형, 악역형, 왕족형, 전사형, 마법사형, 신격형 같은 역할 인상을 담는다.

ageRange
- 어린아이, 청소년, 청년, 성인, 중년, 노년, 초월적 존재 등을 담는다.

bodyType
- 마른 체형, 평균 체형, 근육질, 장신, 거대한 체형 등을 담는다.

heightImpression
- 키 느낌을 담는다.

faceImpression
- 부드러운 인상, 차가운 인상, 사나운 인상, 고귀한 인상 등을 담는다.

expression
- 표정 정보를 담는다.

gaze
- 시선 방향과 눈빛 인상을 담는다.

pose
- 정면 자세, 전투 자세, 대기 자세, 앉은 자세 등을 담는다.

hair
- 머리색, 길이, 형태, 묶음 여부를 담는다.

eyes
- 눈색, 이색동공, 빛나는 눈 등을 담는다.

skin
- 피부색, 피부 타입, 흉터, 비늘, 특수 피부 질감을 담는다.

distinctiveFeatures
- 문신, 흉터, 뿔, 날개, 장식 요소 등을 담는다.

nonHumanTraits
- 동물 귀, 꼬리, 비늘, 악마적 요소, 천사적 요소 등을 담는다.

outfitSummary
- 캐릭터가 입은 의상의 요약 정보를 담는다.

equipmentSummary
- 무기, 장비, 소품 등의 요약 정보를 담는다.

characterMood
- 캐릭터 고유의 정서와 분위기를 담는다.

referenceSheetOptions
- 정면, 후면, 흉상, 키 눈금, 16:9 레퍼런스 시트 여부를 담는다.
```

## 제외해야 할 것

```text
- 세밀한 의상 부위 설계
- 무기 자체의 상세 구조
- 배경 전체 설계
- 몬스터 생물 구조 중심 설계
```

이들은 각각 2.7, 2.6, 2.3, 2.2로 보내는 편이 맞다.

# 4.2 몬스터 / 크리처 전용 필드

## 필드명

```text
creatureSpecification
```

## 역할

몬스터, 괴물, 크리처의 신체 구조, 표피, 위협성, 공격 방식, 생태, 크기감을 담는다.

몬스터는 캐릭터성보다 **생물 구조, 괴물성, 위협성, 생태, 특수 능력**이 중요하다.

## 권장 구조

```text
creatureSpecification

- creatureFocus
- creatureScale
- bodyStructure
- bodyProportion
- movementMethod
- silhouette
- surfaceType
- texture
- colorPattern
- damageOrCorruption
- hornsSpikes
- wings
- tail
- tentacles
- mouthTeeth
- eyes
- limbs
- attackMethod
- specialAbility
- intelligenceLevel
- temperament
- habitat
- ecologicalRole
```

## 세부 설명

```text
creatureFocus
- 단일 크리처, 보스 몬스터, 거대 괴수, 군체 등 강조점을 담는다.

creatureScale
- 소형, 중형, 대형, 거대, 초거대 등 크기를 담는다.

bodyStructure
- 인간형, 사족보행, 다족형, 비행형, 수중형, 비정형 등을 담는다.

bodyProportion
- 상체가 큰지, 팔다리가 긴지, 비대칭인지 등을 담는다.

movementMethod
- 걷기, 기어다니기, 비행, 헤엄, 순간이동, 부유 등을 담는다.

silhouette
- 날카로운 실루엣, 육중한 실루엣, 촉수 중심 실루엣 등을 담는다.

surfaceType
- 털, 비늘, 가죽, 갑각, 뼈, 금속, 점액, 식물성 표피 등을 담는다.

texture
- 매끈함, 거칠음, 축축함, 부패함, 단단함 등을 담는다.

colorPattern
- 생물의 색감과 무늬를 담는다.

damageOrCorruption
- 상처, 부패, 오염, 기생 흔적, 깨진 갑각 등을 담는다.

hornsSpikes
- 뿔, 가시, 돌기 요소를 담는다.

wings
- 날개 유형을 담는다.

tail
- 꼬리 유무와 형태를 담는다.

tentacles
- 촉수 유무와 형태를 담는다.

mouthTeeth
- 입, 턱, 이빨, 포식기관을 담는다.

eyes
- 눈 개수, 배치, 발광 여부를 담는다.

limbs
- 팔, 다리, 발톱, 관절 구조를 담는다.

attackMethod
- 물기, 할퀴기, 돌진, 독, 브레스, 빔, 정신 공격 등을 담는다.

specialAbility
- 재생, 은신, 비행, 차원 이동, 마법 저항 등 특수 능력을 담는다.

intelligenceLevel
- 야생동물 수준, 지능형, 집단지성, 초월적 지능 등을 담는다.

temperament
- 포식자, 광폭함, 교활함, 수호자, 기생성 등을 담는다.

habitat
- 서식 환경을 담는다.

ecologicalRole
- 포식자, 기생체, 수호 생물, 재난급 괴수 등 생태적 역할을 담는다.
```

## 제외해야 할 것

```text
- 인간형 캐릭터의 성격 중심 설계
- 탑승형 기계 병기
- 구조물형 골렘
- 특정 전투 장면의 사건성
```

이들은 각각 2.1, 2.8, 2.4, 2.5로 분리한다.

# 4.3 풍경화 / 배경 / 장소 / 세계관 전용 필드

## 필드명

```text
placeSpecification
```

## 역할

장소 전체의 공간감, 자연 요소, 인공 요소, 랜드마크, 조명, 환경 조건, 세계관성을 담는다.

이 카테고리는 단일 대상보다 **장소 전체의 인상과 공간 구조**가 중심이다.

## 권장 구조

```text
placeSpecification

- placeCategory
- placeType
- spatialStructure
- openness
- terrainElements
- naturalElements
- artificialElements
- landmark
- civilizationTrace
- worldbuildingFeature
- environmentalCondition
- lightingCondition
- weather
- timeOfDay
- populationPresence
- creaturePresence
```

## 세부 설명

```text
placeCategory
- 자연 공간, 문명 공간, 지하 공간, 실내 공간, 초현실 공간 등을 담는다.

placeType
- 숲, 도시, 동굴, 신전, 전장, 차원 공간 등 세부 장소를 담는다.

spatialStructure
- 넓게 펼쳐진 공간, 미로형, 복층, 계단식, 수직 구조 등을 담는다.

openness
- 개방감, 폐쇄감, 깊이감, 압박감 등을 담는다.

terrainElements
- 산, 강, 호수, 절벽, 습지, 사막, 설원 등 지형 요소를 담는다.

naturalElements
- 나무, 물, 바위, 안개, 식생, 동물 흔적 등을 담는다.

artificialElements
- 건물, 길, 다리, 폐허, 장벽, 탑, 제단 등 인공 요소를 담는다.

landmark
- 장소를 대표하는 핵심 랜드마크를 담는다.

civilizationTrace
- 거주 흔적, 전쟁 흔적, 폐허, 의식 흔적 등을 담는다.

worldbuildingFeature
- 세계관 고유 요소, 마법적 현상, 문명적 특징을 담는다.

environmentalCondition
- 습도, 먼지, 연기, 안개, 오염, 신성한 기운 등을 담는다.

lightingCondition
- 자연광, 달빛, 횃불, 마법광, 네온, 어둠 등을 담는다.

weather
- 맑음, 비, 폭풍, 눈, 모래바람 등을 담는다.

timeOfDay
- 새벽, 낮, 황혼, 밤 등을 담는다.

populationPresence
- 사람의 존재감 여부를 담는다.

creaturePresence
- 동물이나 괴물의 흔적 여부를 담는다.
```

## 제외해야 할 것

```text
- 단일 건축물 자체의 상세 설계
- 인물의 행동과 사건
- 지도처럼 위치 관계를 설명하는 구조
```

이들은 각각 2.4, 2.5, 2.10으로 보낸다.

# 4.4 건물 / 건축물 / 구조물 전용 필드

## 필드명

```text
architectureSpecification
```

## 역할

하나의 건물, 구조물, 시설, 장치, 관문, 랜드마크의 외형, 양식, 규모, 재질, 기능을 담는다.

이 카테고리는 장소 전체가 아니라 **단일 인공 대상의 구조적 정체성**이 중심이다.

## 권장 구조

```text
architectureSpecification

- architectureCategory
- architectureType
- cultureStyle
- architecturalStyle
- scale
- silhouette
- structuralForm
- mainFunction
- material
- ornament
- entranceDesign
- roofOrTopStructure
- verticality
- symmetry
- mechanicalElements
- magicalElements
- damageState
- surroundingContext
```

## 세부 설명

```text
architectureCategory
- 건축형, 방어형, 종교형, 연구형, 산업형, 장치형 등을 담는다.

architectureType
- 성, 신전, 마탑, 관문, 제단, 요새, 연구소 등 세부 유형을 담는다.

cultureStyle
- 서양풍, 동양풍, 중동풍, 북방풍, SF풍 등 문화권을 담는다.

architecturalStyle
- 고딕, 중세 유럽, 무협 문파, 마도공학, 미래 건축 등 양식을 담는다.

scale
- 소형, 대형, 거대, 도시급, 산만한 규모 등을 담는다.

silhouette
- 뾰족한 형태, 육중한 형태, 원형, 수직형, 계단형 등을 담는다.

structuralForm
- 탑형, 돔형, 성벽형, 부유형, 지하형, 기하학형 등을 담는다.

mainFunction
- 방어, 거주, 연구, 의식, 봉인, 이동, 감시 등 기능을 담는다.

material
- 석재, 목재, 금속, 수정, 유리, 생체 조직, 마법 에너지 등을 담는다.

ornament
- 조각, 문양, 룬, 깃발, 스테인드글라스, 기계 장식 등을 담는다.

entranceDesign
- 문, 관문, 계단, 다리, 포탈 입구 등을 담는다.

roofOrTopStructure
- 지붕, 첨탑, 돔, 마력 코어, 안테나, 부유 장치 등을 담는다.

verticality
- 낮고 넓은지, 높고 가느다란지, 수직성이 강한지 등을 담는다.

symmetry
- 대칭, 비대칭, 불가능한 기하학 등을 담는다.

mechanicalElements
- 톱니, 피스톤, 케이블, 엔진, 구동부 등을 담는다.

magicalElements
- 룬, 마법진, 결계, 마력 코어, 부유 마법 등을 담는다.

damageState
- 온전함, 폐허, 붕괴, 전투 피해, 오염 등을 담는다.

surroundingContext
- 주변 환경을 보조적으로 담는다.
```

## 제외해야 할 것

```text
- 도시 전체의 풍경
- 내부 평면도
- 조종 가능한 이동 기계
- 손에 드는 소형 장치
```

이들은 각각 2.3, 2.10, 2.8, 2.6으로 분리한다.

# 4.5 장면 / 서사 일러스트 전용 필드

## 필드명

```text
sceneSpecification
```

## 역할

사건, 행동, 갈등, 감정선, 관계, 순간성을 담는다.

이 카테고리는 단일 대상보다 **이야기 속 특정 순간**이 중심이다.

## 권장 구조

```text
sceneSpecification

- sceneCategory
- sceneEvent
- mainActors
- actorRoles
- actorReferences
- backgroundReference
- action
- interaction
- conflict
- emotionalArc
- tensionLevel
- narrativeMoment
- beforeAfterContext
- focalPoint
- cameraDistance
- cameraAngle
- cinematicDirection
```

## 세부 설명

```text
sceneCategory
- 전투, 탐험, 의식, 감정 장면, 재난, 추격, 결말 등을 담는다.

sceneEvent
- 결투, 봉인 해제, 재회, 배신, 도시 붕괴 등 세부 사건을 담는다.

mainActors
- 등장 인물, 몬스터, 집단, 신격 등 장면의 주체를 담는다.

actorRoles
- 공격자, 방어자, 희생자, 관찰자, 추격자 등 역할을 담는다.

- 엄폐물, 장애물, 이동 가능 공간, 전술 요소를 담는다.

gridPolicy
- 격자 없음, 격자 있음, 정사각 격자, 육각 격자 등을 담는다.

modulePolicy
- 모듈형 맵 여부, 연결부 정합성, 이어붙이기 구조를 담는다.

referenceReconstruction
- 참조 이미지 기반 재구성 여부를 담는다.

edgePolicy
- 지도 가장자리, 양피지 여백, 바다 채움, 경계선 처리 등을 담는다.
```

## 제외해야 할 것

```text
- 풍경화처럼 바라보는 장소 이미지
- 장면 일러스트
- 단일 건축물 외관
- 단일 상징 / 엠블럼
```

이들은 각각 2.3, 2.5, 2.4, 2.9로 분리한다.

# 4.11 개념 / 현상 / 효과 전용 필드

## 필드명

```text
effectSpecification
```

## 역할

비물질적인 현상, 에너지, 마법 효과, 오라, 저주, 축복, 차원 균열, 상태이상, 스킬 이펙트, 추상 개념의 시각화를 담는다.

이 카테고리는 형체 있는 대상보다 **현상 자체의 형태, 움직임, 속성, 발광, 밀도, 영향**이 중심이다.

## 권장 구조

```text
effectSpecification

- effectCategory
- effectType
- outputMode
- energyAttribute
- visualForm
- movementFlow
- originPoint
- scale
- colorPalette
- brightness
- density
- transparency
- texture
- environmentalImpact
- emotionalImpression
- stability
- iconPolicy
- vfxSheetPolicy
```

## 세부 설명

```text
effectCategory
- 마법 효과, 원소 현상, 저주, 축복, 오라, 차원 왜곡 등을 담는다.

effectType
- 불꽃, 번개, 검은 안개, 후광, 시간 왜곡 등 세부 효과를 담는다.

outputMode
- 효과 컨셉아트, VFX 시트, 스킬 이펙트, 아이콘 등을 담는다.

energyAttribute
- 불, 얼음, 빛, 어둠, 신성, 사령, 시간, 공간 등을 담는다.

visualForm
- 불꽃형, 안개형, 구체형, 균열형, 소용돌이형 등을 담는다.

movementFlow
- 피어오름, 회전, 분출, 수렴, 번짐, 찢어짐 등을 담는다.

originPoint
- 손, 무기, 마법진, 허공, 지면, 포탈 중심 등 발생 지점을 담는다.

scale
- 손바닥 크기, 캐릭터 주변, 전장 규모, 도시 규모 등을 담는다.

colorPalette
- 효과의 주 색상과 보조 색상을 담는다.

brightness
- 은은한 발광, 강한 발광, 내부 핵 발광 등을 담는다.

density
- 투명함, 안개처럼 흐림, 입자가 많음, 응축됨 등을 담는다.

transparency
- 불투명, 반투명, 거의 투명 등을 담는다.

texture
- 불꽃, 연기, 빛 입자, 플라즈마, 잉크, 유리 파편 등을 담는다.

environmentalImpact
- 주변을 밝힘, 지면을 태움, 공기를 왜곡함, 생명력을 흡수함 등을 담는다.

emotionalImpression
- 신성함, 불길함, 공포, 장엄함, 외계적임 등을 담는다.

stability
- 안정적, 불안정, 폭주, 붕괴, 사라지는 중 등을 담는다.

iconPolicy
- UI 아이콘형 표현 여부를 담는다.

vfxSheetPolicy
- 발동 전, 발동 중, 발동 후 같은 단계 표현 여부를 담는다.
```

## 제외해야 할 것

```text
- 효과를 사용하는 캐릭터 중심 장면
- 효과가 붙은 아이템 자체
- 효과가 포함된 지역 풍경
- 마법 문양이 대표 표식으로 쓰이는 로고
```

이들은 각각 2.5, 2.6, 2.3, 2.9로 분리한다.

# 5. detailDesign 내부 구조 제안

최종적으로 `detailDesign`은 다음처럼 구성하는 것이 좋다.

```text
detailDesign

- characterSpecification
- creatureSpecification
- placeSpecification
- architectureSpecification
- sceneSpecification
- itemSpecification
- costumeSpecification
- machineSpecification
- symbolSpecification
- mapSpecification
- effectSpecification
```

실제 저장 시에는 선택된 카테고리에 해당하는 하나만 활성화한다.

예시는 다음과 같다.

```text
category: character_person

detailDesign:
  characterSpecification:
    characterFocus:
    numberOfCharacters:
    roleArchetype:
    ageRange:
    bodyType:
    hair:
    eyes:
    skin:
    outfitSummary:
    referenceSheetOptions:
```

다른 카테고리의 전용 필드는 비워두거나 저장하지 않는다.

```text
category: concept_phenomenon_effect

detailDesign:
  effectSpecification:
    effectCategory:
    effectType:
    energyAttribute:
    visualForm:
    movementFlow:
    colorPalette:
    brightness:
    density:
    environmentalImpact:
```

이렇게 하면 JSON 구조가 불필요하게 커지는 것을 막을 수 있다.

# 6. 공통 필드와 전용 필드의 연결 방식

공통 필드는 마스터 프롬프트의 전체 방향을 결정한다.

전용 필드는 실제 이미지의 세부 내용을 결정한다.

```text
공통 필드
- 어떤 카테고리인가
- 어떤 사용처인가
- 어떤 세계관인가
- 어떤 결과물을 원하는가
- 어떤 스타일과 분위기인가
- 어떤 배경과 레이아웃인가

전용 필드
- 캐릭터라면 어떤 외형인가
- 몬스터라면 어떤 신체 구조인가
- 장소라면 어떤 공간인가
- 장면이라면 어떤 사건인가
- 아이템이라면 어떤 물건인가
- 효과라면 어떤 현상인가
```

즉, 공통 필드는 “방향”이고 전용 필드는 “내용”이다.
