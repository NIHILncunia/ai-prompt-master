# 6. 참조 이미지 조건부 사용 및 첨부 검증 규칙 통합

## 1. 단계 목적

이 단계는 참조 이미지 기능을 어떤 조건에서 사용할 수 있는지, UI에서 언제 노출할지, 참조 이미지를 선택했을 때 마스터 프롬프트에 어떻게 반영할지, 그리고 실제 이미지 첨부 여부를 어떻게 검증할지 정리하는 단계다.

기존에는 참조 이미지 사용 규칙과 참조 이미지 플레이스홀더 / 첨부 검증 규칙을 별도 단계로 볼 수 있었지만, 실제 웹앱 흐름에서는 하나의 기능 흐름으로 처리하는 것이 자연스럽다.

따라서 참조 이미지 관련 규칙은 모두 6번 단계로 통합한다.

---

## 2. 핵심 결론

참조 이미지는 모든 사용처에서 제공하지 않는다.

참조 이미지는 채팅형 이미지 생성 서비스를 선택했을 때에만 사용할 수 있다.

```text
참조 이미지 사용 가능:
- GPT / ChatGPT 이미지 생성
- Gemini / Imagen
- Grok
```

다음 사용처에서는 참조 이미지 선택지 자체를 UI에서 제거한다.

```text
참조 이미지 선택지 제거:
- Midjourney
- NovelAI
- FLUX
- SDXL
- SD 1.5
- Pony
- Illustrious / IL
- NoobAI
- Z-Image-Turbo / ZIT
- 모르겠음 / 범용
- 기타 / 직접 입력
```

즉, 사용처가 비채팅형 모델 계열이면 참조 이미지 관련 UI는 아예 표시하지 않는다.

이 규칙은 프롬프트 문장 생성 규칙이 아니라, 웹앱의 조건부 UI 노출 규칙으로 처리한다.

---

## 3. 참조 이미지 UI 노출 규칙

사용자가 1단계에서 사용처를 선택하면, 해당 사용처에 따라 참조 이미지 기능의 노출 여부가 결정된다.

```text
사용처가 GPT / ChatGPT 이미지 생성
→ 참조 이미지 기능 노출

사용처가 Gemini / Imagen
→ 참조 이미지 기능 노출

사용처가 Grok
→ 참조 이미지 기능 노출

사용처가 Midjourney, NovelAI, FLUX, SDXL, Pony 등
→ 참조 이미지 기능 미노출
```

참조 이미지 기능이 미노출되는 경우, 사용자는 해당 단계에서 참조 이미지 여부를 선택할 수 없다.

또한 마스터 프롬프트에도 참조 이미지 관련 문구를 넣지 않는다.

---

## 4. 참조 이미지 선택 방식

참조 이미지를 사용할 수 있는 사용처를 선택한 경우, 카테고리와 세부 유형에 따라 필요한 참조 이미지 유형을 선택할 수 있다.

예시는 다음과 같다.

```text
- 캐릭터 참조 이미지
- 몬스터 참조 이미지
- 배경 참조 이미지
- 구조물 참조 이미지
- 아이템 참조 이미지
- 의상 참조 이미지
- 메카 / 기계 참조 이미지
- 상징 / 로고 참조 이미지
- 지도 참조 이미지
- 효과 참조 이미지
- 스타일 참조 이미지
```

단, 참조 이미지 선택지는 카테고리의 중심 대상과 맞아야 한다.

예를 들어 캐릭터 카테고리에서는 캐릭터 참조 이미지가 중심이 되고, 장면 카테고리에서는 캐릭터 참조 이미지와 배경 참조 이미지를 함께 사용할 수 있다.

---

## 5. 캐릭터 참조 이미지 슬롯 규칙

캐릭터 참조를 선택한 경우, 선택한 유형에 따라 필요한 참조 이미지 개수가 정해진다.

```text
캐릭터 1명 참조
→ [캐릭터 참조 이미지 1]

캐릭터 2명 참조
→ [캐릭터 참조 이미지 1]
→ [캐릭터 참조 이미지 2]

여러 명 참조
→ 선택한 인원 수만큼 참조 이미지 슬롯 생성
```

즉, 캐릭터 참조 이미지는 단순히 “참조 있음”으로 끝나지 않는다.

몇 명의 캐릭터를 참조할 것인지에 따라 필요한 이미지 슬롯 수가 달라진다.

---

## 6. 마스터 프롬프트 내 플레이스홀더 규칙

참조 이미지를 선택한 경우, 마스터 프롬프트에는 실제 파일명이나 임의 설명이 아니라 플레이스홀더를 넣는다.

예시는 다음과 같다.

```text
[캐릭터 참조 이미지 1]
[캐릭터 참조 이미지 2]
[배경 참조 이미지 1]
[아이템 참조 이미지 1]
[지도 참조 이미지 1]
[효과 참조 이미지 1]
```

이 플레이스홀더는 사용자가 채팅형 AI에게 실제 이미지를 함께 전달해야 한다는 표시다.

마스터 프롬프트는 해당 플레이스홀더를 기준으로 채팅형 AI에게 어떤 이미지를 어떤 용도로 참고해야 하는지 지시한다.

---

## 7. 참조 이미지 필수 첨부 검증 규칙

참조 이미지를 선택한 경우, 해당 이미지를 실제로 첨부해야 다음 단계로 진행할 수 있다.

```text
참조 이미지 사용 안 함
→ 바로 진행 가능

참조 이미지 사용 선택
→ 필요한 참조 이미지 슬롯 생성

필수 슬롯이 모두 채워짐
→ 다음 단계 진행 가능

필수 슬롯 중 하나라도 비어 있음
→ 마스터 프롬프트 생성 불가
```

즉, 참조 이미지 선택은 단순한 옵션값이 아니라 실제 첨부 검증과 연결되는 조건이다.

사용자가 참조 이미지를 선택해놓고 실제 이미지를 전달하지 않으면, 웹앱은 마스터 프롬프트 생성을 진행하지 않아야 한다.

---

## 8. 참조 이미지 누락 시 처리

참조 이미지 슬롯이 비어 있는 경우, 사용자는 다음 단계로 넘어갈 수 없다.

이때 UI는 누락된 슬롯을 명확히 알려야 한다.

```text
예:
[캐릭터 참조 이미지 2]가 첨부되지 않았습니다.
참조 이미지를 첨부하거나, 해당 참조 사용을 해제해야 합니다.
```

처리 방식은 두 가지다.

```text
1. 누락된 참조 이미지를 첨부한다.
2. 해당 참조 이미지 사용 선택을 해제한다.
```

참조 이미지 사용 선택을 해제하면 해당 플레이스홀더도 마스터 프롬프트에서 제거된다.

---

## 9. 참조 이미지 해석 원칙

참조 이미지는 카테고리의 중심 목적에 맞게 해석해야 한다.

```text
캐릭터 참조 이미지
- 캐릭터의 외형, 얼굴, 의상, 실루엣, 분위기를 참고한다.

배경 참조 이미지
- 장소의 구조, 분위기, 색감, 조명, 공간감을 참고한다.

아이템 참조 이미지
- 아이템의 형태, 재질, 장식, 실루엣을 참고한다.

지도 참조 이미지
- 지형 구조, 공간 배치, 해안선, 동선, 구역 배치를 참고한다.

효과 참조 이미지
- 색상, 발광, 밀도, 움직임, 입자감, 에너지 흐름을 참고한다.

스타일 참조 이미지
- 대상 자체가 아니라 화풍, 렌더링 방식, 색감, 질감, 분위기를 참고한다.
```

참조 이미지는 무조건 그대로 복제하는 용도가 아니다.

웹앱은 참조 이미지가 어떤 목적으로 사용되는지 마스터 프롬프트 안에서 명확히 지시해야 한다.

---

## 10. 참조 이미지와 auto / none 규칙의 관계

참조 이미지 사용 여부는 5번 단계의 `auto`, `none`, `directInput`, `selected` 규칙과 함께 처리된다.

```text
참조 이미지 사용 안 함
→ 참조 이미지 관련 필드는 생성하지 않는다.

참조 이미지 사용 선택
→ selected 상태로 처리한다.

참조 이미지 슬롯이 생성되었으나 파일이 없음
→ 검증 실패

참조 이미지 사용 해제
→ 참조 이미지 관련 필드 제거
```

참조 이미지 선택은 `auto`로 처리하지 않는다.

참조 이미지는 실제 파일 첨부가 필요한 기능이므로, 사용자가 명시적으로 선택해야 한다.

---

## 11. 최종 결론

6번 단계는 다음 내용을 통합한다.

```text
- 참조 이미지 사용 가능 조건
- 사용처별 참조 이미지 UI 노출 여부
- 참조 이미지 유형 선택
- 참조 이미지 슬롯 생성
- 마스터 프롬프트 내 플레이스홀더 삽입
- 실제 이미지 첨부 여부 검증
- 참조 이미지 누락 시 진행 차단
```

가장 중요한 결론은 다음과 같다.

```text
참조 이미지는 채팅형 이미지 생성 서비스를 선택했을 때에만 사용할 수 있다.
비채팅형 모델 계열에서는 참조 이미지 선택지 자체를 UI에서 제거한다.
참조 이미지를 선택했다면 실제 이미지를 첨부해야 하며, 누락 시 마스터 프롬프트 생성을 진행할 수 없다.
```

## 7. 사용처별 프롬프트 스타일 규칙 연결

사용처별로 최종 영문 프롬프트가 어떤 형식으로 작성되어야 하는지 정리한다.

이 웹앱은 최종 이미지 생성 프롬프트를 직접 만드는 것이 아니라, 채팅형 AI에게 전달할 마스터 프롬프트를 생성한다.

따라서 이 단계에서는 사용처별로 “최종 프롬프트를 어떤 방식으로 작성하라고 지시할 것인가”를 정리한다.

---

## 8. 마스터 프롬프트 생성 규칙 설계

공통 필드, 카테고리별 전용 필드, selected / auto / directInput / none 처리 규칙, 참조 이미지 플레이스홀더, 포함 요청, 제외 요청을 실제 마스터 프롬프트 문장 구조로 조립하는 단계다.

이 단계가 통합 설계의 핵심이다.

---

## 9. UI 단계 흐름 및 JSON 데이터 구조화

마지막 단계에서는 실제 웹앱의 입력 흐름과 저장 구조를 정리한다.

사용자가 어떤 순서로 선택하는지, 어떤 항목이 조건부로 노출되는지, 어떤 항목이 필수인지 정리한다.

이후 그 흐름을 바탕으로 최종 JSON 데이터 구조를 확정한다.
