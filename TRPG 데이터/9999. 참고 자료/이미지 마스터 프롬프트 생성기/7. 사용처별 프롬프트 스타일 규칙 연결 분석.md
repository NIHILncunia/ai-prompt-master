# 7. 사용처별 프롬프트 스타일 규칙 연결 분석

## 1. 단계 목적

이 단계는 사용처별로 최종 영문 프롬프트가 어떤 형식으로 작성되어야 하는지 정리하는 단계다.

이 웹앱은 이미지 생성 모델에 직접 넣을 최종 프롬프트를 생성하는 도구가 아니다.

웹앱은 GPT / Gemini / Grok 같은 채팅형 AI에게 전달할 **마스터 프롬프트**를 생성하고, 채팅형 AI가 그 마스터 프롬프트를 바탕으로 실제 이미지 생성용 **영문 프롬프트**를 작성한다.

따라서 이 단계에서 정리해야 하는 것은 “각 이미지 생성 사용처에 맞춰 최종 영문 프롬프트를 어떻게 작성하라고 지시할 것인가”이다.

---

## 2. 핵심 결론

사용처별 프롬프트 스타일 규칙은 최종 이미지 프롬프트의 출력 방식을 결정한다.

같은 캐릭터 이미지라도 사용처가 GPT 이미지 생성인지, Midjourney인지, NovelAI인지, SDXL인지에 따라 최종 프롬프트 문법이 달라져야 한다.

```text
사용처별로 달라지는 것:
- 문장형 프롬프트인지 태그형 프롬프트인지
- 자연어 서술 중심인지 키워드 나열 중심인지
- 부정 조건을 어떻게 처리할지
- 스타일 키워드를 얼마나 강하게 넣을지
- 파라미터나 옵션을 포함할지
- 참조 이미지 플레이스홀더를 사용할 수 있는지
```

사용처별 규칙은 이미지 내용 자체를 바꾸는 것이 아니라, 같은 내용을 해당 사용처가 이해하기 좋은 형식으로 변환하는 역할을 한다.

---

1단계 사용처 선택지는 다음과 같이 유지한다.

```text

```

이 목록은 사용자가 최종 프롬프트를 어디에 사용할지 정하는 단계다.

선택된 사용처는 최종 영문 프롬프트의 구조와 문체를 결정한다.

---

## 4. 사용처 그룹 분류

사용처는 크게 네 그룹으로 나누는 것이 좋다.

```text
A. 채팅형 이미지 생성 서비스
- GPT / ChatGPT 이미지 생성
- Gemini / Imagen
- Grok

B. 자연어 + 파라미터형 서비스
- Midjourney

C. 자연어 / 서술형 모델 계열
- FLUX
- Z-Image-Turbo / ZIT
- 모르겠음 / 범용
- 기타 / 직접 입력

D. 태그형 / Stable Diffusion 계열
- NovelAI
- SDXL
- SD 1.5
- Pony
- Illustrious / IL
- NoobAI
```

이 그룹 분류는 UI와 마스터 프롬프트 생성 규칙에 모두 영향을 준다.

특히 참조 이미지 기능은 A 그룹에서만 제공한다.

# 5. A 그룹: 채팅형 이미지 생성 서비스

## 대상

```text
- GPT / ChatGPT 이미지 생성
- Gemini / Imagen
- Grok
```

## 기본 방향

채팅형 이미지 생성 서비스는 자연어 서술형 프롬프트가 가장 적합하다.

최종 영문 프롬프트는 태그 나열보다 문장형 설명을 중심으로 작성하게 한다.

```text
권장 형식:
- 명확한 자연어 문장
- 이미지의 중심 대상 설명
- 구도와 분위기 설명
- 배경과 조명 설명
- 포함해야 할 요소와 제외해야 할 요소를 자연스럽게 명시
```

## 참조 이미지 사용

A 그룹은 참조 이미지 기능을 사용할 수 있다.

6번 규칙에 따라, 참조 이미지를 선택한 경우 마스터 프롬프트에는 플레이스홀더가 들어간다.

```text
예:
[캐릭터 참조 이미지 1]
[배경 참조 이미지 1]
```

참조 이미지를 선택했다면 실제 이미지 첨부가 필수다.

첨부가 누락되면 마스터 프롬프트 생성 또는 다음 단계 진행을 막아야 한다.

## 최종 프롬프트 지시 방향

A 그룹을 선택한 경우, 마스터 프롬프트는 채팅형 AI에게 다음을 요구해야 한다.

```text
- 최종 프롬프트를 영어 자연어로 작성한다.
- 이미지 생성 모델이 바로 이해할 수 있도록 구체적이고 명확하게 쓴다.
- 지나치게 태그처럼 나열하지 않는다.
- 참조 이미지가 있다면 플레이스홀더를 기준으로 어떤 이미지를 어떻게 참고해야 하는지 명시한다.
- 텍스트 없음, 배경 없음, 날개 없음 같은 none 조건은 자연어로 명확히 반영한다.
```

# 6. GPT / ChatGPT 이미지 생성

## 프롬프트 스타일

GPT / ChatGPT 이미지 생성용 최종 프롬프트는 자연어 설명 중심으로 작성한다.

```text
특징:
- 완성된 이미지 요청문처럼 작성
- 대상, 배경, 분위기, 구도, 스타일을 문장으로 연결
- 참조 이미지가 있을 경우 참조 대상과 유지해야 할 요소를 명확히 설명
```

## 권장 출력 방향

```text
- 한 문단 또는 여러 짧은 문단의 영어 프롬프트
- 장면과 대상의 관계를 명확히 설명
- 이미지 편집이나 참조 이미지 기반 생성에 가까운 경우, 참조 이미지 유지 요소를 구분
```

## 주의점

```text
- 불필요한 태그 나열을 피한다.
- 지나치게 긴 부정 프롬프트를 만들지 않는다.
- 참조 이미지가 없는 경우 참조 이미지 관련 문장을 넣지 않는다.
```

# 7. Gemini / Imagen

## 프롬프트 스타일

Gemini / Imagen용 최종 프롬프트도 자연어 서술형을 기본으로 한다.

```text
특징:
- 대상의 시각적 설명을 명확하게 작성
- 이미지 전체의 분위기와 구도를 자연스럽게 설명
- 현실적 묘사와 창작적 묘사를 모두 처리할 수 있도록 구체적으로 작성
```

## 권장 출력 방향

```text
- 영어 자연어 프롬프트
- 중심 대상과 배경의 관계를 분명히 설명
- 색상, 조명, 분위기, 스타일을 자연어로 연결
```

## 주의점

```text
- 태그형 프롬프트보다 설명형 프롬프트를 우선한다.
- 참조 이미지가 있는 경우, 플레이스홀더와 참조 목적을 명확히 연결한다.
```

---

# 8. Grok

## 프롬프트 스타일

Grok용 최종 프롬프트도 채팅형 이미지 생성 서비스로 보고 자연어 설명 중심으로 작성한다.

```text
특징:
- 프롬프트 의도를 직접적이고 명확하게 설명
- 대상, 스타일, 배경, 구도를 분리해서 이해하기 쉽게 작성
- 참조 이미지가 있는 경우 어떤 요소를 참고할지 명시
```

## 권장 출력 방향

```text
- 영어 자연어 프롬프트
- 핵심 대상과 장면 목적을 먼저 설명
- 세부 묘사는 뒤에 덧붙임
```

## 주의점

```text
- 사용자가 원하는 대상이 흐려지지 않도록 중심 대상을 먼저 쓴다.
- 참조 이미지가 없는 경우 참조 이미지 문구를 생성하지 않는다.
```

# 9. B 그룹: Midjourney

## 기본 방향

Midjourney는 자연어 설명과 키워드형 문구가 섞인 프롬프트가 적합하다.

최종 프롬프트는 너무 긴 문장보다 핵심 시각 요소를 압축적으로 나열하는 방향이 좋다.

```text
권장 형식:
- 핵심 대상
- 주요 스타일
- 배경
- 조명
- 분위기
- 구도
- 세부 디테일
- 필요 시 파라미터
```

## 참조 이미지

이 프로젝트에서는 Midjourney를 선택했을 때 참조 이미지 선택지를 제공하지 않는다.

따라서 마스터 프롬프트에도 참조 이미지 플레이스홀더를 넣지 않는다.

## 최종 프롬프트 지시 방향

```text
- 최종 프롬프트를 영어로 작성한다.
- 자연어 문장과 키워드 구문을 혼합한다.
- 핵심 시각 요소를 앞쪽에 배치한다.
- 쉼표로 구분된 시각 키워드를 사용할 수 있다.
- 필요하면 화면비나 스타일 관련 파라미터를 마지막에 배치한다.
- 참조 이미지 플레이스홀더는 사용하지 않는다.
```

## 주의점

```text
- 과도하게 설명적인 문단형 프롬프트는 피한다.
- Stable Diffusion식 태그만 나열하지 않는다.
- 부정 조건은 간단히 정리한다.
```

# 10. C 그룹: 자연어 / 서술형 모델 계열

## 대상

```text
- FLUX
- Z-Image-Turbo / ZIT
- 모르겠음 / 범용
- 기타 / 직접 입력
```

## 기본 방향

이 그룹은 자연어 서술형 프롬프트를 기본으로 한다.

다만 GPT / Gemini / Grok처럼 참조 이미지 플레이스홀더를 사용하지 않는다.

```text
권장 형식:
- 영어 자연어 중심
- 대상 설명을 구체적으로 작성
- 스타일과 분위기를 명확히 작성
- 태그보다는 문장형 설명 우선
```

## 참조 이미지

이 그룹에서는 참조 이미지 선택지를 제공하지 않는다.

따라서 마스터 프롬프트에는 참조 이미지 관련 항목을 넣지 않는다.

## 최종 프롬프트 지시 방향

```text
- 최종 프롬프트를 영어 자연어로 작성한다.
- 중심 대상, 배경, 스타일, 조명, 구도를 구체적으로 설명한다.
- 불필요한 참조 이미지 플레이스홀더를 넣지 않는다.
- 사용처가 모르겠음 / 범용이면 특정 모델 파라미터에 의존하지 않는 범용 프롬프트로 작성한다.
```


# 13. 모르겠음 / 범용

```text
- 대부분의 이미지 생성 모델에서 의미가 통할 수 있는 영어 프롬프트
- 대상, 스타일, 배경, 조명, 분위기, 구도를 균형 있게 포함
```

# 14. D 그룹: 태그형 / Stable Diffusion 계열

## 대상

```text
- NovelAI
- SDXL
- SD 1.5
- Pony
- Illustrious / IL
- NoobAI
```

## 기본 방향

D 그룹은 태그형 또는 태그 혼합형 프롬프트가 적합하다.

특히 NovelAI, Pony, Illustrious / IL, NoobAI 계열은 태그 기반 프롬프트를 우선하는 방향이 좋다.

SDXL과 SD 1.5는 자연어와 태그를 모두 사용할 수 있지만, 이 프로젝트에서는 구조화된 키워드 중심 프롬프트를 생성하도록 지시하는 것이 안정적이다.

## 참조 이미지

D 그룹에서는 참조 이미지 선택지를 제공하지 않는다.

따라서 마스터 프롬프트에도 참조 이미지 플레이스홀더를 넣지 않는다.

## 최종 프롬프트 지시 방향

```text
- 최종 프롬프트를 영어로 작성한다.
- 핵심 태그와 시각 키워드를 중심으로 구성한다.
- 필요한 경우 positive prompt와 negative prompt를 분리한다.
- 선택값, 직접 입력값, 포함 요청을 positive prompt에 반영한다.
- none과 제외 요청은 negative prompt 또는 부정 조건에 반영한다.
- 참조 이미지 플레이스홀더는 사용하지 않는다.
```

# 15. NovelAI

## 프롬프트 스타일

NovelAI용 최종 프롬프트는 태그 중심으로 작성한다.

```text
특징:
- 쉼표로 구분된 영어 태그
- 캐릭터 외형, 구도, 분위기, 배경, 스타일 태그 중심
- 부정 조건은 별도 negative prompt로 분리 가능
```

## 권장 출력 방향

# 21. none / 제외 요청 처리 방식

사용처별로 none과 제외 요청 처리 방식은 달라진다.

```text
채팅형 이미지 생성 서비스:
- 자연어로 부정 조건을 명확히 설명한다.

Midjourney:
- 간결한 부정 표현 또는 사용처에 맞는 제외 표현을 사용한다.

Stable Diffusion 계열:
- negative prompt로 분리한다.

범용 / 자연어 계열:
- 짧은 부정 문장으로 정리한다.
```

예시는 다음과 같다.

```text
텍스트 없음
- no text
- no letters
- no labels

날개 없음
- no wings
- wingless

배경 없음
- plain background
- no detailed background
- isolated subject
```

다만 부정 조건은 과도하게 늘리지 않는다.

사용자가 명시한 none과 제외 요청을 중심으로만 반영한다.

# 22. directInput 처리 방식

directInput은 사용처와 관계없이 가장 중요한 사용자 의도 중 하나다.

```text
처리 원칙:
- 고유명사는 유지한다.
- 세계관 용어는 임의로 일반화하지 않는다.
- 한국어 직접 입력은 최종 영문 프롬프트에서 의미를 영어로 옮긴다.
- 단, 고유명사는 원문을 유지한다.
```

예시는 다음과 같다.

```text
직접 입력:
룩스테라의 앙그라의 안개

처리:
Angra's Mist of Luxterra
```

또는 고유명사 보존을 더 강하게 할 경우 다음처럼 처리할 수 있다.

```text
Angra's Mist from Luxterra
```

최종 처리 방식은 마스터 프롬프트 생성 규칙에서 확정한다.

# 25. 마스터 프롬프트에 포함할 사용처별 지시
