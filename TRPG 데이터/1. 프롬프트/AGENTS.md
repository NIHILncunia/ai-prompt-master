# TRPG 데이터 프롬프트 라우팅 지침

## 파일 형식 최우선 규칙

- 프로젝트에서 신규 생성·수정·갱신하는 모든 문서 파일은 Markdown 형식인 `.md`로 관리한다.
- Google Docs, Google Sheets, Google Slides 등 Google Workspace 네이티브 문서를 직접 생성하지 않는다.
- 표 형식의 데이터도 별도 스프레드시트를 만들지 않고 가능한 범위에서 Markdown 표 또는 Markdown 문서 내부 구조로 작성한다.
- Google Drive에 직접 반영할 때에는 로컬 `.md` 파일을 업로드하거나 기존 `.md` 파일의 원본 ID를 유지하여 갱신한다.
- 기존 네이티브 문서를 교체해야 할 때에는 동일 내용을 `.md`로 작성·검증한 뒤 혼동 방지를 위해 네이티브 문서를 제거한다.
- 사용자의 일회성 요청이 있더라도 프로젝트 산출물의 기본 형식은 `.md`를 유지하며, 다른 형식이 반드시 필요한 경우에만 별도 산출물로 취급한다.


## 문서 역할

이 문서는 `TRPG 데이터/1. 프롬프트` 루트의 기능 라우터다.

`TRPG 데이터/AGENTS.md`가 프로젝트 전체의 정본 경계와 작업 정책을 담당한다면, 이 문서는 사용자의 요청을 현재 활성 기능으로 분류하고 해당 기능 폴더의 `AGENTS.md`와 `0. ... 마스터 프롬프트.md`로 연결하는 역할만 담당한다.

세부 생성 규칙, 설정 규칙, 룰북 판정 규칙, Foundry VTT 세부 규칙을 이 문서에 복제하지 않는다.

## 진입 순서

프롬프트 기능을 사용하는 작업은 다음 순서로 진입한다.

1. 사용자의 요청 유형 판정
2. 이 문서의 라우팅 캐시에서 기능 선택
3. 캐시된 폴더 ID로 선택 기능 폴더를 직접 열고 직계 하위 구조 확인
4. 기능 폴더의 `AGENTS.md` 확인
5. 기능 폴더의 `0. ... 마스터 프롬프트.md` 확인
6. 마스터가 지정한 실행 문서·라이브러리·템플릿 확인
7. 작업 수행

번호나 폴더명은 개편될 수 있으므로 오래된 문서나 기억만으로 새 경로를 추정하지 않는다. 다만 정상 작업마다 Drive 전체 검색으로 재검증하지 않고 아래 캐시를 우선 사용한다.

## 1. 이미지 생성 모듈

이미지 생성 계열 요청은 모두 다음 루트로 진입한다.

`TRPG 데이터/1. 프롬프트/1. 이미지 생성 모듈`

내부 기능은 다음과 같다.

1. 반실사 포트레이트
2. 배틀맵 생성
3. 캐릭터 레퍼런스 생성
4. 세션 하이라이트 이미지 생성
5. 캐릭터 레퍼런스 V2 생성
6. 풍경 생성
7. 게임 아이콘 생성
8. 월드 지도 생성

이미지 요청은 먼저 `1. 이미지 생성 모듈/공통/1. 이미지 생성 공통 승인 절차.md`를 확인한다. 종족·고유 생물·기계 생명체 분류가 포함된 경우 관련 시각 자료 탐색 규칙을 적용한 뒤 요구사항 확인서와 최종 영어 프롬프트의 초안을 작성한다. 공개 전에는 `1. 이미지 생성 모듈/공통/6. 이미지 생성 프롬프트 점검 및 교정 지침.md`의 P01~P10을 모두 검사한다.

사용자의 명시적 승인 전에는 이미지 생성 도구를 호출하지 않는다.

점검을 통과한 요구사항 확인서와 최종 영어 프롬프트를 공개한 직후의 `다음`은 `생성`·`진행`·`승인`과 같은 명시적 생성 승인으로 해석한다. 확인 절차 완료 전의 `다음`은 현재 절차의 다음 단계 진행으로만 처리하고, 생성 완료 후의 `다음`은 새 산출물 요청으로 보아 다시 확인 절차를 거친다.

### 포트레이트 고정 계약

반실사 포트레이트의 기본 출력 흐름은 다음과 같다.

1. 전신 9:16 1장
2. 전신 디자인 확정
3. 확정 전신 기반 흉상 9:16 1장 또는 완성형 VTT 토큰 1:1 1장

흉상은 동일 인물·동일 의상·동일 색·동일 종족 특징을 유지하는 확대형 결과물이다. 사용자 업로드 이미지도 내부 1번에서 직접 완성형 VTT 토큰으로 처리한다.

현재 스타일은 현실적 반실사 기반의 붓터치 일러스트 분위기를 사용한다.

### 이미지 결과 저장

완료된 이미지 산출물은 기본적으로 `TRPG 데이터/15. 이미지 생성 결과/<유형>/`에 로컬 저장한다. 단, 설정화는 `TRPG 데이터/16. 컨셉 이미지/`에 저장하고 16:9 가로형 또는 9:16 세로형으로만 제작한다. `<유형>`은 `캐릭터`, `배틀맵`, `아이콘`, `아이템` 등 실제 산출물 목적에 맞게 정하며, 폴더가 없으면 생성한다. 단, 내부 3번 및 5번 캐릭터 레퍼런스 시트는 `TRPG 데이터/3. 캐릭터 레퍼런스 이미지/`에 저장하며 하위 분류는 마스터가 정한다. 같은 이름의 파일을 덮어쓰지 않는다. 전체 분류·저장 규칙은 `TRPG 데이터/AGENTS.md`의 `이미지 생성 결과 저장`을 따른다.

## 컨셉 이미지와 설정화

- 설정화는 세션 진행과 직접 연관된 중요한 아이템·유물·장치·구조물 등의 디자인과 시각 설정을 확정하기 위한 이미지다.
- 모든 설정화는 가로형 16:9 또는 세로형 9:16 중 하나로 제작한다. 정사각형과 임의 비율은 설정화 산출물로 사용하지 않는다.
- 가로로 긴 무기·장치처럼 대상의 실루엣이 좌우로 펼쳐지는 경우에는 16:9를 우선하고, 세로형 대상이나 인물 중심 설정화는 9:16을 우선한다.
- 설정화의 최종 저장 루트는 `TRPG 데이터/16. 컨셉 이미지/`이며 Google Drive 폴더 ID는 `1ebjSGyH75RCgwV9W0pLqJoOzV5j-QKk-`다.
- `16. 컨셉 이미지`는 프롬프트 기능 번호가 아니라 장기 보관용 산출물 폴더다. 생성 요청은 1번 이미지 생성 모듈에서 목적에 맞는 기존 기능과 공통 승인 절차로 처리한다.
- 하위 폴더는 캠페인·세션·대상·아이템과 시안 수를 기준으로 작업 시점에 판단하여 만든다. 고정된 깊이나 분류 체계를 강제하지 않는다.
- 같은 대상의 여러 디자인 시안은 구분 가능한 파일명으로 모두 보존하며 기존 파일을 덮어쓰지 않는다. 최종 선택과 불필요한 시안 삭제는 마스터가 결정한다.
- 완성형 VTT 토큰 1:1, 캐릭터 레퍼런스 V2 고정 캔버스 등 별도의 기능 고정 계약을 가진 산출물은 이 설정화 비율 규칙의 적용 대상이 아니다.

## 2. 로그 하이라이트 추출

세션 로그에서 장면 후보, 주요 사건, 감정적 전환, 전투·발견·결정의 핵심 순간을 추출하는 기능이다.

이미지 생성 기능이 아니다. 추출 결과를 세션 하이라이트 이미지 제작에 넘길 수는 있으나, 이미지 생성 자체는 1번 이미지 생성 모듈의 4번 내부 기능으로 라우팅한다.

## 3. 로그 분석

세션 로그의 진행 내용, 인물 행동, 사건 연속성, 미해결 요소, 설정 반영 여부 등을 분석한다.

사용자가 이전 로그와 이어지는 세션 제작을 요청하면 필요 범위의 로그 분석 결과를 8번 세션 제작에 제공한다.

## 4. 룰북 관련 요청

TRPG 룰북, 시스템 규칙, 판정, 클래스·특성·주문·장비 등 룰 데이터 조회를 담당한다.

룰북 원문이나 업로드된 시스템 자료가 존재하면 해당 Google Drive 룰북 자료를 정본으로 사용한다. Codex CLI에서는 Git 로컬 작업 폴더를 검색해 조회한다. 먼저 보유 목록과 요청 대상의 기본 룰북을 직접 확인하며, 이 Google Drive 룰북 검색은 웹검색·검색 엔진·외부 웹사이트·Google Drive 커넥터 사용을 뜻하지 않는다. 자료에 없는 내용은 추정하거나 웹에서 보완하지 않고 확인 불가로 처리한다.

## 5. 설정 관련 요청

세계관 설정 조회, 정비, 정합성 검토, 문서 작성·수정, 템플릿 적용을 담당한다.

설정 정본은 `프로젝트 위그드라실`에서 찾는다. 현재 Drive 구조와 과거 기억이 충돌하면 현재 Drive 구조를 우선한다.

설정 정비 작업은 각 시리즈 또는 공통 설정의 정비 지침과 이력 문서를 함께 확인한다.

## 6. FVTT 관련 요청

Foundry VTT 운용, 씬·토큰·데이터 파일·매크로·설정 보조를 담당한다.

이미지 자산이 새로 필요하면 이미지 생성 모듈로 라우팅하고, 생성된 자산을 FVTT에 적용하는 단계만 이 기능에서 처리한다.

## 7. 창작 지원 모듈

미세단위 TRPG 데이터 제작 기능을 통합 관리한다.

현재 내부 제작 기능에는 다음 범주가 포함된다.

- 아이템 제작
- 특성 제작
- 능력 제작
- 클래스 제작
- 인물 제작
- 기타 추가되는 제작기

내부 제작기 경로는 위 라우팅 캐시를 우선 사용한다. 창작 지원 모듈의 `AGENTS.md`와 마스터 프롬프트는 선택된 제작기 규칙 확인에 사용하며, 구조 변경·캐시 불일치가 있을 때만 직계 하위 구조를 다시 스캔한다.

## 8. 세션 제작

세션 하나를 기본 작업 단위로 삼아 시나리오를 제작한다.

이전 세션과 이어지는 내용이 있으면 관련 로그·설정·NPC·미결 요소를 먼저 확인한다. 새로운 사건의 시작이라면 기존 장기 스토리 전체를 억지로 연결하지 않는다.

세션 산출물 형식은 8번 기능의 마스터와 템플릿을 따른다.

세션 제작 산출물의 고정 저장 루트는 `TRPG 데이터/17. 세션 설계`(폴더 ID `1pJ1_JDhTHjKWxLpjJo2rczk9IhiLn4Xt`)다. `2. 로그`는 플레이 종료 로그·분석·스토리 정리 자료용으로 유지하며, 신규 세션 설계 산출물을 그 하위에 저장하지 않는다.

## `준비` 명령

사용자가 `준비`, `준비.`라고 하면 다음 절차를 따른다.

1. 프롬프트 루트 ID `1PDa8TO0BdKrPaNWTfImJTcYoYY3gpj8N`를 직접 열어 직계 하위 구조 확인
2. 활성 기능 폴더 판정
3. 활성 번호 기능이 아닌 폴더와 `보관` 제외
4. 현재 기준 기능을 1번부터 모두 설명형 목록으로 안내

각 기능 항목은 번호·명칭·처리 대상과 대표 산출물 또는 연결 관계를 1~2문장으로 설명한다.

- 1번 이미지 생성 모듈은 내부 활성 기능 `1·2·3·4·5·6·7·8`을 각각 줄바꿈 불릿으로 나열하고, 5번 `캐릭터 레퍼런스 V2 생성`을 안내한다.
- 이미지 모듈 항목의 끝에는 `요구사항 확인서·최종 영어 프롬프트 초안 → 프롬프트 점검·자동 교정 → 통과본 공개 → 마스터의 명시적 승인(다음 포함) → 실행 문안 재확인 → 생성 또는 수정 실행` 순서의 공통 승인 절차를 표시한다.
- 2~8번 비이미지 기능에는 이미지 승인 절차를 표시하지 않고, 필요한 선행·후속 기능 관계만 짧게 안내한다.

사용자가 `준비 ?번`, `준비. ?번`이라고 하면 해당 번호를 현재 활성 번호 체계에서 해석하고 캐시된 폴더 ID로 바로 진입하여 해당 기능의 작업 프로세스만 나열한다. 이 단계에서는 생성·수정·외부 실행을 시작하지 않는다.

사용자가 `포트레이트 준비`, `포트레이트 준비.`라고 하면 1번 이미지 생성 모듈 내부 1번 `반실사 포트레이트`로 직접 라우팅한다. 이 호출은 해당 기능의 처리 프로세스만 안내하며 생성·수정·외부 실행을 시작하지 않는다.

사용자가 `애니 페인팅 포트 준비`, `애니 페인팅 포트 준비.`, `애니 페인팅 포트레이트 준비`, `애니 페인팅 포트레이트 준비.`라고 하면 같은 내부 1번 포트레이트로 직접 라우팅하고 선택 스타일을 정식 명칭 `애니 페인팅`으로 바인딩한다. 과거 명칭 `세미리얼 애니 페인팅`은 레거시 별칭으로만 받아들인다. 이 호출 역시 처리 프로세스만 안내하며 생성·수정·외부 실행을 시작하지 않는다.

이미지 요청 본문에서 `애니 페인팅`을 화풍으로 명시한 경우에도 준비 호출 여부와 무관하게 같은 스타일 바인딩을 적용한다. 특히 `애니 페인팅으로 전환`, `애니 페인팅 스타일`, `애니 페인팅으로 재생성/리파인`을 명시적 스타일 선택으로 처리한다.

`애니 페인팅` 또는 `붓터치 반실사` 정식 스타일을 적용할 때에는 1번 이미지 생성 모듈 마스터의 `정식 스타일 시각 앵커 하드 게이트`를 적용하고 실제 앵커 픽셀을 확인한다. 두 스타일의 고정 영어 그림체 블록과 공통 고정 영어 마감 블록은 문장 변경 없이 최종 프롬프트에 사용한다.

그림체 적용 방식, 스타일별 활성 앵커 구성, 실제 조합과 참조 예산 축소는 `1. 이미지 생성 모듈/라이브러리/스타일/정식 스타일 호출 규칙.md`에서 판정한다. 이 전역 라우터는 산출물 프레이밍별 앵커 조합을 별도로 정하지 않는다.

모든 이미지 생성 프롬프트는 공개 전에 `1. 이미지 생성 모듈/공통/6. 이미지 생성 프롬프트 점검 및 교정 지침.md`의 전체 점검을 통과해야 한다. 실패 또는 확인 필요 상태에서는 승인 요청과 생성 도구 호출을 금지한다.

캐릭터 레퍼런스 V1·V2와 세션 하이라이트는 제공 이미지가 있으면 별도 스타일 변경 지시가 없는 한 해당 이미지의 그림체를 그대로 따른다. 정식 스타일 변경 시에만 제공 이미지를 디자인 기준, 정식 앵커를 스타일 전용 기준으로 분리하며 앵커의 인물·의상·팔레트·포즈·카메라·배경·구성은 복제하지 않는다.

## SESSION PROGRESS 응답 규칙

모든 응답의 본문 뒤 최하단에 `SESSION PROGRESS`를 표시한다. 단순 질의와 잡담도 대기형을 사용하며, 세부 형식은 `TRPG 데이터/SESSION PROGRESS 운영 지침.md`를 따른다.

- 전체 상태 영역은 코드블럭 안의 플레인 텍스트로 표시하고, 그 뒤에는 본문이나 새 제안을 덧붙이지 않는다.
- 활성형: `작업`, `현재`, `단계`, `완료`, `미결`, `다음`; 중단형: `상태`, `마지막 작업`, `중단 지점`, `재개`; 완료형과 대기형은 정본 지침의 필드를 따른다.
- 실제 진척만 기록하며, 모든 SESSION PROGRESS 필드의 값이 복수이면 쉼표 대신 순차 목록을 사용한다.
- `미결`에는 이전 단계에서 해결되지 않은 채 넘어온 사항만 기록한다. 현재 단계에서 검토·판단·확정 중인 내용과 예정된 후속 작업은 `미결`에 기록하지 않고 `현재`와 `다음`으로 표현하며, 이전 단계에서 넘어온 미해결 사항이 없으면 `미결: 없음`으로 표기한다.
- 이미지 생성 결과는 자가검수 통과·재생성 권고·확인 보류 여부와 관계없이 SESSION PROGRESS를 표시한다.
- 사용자가 표시 생략을 명시하면 표시하지 않는다.

## 기능 폴더 표준

활성 기능 폴더는 기본적으로 다음 구조를 따른다.

```text
기능 폴더/
├─ AGENTS.md
├─ README.md
├─ 0. 기능명 마스터 프롬프트.md
├─ 1. ...
├─ 2. ...
├─ 라이브러리/
└─ 템플릿/
```

- `0.`은 기능 마스터다.
- `1.` 이후는 실행 문서다.
- `9999.`는 조건부 색인·레지스트리 예외로 사용할 수 있다.
- `AGENTS.md`는 얇은 라우터다.
- `README.md`는 사람용 안내다.
- 라이브러리는 재사용 데이터, 템플릿은 산출물 골격을 담당한다.

## 경로 변경 시 동기화

기능 번호, 폴더명, 마스터 경로가 변경되면 다음을 함께 점검한다.

- `TRPG 데이터/AGENTS.md`
- 이 문서 `TRPG 데이터/1. 프롬프트/AGENTS.md`
- `00. TRPG 세션 매니저 프로젝트 기본 지침.md`
- `0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md`
- 변경된 기능의 `AGENTS.md`
- 변경된 기능의 `README.md`
- 변경된 기능의 `0. ... 마스터 프롬프트.md`
- 다른 기능에서 해당 번호·경로를 참조하는 문서

과거 Superpowers 설계·감사 보고서의 구 번호는 역사 기록이므로 현행 라우팅 문서와 구분하여 보존한다.

- 기존 파일 수정본은 원본 파일명을 유지한다.
