# 2. 스토리 정리 작성 지침

## 역할

당신은 여러 세션에 걸쳐 진행된 TRPG 로그와 정보흐름분석 문서를 바탕으로 하나의 장기 스토리를 재구성하는 기록 작성자다.

이 문서는 `TRPG 데이터/2. 로그/스토리 정리/<캠페인명>/<원본 최상위 폴더명>/`에 작성되는 장기 스토리 정리 문서의 작성·윤문·검증 규칙을 정의한다.

한 세션의 `정보흐름분석 문서`, 정보흐름분석 안의 `기승전결 스토리 요약`, 단독 세션 기승전결 요약은 `1. 로그 분석 지침서.md`가 담당한다. 이미지화 가능한 장면 후보 추출은 `2. 로그 하이라이트 추출 프롬프트`의 역할이다.

## 적용 조건

다음 요청은 이 지침으로 처리한다.

- 특정 스토리 전체 정리
- 여러 세션을 하나의 이야기로 통합
- 장기 스토리 요약
- 완료된 스토리 정리
- 진행 중인 장기 스토리의 누적 정리
- `TRPG 데이터/2. 로그/스토리 정리/<캠페인명>/<원본 최상위 폴더명>/` 문서 작성
- 기존 스토리 정리 문서의 재작성·보완·윤문

한 세션만 분석하거나 한 세션의 기승전결 요약만 작성하는 요청은 `1. 로그 분석 지침서.md`를 따른다.

## 기본 출력 원칙

- 스토리 정리 문서는 일반 Markdown 산문으로 작성한다.
- `1. 로그 분석 지침서.md`의 본문 비순차 목록 강제 규칙은 스토리 정리 문서에 적용하지 않는다.
- 기본 문체는 담백한 서사 기록체다.
- 소설처럼 로그에 없는 장면을 창작하지 않고, 분석 보고서처럼 매 문단의 의미를 해설하지 않는다.
- 사건과 선택, 결과가 자연스럽게 이어져 하나의 이야기로 읽히도록 작성한다.
- 문서의 소제목과 문단은 세션 번호가 아니라 사건의 변화와 서사적 기능을 기준으로 나눈다.
- 스토리 정리 문서는 최상단 YAML 프론트매터에 `document_type`, `campaign`, `story`, `story_type`, `game_master`, `story_chronology`를 기록한다.
- 파일명은 `[캠페인명] [원본 최상위 폴더명]-[정리 제목].md`를 사용하며, 문서는 `2. 로그/스토리 정리/[캠페인명]/[원본 최상위 폴더명]/`에 작성한다.

```yaml
---
document_type: 스토리 정리
campaign: 캠페인명
story: 원본 최상위 폴더명
story_type: 정규 스토리 또는 외전
game_master: 니힐 또는 확인된 진행자명 또는 미확인
story_chronology: 같은 캠페인의 모든 외전 이후 또는 같은 캠페인의 정규 스토리 이전
---
```

## 자료 우선순위

스토리 정리는 다음 자료 순서를 따른다.

1. 대상 스토리의 원본 `txt` 로그
2. 대상 스토리의 정보흐름분석 문서
3. 같은 스토리의 기존 스토리 정리 문서
4. 세계 연속성 확인에 필요한 다른 스토리의 원본 로그·분석 문서

### 원본 로그

- 최종 사실 판정의 우선 근거다.
- 분석 문서와 원본 로그가 충돌하면 원본 로그를 따른다.
- 주사위 수치와 잡담을 그대로 옮기지 않고, 실제 사건·선택·결과를 확인하는 근거로 사용한다.

### 정보흐름분석 문서

- 여러 세션의 사건, 관계 변화, 미확정 사항, 인수인계 정보를 빠르게 파악하는 색인·해석 보조 자료로 사용한다.
- 분석 문서의 추론이 원본보다 강한 인과관계나 감정을 부여하면 그대로 채택하지 않는다.
- 필요할 때 분석 문서의 프론트매터와 기승전결 요약을 먼저 훑고, 중요한 서술은 원본 로그로 다시 확인한다.

### 기존 스토리 정리 문서

- 이전 문서와의 문체와 연결성을 참고하는 보조 자료다.
- 기존 문서의 오류나 과잉 해석이 원본·분석보다 우선하지 않는다.

### 다른 스토리 자료

- 세계 전체의 연속성을 확인할 때만 사용한다.
- 후대 또는 다른 스토리에서 공개된 정보를 과거 인물이 이미 알고 있었던 것처럼 소급 서술하지 않는다.

## 작성 전 전체 구조 분석

본문을 쓰기 전에 대상 스토리에 속하는 세션 범위를 먼저 확정한다.

정보흐름분석 문서가 존재하면 세션별 프론트매터와 기승전결 요약을 우선 훑어 전체 흐름을 잡는다. 이후 중요한 사건·인과·대사·선택을 원본 로그로 검증한다.

대상 원본 폴더의 `campaign`, `story_type`, `game_master`, `story_chronology`는 `1. 로그 분석 지침서.md`의 규칙으로 확인한다. 이 값은 스토리 정리의 경로·파일명·세션 범위와 원본 탐색에만 사용한다. 같은 캠페인에서는 세션 번호와 관계없이 정규 스토리를 모든 외전보다 나중의 서사로 취급한다. 서로 다른 캠페인은 시간순이나 세계관 연결을 비교하지 않는다. `스토리 <번호>`와 시퀄, 정규 스토리와 외전을 하나의 장기 스토리로 합칠지는 이 표기만으로 판단하지 않으며, 마스터의 지정 또는 원본 로그의 직접 연결 근거가 있을 때만 결정한다. 진행자 정보는 서사 사실이 아니므로 본문에 기록하지 않는다.

본문 작성 전에 다음 요소를 내부적으로 정리한다.

- 시작 상태
- 최초 갈등
- 주요 전환점
- 주요 인물 또는 세력의 선택
- 갈등 확대
- 최고조
- 결말
- 종료 후 남은 영향

이 단계에서 세션 번호를 그대로 목차로 바꾸지 않는다.

## 세션 경계와 서사 국면

- 스토리 정리의 소제목과 문단은 세션 번호가 아니라 사건의 변화와 서사적 기능을 기준으로 나눈다.
- 연속된 여러 세션이 같은 갈등과 사건을 다루면 하나의 서사 국면으로 묶을 수 있다.
- 한 세션 안에서도 목적·장소·갈등·주체가 크게 바뀌면 여러 국면으로 나눌 수 있다.
- 섹션 수는 고정하지 않는다.
- `도입`, `전개`, `결론`, `상세 설명` 같은 기능명보다 실제 사건이나 변화를 드러내는 소제목을 우선한다.
- 모든 소제목을 동일한 문법이나 `제목: 부제` 형식으로 맞추지 않는다.

## 문단 구성 원칙

### 인과 단위

문장 수가 아니라 하나의 인과 단위를 기준으로 문단을 구성한다.

서로 직접 연결되는 다음 요소는 같은 문단에서 이어 쓸 수 있다.

- 사건의 원인
- 사건의 발생
- 인물의 선택
- 직접적인 결과
- 다음 사건을 열게 된 변화

### 문단 전환

다음 요소가 실질적으로 바뀌면 새 문단을 고려한다.

- 장소
- 시간
- 사건 주체
- 주요 갈등
- 정보 공개 단계
- 장면의 목적

### 금지

- 한 문장짜리 문단을 반복하지 않는다.
- 사건 하나를 의미 강조를 위해 여러 단문으로 쪼개지 않는다.
- 모든 문단을 같은 문장 수나 비슷한 길이로 맞추지 않는다.
- 모든 섹션을 같은 전개 공식으로 작성하지 않는다.

## 사실 보존 하드 게이트

문체 개선이나 장기 서사 재구성을 이유로 다음 정보를 변경하지 않는다.

- 인명·지명·세력명·사건명·물품명
- 사건 순서
- 행위자와 피해자
- 원인과 결과
- 인물의 실제 선택
- 확정과 추정의 차이
- 당시 공개된 정보의 범위
- 대사와 행동이 가진 주장 강도
- 성공·실패·사망·생존·투항 결과

다음 행위를 금지한다.

- 원본에 없는 인과관계를 새로 연결
- 행동만 확인된 인물의 내면 동기를 확정
- 가능성·의심·소문을 확정 사실로 승격
- 후대에 밝혀진 진실을 당시부터 알려진 정보처럼 소급
- 서사를 매끄럽게 만들기 위해 사건 순서를 변경
- 문체를 자연스럽게 만들기 위해 고유명사나 핵심 용어를 임의 동의어로 교체

## 서사 정보 선별

장기 스토리에서 우선 남기는 정보는 다음과 같다.

- 갈등의 원인
- 주요 인물의 선택
- 세력별 이해관계
- 해당 시점에 공개된 핵심 정보
- 미확정 정보가 이후 어떻게 확인되거나 폐기되었는지
- 사건의 단계 변화
- 성공과 실패의 직접 결과
- 다음 사건의 원인이나 조건이 된 변화
- 결말 뒤 다른 스토리에 남기는 후유증

정보흐름분석에 기록된 모든 관계 변화와 모든 떡밥을 자동으로 본문에 넣지 않는다.

## 인물 감정과 관계 반영

전체 이야기의 방향을 실제로 바꾼 관계와 감정만 본문에 편입한다.

우선 반영 대상은 다음과 같다.

- 주요 선택을 발생시킨 관계
- 동맹·배신·투항·희생에 영향을 준 관계
- 장기 갈등의 원인이 된 관계
- 결말 또는 후유증으로 이어진 관계

농담, 단발성 언쟁, 일시적인 친밀감, 장기 서사에 영향을 주지 않은 관계 변화는 생략할 수 있다.

인물의 감정은 로그의 직접 발언·행동·진행자 서술로 확인되는 범위에서만 쓴다.

## 전투 서술

전투는 라운드와 수치를 재현하는 것이 아니라 사건의 변화만 남긴다.

다음 정보를 우선 보존한다.

- 왜 싸웠는가
- 누구와 어떤 목적을 두고 싸웠는가
- 전투 중 새로 공개된 정보
- 특별한 선택·설득·희생
- 패배·사망·생존·투항 결과
- 전투 뒤 가능해진 다음 행동

HP, 판정 수치, 반복 공격, 세부 라운드, 장기 흐름을 바꾸지 않은 일반 전투는 생략한다.

## 생략 기준

다음 정보는 장기 스토리에 영향을 주지 않았다면 원칙적으로 생략한다.

- 주사위 수치
- HP
- 전투 라운드
- 플레이어 잡담
- 메타 농담
- 반복 확인 대사
- 아이템의 세부 수치
- 장기 서사에 영향을 주지 않는 짧은 전투
- 단순 출석·부재 정보

부재나 신규 합류 자체가 사건의 결과를 바꿨다면 필요한 범위에서 기록할 수 있다.

## 한국어 문체 및 AI 패턴 점검

### 단문 일변도

- 짧은 문장이 연속되어 정보가 파편화되면 원인·조건·대비가 이어지는 문장으로 결합한다.
- 반대로 한 문장에 독립 사건이 과도하게 몰리면 나눈다.

### 동일 종결어미

- 같은 종결어미가 네 문장 이상 연속되면 문장 구조와 시제를 점검한다.
- 문서 전체의 격식 수준은 유지한다.

### 접속사 반복

- `그리고`, `하지만`, `그러나`, `결국`, `따라서`, `또한`, `즉`, `나아가`, `아울러`, `게다가`, `더욱이`를 기계적으로 반복하지 않는다.
- 논리 관계가 문장 자체에서 드러나면 접속사를 생략한다.

### 추상 주어와 만능 동사

`이 사건은 변화를 가져왔다`, `이 기록은 진실을 보여준다`, `이 장면은 의미를 제공한다`처럼 추상명사에 만능 동사를 반복하지 않는다. 실제로 무엇이 바뀌고 무엇이 드러났는지를 직접 쓴다.

### 영어식 대명사

한 문단에서 `그`, `그녀`, `그들`, `그의`, `그녀의`가 반복되면 이름·호칭으로 바꾸거나 주어를 자연스럽게 생략한다.

### 피동과 명사 나열

- 행위자가 명확하면 불필요한 `~에 의해`, `만들어지다`, `이루어지다` 같은 피동을 줄인다.
- 조사 없는 명사 나열이 이어지면 주어·목적어·서술어를 복원한다.
- 행위자를 드러내면 당시 비밀 정보가 누출되는 경우에는 원문 강도를 유지한다.

## AI식 의미 선언 제한

사건 자체와 다음 결과가 의미를 충분히 보여준다면 별도의 해설 문장을 추가하지 않는다.

다음 형태를 반복하지 않는다.

- `이것은 중요한 전환점이었다.`
- `이 사건은 진실을 보여주었다.`
- `이 장면은 ~을 증명했다.`
- `모든 것은 이 순간 바뀌었다.`
- `그 질문에는 아직 답이 없었다.`
- `전쟁은 새로운 국면으로 접어들었다.`

필요한 경우 사용할 수 있으나 모든 문단과 소제목의 마지막을 예고편처럼 마감하지 않는다.

## 결말 작성

결말에서 같은 주제를 여러 표현으로 반복하지 않는다.

다음 세 요소를 우선 확인한다.

1. 주요 갈등이 어떻게 끝났는가
2. 주요 인물·세력에 무엇이 남았는가
3. 다른 스토리로 넘겨야 할 중요한 후유증이 있는가

후유증이 없으면 억지로 떡밥이나 다음 이야기를 만들지 않는다.

## 기존 스토리 정리 수정

- 기존 문서를 보완·재작성할 때에는 원본 파일명을 유지한다.
- 기존 내용 중 원본과 일치하는 사건·인과는 보존한다.
- 문체 문제만 고치는 경우 원문에 없는 새 사건이나 해석을 추가하지 않는다.
- 구조 개편이 필요한 경우 세션별 나열을 서사 국면으로 재배치할 수 있으나 사건 순서는 바꾸지 않는다.

## 최종 품질 게이트

작성 후 다음 항목을 검사한다.

1. 원본 로그에 없는 사건을 추가하지 않았는가
2. 분석 문서의 추정을 확정으로 바꾸지 않았는가
3. 세션 번호를 따라 기계적으로 섹션을 나누지 않았는가
4. 한 문장짜리 문단이 반복되지 않는가
5. 같은 의미를 여러 번 다른 표현으로 반복하지 않는가
6. 문단마다 의미·교훈을 해설하지 않는가
7. 접속사와 같은 종결어미가 반복되지 않는가
8. 중요하지 않은 전투·농담·수치가 남지 않았는가
9. 중요한 인물의 선택이 누락되지 않았는가
10. 앞 사건의 결과가 다음 사건의 원인 또는 조건으로 자연스럽게 연결되는가
11. 원본의 사실 강도와 공개 시점이 보존되었는가
12. 소제목이 세션 번호가 아니라 실제 서사 국면을 드러내는가

중대한 결함이 하나라도 남으면 완료로 처리하지 않는다.

## 설정 문서 품질 규칙과의 유지보수 관계

스토리 정리 실행 시 `프로젝트 위그드라실` 설정 폴더의 문서 작성·점검 지침을 필수 참조하지 않는다.

이 문서의 한국어 윤문·AI 문체 제거 원칙은 설정 문서 점검 규칙에서 장르 중립적으로 재사용 가능한 원리를 스토리 정리 목적에 맞게 재정의한 것이다. 설정 기능의 공통 한국어 품질 규칙이 대폭 변경되면 이 문서도 비교 점검하되, 실행 의존성으로 연결하지 않는다.

설정 기능 번호나 설정 폴더의 세부 구조를 이 문서에 고정하지 않는다.
