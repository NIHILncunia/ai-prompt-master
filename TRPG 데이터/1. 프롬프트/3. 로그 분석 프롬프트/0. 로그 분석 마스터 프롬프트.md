# 0. 로그 분석 마스터 프롬프트

## 로컬 운영 진입점과 동기화

이 기능 폴더의 `AGENTS.md`와 `0. 로그 분석 마스터 프롬프트.md`는 함께 운영 진입점으로 취급한다. 폴더를 직접 작업 공간으로 열었을 때에는 상위 `AGENTS.md`와 프로젝트 기본·통합 문서를 읽은 뒤 로컬 `AGENTS.md`를 확인하고, 이 마스터와 필요한 하위 지침·라이브러리를 이어서 읽는다.

폴더 ID, 정식 경로, 진입점, 필수 읽기 순서, 기능 경계, 외부 데이터 원천, 기본 산출물, 파일 작업 정책을 바꾸면 `AGENTS.md`와 이 마스터를 함께 점검한다. 실제 생성·분석·작성 절차와 세부 품질 규칙은 이 마스터와 하위 문서에 두며, 로컬 `AGENTS.md`에는 작업 시작과 유지보수에 필요한 라우팅 정보만 둔다.

전역 응답 규칙·파일 정책·공통 승인 절차를 바꾸면 `TRPG 데이터/AGENTS.md`, `TRPG 데이터/1. 프롬프트/AGENTS.md`, `00. TRPG 세션 매니저 프로젝트 기본 지침.md`, `0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md`를 함께 확인한다. 다른 기능이 소유한 정본 규칙은 이 폴더에 복제하지 않고 해당 기능을 참조한다.

## 문서 목적

이 문서는 `TRPG 데이터/1. 프롬프트/3. 로그 분석 프롬프트` 폴더의 진입점이다.

사용자가 세션 로그 분석, 정보흐름분석, 기승전결 스토리 요약, 세션 연속성 정리, 장기 스토리 정리, 원본 로그 기반 분석본 작성을 요청하면 이 문서를 먼저 읽는다.

이 폴더는 `TRPG 데이터/2. 로그/원본`에 저장된 원본 로그를 분석하여 `TRPG 데이터/2. 로그/분석`에 분석본을 작성하고, 필요한 경우 `TRPG 데이터/2. 로그/스토리 정리`에 장기 스토리 정리 자료를 작성하기 위한 전용 프롬프트 모듈이다.

## 적용 조건

아래 요청은 모두 이 폴더의 지침으로 처리한다.

- 로그 분석
- 세션 분석
- 정보흐름분석 작성
- 기승전결 스토리 요약 작성
- 세션 연속성 프론트매터 작성
- 원본 로그를 분석본으로 변환
- 기존 분석본을 기준으로 다음 세션 분석
- 특정 세션의 업적, 밝혀진 진실, 미확정 사실 정리
- PC 관계 변화, 갈등, 떡밥, 인수인계 정보 정리
- 특정 스토리 전체 또는 여러 세션의 장기 스토리 정리
- 기존 `스토리 정리` 문서의 재작성·보완·윤문

단, 이미지화 가능한 장면 후보를 뽑는 작업은 `2. 로그 하이라이트 추출 프롬프트`의 역할이다. 이 폴더는 하이라이트 추출 기능을 대체하지 않는다.

## 기본 처리 순서

1. 사용자의 요청이 세션 단위 분석·요약인지 장기 스토리 정리인지 판별한다.
2. 이 문서를 읽은 뒤 `1. 로그 분석 지침서.md`와 `라이브러리/플레이어 및 PC 정보.md`를 확인한다.
3. 장기 스토리 정리 요청이면 `2. 스토리 정리 작성 지침.md`를 추가로 읽는다.
4. 원본 로그는 `TRPG 데이터/2. 로그/원본`에서 찾는다.
5. 세션 단위 분석은 같은 스토리명의 직전 분석 문서 프론트매터를 우선 확인한다.
6. 장기 스토리 정리는 대상 스토리의 전체 세션 범위와 정보흐름분석 문서를 확인한 뒤, 중요한 사건·인과·선택을 원본 로그로 검증한다.
7. 원본 로그의 실제 내용만 확정 사실의 최종 근거로 사용한다.
8. 정보흐름분석 문서를 작성할 경우 최상단 YAML 프론트매터를 포함한다.
9. 생성 또는 수정 결과는 기본 파일 정책을 따르며, 사용자가 Drive 직접 반영을 명시한 경우 해당 요청 범위에서 직접 적용할 수 있다.

## 대상 데이터 구조

구글 드라이브 기준 경로는 아래를 따른다.

```text
TRPG 데이터/2. 로그/
├─ 원본/
├─ 분석/
└─ 스토리 정리/
```

프롬프트 기준 경로는 아래를 따른다.

```text
TRPG 데이터/1. 프롬프트/
└─ 3. 로그 분석 프롬프트/
   ├─ 0. 로그 분석 마스터 프롬프트.md
   ├─ 1. 로그 분석 지침서.md
   ├─ 2. 스토리 정리 작성 지침.md
   └─ 라이브러리/플레이어 및 PC 정보.md
```

## PC 정보 참조 규칙

로그 분석을 시작하기 전에 반드시 같은 폴더의 `라이브러리/플레이어 및 PC 정보.md`를 읽는다.

이 파일에 이름이 있는 발화자는 모두 PC로 취급한다.  
이 파일에 `/`로 병기된 이름이 있으면, 각 이름을 모두 독립된 PC급 발화자와 행동 주체로 취급한다.

이 파일에 없는 발화자는 NPC로 취급한다.  
단, 스토리 핸들러 역할의 NPC는 PC와 유사하게 추적할 수 있으나 분류는 NPC로 유지한다.

## 2. 로그 하이라이트 추출 프롬프트와의 관계

이 폴더는 `2. 로그 하이라이트 추출 프롬프트`를 대체하지 않는다.

`3. 로그 분석 프롬프트`는 원본 로그의 서사 정보, 인물 관계, 떡밥, 정보 흐름, 기승전결 요약, 다음 세션 인수인계를 정리하는 장기 기록 분석 모듈이다.

`2. 로그 하이라이트 추출 프롬프트`는 원본 로그 또는 3. 로그 분석 프롬프트의 분석본을 참고하여 이미지화 가능한 장면 후보를 뽑는 하이라이트 추출 모듈이다.

이미 작성된 3. 로그 분석 프롬프트의 분석본은 2. 로그 하이라이트 추출에서 장면 맥락, 등장 인물, 갈등 구조, 떡밥, 사건 흐름을 보강하는 참고 자료로 사용할 수 있다.

## 산출물 종류

이 폴더에서 다루는 기본 산출물은 아래와 같다.

- 정보흐름분석 문서
- 정보흐름분석 문서 안의 기승전결 스토리 요약 섹션
- 단독 기승전결 스토리 요약 문서
- 세션 단위 핵심 결과 데이터
- PC 관계 변화 및 갈등 정리
- 다음 세션 분석용 프론트매터 인수인계
- 여러 세션을 하나의 장기 서사로 재구성한 스토리 정리 문서

## 파일 제공 원칙

분석 결과나 수정 결과는 사용자가 내려받을 수 있는 파일로 제공한다.

에이전트는 사용자의 명시적 요청 없이 구글 드라이브에 파일을 자동 생성하거나, 기존 파일을 덮어쓰거나, 이름을 변경하지 않는다.

파일명은 지침 또는 원본 로그명에 의해 정해진 이름을 그대로 사용한다.  
`재수정`, `최종`, `수정본`, 날짜, 번호 같은 임의 접미사를 붙이지 않는다.

## 반드시 읽을 파일

세션 단위 로그 분석·요약 요청을 처리할 때에는 반드시 아래 파일을 읽고 따른다.

- `1. 로그 분석 지침서.md`
- `라이브러리/플레이어 및 PC 정보.md`

장기 스토리 정리 요청에서는 위 파일에 더해 아래 파일을 반드시 읽는다.

- `2. 스토리 정리 작성 지침.md`

## 최종 실행 지시

사용자가 로그 분석, 정보흐름분석, 기승전결 요약, 세션 연속성 정리를 요청하면 `1. 로그 분석 지침서.md`와 `라이브러리/플레이어 및 PC 정보.md`를 읽고 그 규칙에 따라 작업한다.

사용자가 여러 세션의 장기 스토리 정리 또는 기존 스토리 정리 문서의 재작성·보완을 요청하면 `2. 스토리 정리 작성 지침.md`를 추가로 읽고 그 문서의 산문·문단·품질 규칙을 우선 적용한다. `1. 로그 분석 지침서.md`의 비순차 목록 강제 규칙은 스토리 정리 문서에 적용하지 않는다.

원본 로그에 실제로 나온 정보만 확정 사실의 최종 근거로 삼고, 추정은 확정 사실처럼 작성하지 않는다.
