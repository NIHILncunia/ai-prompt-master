## 기능 경계와 연동

- 원본·분석·스토리 정리 자료는 TRPG 데이터/2. 로그를 기준으로 찾는다.
- 장기 스토리 정리의 작성·문단·문체·품질 검증은 `2. 스토리 정리 작성 지침.md`가 소유한다.
- 세션 분석에서는 기본 하이라이트 `Hxx`를 함께 산출한다. 완전한 이미지 제작용 Highlight Card 정밀화 또는 하이라이트만의 독립 추출은 2. 로그 하이라이트 추출 프롬프트로 라우팅한다.
- 분석 전에 라이브러리/플레이어 및 PC 정보.md를 반드시 읽는다.

## 동기화 원칙

- 이 `AGENTS.md`와 `0. 로그 분석 마스터 프롬프트.md`는 함께 기능 진입점으로 취급한다.
- 폴더 ID·경로·진입점·읽기 순서·기능 경계·외부 데이터 원천·기본 산출물·파일 정책이 바뀌면 두 문서를 함께 점검한다.
- 세부 실행 절차와 품질 규칙은 마스터와 하위 지침에 둔다. 상위 전역 규칙이나 다른 기능이 소유한 정본을 이 폴더에 복제하지 않는다.
- 전역 라우팅이나 파일 정책이 바뀌면 TRPG 데이터 루트·프롬프트 루트 `AGENTS.md`, 프로젝트 기본 지침, 통합 마스터를 함께 갱신한다.
- 새 하위 문서가 진입점·필수 로드 파일·정본 데이터 원천이 되면 이 문서와 마스터의 파일 목록 및 읽기 순서를 함께 수정한다.

## 파일 작업 원칙

- 수정본은 실제 적용 경로와 원래 파일명을 유지한 로컬 파일 또는 ZIP으로 제공한다.
- 기존 문서를 교체할 때에는 ZIP 내부 경로에 따라 덮어쓰고, 삭제가 필요한 파일은 별도 목록으로 명시한다.

## 실제 플레이 장면·설계 대응·기본 하이라이트

## 실제 플레이 장면과 세션 설계 대응

세션 단위 정보흐름분석은 기존 정보·관계·연속성 분석에 더해 실제 플레이 장면과 기본 하이라이트를 함께 산출한다.

### 처리 순서

1. 원본 로그만 기준으로 실제 플레이 흐름을 먼저 분할한다. 세션 설계 장면을 정답지처럼 사용하여 로그를 강제로 자르지 않는다.
2. 실제 플레이 장면은 `P01`, `P02`, `P03` 형식으로 부여한다.
3. 장면 경계는 물리적 장소 변화 하나만으로 정하지 않고, 현재 목적·중심 갈등·비가역적 사건 상태·플레이 모드의 의미 있는 변화를 우선한다.
4. 각 `Pxx`를 만든 뒤에만 대상 세션 설계 패키지의 장면 식별 정보와 대조한다.
5. 세션 설계가 있으면 `Pxx`를 `scene_uuid`에 대응하고, 장면 파일의 직접 `사용 맵` 참조를 따라 `map_uuid`를 연결한다.
6. 실제 플레이와 설계의 차이를 기록한다.
7. `Pxx` 목록에서 이미지화 가치가 충분한 순간을 `H01`, `H02` 형식의 기본 세션 하이라이트로 선정한다.
8. `Hxx`는 `Pxx`를 참조하며 설계 장면·맵 정보를 다시 복제하지 않는다.

### Pxx 장면 경계

새 `Pxx`를 만드는 강한 조건은 다음과 같다.

- 플레이어의 현재 목적이 의미 있게 바뀐다.
- 중심 문제·갈등이 해결되거나 새로운 갈등이 시작된다.
- 협상 가능 상태에서 전투 상태로 바뀌는 것처럼 되돌리기 어려운 사건 상태 변화가 발생한다.
- 중요한 폭로 뒤 플레이어의 행동 방향이 바뀐다.
- 독립적인 전투·추격·도주·의식·잠입 등 새로운 플레이 국면이 시작된다.
- 장소·시간이 크게 이동하면서 이전 장면의 목적과 맥락도 함께 종료된다.
- 주요 참여자 변화가 장면의 중심 자체를 바꾼다.

단순 위치 이동, 같은 대화 안의 화제 변화, 짧은 판정, 전투 페이즈 변화, 같은 갈등 안의 접근법 변경만으로는 자동 분할하지 않는다. 하이라이트 컷을 만들기 위해 `Pxx`를 잘게 쪼개지 않는다.

### Pxx 필수 데이터

각 실제 플레이 장면은 필요한 범위에서 다음을 기록한다.

- 실제 전개
- 장면 시작
- 장면 종료
- 주요 장소
- 주요 참여자
- 핵심 사건
- 세션 설계 대응
- 설계 맵
- 설계 대비 실제 변화

원본 로그에 타임스탬프가 있으면 장면 시작·종료에 시간 범위를 병기할 수 있다. 타임스탬프가 없거나 검색에 더 유용하면 대표 발화·사건을 경계 근거로 기록한다.

### 세션 설계 대응 상태

- `matched`: 하나의 실제 장면과 하나의 설계 장면이 정상 대응한다.
- `merged`: 실제 플레이에서 둘 이상의 설계 장면이 하나의 `Pxx`로 합쳐졌다.
- `split`: 하나의 설계 장면이 실제 플레이에서 둘 이상의 `Pxx`로 갈라졌다.
- `skipped`: 설계에는 있으나 실제 플레이에서 진행되지 않았다. `Pxx`가 없으므로 별도 `진행되지 않은 설계 장면` 목록에 기록한다.
- `unplanned`: 실제 플레이 장면이 세션 설계에 없었다.
- `uncertain`: 근거가 부족해 설계 장면 대응을 확정할 수 없다.

### 설계 맵 상태

- `confirmed`: 대응 장면의 직접 맵 참조를 따라 맵이 확정되었다.
- `none`: 해당 설계 장면이 의도적으로 맵을 사용하지 않는다.
- `unavailable`: 세션 설계 자체가 없어서 설계 맵도 없다.
- `unmapped`: 세션 설계는 있으나 해당 장면에 맵이 아직 할당되지 않았다.
- `uncertain`: 설계 장면 대응이 불확실하여 맵도 확정할 수 없다.

`설계 장면 UUID`, `설계 맵 UUID`, `FVTT Scene ID`는 서로 다른 값이다. 설계 장면·맵을 `scene_uuid` 하나에 혼합하지 않는다.

### 분석 문서 배치

- `기승전결 스토리 요약`은 기존 규칙대로 `정보 흐름 지도` 바로 위에 둔다.
- `## 실제 플레이 장면 및 세션 설계 대응`은 `정보 흐름 지도` 다음, `서사 심층 분석` 앞에 둔다.
- `## 세션 하이라이트`는 `PC 관계 변화` 등 기존 분석이 끝난 뒤, 문서 말미의 `세션 단위 핵심 결과 데이터` 바로 앞에 둔다.
- `세션 단위 핵심 결과 데이터`는 계속 문서의 최종 핵심 결과 섹션으로 유지한다.

### Hxx 기본 하이라이트

3번 로그 분석의 `Hxx`는 하이라이트의 기본 선정 결과이며 완전한 이미지 생성용 Highlight Card가 아니다.

각 `Hxx`는 다음 정도를 기록한다.

- 우선순위: `high / medium / low`
- 유형
- 실제 장면: 하나 이상의 `Pxx`
- 선정 이유
- 하이라이트 순간
- 중심 인물
- 핵심 시각 요소
- 이미지화 준비 상태

`Hxx`에서 `scene_uuid`, `map_uuid`를 다시 복제하지 않는다. 필요한 설계 정보는 `Hxx → Pxx → scene_uuid → map_uuid` 참조를 따른다.

### 세션 설계 프론트매터 참조

정보흐름분석 프론트매터에는 다음 메타데이터를 둘 수 있다.

```yaml
session_design:
  status: found
  package:
  scene_index:
  map_index:
```

세션 설계가 없으면 다음과 같이 기록한다.

```yaml
session_design:
  status: not_found
```

이 메타데이터는 어떤 설계 패키지와 대조했는지를 빠르게 확인하기 위한 것이며 `Pxx`나 `Hxx` 전체를 프론트매터에 복제하지 않는다.
