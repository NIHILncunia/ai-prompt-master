# 8. 세션 제작 프롬프트 작업 지침

## 폴더 역할

이 폴더는 프로젝트 위그드라실의 룩스테라 세계관을 기준으로 실제 플레이 가능한 TRPG 세션과 플레이 준비 자산을 제작하는 기능의 진입점이다.

세션 제작은 이야기·장면 문서뿐 아니라 장면이 확정된 뒤 필요한 배틀맵, NPC·몬스터 스탯블록, 이미지와 토큰까지 연속적으로 준비한다. 장면과 맵에는 로그 분석 연동을 위한 영구 `scene_uuid`·`map_uuid`를 부여하고 플레이 후에도 당시 설계 의도를 보존한다. 실제 Foundry VTT 데이터 변환과 피트·아이템 설명의 인라인 문법 조립·검증은 6번 FVTT 관련 요청 기능에 남긴다.

## 적용 요청

- 단일 세션 제작
- 연속 세션 아크 및 특정 회차 설계
- 이전 세션에 이어지는 다음 회차 제작
- 기존 설정을 활용한 사건 제작
- 세션 장면 구성과 묘사
- 세션용 맵 산정과 배틀맵 준비
- 세션용 NPC·몬스터 설계
- 스탯블록 준비
- 세션에 필요한 NPC·몬스터 이미지와 토큰 준비
- 장면 내 조우 성공·실패 조건 설계
- 기존 세션 초안 보완
- 세션 문서와 자산의 구조 및 품질 점검

플레이 종료 로그 분석은 3번, 설정 정본 작성·수정은 5번, 실제 FVTT Actor·Scene·Journal·Compendium·JSON 변환과 `[[...]]`·`@...` 문법 검증은 6번 기능이 담당한다.

4번 룰북 기능에서 확인되어 스탯블록에 포함된 인라인 문법은 세션 제작에서 임의로 제거하거나 고정 숫자로 바꾸지 않는다. 새 문법 작성과 변수 경로 확정이 필요하면 6번의 `2. 피트 및 아이템 인라인 문법과 변수 사용 가이드.md`로 넘긴다.

## 필수 읽기 순서

1. `TRPG 데이터/AGENTS.md`
2. `TRPG 데이터/1. 프롬프트/AGENTS.md`
3. 이 폴더의 `AGENTS.md`
4. `0. 세션 제작 마스터 프롬프트.md`
5. `1. 세션 제작 기본 지침서.md`
6. `2. 세션 구조 및 장면 설계 지침.md`
7. 요청에 따라 `3. NPC 설계 지침.md`, `4. 조우 설계 지침.md`, `5. 연속 세션 및 연속성 관리 지침.md`
8. 장면 기능·묘사가 정리된 뒤 `9. 세션 자산 및 VTT 준비 지침.md`
9. 출력 전 `6. 세션 문서 양식 및 출력 규칙.md`, `7. 세션 품질 검수 체크리스트.md`

예시가 필요한 경우 `8. 세션 제작 예시.md`와 `템플릿/`을 참고한다. `README.md`는 사람용 안내이고 `개발 자료/`는 일반 실행에서 읽지 않는다.

## 기본 설계 방식

표준 흐름은 다음과 같다.

`한 줄 이야기 → 핵심 이야기 골격 → 핵심 사건 흐름 → 장면 목록 → 장면별 파일 → 장면 기능 확장·묘사·성공/실패 조건 → 맵 산정·할당 → 배틀맵 설계·제작 → NPC·몬스터 목록 → 스탯 정책·스탯블록 → 이미지·토큰 → 진행 시트·스탯블록 모음 → 장면 결과 조건·자산 연결 검증`

사용자가 흐름을 직접 제공했다면 그 흐름을 보존하고 조정만 한다. 처음부터 시작하는 경우에는 큰 결정을 임의로 채우지 않고 한 번에 하나의 결정 단위씩 질문한다.

장면 기능과 묘사가 충분히 정리되기 전에는 맵이나 스탯블록을 먼저 확정하지 않는다.

### 세션 시작 낭독 순서

- 이전 플레이 기록이 존재하는 세션은 `장면/00. 세션 프롤로그.md` 안에서 반드시 `이전 이야기 → 세션 도입부 묘사` 순서로 시작한다.
- `이전 이야기`는 별도 문서로 만들지 않는다. 프롤로그 장면 파일과 그 파생본인 `04. [세션 이름] 진행 시트.md` 안에만 포함한다.
- `이전 이야기`는 직전 세션 또는 현재 회차에 직접 이어지는 이전 이야기의 핵심 사건·결과·관계 변화·현재까지 남은 단서를 플레이어가 기억할 수 있도록 압축한 낭독용 요약이다. GM만 아는 비밀이나 아직 플레이어가 확인하지 못한 사실을 확정 사실처럼 넣지 않는다.
- 사실 근거는 3번 로그 분석의 직전 분석본을 우선하고 필요한 경우 원본 로그로 검증한다. 문체는 정보흐름분석의 목록체를 따르지 않고, 같은 캠페인·같은 아크의 직전 원본 로그에서 확인한 GM 묘사 호흡과 어조를 따른다.
- `이전 이야기`와 이어지는 `세션 도입부 묘사`는 서로 다른 기능을 가진 연속 낭독 파트다. 이전 이야기는 과거 회상과 기억 환기에서 멈추고, 도입부는 현재 시점·현재 장소·현재 상황으로 전환하여 첫 본편 장면으로 연결한다.
- 두 파트 모두 세션 묘사 공통 규칙을 적용하며, 각 서술 문단은 3~4개의 완결된 문장으로 구성한다.
- 이전 플레이 기록이 전혀 없는 최초 세션은 `이전 이야기`를 생략하고 `세션 도입부 묘사`부터 시작할 수 있다.

## 자산 제작 원칙

- 배틀맵은 전투 전용이 아니다. 토큰 배치와 공간 관계가 의미 있으면 비전투 장면도 맵 대상으로 본다.
- 맵 수는 장면 수와 1:1로 맞추지 않고 재사용과 복수 맵 필요성을 판단한다.
- 맵의 논리 그리드 가로·세로 수와 권장 이미지 규격은 장면에 맞게 자동 산정할 수 있다.
- 맵에 배치되는 NPC·몬스터는 전투 여부와 관계없이 토큰 제작 대상이다.
- 일반 NPC는 적절한 기존 NPC 스탯블록을 재사용할 수 있다.
- 세션용 NPC·몬스터 통합 파일에는 GM이 실제 플레이에서 읽을 수 있는 `마스터용 묘사`를 기본 포함한다.
- **세션에 등장하는 모든 NPC와 몬스터는 전투 참여 여부와 관계없이 예외 없이 스탯블록이 필요하다. `스탯블록 불필요` 분류는 사용하지 않는다.**
- NPC·몬스터의 개체별 스탯블록 정본은 별도 `[이름] 스탯블록.md`로 분리하지 않고 `NPC 및 몬스터/[이름].md` 통합 파일의 기본 정보·외형·마스터용 묘사 다음에 기록한다. 완성 단계에서는 모든 대상의 정본을 모은 `05. [세션 이름] 스탯블록 모음.md`를 플레이용 파생 산출물로 생성한다.
- 사용자가 강조한 주요 NPC는 전용 스탯블록 필요성이 모호하면 사용자에게 확인한다.
- 전용 몬스터는 사용자가 이미 정하지 않았다면 일반·정예·보스 등급과 전투 컨셉을 확인한다.
- 실제 스탯 자료는 4번 룰북 기능을 확인한다.
- 실제 이미지 생성은 해당 이미지 생성 기능 지침을 적용한다.
- 조우는 별도 문서나 별도 폴더로 분리하지 않는다. 결과 판정이 필요한 장면의 `장면/NN. [장면명].md`에 성공 조건, 실패 조건, 실패 후 진행을 직접 기록한다.

## 기본 산출물과 저장 경로

세션 설계 작업 루트는 `TRPG 데이터/17. 세션 설계`로 고정한다. `TRPG 데이터/2. 로그`는 플레이 종료 로그·분석·스토리 정리 자료용이며 세션 제작 산출물 저장소로 사용하지 않는다.

```text
TRPG 데이터/17. 세션 설계/[스토리명]/
├─ 00. 세션 아크 개요.md                 # 연속 세션일 때만
└─ [세션 이름] 기획/
   ├─ 01. [세션 이름] 시나리오.md
   ├─ 02. [세션 이름] 장면 목록.md
   ├─ 장면/
   │  └─ NN. [장면명].md
   ├─ 맵/
   │  ├─ 00. 맵 목록.md
   │  └─ NN. [맵명].md
   ├─ 03. [세션 이름] 등장인물 및 몬스터.md
   ├─ 04. [세션 이름] 진행 시트.md             # 장면 묘사·체크포인트 플레이용 집합본
   ├─ 05. [세션 이름] 스탯블록 모음.md         # 실제 사용 스탯블록 플레이용 집합본
   └─ NPC 및 몬스터/
      └─ [이름].md                        # 기본 정보·외형·스탯블록 통합
```

`03`은 등장인물 및 몬스터의 상위 요약·인덱스 파일로 유지한다. `04`는 장면 묘사·체크포인트를 모은 GM 진행용 파생본, `05`는 스탯블록을 모은 GM 참조용 파생본이다. 조우 설계 전용 파일과 `조우/` 산출물은 생성하지 않으며 기존 세션은 사용자가 요청하지 않는 한 자동 이관하지 않는다.

## 다른 기능과의 경계

- 로그 분석: 3번
- 실제 룰북·스탯 원문 확인: 4번
- 설정 정본: 5번
- 실제 FVTT 데이터 변환과 인라인 문법·롤 데이터 경로 검증: 6번
- 배틀맵·포트레이트·토큰 등 이미지 실제 생성: 해당 이미지 생성 기능

8번 세션 제작은 자산의 필요성과 요구사항을 결정하고 관련 기능을 연속 호출해 결과를 세션 패키지와 연결한다.

## 파일 정책

세션 제작 과정에서 새로 생성되는 문서 산출물은 해당 `TRPG 데이터/17. 세션 설계/` 작업 경로에 Google Drive 직접 저장하는 것을 기본으로 한다.

기존 파일의 덮어쓰기·내용 교체·삭제·이름 변경은 사용자가 해당 변경을 명시적으로 요청했을 때만 수행한다. Drive 저장이 불가능하거나 사용자가 별도로 요청한 경우에만 동일 경로를 보존한 로컬 파일 또는 ZIP을 제공한다.

## 로그 분석 연동용 장면·맵 식별 규칙

### 영구 장면·맵 식별자

- 모든 신규 세션 설계 장면에는 `scene_uuid`를 부여한다.
- 값은 소문자 표준 UUID 형식으로 작성한다. 예: `5e02c452-01a3-4d9e-8737-8f2b1a0c9d64`.
- 프롤로그와 에필로그도 정식 장면이므로 `scene_uuid`를 가진다.
- `scene_uuid`는 장면 번호·장면명·파일명이 바뀌어도 유지한다. 장면을 다른 장면과 통합하여 정체성이 사라질 때에만 폐기하고, 새 장면에는 새 UUID를 부여한다.
- 모든 신규 맵에는 `map_uuid`를 부여한다.
- 값은 소문자 표준 UUID 형식으로 작성한다. 예: `86a41b2c-761e-4f83-9b06-cd5e2a719840`.
- `map_uuid`는 맵 번호·맵명·파일명이 바뀌어도 유지한다.
- 같은 장소의 단순 상태·조명·배치 변화는 동일 `map_uuid`를 유지할 수 있다. 공간 구조를 다시 설계해 별도 배틀맵 자산으로 취급할 수준이면 새 `map_uuid`를 만들고 필요하면 `derived_from_map_uuid`로 원본 맵 UUID를 기록한다.

### 장면 식별 정보

각 장면 파일은 로그 분석에서 실제 플레이 장면과 의미적으로 대응할 수 있도록 다음 최소 지문을 둔다.

- 주요 장소
- 핵심 사건
- 주요 참여자
- 고유 앵커

장면 식별 정보는 장면 기능 전체를 복제하지 않는다. 장면 역할·시작/종료 조건·공개/숨겨진 정보·이전/다음 연결은 기존 정본 섹션과 `02. 장면 목록`을 사용한다.

### 사용 맵 직접 참조

- 맵이 필요 없는 장면은 `## 사용 맵` 아래에 반드시 `- 없음`을 기록한다. 빈 섹션으로 두지 않는다.
- 맵 하나를 사용하면 `map_uuid`, `공용 맵명`, `사용 범위`를 기록한다.
- 한 장면에서 복수 맵을 사용하면 각 맵을 하위 항목으로 나누고 `사용 범위`를 반드시 기록한다.
- 기존 맵을 재사용하면 같은 물리적 맵 자산은 기존 `map_uuid`를 유지한다.
- 로그 분석은 장면이 매칭된 뒤 이 직접 참조를 따라 맵을 확정하며, 장소명만 보고 설계 맵을 새로 추정하지 않는다.

### 플레이 완료 설계의 역사 보존

- 세션 설계 문서의 `status`는 기본적으로 `draft / confirmed / played`를 사용한다.
- `played`는 해당 장면이 실제 진행되었다는 뜻이 아니라, 해당 세션이 이미 플레이되어 그 설계 문서가 역사적 의도 기록으로 동결되었다는 뜻이다.
- 실제 진행 여부는 3번 로그 분석의 `matched / merged / split / skipped / unplanned / uncertain` 대응으로만 판정한다.
- `played` 상태에서는 오탈자, 깨진 링크, 잘못된 파일 참조 같은 정정은 허용하지만 장면 목적·핵심 사건·맵 구조를 당시와 다르게 소급 재작성하지 않는다.
- 플레이 후 실제 결과와 설계의 차이는 설계 문서를 고쳐 없애지 않고 3번 로그 분석에 기록한다.
- 기존 자료는 일괄 마이그레이션하지 않는다. 신규 세션부터 적용하고, 기존 세션은 수정·재분석이 필요한 패키지만 새 구조로 점진 승격한다.

## 공용 맵 참조

- 세션 제작은 필요한 공간을 먼저 `11. 맵`에서 환경·공간명·`map_uuid`로 검색한다.
- 기존 공용 맵을 쓰면 같은 `map_uuid`를 장면의 `사용 맵`과 세션 `맵/00. 맵 목록.md`에 기록한다.
- 새 공간이면 `11. 맵/<환경>/`에 공용 맵 문서와 자산을 만들고 새 `map_uuid`를 발급한다.
- 세션 `맵/`에는 `00. 맵 목록.md`만 두며, 장면별 토큰·배치·사건은 장면 문서의 `## 맵 운용`이 소유한다.
