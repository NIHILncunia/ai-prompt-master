# 6. 세션 문서 양식 및 출력 규칙

## 기본 산출 단위

세션 하나는 `TRPG 데이터/17. 세션 설계/[스토리명]/[세션 이름] 기획/`의 세션 패키지다.

```text
[세션 이름] 기획/
├─ 01. [세션 이름] 시나리오.md
├─ 02. [세션 이름] 장면 목록.md
├─ 장면/
│  ├─ 00. 세션 프롤로그.md
│  ├─ 01. [장면명].md
│  ├─ ...
│  └─ NN. 세션 에필로그.md
├─ 맵/
│  ├─ 00. 맵 목록.md
│  ├─ 01. [맵명].md
│  └─ ...
├─ 03. [세션 이름] 등장인물 및 몬스터.md
└─ NPC 및 몬스터/
   ├─ [NPC명].md
   ├─ [몬스터명].md
   └─ ...
```

`03`은 등장인물 및 몬스터의 상위 요약·인덱스 파일로 유지한다. NPC·몬스터의 상세 정보와 스탯블록은 `NPC 및 몬스터/[이름].md` 하나에 통합한다. 조우는 별도 `04` 또는 `조우/` 산출물로 분리하지 않고 해당 장면 파일에 성공 조건·실패 조건·실패 후 진행을 기록한다.

연속 세션의 아크 개요는 스토리 폴더에 `00. 세션 아크 개요.md`로 둔다.

## 단계별 파일 생성 시점

세션 제작 과정에서 모든 파일을 처음부터 한꺼번에 만들지 않는다.

1. 한 줄 이야기, 핵심 이야기 골격, 핵심 사건 흐름이 정리되면 `01. 시나리오`를 작성하거나 갱신할 수 있다.
2. 핵심 사건 흐름을 장면으로 나누기 시작하면 `02. 장면 목록`을 작성한다.
3. `02. 장면 목록`의 순서와 기능이 확정되기 전에는 `장면/` 하위 장면별 파일을 만들지 않는다.
4. 장면 목록 확정 후 장면별 파일을 생성하고 기능·체크·묘사를 확장한다.
5. 장면 기능과 묘사가 충분히 정리된 뒤 `맵/`을 만들고 필요한 맵 수와 장면 할당을 확정한다.
6. 맵 설계가 확정되면 필요한 배틀맵 이미지를 해당 이미지 기능으로 제작한다.
7. 이후 `03`과 `NPC 및 몬스터/`를 정리하고 스탯 정책을 판정한다.
8. 각 NPC·몬스터 통합 파일에 필요한 스탯블록을 추가하고, NPC·몬스터 이미지와 토큰을 제작한다.
9. 결과 판정이 필요한 장면에 성공 조건·실패 조건·실패 후 진행을 기록하고 장면에서 맵·NPC·몬스터 통합 파일 참조를 연결한다.

## 공통 프론트매터

기본 관리 파일은 `document_type`, `campaign`, `story`, `session_title`, `status`를 공통으로 사용할 수 있다. 정해지지 않은 값은 생략하며 임의로 만들지 않는다.

장면 파일은 `scene_number`, `scene_title`, 맵 파일은 `map_number`, `map_title`을 추가할 수 있다.

### NPC 및 몬스터/[이름].md

이 파일은 해당 NPC·몬스터의 상세 정보와 스탯블록을 함께 관리하는 정본이다. 별도의 `[이름] 스탯블록.md` 파일은 만들지 않는다.

권장 순서는 다음과 같다.

- 기본 정보와 공통 프로필
- 외형과 장비
- 마스터용 묘사
- 스탯블록 정책
- 스탯블록
- 목적과 태도 또는 전투 역할
- 행동 기준
- 장면별 등장 관계
- 이미지·토큰 결과 참조


`마스터용 묘사`는 GM이 실제 플레이에서 읽을 수 있는 등장 묘사다. 기본 1~2문단으로 작성하며, 플레이어가 감지 가능한 외형·움직임·기세·장비·마력 연출을 중심으로 한다. 숨겨진 정체나 미공개 목적, 기계 수치를 선행 공개하지 않으며, 상태 변화가 큰 대상은 상황별 하위 묘사를 둘 수 있다. 문체는 반말이나 소설 독백체가 아니라, 마스터가 플레이어에게 상황을 설명하는 정중체 기반의 설명형 서술을 기본으로 한다. 확정 이미지가 있는 대상은 최신 확정 이미지와 묘사의 외형·색상·장비·분위기가 어긋나지 않게 맞춘다.

`스탯블록 불필요`라면 이유만 기록하고 실제 스탯 섹션은 생략할 수 있다. `기존 스탯블록 재사용`은 스탯블록명·출처·사용 방침을 기록하며 원문 수치를 불필요하게 복제하지 않는다. `전용 스탯블록 제작`은 4번 룰북 기능의 형식에 따라 실제 스탯블록을 이 파일 안에 직접 삽입한다.

### 장면 내 조우 결과 조건

조우는 별도 파일로 분리하지 않는다. 결과 판정이 필요한 `장면/NN. [장면명].md`에 다음을 직접 기록한다.

- 성공 조건
- 실패 조건
- 실패 후 진행

부분 성공이나 대가가 있는 성공이 필요하면 성공 결과 안에서 함께 설명한다. 실패는 세션 중단이 아니라 불리한 상태와 대가를 남긴 채 다음 장면으로 이어지는 페일포워드를 기본으로 한다.

## 장면 확정 시 대화 출력 규칙

장면이 `확정` 상태가 되는 응답에서는 Drive 파일 저장·갱신과 함께 해당 장면 파일의 확정 내용을 대화 본문에도 전체 표시한다.

- 파일 링크나 저장 완료 보고만 제공하지 않는다.
- 사용자가 별도로 Drive 파일을 열지 않아도 장면의 확정 내용을 검토할 수 있어야 한다.
- 장면 파일에 포함된 실제 운영 정보와 묘사를 대화 본문에서 동일한 내용으로 보여준다.
- 초안·검토 단계는 변경점과 검토 대상 중심으로 표시할 수 있다.
- 프롤로그와 에필로그에도 동일하게 적용한다.

## 실제 플레이용 묘사 문체 기준

세션 프롤로그, 에필로그와 장면 파일의 실제 플레이용 묘사는 같은 캠페인·같은 아크의 원본 로그가 존재하면 해당 원본 로그의 GM 서술을 반드시 먼저 확인한 뒤 작성한다.

- 정보흐름분석 문서는 사실·연속성 확인에 사용하고 문체 표본으로 대체하지 않는다.
- 바로 이전 회차 원본 로그를 최우선으로 하고, 필요하면 같은 아크의 인접 회차와 같은 캠페인의 최근 원본 로그를 추가 확인한다.
- 플레이어 채팅이 아니라 GM 서술의 문장 길이, 줄바꿈, 2인칭 호명, 구어적 종결 표현, 정보 공개 순서, 장면 전환 호흡을 재현한다.
- 원문을 그대로 복제하지 않고 현재 장면의 내용으로 다시 쓴다.
- 특별한 지시가 없으면 반말, 독백체, 소설 내면 묘사를 피하고 `~보입니다`, `~들립니다`, `~느껴집니다`, `~드러납니다`, `~하고 있습니다`처럼 마스터의 정중체 설명에 바로 사용할 수 있는 종결을 우선한다.
- 사용자가 별도의 묘사 문체를 지정하면 그 지시를 우선한다.

## 이미지와 토큰

배틀맵, NPC·몬스터 이미지와 토큰의 실제 생성은 기존 이미지 생성 기능 지침을 사용한다.

세션 문서는 어떤 이미지가 필요한지, 어떤 장면·대상에 연결되는지, 생성 상태와 결과 참조를 관리한다.

맵에 배치되는 NPC·몬스터는 전투 여부와 관계없이 기본 토큰 제작 대상이다.

## FVTT 데이터와의 경계

세션 패키지는 이미지와 스탯 데이터를 준비하는 데까지 담당한다.

다음은 6번 FVTT 기능으로 넘긴다.

- Actor
- Scene
- Journal
- Compendium
- JSON
- 모듈·팩 데이터
- 피트·아이템·주문·액터 설명의 `[[...]]` 인라인 문법 조립과 `@...` 롤 데이터 경로 검증

4번 룰북 기능에서 확인되어 스탯블록에 포함된 인라인 문법은 세션 문서에서 보존한다. 미확인 문법을 새로 만들거나 동적 값을 고정 숫자로 바꾸지 않는다. 실제 FVTT 변환 단계에서는 6번의 `2. 피트 및 아이템 인라인 문법과 변수 사용 가이드.md`를 적용한다.

## 장면 목록과 장면 파일 동기화

`02. 장면 목록`을 장면 구조의 기준 원장으로 사용한다.

장면을 추가·삭제·통합하거나 순서를 바꿀 때에는 먼저 장면 목록을 수정하고 장면 파일명·번호·연결·맵 할당을 함께 갱신한다.

## 파일명과 제공

세션 번호는 사용하지 않는다. 세션 폴더명은 `[세션 이름] 기획`으로 고정하며 `최종`, `수정본`, 날짜, 임의 버전 접미사를 붙이지 않는다.

장면 파일명은 `NN. [장면명].md`, 맵 파일명은 `NN. [맵명].md`를 기본으로 한다. 프롤로그는 `00. 세션 프롤로그.md`, 에필로그는 마지막 본편 장면 다음 번호의 `NN. 세션 에필로그.md`를 사용한다.

신규 세션 파일은 위 경로의 Google Drive 폴더에 직접 저장하는 것을 기본으로 한다. 기존 파일의 덮어쓰기·삭제·이름 변경은 명시적 요청이 있을 때만 수행한다. Drive 저장이 불가능하거나 사용자가 별도로 요청한 경우에만 동일 경로를 보존한 로컬 파일 또는 ZIP을 제공한다.

기존 단일 파일 세션, 기존 `02. 장면 모음` 패키지, 기존 4파일 중심 패키지는 사용자가 이관을 요청하지 않는 한 자동 변환하지 않는다.
