# 9. 세션 자산 및 VTT 준비 지침

## 역할

이 문서는 장면 기능과 실제 진행 묘사가 확정된 세션을 기준으로 실제 플레이 준비에 필요한 맵, NPC·몬스터 스탯블록, 이미지와 토큰을 설계·제작하는 절차를 정의한다.

세션 제작 기능은 여기까지를 하나의 연속 작업으로 관리한다. 실제 Foundry VTT Actor, Scene, Journal, Compendium, JSON, 모듈 데이터 변환과 피트·아이템 설명의 인라인 문법 검증은 6번 FVTT 관련 요청 기능이 담당한다.

## 진입 조건

다음이 충분히 정리된 뒤 이 단계로 진입한다.

- 장면 목록이 확정되어 있다.
- 장면별 파일이 존재한다.
- 각 장면의 목적, 장소, 주요 등장 대상, 갈등과 종료 조건이 정리되어 있다.
- 필요한 장면 묘사·진행 묘사·등장 묘사가 정리되어 있다.

장면 구조가 계속 변하는 상태에서는 맵이나 스탯블록을 먼저 만들지 않는다.

## 전체 순서

`필요 맵 산정 → 장면별 맵 할당 → 맵 규격·구조 설계 → 배틀맵 이미지 제작 → NPC·몬스터 목록 확정 → 스탯블록 정책 판정 → 전용 제작 대상 컨셉 확인 → 스탯블록 제작 → NPC·몬스터 이미지 제작 → 토큰 제작 → 장면 결과 조건·맵·자산 연결 검증`

## 배틀맵의 정의

이 기능에서 배틀맵은 전투 전용 지도가 아니다.

토큰을 배치하여 위치, 거리, 이동, 공간 관계를 표현할 가치가 있는 장면이면 전투가 없어도 맵 대상으로 본다.

다음과 같은 장면은 맵을 적극 검토한다.

- 전투
- 탐사
- 추적·도주
- 구조·호위
- 잠입
- 복수의 NPC가 위치 관계를 가지고 움직이는 사회적 장면
- 도시 광장, 건물 내부, 유적, 비공정 내부처럼 공간 자체가 플레이에 영향을 주는 장면

단순 전환, 짧은 대화, 위치 관계가 의미 없는 장면은 맵을 생략할 수 있다.

## 맵 개수 산정

장면 수와 맵 수를 1:1로 맞추지 않는다.

- 같은 장소에서 이어지는 여러 장면은 하나의 맵을 재사용할 수 있다.
- 한 장면이 서로 다른 대규모 구역을 오가면 둘 이상의 맵을 사용할 수 있다.
- 기존에 제작된 적절한 맵이 있으면 재사용을 우선 검토한다.
- 전투가 없다는 이유만으로 맵을 생략하지 않는다.
- 토큰 배치의 의미가 없는 장면에는 불필요한 맵을 만들지 않는다.

## 장면별 맵 할당

`02. [세션 이름] 장면 목록.md`에는 각 장면의 `맵` 참조를 기록한다.

맵이 없는 장면은 빈 값이 아니라 반드시 `없음`으로 명시한다. 맵이 있으면 장면 파일에서 `map_uuid`와 공용 맵명을 참조한다. 하나의 맵을 여러 장면에서 재사용할 수 있고 한 장면에서 복수 맵을 사용하는 경우 각 맵의 사용 범위를 명시한다.

`맵/00. 맵 목록.md`는 이번 세션의 공용 맵 UUID 참조 원장이다.

## 맵 설계 정보

각 맵 파일에는 필요한 만큼 다음을 기록한다.

- 영구 `map_uuid`
- 맵 번호와 이름
- 사용 장면
- 신규 제작 / 기존 맵 재사용
- 맵의 목적
- 장소와 시점
- 가로형 / 세로형 / 정방형
- 논리 그리드 가로 칸 수
- 논리 그리드 세로 칸 수
- 권장 이미지 가로·세로 비율
- 권장 이미지 해상도
- 주요 구조물
- 출입 지점
- 토큰 활동 범위
- 고저차
- 엄폐물
- 이동 제약
- 조우·이벤트 특수 구역
- 생성 상태
- 결과 이미지 참조

그리드 수와 이미지 비율·해상도는 장면 규모, 참여자 수, 이동 거리, 원거리 전투 가능성, 공간 밀도와 이미지 생성 기능의 출력 제약을 기준으로 적절한 수준으로 자동 산정한다. 사용자가 수치를 지정하면 그 값을 우선한다.

문서의 그리드 수는 FVTT에서 사용할 논리 그리드 설계값이다. 실제 이미지에 격자를 그릴지 여부와 이미지 생성 세부 규칙은 배틀맵 이미지 기능 지침을 따른다.

## 배틀맵 이미지 제작

맵 설계가 확정되면 기존 이미지 생성 모듈의 배틀맵 기능으로 실제 이미지를 제작한다.

세션 제작 기능은 다음 정보를 배틀맵 기능에 전달한다.

- 장면과 맵 목적
- 공간 구조
- 주요 구조물
- 필요한 분위기와 환경
- 논리 그리드 크기
- 권장 가로·세로 비율

이미지 생성 기능의 승인 절차, 스타일, 해상도, 세부 출력 규칙은 해당 기능 지침을 그대로 적용한다.

## NPC·몬스터 목록 확정

맵 설계 뒤 세션에서 실제로 등장하는 NPC·몬스터를 정리한다.

`03. [세션 이름] 등장인물 및 몬스터.md`는 전체 목록과 요약 인덱스로 사용하고, 상세 정보와 스탯블록은 `NPC 및 몬스터/[이름].md` 통합 파일 하나에 둔다.

맵 위에 배치되는 NPC·몬스터는 전투 여부와 관계없이 기본적으로 토큰 제작 대상이다.

### 통합 상세 파일 원칙

`NPC 및 몬스터/[이름].md`는 외형 문서와 스탯블록 문서를 겸하는 단일 정본이다.

권장 순서는 `기본 정보 → 외형 및 장비 → 마스터용 묘사 → 스탯블록 정책 → 스탯블록 → 성격·행동 원리 또는 전투 역할 → 등장 관계 → 이미지·토큰`이다.

스탯블록이 불필요한 경우에는 정책과 이유만 남기고 실제 스탯블록 섹션을 생략할 수 있다. 별도의 개체별 `[이름] 스탯블록.md` 파일은 생성하지 않는다. 단, 세션에 실제 사용할 스탯블록 정리가 끝나면 개별 정본의 스탯블록을 모은 `05. [세션 이름] 스탯블록 모음.md`를 플레이용 파생 집합본으로 생성한다.


### 마스터용 묘사

모든 세션용 NPC·몬스터 통합 정본에는 기본적으로 `마스터용 묘사`를 둔다. 이는 GM이 첫 등장 또는 주요 상태 변화 시 그대로 읽을 수 있는 플레이 전달용 문장이다.

- 기본 1~2문단으로 작성하며, 각 서술 문단은 반드시 3~4개의 완결된 문장으로 구성한다. 한 문장짜리 서술 문단은 허용하지 않으며, 5문장 이상이면 의미와 장면 호흡을 기준으로 각각 3~4문장인 복수 문단으로 분리한다.
- 플레이어가 감지 가능한 외형, 움직임, 자세, 무장, 마력 연출, 위압감과 분위기를 중심으로 한다.
- 문체는 마스터가 플레이어에게 장면을 설명하는 정중체 기반의 상황 설명체를 기본으로 한다.
- 반말, 소설 독백체, 감상문체, 내면 서술 중심 문체는 사용하지 않는다. 특별한 지시가 없으면 `~보입니다`, `~드러납니다`, `~느껴집니다`, `~하고 있습니다` 같은 설명형 종결을 우선한다.
- 숨겨진 정체·목적·기계 수치·아직 공개되지 않은 설정은 선행 공개하지 않는다.
- 외형 데이터와 중복 나열하지 않고, 실제 장면에서 눈에 들어오는 순서와 인상을 중심으로 쓴다.
- 위장/본색, 비전투/전투 등 인상이 크게 달라지는 경우 상황별 하위 묘사를 작성할 수 있다.
- 몬스터도 예외가 아니며, 공용 몬스터는 반복 사용 가능한 대표 등장 묘사를 작성한다.
- 확정 이미지가 있는 대상은 최신 확정 이미지와 외형, 색상, 장비, 분위기, 노출 범위가 어긋나지 않도록 묘사를 맞춘다.

## 스탯블록 정책

**모든 NPC와 몬스터는 예외 없이 스탯블록이 필요하다.** 다만 모든 대상에게 새 전용 스탯블록을 만들 필요는 없으며, 적절한 기존 스탯블록이 있으면 재사용한다. 전투에 참여하지 않는 단역·대화용·지원 NPC도 스탯블록을 생략하지 않는다.

각 대상을 다음 셋 중 하나로 분류한다.

1. `기존 스탯블록 재사용`
2. `전용 스탯블록 제작`

### 일반 NPC

일반 경비, 병사, 사제, 상인, 용병, 주민 등은 역할에 맞는 기존 NPC용 스탯블록을 우선 검토한다.

기존 스탯을 사용하면 `스탯블록명`, `출처`, `사용 이유`를 기록한다.

### 강조된 NPC

사용자가 중요하다고 강조한 NPC, 고유한 전투 능력이 필요한 NPC, 이야기상 특별한 힘이 중요한 NPC는 임의로 평범한 기존 스탯에 치환하지 않는다.

전용 스탯블록이 필요한 경우 확정된 설정과 전투·운용 컨셉을 반영한다. 필요한 컨셉이 이미 제공되어 있으면 다시 묻지 않는다.

사용자가 이미 컨셉을 제공했다면 다시 묻지 않는다.

### 몬스터

몬스터를 전용 제작할 때에는 사용자가 이미 정하지 않았다면 `일반 / 정예 / 보스` 중 어떤 등급인지 확인한다.

등급과 함께 전투·운용 컨셉이 비어 있으면 사용자에게 묻는다.

## 룰북 참조와 스탯블록 제작

실제 룰 시스템 스탯을 선택하거나 제작할 때에는 4번 룰북 관련 요청 기능과 현재 룰북 자료를 확인한다.

세션 본문은 시스템 중립 구조를 유지하더라도 NPC·몬스터 통합 파일의 `스탯블록` 섹션은 선택한 룰 시스템의 실제 형식과 수치를 사용할 수 있다.

별도의 개체별 `[이름] 스탯블록.md` 파일은 만들지 않는다. `05. [세션 이름] 스탯블록 모음.md`는 이 규칙의 예외인 플레이용 파생 집합본이다. **모든 NPC와 몬스터는** `NPC 및 몬스터/[이름].md`에서 기본 정보, 외형·장비, 마스터용 묘사 다음에 `스탯블록 정책`과 `스탯블록`을 두고 같은 파일 안에 기록한다. 기존 스탯블록 재사용도 같은 위치에 이름·출처·사용 방침과 실제 운용할 스탯을 연결한다.

## NPC·몬스터 이미지 제작

외형과 역할이 확정된 대상은 기존 이미지 생성 기능으로 이미지를 제작한다.

세션 제작 기능은 대상의 확정된 외형, 장비, 분위기, 역할과 중요도를 이미지 기능에 전달한다.

이미지의 스타일, 비율, 승인 절차는 대상에 맞는 이미지 기능 지침을 따른다.

## 토큰 제작

맵에 배치되는 NPC와 몬스터는 기본적으로 토큰을 제작한다.

전투하지 않는 NPC도 맵 위에 존재한다면 토큰 대상이다.

토큰 이미지는 기존 토큰 제작 기능의 지침을 적용하며, 세션 자산 문서에는 결과 이미지 참조와 제작 상태를 기록한다.

## 장면 결과 조건과 자산 연결

조우는 별도 문서로 분리하지 않는다. 결과 판정이 필요한 장면의 `장면/NN. [장면명].md`에 성공 조건, 실패 조건, 실패 후 진행을 직접 기록한다.

장면은 필요한 경우 다음 자산을 참조한다.

- 사용 맵
- 참여 NPC·몬스터
- 참여자 상세 파일
- 환경 특수 구역

스탯블록 수치는 장면 파일에 복제하지 않고 `NPC 및 몬스터/[이름].md` 통합 파일을 참조한다.

## 표준 폴더 구조

```text
[세션 이름] 기획/
├─ 01. [세션 이름] 시나리오.md
├─ 02. [세션 이름] 장면 목록.md
├─ 장면/
│  ├─ 01. [장면명].md
│  └─ ...
├─ 맵/
│  ├─ 00. 맵 목록.md
│  ├─ 01. [맵명].md
│  └─ ...
├─ 03. [세션 이름] 등장인물 및 몬스터.md
├─ 04. [세션 이름] 진행 시트.md
├─ 05. [세션 이름] 스탯블록 모음.md
└─ NPC 및 몬스터/
   ├─ [NPC명].md
   ├─ [몬스터명].md
   └─ ...
```

기존 세션은 사용자가 이관을 요청하지 않는 한 자동으로 이 구조로 변환하지 않는다.

## 모호성 처리

다음처럼 결과가 크게 달라지는 결정은 임의로 확정하지 않고 사용자에게 묻는다.

- 주요 NPC의 전용 스탯블록 제작 여부
- 전용 스탯블록의 전투 컨셉
- 몬스터의 일반·정예·보스 분류
- 이미지 디자인이 여러 방향으로 갈리는 경우
- 맵 규모가 전혀 다른 두 방향으로 갈리고 플레이 방식에 영향을 주는 경우

다음은 합리적인 범위에서 자동으로 정할 수 있다.

- 일반적인 맵 가로·세로 비율
- 논리 그리드 수
- 일반 NPC에 사용할 기존 스탯블록 후보
- 같은 장소 맵의 재사용 여부

## FVTT 기능과의 경계

세션 제작 기능은 이미지와 스탯 데이터를 준비하는 데까지 담당한다.

다음 실제 FVTT 데이터 변환은 6번 기능으로 넘긴다.

- Actor
- Scene
- Journal
- Compendium
- JSON

## 완료 기준

세션 자산 단계가 완료되려면 다음을 확인한다.

- 필요한 맵 수가 산정되었다.
- 각 장면의 맵 참조가 정리되었다.
- 필요한 배틀맵 이미지가 준비되었다.
- NPC·몬스터 목록이 확정되었다.
- 각 대상의 스탯 정책이 결정되었다.
- 세션에 등장하는 모든 NPC·몬스터의 `NPC 및 몬스터/[이름].md` 통합 파일에 스탯블록이 준비되었다.
- 필요한 NPC·몬스터 이미지가 준비되었다.
- 맵에 배치되는 NPC·몬스터의 토큰이 준비되었다.
- 결과 판정이 필요한 장면에 성공 조건·실패 조건·실패 후 진행이 있으며 관련 맵·NPC·몬스터 통합 파일을 올바르게 참조한다.
- 실제 FVTT 데이터 변환은 아직 수행하지 않았다.
- 새 인라인 문법과 롤 데이터 경로가 필요하면 6번 기능으로 넘길 대상과 문맥이 정리되었다.

## 로그 분석 연동용 장면·맵 식별 규칙

### 영구 장면·맵 식별자

- 모든 신규 세션 설계 장면에는 `scene_uuid`를 부여한다.
- 값은 소문자 표준 UUID 형식으로 작성한다. 예: `5e02c452-01a3-4d9e-8737-8f2b1a0c9d64`.
- 프롤로그와 에필로그도 정식 장면이므로 `scene_uuid`를 가진다.
- `scene_uuid`는 장면 번호·장면명·파일명이 바뀌어도 유지한다. 장면을 다른 장면과 통합하여 정체성이 사라질 때에만 폐기하고, 새 장면에는 새 UUID를 부여한다.
- 모든 신규 맵에는 `map_uuid`를 부여한다.
- 값은 소문자 표준 UUID 형식으로 작성한다. 예: `86a41b2c-761e-4f83-9b06-cd5e2a719840`.
- `map_uuid`는 맵 번호·맵명·파일명이 바뀌어도 유지한다.
- 같은 장소의 단순 상태·조명·배치 변화는 동일 `map_uuid`를 유지할 수 있다. 공간 구조를 다시 설계해 별도 배틀맵 자산으로 취급할 수준이면 새 `map_uuid`를 만들고 필요하면 `derived_from_map_uuid`로 원본 맵 UUID를 기록한다.

### 장면 식별 정보

각 장면 파일은 로그 분석에서 실제 플레이 장면과 의미적으로 대응할 수 있도록 다음 최소 지문을 둔다.

- 주요 장소
- 핵심 사건
- 주요 참여자
- 고유 앵커

장면 식별 정보는 장면 기능 전체를 복제하지 않는다. 장면 역할·시작/종료 조건·공개/숨겨진 정보·이전/다음 연결은 기존 정본 섹션과 `02. 장면 목록`을 사용한다.

### 사용 맵 직접 참조

- 맵이 필요 없는 장면은 `## 사용 맵` 아래에 반드시 `- 없음`을 기록한다. 빈 섹션으로 두지 않는다.
- 맵 하나를 사용하면 `map_uuid`, `공용 맵명`, `사용 범위`를 기록한다.
- 한 장면에서 복수 맵을 사용하면 각 맵을 하위 항목으로 나누고 `사용 범위`를 반드시 기록한다.
- 기존 맵을 재사용하면 같은 물리적 맵 자산은 기존 `map_uuid`를 유지한다.
- 로그 분석은 장면이 매칭된 뒤 이 직접 참조를 따라 맵을 확정하며, 장소명만 보고 설계 맵을 새로 추정하지 않는다.

### 플레이 완료 설계의 역사 보존

- 세션 설계 문서의 `status`는 기본적으로 `draft / confirmed / played`를 사용한다.
- `played`는 해당 장면이 실제 진행되었다는 뜻이 아니라, 해당 세션이 이미 플레이되어 그 설계 문서가 역사적 의도 기록으로 동결되었다는 뜻이다.
- 실제 진행 여부는 3번 로그 분석의 `matched / merged / split / skipped / unplanned / uncertain` 대응으로만 판정한다.
- `played` 상태에서는 오탈자, 깨진 링크, 잘못된 파일 참조 같은 정정은 허용하지만 장면 목적·핵심 사건·맵 구조를 당시와 다르게 소급 재작성하지 않는다.
- 플레이 후 실제 결과와 설계의 차이는 설계 문서를 고쳐 없애지 않고 3번 로그 분석에 기록한다.
- 기존 자료는 일괄 마이그레이션하지 않는다. 신규 세션부터 적용하고, 기존 세션은 수정·재분석이 필요한 패키지만 새 구조로 점진 승격한다.
