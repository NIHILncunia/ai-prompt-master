# 0. 세션 제작 마스터 프롬프트

## 문서 목적

이 문서는 `TRPG 데이터/1. 프롬프트/8. 세션 제작 프롬프트`의 실행 진입점이다.

사용자가 룩스테라 세계에서 플레이할 단일 세션, 연속 세션 아크, 특정 회차, 장면, NPC, 조우를 설계하거나 기존 초안을 보완해 달라고 요청하면 이 문서를 먼저 적용한다.

## 적용 조건

다음 요청을 이 기능으로 처리한다.

- 세션 제작
- 단편 또는 단일 세션 제작
- 여러 회차로 이어지는 사건 또는 아크 설계
- 이전 세션에 이어지는 다음 회차 제작
- 특정 설정·지역·인물·세력을 이용한 사건 제작
- 세션용 장면·NPC·조우 구성
- 기존 세션 초안 보완
- 플레이 전에 사용할 GM용 세션 문서 작성

다음 작업은 다른 기능으로 라우팅한다.

- 종료된 세션 로그 분석: 3번
- 설정 정본 신규 작성·수정: 5번
- 독립적인 이미지·배틀맵·토큰·아이콘 제작 요청: 해당 이미지 기능. 단, 세션 제작 중 필요한 자산은 이 기능이 필요성을 확정하고 해당 이미지 기능을 호출해 연속 제작한다.
- 특정 룰 시스템 수치와 판정 해석: 4번
- FVTT 데이터 작성과 피트·아이템 설명의 `[[...]]`·`@...` 문법 검증: 6번

## 기본 세계관

기본 세계관은 프로젝트 위그드라실의 룩스테라다.

사용자가 세계관을 별도로 말하지 않아도 룩스테라 설정 정본을 기준으로 삼는다. `룩스테라`, `마키나즈`, `남아있는 이야기`는 같은 세계 안의 스토리 구분으로 취급한다.

## 세션 제작 모드

### 단일 세션 제작

하나의 사건 또는 사건의 한 국면을 한 회차 분량으로 제작한다.

한 회차가 끝났을 때 플레이어는 반드시 무언가를 발견하거나, 선택하거나, 변화시키거나, 얻거나, 잃어야 한다.

### 연속 세션 아크 설계

여러 회차에 걸친 핵심 갈등, 진실, 세력, 회차별 목표와 변곡점을 설계한다.

모든 회차를 같은 수준으로 상세 작성하지 않는다. 사용자가 요청한 회차만 상세 세션 문서로 제작한다.

### 연속 세션 회차 제작

아크 개요, 이전 분석본, 원본 로그와 실제 플레이 결과를 참고해 특정 회차 하나를 상세 제작한다.

산출물 형식은 단일 세션과 동일한 세션 패키지 구조를 사용하며, 장면 목록이 확정된 뒤 장면별 독립 파일을 생성한다.

### 기존 초안 보완

사용자가 제공한 초안의 사건 의도와 고정 요소를 유지하면서 장면, NPC, 조우, 정보 흐름, 분기, 실패 처리, 결말 가능성을 보완한다.

## 계단식 설계 원칙

세션 제작은 처음부터 장면 디테일을 작성하지 않고 추상적인 이야기에서 실제 플레이 장면으로 단계적으로 내려간다.

기본 단계는 다음과 같다.

`한 줄 이야기 → 핵심 이야기 골격 → 핵심 사건 흐름 → 장면 목록 → 장면별 파일 생성 → 장면 기능 확장·묘사·성공/실패 조건 → 맵 산정·할당 → 배틀맵 설계·제작 → NPC·몬스터 목록 확정 → 스탯 정책 판정·제작 → 이미지·토큰 제작 → 장면 결과 조건·자산 연결 검증 → 전체 검수`

각 단계는 바로 다음 단계에 필요한 범위까지만 확정한다. 앞 단계가 정리되지 않았는데 NPC 세부 프로필, 전투 기믹, 능력 체크 수치, 장면 묘사 같은 하위 디테일을 먼저 만들지 않는다.

사용자 입력은 두 유형으로 나눈다.

### 흐름 제공형

사용자가 사건 순서, 장면 흐름, 핵심 전개를 직접 제공했다면 그 흐름을 우선한다. 이미 제공된 내용을 다시 질문하거나 처음부터 재설계하지 않는다.

제공된 흐름을 한 줄 이야기와 상위 골격으로 압축해 정합성을 확인하고, 충돌·누락·호흡 문제만 조정한 뒤 사용자가 제공한 단계 다음부터 확장한다.

### 처음부터 설계형

사용자가 소재나 출발점만 제시하고 이야기 흐름을 정하지 않았다면 질문을 적극적으로 사용한다.

가장 먼저 `이 세션을 한 줄로 요약하면 어떤 이야기인가`를 정한다. 사용자가 바로 답하기 어려우면 2~3개의 서로 다른 한 줄 방향을 제안하고 선택 또는 수정을 요청할 수 있다.

처음부터 설계형에서는 큰 이야기 결정을 임의로 채우지 않는다. 한 번에 하나의 결정 단위만 묻고, 답이 확정될 때마다 다음 계단으로 내려간다.

## 기본 처리 순서

1. 요청이 세션 제작 기능의 범위인지 판별한다.
2. 단일 세션, 아크 설계, 연속 회차, 초안 보완 중 작업 모드를 판별한다.
3. 사용자가 고정한 사건, 인물, 지역, 분위기, 금지 요소를 정리한다.
4. 이전 내용의 존재 여부를 판별한다.
5. 관련 룩스테라 설정 문서를 탐색한다.
6. 이전 내용이 있으면 지정된 분석본과 필요한 원본 로그를 확인한다.
7. 사용자 입력이 `흐름 제공형`인지 `처음부터 설계형`인지 판별한다.
8. 세션을 한 문장으로 압축한 `한 줄 이야기`를 확정한다.
9. 시작 상황, 중심 문제, 이번 회차의 핵심 변화, 종료 지점을 포함한 `핵심 이야기 골격`을 확정한다.
10. 골격을 장면보다 큰 사건 단위인 `핵심 사건 흐름`으로 확장한다.
11. 핵심 사건 흐름이 확정된 뒤에만 `02. [세션 이름] 장면 목록.md`에서 장면명과 한 줄 기능을 정리한다.
12. 장면 목록의 순서, 연결성, 중복, 누락, 절정·결말 배치를 점검한다.
13. 장면 목록이 확정된 뒤에만 `장면/NN. [장면명].md` 파일을 장면별로 생성한다.
14. 각 장면 파일에서 장면 목적, 정보, 갈등, 체크·내성 포인트, 장면·진행·NPC·몬스터 묘사 등 `장면 기능 확장`을 진행한다.
15. 결말 가능성과 이후에 남는 변화를 설계하여 세션의 이야기·장면·묘사 단계를 정리한다.
16. 모든 장면을 검토해 토큰 배치가 의미 있는 장면의 맵 필요성을 판정하고 필요한 맵 수를 산정한다.
17. 장면별 맵을 할당하고 맵마다 논리 그리드 가로·세로 수, 권장 비율·해상도와 공간 구조를 설계한다.
18. 필요한 배틀맵은 이미지 생성 모듈의 배틀맵 기능을 사용해 제작한다.
19. 세션에 등장하는 NPC·몬스터 목록을 확정하고 `스탯블록 불필요 / 기존 재사용 / 전용 제작`으로 분류한다.
20. 전용 제작 대상 중 사용자가 이미 정하지 않은 주요 NPC의 컨셉과 몬스터의 일반·정예·보스 등급 및 전투 컨셉을 한 결정 단위씩 확인한다.
21. 실제 스탯블록이 필요하면 4번 룰북 기능의 자료를 확인해 기존 스탯을 선택하거나 전용 스탯블록을 제작하고 `NPC 및 몬스터/[이름].md` 통합 파일의 `스탯블록 정책`과 `스탯블록` 섹션에 직접 기록한다.
22. 필요한 NPC·몬스터 이미지를 제작하고, 맵에 배치되는 NPC·몬스터는 전투 여부와 관계없이 토큰을 제작한다.
23. 결과 판정이 필요한 장면에 성공 조건, 실패 조건, 실패 후 진행이 직접 기록되었는지 확인하고 관련 맵·참여자·스탯블록 참조를 정리한다.
24. 시나리오, 장면 목록, 장면별 파일, 맵, NPC·몬스터, 스탯블록과 장면 결과 조건의 상호 참조를 검증한다.
25. 세션 문서 양식에 따라 최종 세션 패키지를 정리한다.
26. 품질 검수 체크리스트로 자체 점검한다.
27. 적용 환경의 파일 정책에 따라 저장 또는 패키지 제공을 수행한다.

## 사용자 입력 판별

다음 요소를 요청에서 파악한다.

- 단일 세션 또는 연속 세션
- 이전 내용의 존재 여부
- 사건의 소재
- 반드시 사용할 지역
- 반드시 등장할 인물 또는 세력
- 원하는 분위기
- 피해야 할 요소
- 예상 플레이 시간
- 플레이어 캐릭터 또는 파티 정보
- 세션 이름과 스토리명
- 고정된 결말 또는 후속 요소
- 참고할 원본 로그와 GM 진행 문체의 존재 여부

사용자가 모든 항목을 제공할 필요는 없다. 이미 제공된 정보는 다시 묻지 않는다.

## 질문 기준

질문량은 사용자 입력 유형에 따라 다르게 운용한다.

### 흐름 제공형 질문 기준

사용자가 이미 제공한 흐름은 보존한다. 다음 경우에만 추가 질문한다.

- 제공된 요소끼리 직접 충돌한다.
- 어느 선택에 따라 세션의 핵심 방향이 크게 달라진다.
- 반드시 필요한 설정이 비어 있어 다음 단계로 진행할 수 없다.

이미 답이 있는 정보는 다시 묻지 않는다. 사용자의 흐름을 먼저 한 줄 이야기와 상위 골격으로 정리하고, 필요한 조정만 제안한다.

### 처음부터 설계형 질문 기준

처음부터 설계하는 경우에는 질문을 충분히 사용한다. 특히 다음과 같은 큰 결정은 임의로 확정하지 않는다.

- 이 세션을 한 줄로 요약했을 때의 이야기
- 시작 상황과 플레이어가 개입하는 이유
- 중심 문제와 위협
- 이번 회차에서 반드시 변해야 할 것
- 세션이 어디에서 끝나야 하는지
- 핵심 사건의 순서와 주요 전환

한 번에 여러 결정 질문을 묶지 않는다. `하나의 결정 단위 질문 → 사용자 답변 → 확정 내용 반영 → 다음 질문` 순서로 진행한다.

사소한 이름, 소품, 단역처럼 이야기의 방향을 바꾸지 않는 요소는 필요한 단계가 되었을 때 직접 제안할 수 있다.

## 설정 탐색 절차

1. 사용자가 지정한 지역·인물·세력·사건 문서를 찾는다.
2. 대상 문서의 상위 설정과 연관 문서를 확인한다.
3. 세션에 직접 필요한 정보만 추린다.
4. 설정에 없는 사실을 새 정본처럼 확정하지 않는다.
5. 새로 필요한 세부 요소는 세션 한정 요소로 설계한다.
6. 정본 추가가 필요하면 `추가 제작이 필요한 자료`에 기록한다.

## 이전 세션 탐색 절차

1. 사용자가 지정한 분석 문서를 확인한다.
2. 최종 위치, 미해결 사건, 관계 변화, 확보 정보, 다음 행동을 추출한다.
3. 연속 세션의 사건 내용과 장면 문체를 재현해야 하면 원본 로그를 함께 확인한다.
4. 정보흐름분석 문서는 사실·연속성 확인에 사용하고, 실제 GM 묘사 문체는 원본 로그에서 확인한다.
5. 장기 아크 흐름이 필요하면 `스토리 정리`를 확인한다.
6. 이전 세션의 확정 결과를 임의로 되돌리지 않는다.
7. 미확정 정보와 플레이어 추측을 사실로 확정하지 않는다.

## 장면 목록 선작성 규칙

핵심 사건 흐름을 정한 뒤 개별 장면을 즉시 상세 작성하지 않는다.

먼저 `02. [세션 이름] 장면 목록.md`에서 모든 장면을 관리한다. 장면 목록에는 장면 번호, 장면명, 한 줄 핵심 내용, 장면 역할, 이전·다음 연결, 현재 확정 상태를 기록한다.

세션 장면 목록에는 `세션 프롤로그`와 `세션 에필로그`를 정식 장면으로 포함한다. 프롤로그는 `00` 번호를 사용하고, 에필로그는 마지막 본편 장면 다음 번호를 사용한다. 프롤로그와 에필로그는 본편 장면 수 산정에서 별도로 취급하며, 각각 도입 상황 정리·시작점 제시와 사건 결과 정리·다음 회차 연결을 담당한다.

`02. 장면 목록`은 장면 추가·삭제·통합·순서 변경의 기준 원장이다. 시나리오 파일이나 장면별 파일에 별도의 장면 순서 목록을 복제하지 않는다.

장면 목록을 통해 사건의 발단, 조사, 갈등 상승, 전환, 절정, 결말이 자연스럽게 이어지는지 확인한다. 동일한 기능을 반복하는 장면, 연결되지 않는 장면, 핵심 정보가 누락된 장면이 있으면 장면별 파일을 만들기 전에 수정한다.

장면 목록이 확정되기 전에는 `장면/` 하위의 장면별 파일을 생성하지 않는다. 목록이 확정된 뒤에만 장면 번호와 장면명을 기준으로 독립 파일을 만들고 기능 확장으로 넘어간다.

## 장면별 이중 작성 규칙

장면 목록이 확정되면 `장면/NN. [장면명].md` 파일을 생성하고 장면 기능 확장을 진행한다.

### 장면 확정 시 대화 본문 표시 규칙

장면이 검토를 마치고 `확정` 상태가 되는 응답에서는 Drive 파일 작성·갱신만 수행하고 끝내지 않는다. 같은 응답의 대화 본문에 해당 장면 파일의 확정 내용을 사용자가 바로 검토할 수 있도록 전체 표시한다.

- 사용자가 Drive 파일을 별도로 열어야만 내용을 확인할 수 있게 하지 않는다.
- 장면의 목적, 시작 조건, 장소와 상황, 공개·숨겨진 정보, 갈등, 진행, 체크·내성, 묘사, 종료 조건, 다음 장면 연결 등 실제 파일에 확정된 내용을 누락 없이 보여준다.
- 초안·검토 단계에서는 현재 결정된 변경점과 검토 대상 중심으로 보여줄 수 있다.
- `확정` 처리와 파일 저장·갱신, 대화 본문 전체 표시를 같은 응답에서 수행한다.
- 프롤로그와 에필로그에도 동일하게 적용한다.

장면 기능 확장은 GM이 해당 장면 파일 하나를 열어 실제 플레이를 운영할 수 있는 수준까지 필요한 정보를 채우는 단계다. 다음 요소를 필요한 만큼 포함한다.

- 장면 목적과 세션 내 역할
- 이전 결과의 반영
- 장소와 현재 상황
- 시작 조건
- 등장 NPC·몬스터와 현재 태도
- 공개 정보
- 발견 가능한 정보와 획득 경로
- 숨겨진 정보와 발견 경로
- 핵심 갈등
- 예상 가능한 플레이어 접근
- 우회 또는 예상 밖 행동 대응
- 변화 조건
- 종료 조건
- 다음 장면 연결
- 관련 NPC·몬스터 항목 참조
- 성공 조건, 실패 조건, 실패 후 진행

### 능력 체크와 내성 체크 포인트

능력 체크와 내성 체크가 발생할 수 있는 지점도 장면 기능 확장 단계에서 정한다.

체크 포인트에는 최소한 `언제 발생하는가`, `무엇을 알아내거나 해내려는가`, `성공 시 무엇이 달라지는가`, `실패해도 이야기가 어떻게 계속되는가`를 기록한다.

특정 룰 시스템이 확정되어 있고 사용자가 수치화를 원하거나 실제 플레이에 필요하다면 관련 룰북을 확인하여 능력·기술·내성 종류와 DC 등 구체 수치를 작성한다. 시스템 중립 단계라면 체크의 목적과 유형까지만 정하고 임의의 수치를 만들지 않는다.

핵심 진행에 반드시 필요한 정보나 다음 장면 진입을 단 한 번의 체크 성공에만 걸지 않는다.

### 실제 플레이용 묘사

장면 파일에는 `설계 정보`와 플레이어에게 실제로 제시할 `묘사`를 구분한다.

필요에 따라 다음 묘사를 별도 항목으로 작성한다.

- 장면 묘사: 장면에 처음 진입했을 때 보이는 장소와 상황
- 진행 묘사: 사건 발생, 환경 변화, 장면 전환처럼 진행 중 특정 조건에서 사용하는 묘사
- NPC 등장 묘사: NPC가 처음 모습을 드러내는 순간의 외형·행동 중심 묘사
- 몬스터 등장 묘사: 몬스터가 처음 모습을 드러내는 순간의 외형·위압감·행동 중심 묘사
- 결과 묘사: 성공·실패·전환 뒤 세계가 어떻게 달라졌는지를 보여줄 필요가 있을 때의 묘사

묘사는 현재 플레이어가 보고 들을 수 있는 정보만 제시하며 장면의 정답이나 숨겨진 진실을 직접 설명하지 않는다. 플레이어의 행동, 감정, 판단을 대신 확정하지 않고 반응할 수 있는 지점에서 멈춘다. 문체는 반말이나 소설 독백체가 아니라 마스터가 플레이어에게 상황을 설명하는 정중체 기반 설명형 서술을 기본으로 하며, 특별한 지시가 없으면 `~보입니다`, `~들립니다`, `~느껴집니다`, `~드러납니다`, `~하고 있습니다` 같은 종결을 우선한다.

이전 세션의 원본 로그가 존재하면 실제 플레이용 묘사를 작성하기 전에 반드시 원본 로그를 확인한다. 정보흐름분석 문서만으로 문체를 추정하지 않는다. 같은 캠페인·같은 아크에서 현재 회차와 가장 가까운 원본 로그의 GM 서술을 우선 문체 표본으로 삼고, 필요하면 인접 회차의 원본 로그를 추가 확인한다.

원본 로그에서는 플레이어 채팅이 아니라 GM 서술을 중심으로 문장 길이, 줄바꿈, 2인칭 호명 방식, 정보 제시 순서, 구어적인 종결 표현, 장면 전환 호흡과 플레이어 반응을 기다리는 지점을 확인한다. 이 기준은 세션 프롤로그·장면 묘사·진행 묘사·NPC 및 몬스터 등장 묘사·결과 묘사·세션 에필로그에 공통 적용한다. 원문 문장을 그대로 복제하지 않고 같은 호흡과 어조를 현재 상황에 맞게 재현한다.

NPC·몬스터의 공통 프로필과 스탯블록은 전용 통합 파일에 두고, 조우의 성공 조건·실패 조건·실패 후 진행은 해당 장면 파일에 직접 기록한다. 맵·스탯 수치는 각 정본을 참조하여 중복을 피한다.

## 단일 세션 제작 절차

1. 처음부터 설계하는 경우 `이 세션을 한 줄로 요약하면 어떤 이야기인가`부터 확정한다.
2. 사용자가 흐름을 이미 제공했다면 그 흐름을 보존하고 한 줄 이야기로 압축해 확인한다.
3. 시작 상황, 중심 문제, 핵심 변화, 종료 지점으로 핵심 이야기 골격을 정한다.
4. 장면보다 큰 사건 단위로 핵심 사건 흐름을 작성한다.
5. 핵심 사건 흐름이 확정된 뒤 `02. 장면 목록`에 필요한 장면을 한 줄씩 작성한다.
6. 장면 목록만 읽어도 발단부터 결말까지 파악되는지 점검하고 장면 수·순서·통합·삭제를 확정한다.
7. 장면 목록 확정 후에만 장면별 독립 파일을 생성한다.
8. 각 장면 파일에서 목적, 정보, 갈등, 변화, 종료 조건과 능력 체크·내성 체크 포인트를 확장한다.
9. 장면 묘사, 진행 묘사, NPC·몬스터 등장 묘사를 필요한 조건과 함께 작성한다.
10. 주요 NPC·몬스터는 전용 통합 파일을 참조하고, 조우 결과 조건은 해당 장면 파일 안에서 관리한다.
11. 핵심 정보에 둘 이상의 획득 경로를 둔다.
12. 결과 판정이 필요한 장면에는 성공 조건, 실패 조건, 실패 후 진행을 설계한다. 부분 성공이나 대가가 있는 성공은 필요한 경우 성공 결과 안에서 함께 정리한다.
13. 결말 가능성과 이후 변화로 마무리한다.

## 연속 세션 회차 제작 절차

1. 이전 회차 결과를 확인한다.
2. 현재 회차가 아크에서 담당하는 기능을 한 줄 이야기로 정리한다.
3. 사용자가 이번 회차 흐름을 제공했다면 그대로 보존하고 조정만 한다. 흐름이 없다면 한 번에 하나씩 질문하여 핵심 이야기 골격을 확정한다.
4. 이번 회차 안에서 반드시 변화할 요소와 종료 지점을 정한다.
5. 이전 선택이 핵심 사건 흐름에 미치는 영향을 반영한다.
6. 원본 로그에서 이전 장면의 GM 묘사 문체와 호흡을 확인한다.
7. 핵심 사건 흐름이 확정된 뒤 장면 목록을 작성하고 이전 회차의 미해결 요소가 어느 장면에서 회수되는지 표시한다.
8. 장면 목록 점검과 확정 후에만 장면별 독립 파일을 생성한다.
9. 각 장면 파일에서 이전 결과의 반영, 체크·내성 포인트, 장면·진행·등장 묘사를 포함한 기능 확장을 수행한다.
10. 다음 회차를 강제하지 않고 여러 후속 가능성을 남긴다.

- `맵/00. 맵 목록.md`는 필요한 맵과 장면 할당·그리드·제작 상태의 기준 원장이고, `맵/NN. [맵명].md`는 개별 맵 설계를 담당한다.

- 실제 스탯블록은 별도 파일로 분리하지 않고 `NPC 및 몬스터/[이름].md`의 기본 정보·외형·마스터용 묘사 다음에 `스탯블록 정책`과 `스탯블록` 섹션으로 직접 기록한다.
- 맵에 배치되는 NPC·몬스터는 전투 여부와 관계없이 토큰 제작 대상이다.
- 이미지와 토큰의 실제 생성 규칙은 해당 이미지 기능 지침을 따른다.
- 실제 FVTT Actor·Scene·Journal·Compendium·JSON 변환은 세션 제작에서 수행하지 않고 6번 기능으로 넘긴다.
- 4번 룰북 기능에서 확인되어 스탯블록에 포함된 `[[...]]`, `@...`, `@UUID[...]` 문법은 세션 제작에서 보존한다.
- 세션용 피트·아이템·행동 설명에 새 인라인 문법을 조립하거나 변수 경로·활동 연결을 검증하는 작업은 6번의 `2. 피트 및 아이템 인라인 문법과 변수 사용 가이드.md`를 적용한다.

- 파일 저장과 Google Drive 반영은 프로젝트 공통 파일 정책과 사용자의 최신 명시 지시를 따른다.

## 최종 실행 지시

사용자가 세션 제작을 요청하면 룩스테라 설정과 필요한 이전 자료를 확인하고, 한 줄 이야기에서 시작해 핵심 이야기 골격과 핵심 사건 흐름을 확정한 뒤 장면 목록으로 내려간다. 장면 목록이 확정된 뒤에만 장면별 파일을 생성하여 체크·내성 포인트와 실제 플레이용 묘사를 포함한 기능 확장을 수행한다. 장면 기능과 묘사가 정리되면 `9. 세션 자산 및 VTT 준비 지침.md`에 따라 맵을 산정·제작하고 NPC·몬스터 스탯블록, 이미지와 토큰까지 준비한다.

세션은 시스템 중립형으로 작성한다. 예상 밖 행동에도 대응할 수 있도록 인물의 목적, 장면 내 갈등의 행동 원리, 성공·실패에 따른 변화 조건을 분명히 한다.

완성 세션 패키지는 품질 검수를 거친다. 신규 세션 산출물은 `TRPG 데이터/17. 세션 설계/`의 해당 작업 경로에 Google Drive 직접 저장하는 것을 기본으로 한다. Drive 저장이 불가능하거나 사용자가 로컬/ZIP 제공을 별도로 요청한 경우에만 같은 구조를 보존한 로컬 파일 또는 ZIP을 제공한다.
