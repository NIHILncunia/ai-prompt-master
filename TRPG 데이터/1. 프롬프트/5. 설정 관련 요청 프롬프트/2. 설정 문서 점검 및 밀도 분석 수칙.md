# 2. 설정 문서 점검 및 밀도 분석 수칙

## 문서 목적

이 문서는 `TRPG 데이터/1. 프롬프트/5. 설정 관련 요청 프롬프트` 기능에서 설정 문서를 점검할 때 적용하는 세부 수칙이다.

사용자가 프로젝트 위그드라실과 현재 등록된 시리즈의 설정 점검, 문서 보강, 밀도 분석, 설정 정합성 검토, 공개/비밀 설정 분리, 세력 관계 점검, 스토리 설계 점검을 요청하면 이 문서를 품질 기준으로 적용한다.

이 문서는 기존 `0. 설정 관련 요청 마스터 프롬프트.md`와 `1. 설정 관련 요청 지침서.md`를 대체하지 않는다. 설정 관련 요청의 진입점은 여전히 `0. 설정 관련 요청 마스터 프롬프트.md`이며, 세부 라우팅과 설정 폴더 기준은 `1. 설정 관련 요청 지침서.md`를 따른다.

대상 문서가 최신 템플릿과 같은 구조인지 판정하는 작업은 `3. 설정 문서 템플릿 구조 점검 수칙.md`를 함께 적용한다. 2번 수칙은 문체·밀도·정합성·내용 보존을 담당하고, 3번 수칙은 적용 템플릿 선택과 프론트매터·상위 섹션 구조를 담당한다.

## 적용 조건

아래 요청은 이 수칙을 반드시 적용한다.

- 설정 문서 점검
- 설정 문서 보강
- 설정 문서 밀도 분석
- 설정 문서 개편
- 기존 설정 문서 재작성
- 설정 문서 문체 윤문
- 번역투·AI 상투구·기계적 문장 구조 점검
- 신격 문서 점검
- 비밀 설정 문서 점검
- 세력 관계 문서 점검
- 스토리 설계 문서 점검
- 프로젝트 위그드라실 공통 운영 문서 점검
- Google Drive 설정 정본 반영용 수정본 작성
- 설정 문서 ZIP 산출물 생성

## 적용 대상 문서군

이 수칙은 아래 문서군에 적용한다.

- `위그드라실` 공통 설정과 공통 비밀 설정 문서
- 현재 등록된 모든 시리즈의 설정 문서
- 각 시리즈의 신격, 비밀 설정, 세력 관계, 스토리 설계, 설정 정비 문서
- 여러 정본을 횡단해 비교·탐색하는 인덱스 문서
- 향후 프로젝트 루트에 추가되는 신규 시리즈 문서
- 프로젝트 위그드라실 공통 운영 문서

시리즈마다 장르와 문체는 달라질 수 있다. 그러나 설정 문서의 기본 품질 기준과 섹션 밀도 기준은 공통으로 적용한다.

## 최우선 운영 금지 규칙

Codex는 동기화된 로컬 설정 원천을 사용하며 Google Drive 커넥터를 호출하지 않는다. 파일 산출물이 필요하면 사용자가 적용할 수 있는 로컬 파일 또는 ZIP으로 제공한다.

이 문서에 남아 있는 과거 `Google Drive`·`구글 드라이브` 표현은 해당 Git 로컬 저장소 경로를 뜻하는 레거시 용어로 해석한다. 커넥터 접근·원격 파일 조작·Drive 접근 시작 문구를 요구하지 않는다.

수정본이 필요할 경우에는 사용자가 직접 적용할 수 있도록 파일로 제공한다. 파일은 가능한 한 실제 적용 경로와 동일한 폴더 구조로 제공하며, 결과물은 기본적으로 `zip` 형식으로 묶는다.

기존 문서를 수정하는 작업이라면 파일명은 원본과 동일하게 유지한다. 새 문서가 필요한 경우에도 폴더명과 파일명은 가능한 한 한글로 작성한다.


설정 문서 ZIP 산출물은 로컬 정본의 실제 적용 계층을 반영한다. 시리즈 설정 문서는 `프로젝트 위그드라실/<시리즈명>/설정/(청연/)?<type>/...`, 공통 설정은 `프로젝트 위그드라실/위그드라실/<설정 또는 비밀 설정>/...` 경로로 제공한다. 대상 하위 경로가 확정되지 않았다면 임의로 만들지 않고 README에 후보 위치를 기록한다.

### 설정 문서 분류 경로

- 룩스테라·엘드로스의 일반 설정 문서는 `설정/<type>/문서.md`에 둔다.
- 룩스테라 `region: 청연` 문서는 `설정/청연/<type>/문서.md`에 둔다.
- 문서명으로 점검할 때에는 시리즈 `설정` 폴더를 재귀 검색하고, 분류값이 확인되면 해당 경로를 우선한다.

- `프로젝트 위그드라실` 루트 ID만 고정 진입점으로 사용한다. 개별 시리즈와 하위 폴더의 목록은 루트를 실제 조회하여 갱신한다.
- 루트의 직계 하위 폴더 중 `위그드라실`은 시리즈가 아니라 모든 시리즈를 포괄하는 공통 설정 허브다.
- `위그드라실`을 제외한 직계 하위 폴더는 기본적으로 시리즈 후보로 취급한다. 새 폴더가 추가되면 기존 프롬프트 개정 없이 시리즈 목록에 포함한다.
- 사용자가 `설정 폴더에서 찾아라`, `설정에서 찾아라`처럼 시리즈를 지정하지 않으면 이 루트 전체를 검색 범위로 삼는다.
- 대상 시리즈에 `인덱스` 폴더가 있고 정치 체제·대륙별 세력·연표·관계처럼 여러 정본을 횡단해야 하면 관련 인덱스를 먼저 확인한다.
- 인덱스는 탐색과 비교의 기준이며, 개별 사실은 연결된 정본 문서에서 검증한다.
- 요청에 시리즈명이 명시되면 해당 직계 하위 폴더를 우선한다. 시리즈를 판별할 수 없으면 공통 설정과 모든 시리즈를 검색하되, 결과가 어느 시리즈에 속하는지 구분한다.
- 세계 간 연결, 공통 우주론, 공통 용어, 프로젝트 전체 규칙은 `위그드라실` 폴더를 먼저 확인하고 관련 시리즈를 대조한다.
- 시리즈 고유 설정은 해당 시리즈 폴더가 정본이다. 공통 설정과 시리즈 설정이 충돌하는 듯 보이면 적용 범위가 다른지 먼저 판별하고, 같은 범위의 충돌은 임의로 병합하지 않고 보고한다.
- 문서를 작성·수정·개편할 때에는 프로젝트 루트 `AGENTS.md`, `문서 작성 및 수정 지침.md`, 대상 시리즈의 `AGENTS.md`, 대상 시리즈에 존재하는 관련 `인덱스`, 필요 시 `템플릿`을 읽는다.
- 개별 하위 폴더 ID는 편의를 위한 캐시일 뿐 영구 정본으로 간주하지 않는다. 폴더 이동이나 신규 시리즈 추가 가능성이 있으므로 루트 조회 결과를 우선한다.

`설정 정비` 문서는 확정 정본과 변경 예정 사항을 혼동하지 않았는지 별도로 점검한다. `템플릿`은 형식 기준이므로 일반 설정 문서의 300토큰·2문단 기준을 일괄 적용하지 않는다. `이미지`는 시각 자료이므로 텍스트 설정 문서의 밀도 점검 대상에서 제외하되, 명칭이나 외형 설정의 충돌을 확인해 달라는 요청이 있으면 보조 자료로 대조한다.

설정 정본은 `프로젝트 위그드라실` 루트와 그 직계 하위 폴더의 현재 문서로만 판정한다. 공개 수준과 확정 여부는 폴더 위치, 문서군, 프론트매터 상태값을 기준으로 확인한다.

### 용종 이미지 경로 정합성

`TRPG 데이터/14. 용종`은 용종 자산을 생성·수집한 뒤 보관하는 작업용 저장소다. 이 폴더는 설정 문서가 참조하는 정식 이미지 경로가 아니므로, 용종 문서의 `thumbnail`, Obsidian 이미지 임베드, Markdown 이미지 링크 또는 다른 파일 참조에 사용되면 S1 경로 오류로 판정한다.

룩스테라 용종 문서의 모든 이미지 참조는 다음 루트를 사용해야 한다.

```text
프로젝트 위그드라실/룩스테라/이미지/용종 도감/<파일명>
```

점검 시에는 프론트매터의 `thumbnail`과 본문 전체의 이미지 임베드를 함께 검사한다. 경로 접두어뿐 아니라 파일명과 확장자가 정식 이미지 루트의 실제 파일과 일치하는지 확인한다. 파일이 보관 폴더에만 존재한다면 해당 보관 경로를 문서에 남기지 않고, 정식 이미지 루트로의 복사·이동 필요 사항을 별도로 보고한다.

- `TRPG 데이터/14. 용종`, `14. 용종` 또는 그 하위 경로를 참조하면 즉시 수정 대상으로 분류한다.
- `프로젝트 위그드라실/룩스테라/이미지/용종 도감` 밖의 경로를 사용하는 룩스테라 용종 이미지는 시리즈 지침이나 사용자의 최신 지시로 명시된 예외가 없는 한 오류로 판정한다.
- 정식 이미지 루트에 파일이 없으면 존재하지 않는 경로를 추정해 채우지 않는다. `thumbnail: ''` 유지 또는 임베드 보류 여부를 원문과 사용자의 요청 범위에 따라 결정하고, 누락 파일을 보고한다.
- 경로를 수정한 뒤에는 같은 문서에 남은 이전 경로와 저장소 전체의 동일 패턴을 다시 검색한다.

### 인덱스 문서의 정본성

인덱스는 여러 정본 문서의 이름·분류·핵심 차이·직접 링크를 정렬하는 탐색 문서다. 인덱스가 독자적인 설정 사실을 확정하거나 연결된 정본의 세부 서술을 축약된 문장으로 대체해서는 안 된다. 정치 체제·정당성·현재 압력·관계처럼 인덱스에 기록된 판단은 연결된 정본에서 근거를 다시 확인한다.

근거가 부족한 항목은 일반적인 국가 운영 방식이나 장르 관습으로 추정해 채우지 않는다. `보강 필요`로 표시하고, 누락된 정본 또는 설정 정비 문서를 보강 대상으로 분리한다. 이름·분류·정치 체제·관계가 변경된 작업에서는 관련 인덱스의 동시 갱신, 위키 링크 유효성, 누락·중복 여부까지 점검 완료 조건에 포함한다.

## 점검의 목적

설정 점검의 목적은 문서를 무조건 길게 만드는 것이 아니다. 각 섹션이 충분한 맥락과 해석을 품도록 만들어, 읽는 사람이 설정의 기능과 장면을 함께 이해하게 만드는 것이다.

설정 문서는 단순 정보 카드가 아니라 세계를 구성하는 문단이어야 한다. 한 섹션을 읽었을 때 그 설정이 어디에서 작동하고, 누가 영향을 받고, 어떤 갈등이 생기는지 떠올라야 한다.

룩스테라 설정 문서는 섹션 밀도의 주요 참고점이다. 엘드로스 문서는 장르상 더 건조하고 절박한 문체를 사용할 수 있으나, 섹션이 품는 정보와 해석의 깊이는 룩스테라 수준을 목표로 한다.

## 세계관 내부 서술 원칙

설정 문서의 제목과 본문은 세계관 안에서 성립하는 표현만으로 작성한다. 설정을 만든 사람, 문서를 읽는 사람, 게임을 진행하는 사람의 관점이 문장에 드러나서는 안 된다. 문서는 외부에서 세계를 해설하는 작업 지시서가 아니라, 그 세계의 역사·지리·생태·문화·인식이 스스로 살아 움직이는 기록처럼 읽혀야 한다.

`이 문서는 ~을 정리한다`, `룩스테라 세계관에서`, `설정상`, `문서 작성 시`, `이미지 생성`, `NPC 묘사`, `플레이어`, `GM`, `세션`, `캠페인`, `TRPG`, `게임 규칙`, `시나리오 활용`, `모험 활용`, `설정 고정 문장`, `관련 문서와 활용`처럼 창작물 바깥의 제작·운영·사용 관점을 드러내는 표현은 설정 본문과 섹션 제목에서 제거한다. 실제 게임 운용, 이미지 제작, 문서 관리, 작성 지침에 필요한 정보는 설정 문서가 아니라 별도의 프롬프트·운영 문서·제작 가이드로 분리한다.

메타 정보를 삭제할 때 필요한 설정 정보까지 함께 없애서는 안 된다. 같은 내용을 세계 안의 관찰 주체와 제도로 환원한다. `플레이어는 이 지역에서 선택해야 한다`는 `이 땅에 들어선 탐험대는 선택을 강요받는다`로, `설정상 용성은 생태계를 연결하는 축이다`는 `용성은 지형과 생물의 변화를 하나의 원인으로 묶는다`로, `시나리오 활용`은 `현재의 분쟁과 위기` 또는 `발생 가능한 사건`으로 바꾼다. 학자, 도감 편찬자, 부족의 전승, 교단, 국가의 법, 상인의 소문, 탐험대의 기록처럼 세계 안에 실제로 존재하는 주체를 통해 설명하면 정보와 생동감을 함께 유지할 수 있다.

다만 YAML 프론트매터, 위키 링크, 대표 이미지 임베드와 같은 설정 폴더 관리 문법은 서술 본문이 아니므로 이 원칙의 직접적인 제거 대상에서 제외한다. 사용자의 편집을 위한 `항목` 섹션과 문서 탐색을 위한 `요약` 섹션도 구조적 예외로 유지할 수 있다. 그 밖의 본문과 섹션 제목에는 메타 서술을 남기지 않는다.

## 한국어 윤문 및 AI 문체 제거 수칙

### 적용 목적

이 수칙의 목적은 설정 문서의 의미와 장르를 유지하면서 번역투, AI 상투구, 기계적인 문장 구조, 과도한 완곡 표현, 반복적인 접속사와 형식명사를 줄이는 데 있다. 목표는 탐지기를 속이는 문장을 만드는 것이 아니라, 한국어 설정 문서로서 자연스럽고 직접적이며 읽기 쉬운 문장을 확보하는 것이다.

윤문은 설정 보강과 구분한다. 사용자가 문체 교정이나 윤문만 요청했다면 원문에 없는 설정, 사례, 인물, 사건, 해석을 추가하지 않는다. 보강·개편·재작성 요청에서는 새 내용을 제안할 수 있지만, 기존 정본과 사용자의 최신 지시를 근거로 삼고 정설·추정·제안을 구분한다.

### 적용 범위 분기

- 공개 설정, 비밀 설정, 신격, 국가, 도시, 종족, 인물, 사건, 개념 문서의 서술 본문에는 이 장의 전체 규칙을 적용한다.
- 스토리 설계와 세력 관계 문서는 운영상 필요한 표·목록·단계·관계값을 유지하고, 서술 문단에 번역투·상투구·리듬 규칙을 적용한다.
- 프롬프트, 운영 지침, 템플릿, AGENTS 문서에는 의미 보존·번역투·상투구·중복 표현 규칙을 적용하되, 번호 목록과 명령형 문장처럼 기능상 필요한 구조까지 제거하지 않는다.
- YAML 프론트매터, 위키 링크, 이미지 임베드, 표의 필드명, 코드 블록, 명령어, 파일 경로는 일반 문장 윤문의 직접 대상에서 제외한다.

윤문 판단은 아래 순서를 따른다. 아래 단계가 충돌하면 앞선 항목을 우선한다.

3. 문서 유형, 템플릿, 세계관 내부 서술 원칙

### 심각도 기준

- `S1 필수 수정`: 한 번만 나타나도 부자연스럽거나 명백한 번역투로 읽히는 표현이다. 의미가 바뀌지 않는 범위에서 반드시 수정한다.
- `S2 반복 시 수정`: 한두 번은 자연스러울 수 있으나 한 문서 또는 한 섹션에서 세 번 이상 반복되면 수정한다.
- `S3 보조 조정`: 단독으로는 문제가 아니다. 다른 패턴과 겹치거나 문서 전체의 기계적인 인상을 강화할 때만 조정한다.

심각도는 자동 삭제 명령이 아니다. 실제 지명, 제도명, 교리문, 법률 문구, 직접 인용, 고유한 말버릇이라면 문맥을 우선한다.

윤문 전에는 원문에서 보존해야 할 정보를 먼저 고정한다. 아래 항목이 바뀌면 문체가 자연스러워졌더라도 윤문 실패로 판정한다.

4. 설정의 원인과 결과, 사건의 행위자와 피해자, 주체와 객체

의미가 달라졌을 가능성이 조금이라도 실질적으로 남으면 원문 표현을 유지하거나 수정 범위를 줄인다. `~할 수 있다`를 단정형으로 바꾸거나 `필요하다`를 `반드시 해야 한다`로 바꾸는 식의 주장 강도 변화는 금지한다.

### A. 번역투 점검

#### A-1. `~에 대하여`, `~에 대해` 남발 `[S1]`

주제를 매번 `대해`로 연결하지 않는다. `용성에 대해 연구한다`는 `용성을 연구한다`, `용성은 연구자들에게`처럼 목적격이나 주제 조사로 직접 연결한다. 다만 실제 대상 범위를 구분하는 데 필요한 한두 번의 사용은 허용한다.

#### A-2. `~를 통하여`, `~를 통해` 남발 `[S1]`

수단, 원인, 경로, 매개를 모두 `통해`로 처리하지 않는다. `의식을 통해 힘을 얻는다`는 `의식을 치러 힘을 얻는다`, `의식으로 힘을 얻는다`처럼 실제 행위를 드러낸다. 매개체 자체가 설정상 중요한 경우에는 유지한다.

#### A-3. `~에 있어서` `[S1]`

`신앙에 있어서 중요한 것은`처럼 전제를 길게 세우지 않는다. `신앙에서 중요한 것은`, `이 교단이 중시하는 것은`처럼 직접 서술한다.

#### A-4. `~라는 점에서` 반복 `[S2]`

근거와 결론을 매번 `점에서`로 연결하지 않는다. `금기를 어겼다는 점에서 처벌받는다`는 `금기를 어겼기 때문에 처벌받는다`처럼 원인 관계를 직접 쓴다.

#### A-5. `~와 관련하여`, `~와 관련된` 반복 `[S2]`

대상을 포괄적으로 가리키는 말로 문장을 흐리지 않는다. `왕위 계승과 관련된 분쟁`은 `왕위 계승 분쟁`, `왕위를 둘러싼 분쟁`처럼 구체화한다.

#### A-6. `~에 기반하여`, `~을 바탕으로` 반복 `[S2]`

근거가 무엇인지 직접 밝힌다. `고대 기록을 바탕으로 추정한다`는 `고대 기록에 따르면`, `학자들은 고대 기록을 근거로`처럼 문맥에 맞게 바꾼다.

#### A-7. `가지고 있다`와 가벼운 동사 구문 `[S1]`

`특징을 가지고 있다`, `영향력을 가지고 있다`, `회의를 가졌다`, `결정을 내렸다`처럼 명사를 앞세운 표현을 동사·형용사로 환원한다. `비늘을 가지고 있다`는 `비늘이 있다`, `영향력을 가지고 있다`는 `영향력이 크다`, `결정을 내렸다`는 `결정했다`로 다듬는다. 실제 소유 관계를 설명할 때에는 유지한다.

#### A-8. 이중 피동 `[S1]`

`되어진다`, `보여진다`, `잊혀지게 된다`처럼 피동이 겹치면 능동문 또는 단일 피동으로 바꾼다. 행위자가 불명확하거나 의도적으로 감춰진 설정이라면 단일 피동만 유지한다.

#### A-9. `~에 의해` 피동문 `[S2]`

행위자가 분명하면 주어로 돌린다. `왕명에 의해 폐쇄되었다`는 `왕이 명령해 폐쇄했다` 또는 `왕명으로 폐쇄되었다`로 고친다. 행위자를 드러내면 비밀 설정이 누출되는 경우에는 원문을 유지한다.

#### A-10. `~할 수 있다` 남발 `[S2]`

확정된 기능과 효과를 가능형으로 흐리지 않는다. `용성은 생물을 변이시킬 수 있다`가 확정 규칙이라면 `용성은 생물을 변이시킨다`로 쓴다. 확률, 조건, 미확정 가능성을 뜻한다면 반드시 유지한다.

#### A-11. `~을 위해` 목적절 남발 `[S2]`

목적을 반복해서 추상적으로 제시하지 않는다. `도시를 지키기 위해 성벽을 세웠다`는 자연스러울 수 있으나, 연속될 때는 `도시를 지키려고`, `방어선으로`, `침공을 막고자`처럼 실제 관계를 구체화한다.

#### A-12. `만들어지다`, `이루어지다` 남발 `[S2]`

행위자와 과정을 숨기는 자동 피동을 줄인다. `동맹이 이루어졌다`는 `두 국가는 동맹을 맺었다`, `교단이 만들어졌다`는 `사제들이 교단을 세웠다`로 바꾼다. 자연 발생이나 창조 주체가 미상인 경우에는 유지할 수 있다.

#### A-13. 조사 없는 명사 나열 `[S2]`

`왕국 북부 국경 방어 체계 붕괴`처럼 명사가 연쇄되면 조사와 서술어를 복원한다. `왕국 북부의 국경 방어 체계가 무너졌다`처럼 누가 무엇을 했는지 읽히게 한다. 공식 기관명과 문서 제목은 예외다.

#### A-14. 문두 `그리고`의 기계적 반복 `[S2]`

문장마다 `그리고`로 이어 쓰지 않는다. 같은 주체의 연속 행동은 `-고`, `-며`, `-면서`로 묶고, 새 정보라면 접속사 없이 시작한다. 장면 전환이나 의도적인 구어체에서는 유지할 수 있다.

#### A-15. 추상 주어와 만능 동사 `[S2]`

`이 사건은 변화를 가져왔다`, `이 기록은 진실을 보여 준다`, `이 제도는 안정성을 제공한다`처럼 추상명사에 `가져오다`, `보여 주다`, `제공하다`, `시사하다`를 반복하지 않는다. `사건 뒤로 제도가 바뀌었다`, `기록에서 진실이 드러난다`, `이 제도로 국경이 안정되었다`처럼 실제 변화와 관찰 결과를 쓴다.

#### A-16. 영어 대명사 직역 `[S1]`

한 문단에서 `그`, `그녀`, `그것`, `그들`, `그의`, `그녀의`가 반복되면 생략하거나 이름·호칭·집단명으로 바꾼다. 같은 인물이 이어지는 문장에서는 주어를 생략하고, 인물이나 장면이 바뀌는 지점에서만 명시한다. `그의 손`, `그녀의 머리`처럼 소유가 자명한 신체 표현도 줄인다.

#### A-17. 무정물·추상명사의 `-들` `[보류]`

`문제들`, `가능성들`, `정보들`은 기계적으로 삭제하지 않는다. 실제로 복수 구분이 불필요하고 반복될 때만 단수형을 검토한다. 이 항목만으로 윤문 결함을 판정하지 않는다.

#### A-18. 긴 좌향 관형 수식 `[S2]`

핵심 명사 앞에 관형절이 여러 겹 쌓이면 문장을 나누거나 뒤에서 설명한다. `사고를 일으킨 유물을 만든 학파에 속했던 마법사`처럼 핵심 명사에 도달하기 어려운 문장은 `한 마법사가 있었다. 그는 사고를 일으킨 유물을 만든 학파에 속했다`처럼 재구성한다.

#### A-19. 이중 조사 결합 `[S2]`

`~에서의`, `~으로부터의`, `~에로의`, `~에의`가 반복되면 절이나 동사구로 푼다. `전쟁으로부터의 해방`은 `전쟁에서 벗어남`, `성소에의 접근`은 `성소로 들어가는 일`처럼 바꾼다. 단순한 `~의`는 이 규칙만으로 수정하지 않는다.

### B. 영어 인용과 용어 점검

#### B-1. 모든 용어의 영문 병기 `[S2]`

전문용어마다 영문과 약자를 붙이지 않는다. 독자에게 필요한 경우 첫 등장에 한 번만 병기하고 이후에는 한국어 명칭이나 확정된 약칭을 사용한다.

#### B-2. 번역 가능한 영어의 잔존 `[S2]`

일반적인 의미의 `framework`, `leverage`, `seamless`, `robust` 같은 단어는 문맥에 맞는 한국어로 바꾼다. 세계관 고유어, 공식 제품명, 주문명, 체계상 고정된 약어는 유지한다.

#### B-3. 영어 원문과 전체 번역의 중복 `[S2]`

원어 자체가 논점이 아니라면 동일 문장을 영문과 한국어로 연속 제시하지 않는다. 어원, 암호, 고대어 해석처럼 원문이 설정상 중요할 때만 함께 둔다.

#### B-4. `~라고 알려진`, `~로 일컬어지는` 반복 `[S3]`

명칭을 소개할 때마다 우회하지 않는다. `검은 비라고 알려진 현상`은 `검은 비`로 바로 명명한다. 별칭이 형성된 역사나 누가 그렇게 부르는지가 중요하면 유지한다.

### C. 구조와 서식 점검

#### C-1. `첫째·둘째·셋째`의 기계적 병렬 `[S1]`

설명 문단을 매번 동일한 번호와 문장 구조로 나누지 않는다. 다만 법률 조항, 의식 단계, 계급 순서, 역사적 단계처럼 순서가 설정 정보인 경우에는 유지한다.

#### C-2. 불릿과 표의 과다 사용 `[S2]`

목록은 계급, 구성원, 품목, 지역, 연표처럼 탐색성이 중요한 정보를 정리할 때 사용한다. 원인, 사회적 의미, 갈등, 인식까지 목록으로 대체하지 않는다. 목록 전후에는 필요한 해설 문단을 둔다.

#### C-3. 기능만 표시하는 헤딩 `[S2]`

`도입`, `본론`, `결론`, `상세 설명` 같은 제목 대신 실제 설정 내용을 드러내는 제목을 사용한다. `개요`, `항목`, `요약`처럼 프로젝트가 구조상 요구하는 제목은 예외다.

#### C-4. 모든 문단의 동일한 요약문 시작 `[S2]`

모든 문단을 정의문으로 시작하지 않는다. 문서 성격에 따라 사례, 기록, 관습, 사건, 사회의 반응에서 시작할 수 있다. 다만 백과사전식 개요 문단의 첫 문장은 정의를 우선한다.

#### C-5. 이모지와 장식 기호 `[S1]`

설정 문서 제목과 본문에 이모지, 체크 표시, 경고 아이콘을 장식으로 사용하지 않는다. 실제 세계관 문자나 문장부호를 재현하는 경우에는 예외다.

#### C-6. 헤딩 직후의 안내문 반복 `[S2]`

`이 절에서는 ~을 살펴본다` 같은 문장을 반복하지 않는다. 해당 섹션의 설정 내용으로 바로 들어간다.

#### C-7. `먼저·반면·결국` 삼단 공식 `[S2]`

문단마다 동일한 전개 표지를 배치하지 않는다. 논리 관계가 문장 자체에서 드러나면 접속사를 생략한다.

#### C-8. 대칭 대구와 이항 질문 반복 `[S2]`

`축복인가 저주인가`, `구원인가 파멸인가` 같은 대칭 표현을 반복하지 않는다. 설정상 실제 논쟁을 요약하는 한 번의 표현은 허용한다.

#### C-9. 문단 내부 숫자 괄호 인덱싱 `[S2]`

설명 문단 안에서 모든 요소를 `1)`, `2)`, `3)`으로 나누지 않는다. 순서가 기능적이라면 정식 목록으로 분리하고, 그렇지 않으면 산문으로 통합한다.

#### C-10. 모든 헤딩의 `제목: 부제` 공식 `[S2]`

콜론이 붙은 헤딩을 반복하지 않는다. 하나의 명사구나 문장형 제목으로 정리한다. 템플릿 필드와 표 머리글은 예외다.

#### C-11. 연결어미 직후 쉼표 `[S1]`

`~고,`, `~지만,`, `~면서,`, `~는데,` 뒤의 쉼표가 불필요하면 제거한다. 문장이 너무 길다면 쉼표를 남기기보다 문장을 나누거나 주절 경계를 다시 잡는다.

#### C-12. 문서 전체 쉼표 밀도 `[S2]`

대부분의 문장에 쉼표가 들어가면 문장 분리와 어순 조정을 검토한다. 열거, 동격, 삽입 설명처럼 쉼표가 실제 기능을 할 때만 남긴다.

### D. AI 상투구 점검

#### D-1. 요약·결론 상투구 `[S1]`

`결론적으로`, `종합하면`, `정리하자면`, `~라고 할 수 있다`, `~에 다름 아니다`를 습관적으로 쓰지 않는다. 위치와 문맥만으로 결론이 드러나면 삭제하고 핵심 내용을 직접 쓴다.

#### D-2. 중요성의 공허한 강조 `[S1]`

`매우 중요하다`, `시사하는 바가 크다`, `주목할 만하다`, `간과할 수 없다`만으로 평가를 끝내지 않는다. 왜 중요한지, 누구에게 어떤 결과가 생겼는지 구체적으로 설명한다.

#### D-3. 열거 예고문 `[S1]`

`크게 세 가지로 나뉜다`, `다음과 같은 특징이 있다` 뒤에 목록이 바로 이어진다면 예고문을 줄이거나 삭제한다. 분류 기준 자체가 설정상 중요하다면 남길 수 있다.

#### D-4. 과장 홍보 어휘 `[S1]`

`혁신적인`, `획기적인`, `전례 없는`, `압도적인`, `막강한`, `폭발적인`, `파격적인`은 객관적 근거가 없으면 삭제한다. 최초, 최대, 유일 같은 사실을 쓸 때에는 근거가 정본에 있는지 확인한다.

#### D-5. 추상 개념의 과도한 의인화 `[S2]`

`역사가 질문을 던진다`, `기술이 미래를 요구한다` 같은 표현을 반복하지 않는다. 전승·신화·종교 문체에서 의도적으로 의인화한 경우에는 장르 표현으로 인정한다.

#### D-6. `~해야 할 때다` 결말 `[S2]`

설정 문서를 독자에게 행동을 촉구하는 문장으로 끝내지 않는다. 세계 내부에서 실제로 어떤 선택과 압력이 생기는지를 쓴다.

#### D-7. `X에서 Y로`, `X을 넘어 Y로` 공식 `[S2]`

변화를 매번 구호처럼 압축하지 않는다. 무엇이 어떻게 바뀌었고 그 결과 누가 영향을 받았는지 직접 설명한다.

#### D-8. 불필요한 `A가 아니라 B` 대조 공식 `[S1]`

`A가 아니라 B`, `A라기보다 B`, `단순한 A가 아닌 B`처럼 앞항을 부정해 뒤항을 강조하는 대조 공식을 습관적으로 쓰지 않는다. 앞항 A가 실제 오해·통념·주장으로 제시되지 않았고 B만으로 의미가 완결되면 앞항과 부정 연결을 삭제한다.

- `이들에게 국경은 협상의 선이 아니라 반드시 지켜야 할 껍질이다.` → `이들에게 국경은 반드시 지켜야 할 껍질이다.`
- `그 의식은 단순한 축제가 아니라 공동체의 결속을 확인하는 행사다.` → `그 의식은 공동체의 결속을 확인하는 행사다.`

앞항을 명시적으로 부정해야 설정의 의미가 보존되는 경우에는 대조를 유지한다. 기존에 제시된 오해를 바로잡거나, 서로 배타적인 분류를 구분하거나, 교리·법문·논쟁에서 대립 자체가 핵심 정보인 경우가 이에 해당한다. 불필요한 대조를 `A를 넘어 B`, `A에 그치지 않고 B`, `A라기보다 B` 같은 유사 공식으로 바꾸는 것도 수정으로 인정하지 않는다.

### E. 리듬과 문장 구조 점검

#### E-1. 문장 길이의 과도한 균일성 `[S2]`

모든 문장이 비슷한 길이로 이어지면 정보 단위를 기준으로 합치거나 나눈다. 짧은 문장과 긴 문장을 억지로 일정 비율로 섞지 말고, 의미의 무게에 따라 호흡을 조절한다.

#### E-2. 동일 종결어미와 `~고 있다` 반복 `[S2]`

같은 종결어미가 네 문장 이상 연속되면 문장 구조와 시제를 점검한다. 현재의 일반 규칙은 단순 현재로, 진행 중인 사건만 `~고 있다`로 쓴다. 격식 수준은 문서 전체에서 유지한다.

#### E-3. 문단 길이의 기계적 균일성 `[S2]`

모든 문단을 같은 문장 수로 맞추지 않는다. 다만 이 프로젝트의 최소 2문단·300토큰 기준은 유지하며, 문단 수 변화만을 위해 내용을 쪼개지 않는다.

#### E-4. 단문 일변도 `[S2]`

짧은 문장을 연속으로 끊어 정보 흐름이 파편화되면 원인, 조건, 대비가 이어지는 문장을 결합한다. 반대로 한 문장에 정보가 과도하게 몰리면 나눈다.

#### E-5. 쉼표로 이어진 긴 절 `[S2]`

긴 부속절을 쉼표로 계속 연결하지 않는다. 두 개 이상의 독립된 판단이 들어가면 문장을 나누고, 관련 정보는 관형절이나 연결어미로 정리한다.

#### E-6. 쉼표 위치의 무차별 확산 `[S2]`

명사, 부사, 연결어미 뒤에 습관적으로 쉼표를 찍지 않는다. 주절 경계, 삽입, 동격, 긴 열거처럼 기능이 분명한 위치에만 사용한다.

#### E-7. 경어법과 서술체 불일치 `[S2]`

동일 문서에서 해라체, 해요체, 합쇼체가 이유 없이 섞이지 않게 한다. 설정 본문은 문서가 채택한 서술체를 유지하고, 직접 인용과 대화문은 화자 관계에 따라 예외를 인정한다.

### F. 수식어와 명사화 점검

#### F-1. 정도부사 반복 `[S2]`

`매우`, `정말`, `대단히`, `극히`를 반복하지 않는다. 강도를 보여 주는 피해, 규모, 기간, 비교 대상이 있으면 구체적으로 쓴다.

#### F-2. 동의어 이중 수식 `[S2]`

`중요하고 핵심적인`, `새롭고 혁신적인`, `지속적이고 꾸준한`처럼 뜻이 겹치면 더 정확한 하나만 남긴다.

#### F-3. 추상명사 쌍의 중복 `[S2]`

`역할과 기능`, `의미와 가치`, `방식과 방법`이 실제로 다른 내용을 가리키지 않으면 하나로 줄인다.

#### F-4. `~적`, `~성`, `~화`와 명사화 반복 `[S2]`

`구조적 변화`, `효율성 강화`, `체계 고도화`가 연속되면 동사와 형용사로 푼다. `구조가 바뀌었다`, `효율이 높아졌다`, `체계가 정교해졌다`처럼 실제 변화를 드러낸다. 학술·법률 용어로 굳어진 말은 유지한다.

#### F-5. `~적 N` 추상어 연쇄 `[S2]`

`정치적 안정성`, `사회적 영향력`, `문화적 정체성`이 연속될 때에는 누가 어떻게 안정되고, 무엇에 영향을 주며, 어떤 관습으로 정체성이 드러나는지 구체화한다.

### G. 완곡 표현 점검

#### G-1. 추측형 종결 남발 `[S2]`

`~로 보인다`, `~라고 여겨진다`, `~인 것으로 판단된다`를 반복하지 않는다. 정본으로 확정된 내용은 단언하고, 학설·소문·추정만 불확실성을 유지한다.

#### G-2. 이중·삼중 완곡 `[S2]`

`가능성이 있을 수 있다`, `~할 수 있을 것으로 보인다`처럼 불확실성이 겹치면 한 단계만 남긴다. 원문의 확실성 수준은 바꾸지 않는다.

#### G-3. 판단을 피하는 균형 표현 `[S2]`

`양쪽 모두`, `장점도 있지만`, `균형 잡힌 시각`, `신중한 접근`을 반복하며 결론을 피하지 않는다. 세력마다 판단이 다르면 어느 세력이 어떤 조건에서 그렇게 보는지 분리한다.

### H. 접속사 점검

#### H-1. 문두 접속사 남발 `[S2]`

`또한`, `따라서`, `즉`, `나아가`, `아울러`, `게다가`, `더욱이`가 문장마다 나오면 대부분 삭제한다. 논리 관계가 불분명한 경우에만 남긴다.

#### H-2. 역접 접속사 반복 `[S2]`

`하지만`, `그러나`, `반면`을 모든 문단에 배치하지 않는다. 대비가 문장 내용에서 분명하면 생략한다.

#### H-3. `이는 ~` 메타 부연 `[S2]`

앞 문장을 `이는 무엇을 의미한다`, `이 점에서`, `이 관점에서 보면`으로 다시 설명하지 않는다. 앞 문장과 합치거나 실제 결과를 곧바로 쓴다.

#### H-4. `즉` 반복 `[S2]`

모든 보충 설명 앞에 `즉`을 붙이지 않는다. 재정의가 꼭 필요할 때만 사용하고, 같은 문서에서 반복되면 문장 구조를 바꾼다.

### I. 형식명사와 의존명사 점검

#### I-1. `것이다` 종결 반복 `[S2]`

주요 문장이 계속 `~한 것이다`, `~일 것이다`로 끝나면 직접 종결한다. 미래 추정이나 강조 기능이 실제로 필요하면 유지한다.

#### I-2. `점·바·수·데` 반복 `[S2]`

`주목할 점은`, `알 수 있는 바는`, `하는 데에`, `~라는 점에 있다`를 반복하지 않는다. 구체적인 주어와 서술어로 바꾼다.

#### I-3. `~라는 것`, `~다는 뜻이다` 반복 `[S2]`

결론을 형식명사로 한 번 더 포장하지 않는다. `권력이 약해졌다는 뜻이다`는 `권력이 약해졌다`로 직접 쓴다. 해석 자체가 핵심이면 유지한다.

#### I-4. `~할 필요가 있다`, `~해야 한다` 반복 `[S2]`

설정 본문에서 독자에게 지시하는 권고형 문장을 쓰지 않는다. 세계 내부의 법, 의무, 금기를 설명하는 `해야 한다`는 유지하며, 누가 누구에게 요구하는지 명시한다.

#### I-5. `~이 필요하다` 추상 권고 `[S2]`

`변화가 필요하다`, `대응이 필요하다`에서 멈추지 않는다. 어떤 세력이나 인물이 무엇을 바꾸려 하는지 세계 내부의 행위로 풀어 쓴다.

#### I-6. `N 능력` 연쇄 `[S2]`

`추론 능력`, `통제 능력`, `회복 능력`이 반복되면 `추론한다`, `통제한다`, `회복이 빠르다`처럼 동사와 형용사로 푼다. 규칙 용어나 능력치 명칭은 예외다.

### J. 시각적 장식 점검

#### J-1. 과도한 볼드 `[S2]`

본문의 단어와 문장을 습관적으로 굵게 표시하지 않는다. 구조상 핵심 경고, 표의 필드, 정식 문서 표기처럼 기능이 있을 때만 사용한다.

#### J-2. 강조용 따옴표 남발 `[S2]`

개념어마다 따옴표를 붙이지 않는다. 직접 인용, 별칭, 특수 용례, 세계 내부에서 논쟁적인 명칭에만 사용한다.

#### J-3. 긴 대시 남발 `[S3]`

대시로 부연 설명을 계속 삽입하지 않는다. 괄호, 쉼표, 별도 문장 가운데 가장 자연스러운 구조를 선택한다.

#### J-4. 괄호 부연 과다 `[S2]`

중요한 설정을 괄호 안에 몰아넣지 않는다. 필요한 정보는 본문에 편입하고, 없어도 의미가 같은 부연은 삭제한다. 약칭·연도·단위·원어 표기는 예외다.

### 설정 문서 구조상의 예외

구조적 규칙은 설정 문서의 탐색성과 문서 구조 기능을 해치지 않는 범위에서 적용한다. 아래 요소는 AI 문체로 단정하지 않는다.

- 문서 유형에 맞는 `##` 섹션과 하위 제목
- 계급, 연표, 의식 단계, 구성원, 물품, 능력, 지역 목록
- 비교가 필요한 표와 구조화된 데이터
- 인덱스의 비교 항목, `원문 링크`, `보강 필요` 상태값과 관리용 필드
- 프로젝트가 요구하는 `개요`, `항목`, `요약` 섹션
- YAML 프론트매터와 위키 링크
- 직접 인용된 교리, 법문, 전승, 선언문
- 문서 내부 탐색을 위한 제한적인 볼드와 코드 표기

문제가 되는 것은 구조의 존재가 아니라, 모든 섹션과 문단이 동일한 공식으로 반복되거나 목록이 설명형 문단을 대체하는 경우다.

인덱스는 탐색과 검증을 위한 운영 문서이므로 `원문 링크`, `보강 필요`, 분류명과 비교 필드를 창작물 바깥의 메타 표현으로 삭제하지 않는다. 다만 각 실질 섹션의 설명형 본문은 정본의 주장 강도와 공개 수준을 보존하고, 표나 링크만으로 밀도 기준을 대신하지 않는다.

### 윤문 실행 절차

1. 원문에서 고유명사, 수치, 연대, 인과관계, 공개 수준, 직접 인용을 보존 목록으로 만든다.

3. S1 패턴을 먼저 찾고 의미가 바뀌지 않는 범위에서 국소 수정한다.

8. 과윤문 신호와 장르 이탈을 검사한다.

10. 잔존 S1, 반복 S2, 정량 기준 미충족 구간만 한 차례 더 수정한다.

### 변경률과 과윤문 방지

순수 윤문 작업의 권장 변경률은 원문 대비 약 5~30%다. 30%를 넘으면 의미와 장르가 훼손되지 않았는지 재검토하고, 50%를 넘으면 전체 재작성 대신 문제 구간만 남기고 되돌리는 것을 우선한다. 변경률이 5% 미만인데 S1 패턴이 남아 있다면 누락된 구간을 다시 확인한다.

보강·개편·재작성처럼 새 설정 문단을 추가하는 작업에는 전체 변경률을 기계적으로 적용하지 않는다. 이 경우 기존 문장에 대한 윤문 변경과 새로 추가한 설정을 분리해 검토한다.

아래 신호 중 두 가지 이상이 나타나면 과윤문으로 판정한다.

- 백과사전·사료풍 설정 문서가 에세이 또는 감상문처럼 변했다.
- 원문에 없던 비유, 수사, 감정적 평가가 추가되었다.
- 격식 있는 서술이 갑자기 구어체나 해요체로 바뀌었다.
- 모든 문장이 의도적으로 짧아지거나 장문이 과도하게 섞였다.
- 핵심 설정 용어가 동의어로 바뀌어 문서 간 추적이 어려워졌다.
- 문단 밀도를 유지하려고 같은 의미를 다른 말로 반복했다.
- 윤문 과정에서 공개 설정과 비밀 설정의 경계가 흐려졌다.

## 섹션 밀도 정의

섹션 밀도란 문서 전체 분량이 아니라, 각 제목 아래의 서술이 얼마나 독립적인 설정 단위로 기능하는지를 뜻한다.

`## 개요`, `## 형성 배경`, `### 문화와 규범`, `### 사회적 인식`, `#### 현재 동향`처럼 실제 설정 내용을 구분하는 모든 제목은 단순 요약으로 끝나면 안 된다. 제목 단계와 관계없이 각 섹션은 해당 설정의 정의와 작동 방식, 사회적 의미, 갈등 가능성을 어느 정도 담아야 한다.

글자 수가 많아도 추상적인 문장이 반복되면 밀도는 낮다. 반대로 지나치게 짧은 섹션은 설정의 핵심이 드러나지 않으므로 보강 대상으로 본다.

## 정량 작성 기준

설정 문서의 밀도는 정성 평가만으로 판정하지 않는다. 신규 작성, 보강, 개편, 재작성, 점검 작업에서는 섹션별 토큰 수와 문단 수를 함께 확인한다. 이 정량 기준은 문서를 기계적으로 늘리기 위한 목표가 아니라, 각 섹션이 독립적인 설정 단위로 기능할 최소 분량을 확보하기 위한 하한선이다.

### 토큰 계산 범위

토큰은 문서에서 실제 설정 본문으로 읽히는 내용을 기준으로 계산한다. 기준 토크나이저는 가능한 경우 `o200k_base`를 사용하며, 다른 토크나이저를 사용했다면 점검 결과에 그 기준을 명시한다. 토크나이저에 따라 수치가 달라질 수 있으므로, 최소 기준에 간신히 맞추기보다 320토큰 이상을 작성 목표로 삼는다.

문서 제목으로 사용하는 `#`을 제외하고, 실제 설정 내용을 구분하는 모든 Markdown 제목은 각각 독립된 섹션이다. `##` 아래에 `###`가 있으면 두 제목을 하나의 섹션으로 묶지 않고 `##`와 `###`를 각각 판정하며, `####` 이하도 같은 원칙을 적용한다. 제목 단계가 낮다는 이유로 정량 기준을 완화하지 않는다.

각 섹션의 계산 범위는 해당 제목 직후부터 다음 Markdown 제목이 나오기 전까지의 직접 본문이다. `##` 아래에 `###`가 있다면 상위 `##`는 첫 `###`가 나오기 전의 내용만으로 계산하고, `###` 아래의 본문은 상위 `##`의 문단 수나 토큰 수에 포함하지 않는다. `###` 아래에 `####`가 있다면 `###` 역시 첫 `####` 전까지의 직접 본문만으로 계산한다. 상위 섹션과 하위 섹션의 분량을 중복 계산하지 않는다.

섹션 제목 자체와 YAML 프론트매터, 대표 이미지 임베드는 계산에서 제외한다. 직접 본문 안에 있는 일반 문단과 실제 내용이 채워진 목록·표는 토큰 계산에 포함할 수 있지만, 하위 제목 아래의 내용은 해당 하위 섹션에서만 계산한다. 코드 블록, 인용문 또는 예시 안에 등장하는 `#` 기호는 실제 Markdown 제목이 아닌 경우 섹션 경계로 판정하지 않는다.

### 섹션 최소 토큰

모든 실질 설정 섹션은 제목 단계와 관계없이 직접 본문만으로 최소 300토큰 이상이어야 한다. 안정적인 작성 목표는 섹션마다 320~450토큰이며, 설정의 중요도와 복합성에 따라 그 이상 작성할 수 있다. 상위 섹션이 하위 섹션을 포함해 300토큰을 넘더라도 상위 섹션의 직접 본문이 300토큰 미만이면 정량 기준 미충족이다. 300토큰 미만인 섹션은 문장 완성도가 높더라도 부족한 토큰 수와 보강 방향을 함께 제시한다.

토큰을 채우기 위해 같은 의미를 반복하거나 수식어만 늘려서는 안 된다. 보강분은 정의, 작동 방식, 사회적 의미, 갈등과 위험성, 사건 발생 가능성 가운데 부족한 요소를 추가하는 데 사용한다. 이미 충분히 설명된 내용을 다른 표현으로 반복한 분량은 밀도 향상으로 인정하지 않는다.

### 문단 구성

모든 실질 설정 섹션은 제목 단계와 관계없이 직접 본문에 최소 2개의 실질 서술 문단을 둔다. 상위 섹션은 첫 하위 제목이 나오기 전에 두 문단을 확보해야 하며, 하위 섹션의 문단을 상위 섹션의 문단 수로 인정하지 않는다. 두 문단으로 작성할 때는 문단당 약 150토큰 이상, 세 문단으로 작성할 때는 문단당 약 100토큰 이상을 권장하지만, 이는 고정 템플릿이 아니라 300토큰 하한을 안정적으로 충족하기 위한 작성 지표다.

문단 내부에서는 임의 줄바꿈을 지양한다. 하나의 의미 흐름을 이루는 문단은 Markdown 원문에서도 한 덩어리로 유지하고, 의미 단위가 바뀔 때만 빈 줄을 두어 다음 문단으로 나눈다. 목록과 표는 직접 본문의 토큰 수를 보조할 수 있으나 최소 2개의 실질 서술 문단으로 계산하지 않는다. 사용자가 구조화된 데이터 문서를 명시하지 않은 한 목록과 표가 실질 서술 문단을 완전히 대체해서도 안 된다.

### 제목 단계별 독립 판정 예시

아래 구조에서는 `## 사회 구조`와 `### 귀족 계층`이 서로 다른 두 섹션이다. `## 사회 구조`는 첫 `###`가 나타나기 전에 자체 본문 두 문단과 300토큰을 충족해야 하며, `### 귀족 계층`도 다음 제목이 나타나기 전까지 같은 기준을 충족해야 한다.

```md
## 사회 구조

상위 섹션의 첫 번째 실질 서술 문단.

상위 섹션의 두 번째 실질 서술 문단.

### 귀족 계층

하위 섹션의 첫 번째 실질 서술 문단.

하위 섹션의 두 번째 실질 서술 문단.
```

아래 구조는 `### 귀족 계층`에 본문이 충분하더라도 `## 사회 구조`가 빈 컨테이너이므로 상위 섹션 기준 미충족이다.

```md
## 사회 구조

### 귀족 계층

하위 섹션의 첫 번째 실질 서술 문단.

하위 섹션의 두 번째 실질 서술 문단.
```

### 문서 경계 섹션

설정 문서의 첫 번째 실질 본문 섹션은 반드시 `개요`로 한다. 프론트매터, 문서 제목, 대표 이미지와 같은 메타 요소는 `개요` 앞에 둘 수 있지만, 다른 설정 본문 섹션이 `개요`보다 먼저 나와서는 안 된다.

그 밖의 섹션 제목, 순서, 개수는 고정하지 않는다. 국가, 도시, 신격, 종족, 사건, 단체, 인물, 개념 등 문서 유형과 최신 템플릿에 따라 자유롭게 바꿀 수 있으며, 이 수칙은 `개요`, `항목`, `요약`을 제외한 고정 섹션 템플릿을 강제하지 않는다.

`요약` 섹션은 선택 사항이다. `요약`이 존재한다면 반드시 문서의 마지막 섹션으로 배치한다. 이때 `요약` 바로 위에는 `항목` 섹션을 두고, 그 본문은 다른 설명 없이 정확히 `내용`으로 유지한다. `항목`은 사용자가 직접 내용을 추가하기 위한 편집용 자리표시자다.

`항목`과 `요약`은 실질 설정 본문이 아니므로 최소 300토큰과 최소 2문단 규칙에서 제외한다. `요약`이 없는 문서에는 이 규칙만을 이유로 `항목`을 강제로 추가하지 않는다.

### 정량 판정 우선순위

섹션 점검은 먼저 모든 실질 설정 제목을 계층별로 추출하고, 각 제목의 직접 본문을 분리한 뒤 정량 기준을 확인한다. 직접 본문이 최소 2문단 또는 최소 300토큰을 충족하지 못한 섹션은 하위 섹션의 분량이 충분하거나 정성 평가가 우수하더라도 `형식 미충족`을 함께 표시한다. 정량 기준을 충족한 뒤에야 정의, 작동 방식, 사회적 의미, 갈등과 위험성, 사건 발생 가능성을 기준으로 부족·보통·적정·우수를 판정한다.

## 섹션 밀도 구성 요소

주요 섹션은 가능하면 아래 요소를 포함한다.

### 정의

이 섹션에서 다루는 대상이 무엇인지 분명히 밝힌다. 독자가 해당 설정의 기본 위치를 바로 이해할 수 있어야 한다.

### 작동 방식

그 대상이 세계 안에서 어떻게 기능하는지 설명한다. 조직이라면 어떻게 운영되는지, 도시라면 어떤 생활 구조를 만드는지, 신격이라면 어떤 신앙 실천으로 이어지는지 적는다.

### 사회적 의미

그 설정이 사람들, 세력, 국가, 도시, 종교, 경제, 전쟁, 일상에 어떤 영향을 주는지 설명한다. 설정은 세계 안에서 파장을 가져야 한다.

### 갈등과 위험성

그 설정이 어떤 문제를 만들 수 있는지 적는다. 권력 다툼, 오해, 금기, 남용, 부작용, 세대 갈등, 계층 차이, 신앙적 충돌 등이 여기에 해당한다.

### 사건 발생 가능성

그 설정이 세계 안에서 어떤 사건으로 이어질 수 있는지 보여 준다. 마지막 섹션에만 몰아넣지 말고, 본문 중간에도 갈등의 씨앗이 보이도록 한다. 실제 설정 문서에서는 `시나리오 활용성` 같은 메타 제목보다 `현재의 분쟁과 위기`, `발생 가능한 사건`, `불안 요소`처럼 세계 내부의 제목을 사용한다.

## 밀도 판정 등급

### 부족

섹션이 1~2문장 설명으로 끝난다. 정의는 있지만 구체적 작동 방식, 사례, 고유명사, 사회적 파장, 갈등 가능성이 거의 없다.

이 단계의 문서는 정보는 전달하지만 읽는 맛이 약하다. 설정 카드처럼 보이며, 문단 하나가 독립적인 세계 조각으로 기능하지 못한다.

### 보통

개념 설명은 되어 있으나 추상적이다. 역할과 기능은 이해할 수 있지만, 실제 장면이나 인물 반응, 사회적 긴장으로 이어지는 힘이 부족하다.

이 단계는 초안으로는 사용할 수 있다. 그러나 룩스테라식 풍부함을 목표로 한다면 보강이 필요하다.

### 적정

정의, 작동 방식, 사회적 의미, 위험성, 활용 가능성이 한 섹션 안에서 연결된다. 섹션 하나를 읽어도 해당 설정이 왜 중요한지 이해할 수 있다.

이 단계부터 정식 설정 문서로 안정적으로 사용할 수 있다. 읽는 사람은 문서에서 바로 장면과 사건의 가능성을 떠올릴 수 있다.

### 우수

섹션 하나만 읽어도 장면, 갈등, 인물 반응, 후속 사건이 떠오른다. 설명을 넘어 이야기의 씨앗이 들어 있다.

룩스테라의 풍부한 설정 문단을 기준으로 삼을 때 목표가 되는 단계다. 신격, 국가, 주요 도시, 핵심 개념 문서는 가능하면 이 단계에 가깝게 작성한다.

## 룩스테라식 밀도 기준

룩스테라 문서는 한 섹션 안에서 단순 정의와 해석을 함께 제공한다. 신격 문서라면 신의 이름과 권능만 적는 것이 아니라, 교단의 성격, 신앙의 태도, 의식, 성물, 외부 시선, 금기까지 함께 다룬다.

룩스테라식 밀도는 장식적인 문장 길이가 아니다. 하나의 설정이 문화, 정치, 신앙, 전쟁, 일상, 시나리오로 확장되는 연결성을 뜻한다.

엘드로스 문서도 이 기준을 따른다. 헌터, 길드, 위그드라실, 정제사, 클래스, 도시 구역 같은 문서는 단순 기능 설명에서 끝나지 않고 사회적 파장과 갈등 구조까지 가져야 한다.

## 장르별 문체 기준

룩스테라는 판타지, 신화, 국가, 종족, 신격, 대륙 문명의 풍부함을 살린다. 문단은 전승, 신앙, 역사, 문화적 해석이 함께 흐르도록 작성한다.

엘드로스는 포스트 아포칼립스 헌터물의 질감을 살린다. 문단은 생존, 자원, 신목 의존, 계급, 게이트 위협, 기술 잔재, 도시 통제, 후방 관제의 긴장감을 중심으로 작성한다.

두 프로젝트의 문체는 다를 수 있다. 그러나 섹션 하나가 독립적으로 읽히는 밀도 기준은 동일하다.

## 문서 유형별 점검 기준

아래 기준은 각 문서에서 확인해야 할 내용의 범위를 제시한다. 특정 섹션 제목이나 고정된 순서, 개수를 강제하는 템플릿이 아니며, 실제 문서 구조는 사용자의 최신 지시와 해당 문서가 채택한 최신 템플릿을 우선한다.

### 도시 문서

도시 문서는 기능 설명만으로 끝나면 안 된다. 인구, 구역, 경제, 방어, 문화, 신앙, 계급, 일상 체감이 함께 들어가야 한다.

구역이 있다면 가능하면 고유 명칭을 부여한다. 구역명은 독자가 도시를 실제 공간처럼 상상하게 만드는 핵심 장치다.

### 국가 문서

국가 문서는 지리, 정치 체제, 경제, 군사, 문화, 대외 관계가 서로 연결되어야 한다. 단순히 강한 국가, 신성 국가, 해양 국가처럼 설명하면 부족하다.

각 국가는 무엇을 두려워하고, 무엇을 자랑하며, 어떤 방식으로 타국과 충돌하는지 드러나야 한다. 국가 문서는 곧 시나리오의 무대이자 세력 갈등의 출발점이다.

### 신격 문서

신격 문서는 권능 목록만으로 끝나면 안 된다. 신앙의 방식, 교단, 성물, 의식, 금기, 계시, 외부 인식, 신도에게 생기는 축복과 부담을 함께 다뤄야 한다.

신은 단순 초월자가 아니라 사회와 문화 속에서 작동하는 권위다. 신격 문서는 그 신이 세계를 어떻게 바꾸는지 보여 주어야 한다.

### 주요 개념 문서

헌터, 클래스, 길드, 클랜, 위그드라실, 정제사, 앙그라의 안개 같은 문서는 세계관의 축이다. 이 문서들은 반드시 다른 문서와의 연결성을 고려한다.

주요 개념 문서는 정의보다 파장이 중요하다. 그 개념이 사회 구조, 임무 방식, 계급, 금기, 종교, 전쟁에 어떤 변화를 만드는지 확인한다.

### 사건 문서

사건 문서는 발생 배경, 전개, 직접 결과, 장기 영향, 후대 해석을 모두 갖춰야 한다. 단순 연표형 요약만으로는 밀도가 부족하다.

사건 문서는 세계의 상처이자 기억이다. 누가 이 사건을 영웅담으로 기억하고, 누가 경고담으로 기억하며, 어떤 집단이 기록을 왜곡하는지도 고려한다.

### 단체 문서

길드, 클랜, 교단, 군대, 학파, 산문 같은 단체 문서는 설립 배경, 이념, 운영 구조, 구성원, 자원, 대외 관계, 내부 갈등을 포함해야 한다.

단체는 단순 역할 묶음이 아니다. 구성원이 무엇을 믿고, 무엇을 숨기며, 무엇을 두려워하는지까지 드러나야 읽는 맛이 생긴다.

### 클래스 문서

클래스 문서는 해당 문서가 채택한 최신 템플릿을 우선한다. 기본 정보, 한 줄 정의, 운용 설명, 대표 기술, 서브클래스, 비고와 같은 정보가 필요할 수 있으나, 이를 고정된 섹션명이나 순서로 강제하지 않는다.

포지션 표기가 필요한 템플릿에서는 `상위 담당 - 세부 태그` 형식을 권장한다. 예를 들어 `공격 담당 - 딜러`, `방어 담당 - 탱커`, `지휘 및 관제 담당 - 커맨더`, `특수 대응 담당 - 스페셜리스트`처럼 적는다.

서브클래스는 단순 성능 차이가 아니라, 기본 클래스의 서로 다른 해석이어야 한다. 성장 단계, 운용 방식, 사회적 인식, 약점이 함께 드러나야 한다.

### 스토리 설계 문서

스토리 설계 문서는 사건의 나열만으로 끝나면 안 된다. 갈등의 원인, 주요 인물의 선택, 세력의 이해관계, 드러나는 정보와 숨겨진 정보, 이후 전개에 남는 상처를 함께 정리한다.

모든 시리즈의 스토리 설계 문서는 설정 문서와 연결되어야 한다. 스토리에서 등장한 사건이 세계관 문서에 남고, 세계관 문서의 갈등이 다시 스토리를 낳는 순환 구조를 목표로 한다.

### 세력 관계 문서

세력 관계 문서는 관계값만으로 끝나면 안 된다. 우호, 견제, 대립, 전쟁 같은 상태가 왜 생겼는지, 어떤 사건으로 악화되거나 완화될 수 있는지 설명해야 한다.

관계 문서에는 표면적 명분과 실제 이해관계를 함께 적는다. 세력 간 관계는 정적인 표가 아니라 시나리오를 밀어내는 압력이어야 한다.

### 비밀 설정 문서

비밀 설정은 공개 문서와 분리한다. 공개 문서에는 세계 안에서 알려진 사실, 추정, 신앙적 해석, 공식 기록을 적는다.

비밀 설정 문서에는 실제 원인, 은폐된 진실, 왜곡된 기록, 후대에 드러날 반전, 세계관 핵심 연결고리를 적는다. 비밀 설정은 공개 문서를 더 깊게 만드는 뿌리 역할을 해야 한다.

### 인덱스 문서

인덱스 문서는 여러 정본의 범위와 차이를 한눈에 비교할 수 있어야 한다. 포함 대상이 누락되거나 중복되지 않았는지, 분류와 정렬 기준이 일관적인지, 각 항목의 위키 링크가 실제 정본 파일을 가리키는지 확인한다. 인덱스의 실질 `##`와 `###` 섹션도 독립 섹션으로 판정하며, 표나 항목 목록만으로 끝나지 않고 해당 분류의 범위·판정 기준·예외를 설명하는 직접 본문 2문단과 300토큰 이상을 확보해야 한다.

인덱스에 기록된 정치 체제·정당성·현재 압력·관계는 연결된 정본의 주장 강도와 공개 수준을 보존해야 한다. 정본에 근거가 없으면 임의 설정을 만들지 않고 `보강 필요`로 표시한다. 이름·분류·정치 체제·관계 변경 작업에서는 정본 수정과 인덱스 갱신을 하나의 작업 단위로 보고, 링크와 항목 수를 다시 검증한다.

## 공개 설정과 비밀 설정 분리

공개 문서에는 인물과 사회가 알고 있는 사실을 적는다. 이때 잘못된 믿음이나 공식 선전도 공개 설정에 포함될 수 있다.

비밀 문서에는 실제 진실을 적는다. 예를 들어 어떤 사건의 공식 원인이 시민에게 알려진 것과 다르다면, 공개 문서에는 공식 기록을 적고 비밀 문서에는 실제 원인을 적는다.

이 분리는 모든 시리즈와 공통 설정에 적용한다. 특히 세계관 전체를 잇는 위그드라실 관련 진실, 신격의 실제 의도, 고대 사건의 원인은 비밀 설정으로 분리하는 것을 우선 검토한다.

## 연대와 사건 흐름 점검

연대가 있는 문서는 사건 발생 연도와 본문 표현이 충돌하지 않는지 확인한다. 사건 시점과 맞지 않는 표현은 반드시 수정한다.

연표 문서는 단순 날짜 목록이 아니라 사건의 인과관계를 보여 주어야 한다. 어떤 사건이 다음 사건을 가능하게 했는지, 어느 사건이 세계관의 가치관을 바꾸었는지 드러나야 한다.

복수 시리즈가 같은 프로젝트 계통에 속하더라도, 직접 연결되는 설정과 간접적으로만 이어지는 설정을 구분한다. 연결성은 명확해야 하지만, 불필요하게 한 세계처럼 섞지 않는다.

밀도가 부족한 섹션은 단순히 문장을 늘리지 않는다. 아래 방식으로 보강한다.

- 장소명 추가

- 의식명 추가

- 내부 갈등 추가
- 실패 사례 추가

- 시나리오 접점 추가

보강 후에는 섹션이 요약문이 아니라 설정 문단으로 읽히는지 다시 확인한다.

### 전체 판정

문서 전체의 구조, 정합성, 밀도, 보강 우선도를 간단히 정리한다.

### 문서별 점검

#### 문서별 밀도 점검 요약표

설정 밀도 점검을 포함하는 보고서는 문서별 상세 설명보다 먼저 대상 문서 전체를 아래 고정 컬럼의 Markdown 테이블로 제시한다. 컬럼명과 순서는 임의로 바꾸지 않으며, 점검 대상 문서를 한 건도 누락하지 않는다.

| 문서 이름 | 타입 | 섹션 수 | 통과 섹션 | 보강 대상 섹션 | 보강 사유 | 우선순위 |
| --- | --- | ---: | ---: | ---: | --- | --- |
|  |  |  |  |  |  |  |

- `문서 이름`은 실제 파일명 또는 문서 제목을 기록한다. 동명이 존재하면 시리즈명이나 상대 경로를 함께 적어 식별한다.
- `타입`은 프론트매터의 `type` 값을 우선 사용한다. 값이 없으면 문서군과 템플릿을 근거로 판정하고, 확정할 수 없으면 `미지정`으로 적는다.
- `섹션 수`는 `항목`, `요약`처럼 지침에서 명시적으로 제외한 템플릿 예외를 빼고 실제 밀도 판정에 포함한 실질 섹션의 총수다.
- `통과 섹션`은 섹션당 300토큰 이상, 실질 서술 2문단 이상, 문단당 100토큰 이상과 정성 밀도 기준을 모두 충족한 섹션 수다.
- `보강 대상 섹션`은 하나 이상의 정량·정성·구조 기준을 충족하지 못한 섹션 수다. 한 섹션에 여러 문제가 있어도 섹션 수에는 한 번만 집계한다.
- `보강 사유`에는 `300토큰 미달`, `2문단 미달`, `문단당 100토큰 미달`, `직접 본문 없음`, `목록·표 의존`, `정성 밀도 부족`, `템플릿 구조 불일치`, `메타 표현` 등 실제 발견 사유를 적는다. 사유가 여러 개면 하나로 뭉뚱그리지 말고 `<br>` 또는 세미콜론으로 모두 병기한다.
- `우선순위`는 `최우선`, `높음`, `보통`, `낮음` 중 하나로 기록한다. 직접 본문 없음·상위 구조 결손·대규모 확정 부족이 겹치면 `최우선`, 여러 확정 부족과 문단 결손이 있으면 `높음`, 일부 섹션 보강이 필요하면 `보통`, 경계 재측정이나 제한적인 정성 보강만 필요하면 `낮음`으로 판정한다.
- 표는 우선순위가 높은 문서부터 정렬하고, 같은 우선순위에서는 보강 대상 섹션 수와 확정 부족량이 큰 문서를 먼저 둔다.

각 문서의 핵심 문제와 강점을 적는다. 문제가 있는 섹션은 섹션명을 직접 표시한다. 요약표의 수치만으로 보고를 끝내지 않고, 보강 대상 섹션의 정확한 이름과 판정 근거를 문서별 상세 항목에 이어서 기록한다.

### 섹션 밀도 판정

`##`, `###`, `####` 등 제목 단계와 섹션명을 함께 표시하고, 각 섹션의 직접 본문에 대한 토큰 수, 실질 서술 문단 수, 정량 기준 충족 여부를 먼저 기록한다. 상위 섹션에 하위 섹션 분량을 합산하지 않는다. 이어서 부족, 보통, 적정, 우수 중 하나를 판정하고, 300토큰 또는 2문단 기준을 충족하지 못했거나 정성 밀도가 부족한 경우 보강 방향을 함께 적는다.

### 문체 및 윤문 판정

S1·S2·S3별 발견 항목과 수정 여부를 기록한다. 문제가 있는 표현은 문서명과 섹션명을 표시하고, 의미가 바뀌지 않는 범위의 대표 수정 전·후 예시를 제시한다. 구조적 예외나 고유한 세계관 표현을 유지했다면 그 이유를 함께 적는다.

### 내용 보존 감사

고유명사, 수치, 연대, 인과관계, 주장 강도, 공개 수준, 직접 인용, 분류와 소속이 유지되었는지 원문과 대조한다. 누락·첨가·행위자 변경이 발견되면 해당 윤문을 되돌리고 재검토한다.

### 과윤문 및 장르 보존 판정

문서가 에세이화·문학화·구어화되지 않았는지, 문장 길이를 억지로 조작하지 않았는지, 핵심 용어를 불필요하게 바꾸지 않았는지 확인한다. 과윤문 신호가 두 개 이상이면 문제 구간을 롤백한다.

### 충돌 및 정합성 문제

연대 오류, 용어 충돌, 분류 충돌, 공개/비밀 설정 혼재, 파일명 규칙 위반을 따로 정리한다.

### 보강 우선순위

즉시 수정해야 할 문서, 나중에 보강해도 되는 문서, 구조는 유지하되 표현만 늘리면 되는 문서를 구분한다.

## 수정본 제공 방식

수정본은 Google Drive 설정 정본에 직접 반영하지 않는다. 사용자가 적용할 수 있도록 파일로 제공한다.

기본 제공 방식은 `zip`이다. zip 내부에는 실제 설정 폴더에 넣을 폴더 구조를 유지한다. 필요한 경우 `README.md` 또는 `적용 안내.md`를 함께 포함한다.

수정 대상 파일은 가능하면 원래 파일명을 유지한다. 새 문서를 만들 경우에도 사용자가 바로 위치를 알 수 있도록 경로를 분명히 적는다.

## 최종 확인 기준

점검이 끝난 문서는 아래 질문에 답할 수 있어야 한다.

- 첫 번째 실질 본문 섹션이 `개요`인가?
- `##`, `###`, `####` 등 모든 실질 설정 제목을 각각 독립 섹션으로 판정했는가?
- 각 상위 섹션이 첫 하위 제목으로 내려가기 전에 직접 본문만으로 최소 300토큰을 확보했는가?
- 각 상위 섹션이 첫 하위 제목으로 내려가기 전에 직접 본문에 최소 2개의 실질 서술 문단을 두었는가?
- 각 하위 섹션도 다음 제목이 나오기 전까지 직접 본문만으로 최소 300토큰과 2문단을 충족하는가?
- 하위 섹션의 문단과 토큰을 상위 섹션에 중복 합산하지 않았는가?
- 문단 내부에 불필요한 강제 줄바꿈이 없는가?
- `요약`이 존재한다면 마지막 섹션이며, 바로 위에 본문이 `내용`인 `항목` 섹션이 있는가?
- 이 문서의 각 주요 섹션은 한두 문장 요약으로 끝나지 않는가?
- 섹션마다 정의와 작동 방식이 들어 있는가?
- 사회적 의미나 파장이 드러나는가?
- 갈등, 금기, 위험성, 시나리오 가능성이 보이는가?
- 룩스테라 문서처럼 읽는 맛이 있는가?
- 엘드로스 문서라면 장르 특유의 생존감과 긴장감이 살아 있는가?
- 공개 설정과 비밀 설정이 섞이지 않았는가?
- 다문서 횡단 작업에서 관련 인덱스를 먼저 확인하고, 인덱스의 사실을 연결된 정본으로 검증했는가?
- 이름·분류·정치 체제·관계 변경이 관련 인덱스와 위키 링크에 함께 반영되었는가?
