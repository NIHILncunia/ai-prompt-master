# 피트 및 아이템 인라인 문법과 변수 사용 가이드

## 목적

이 문서는 Foundry VTT의 D&D5e 시스템에서 피트, 아이템, 주문, 액션과 액터 설명에 사용하는 `[[...]]` 인라인 문법과 `@...` 롤 데이터 경로의 작성·검증 기준을 정의한다.

`[[...]]` 전체를 단순히 “변수”라고 부르지 않는다. `[[...]]`는 인라인 롤 또는 D&D5e 인리처를 표시하는 바깥 문법이고, 그 안에서 `@abilities.str.mod`, `@prof`, `@scale...`처럼 실제 데이터를 읽는 경로가 변수 역할을 한다.

## 기준 환경

```text
Foundry VTT 13.351
D&D5e 5.2.4
MIDI-QOL 13.0.31
DAE 13.0.17
```

- 이 문법의 기본 제공 주체는 Foundry VTT 코어와 D&D5e 시스템이다.
- MIDI-QOL과 DAE는 이 문법을 사용하기 위한 필수 전제가 아니다.
- 시스템 버전이 바뀌면 지원 인리처, 옵션, 롤 데이터 경로가 달라질 수 있으므로 현재 설치본과 공식 문서를 다시 확인한다.
- 이 문서는 D&D5e `5.2.4` 설치본에 실제 등록된 인리처를 기준으로 작성한다. 공식 D&D5e 위키의 현행 문서가 더 높은 버전을 대상으로 하면 대상 버전의 설치 소스와 대조한다.

## 적용 범위

다음과 같이 Foundry가 리치 텍스트를 해석하는 설명 필드에 적용한다.

- 피트와 클래스 기능의 설명
- 무기, 장비, 소모품, 도구 등 아이템 설명
- 주문 설명
- NPC와 액터의 기능·행동 설명
- 저널과 채팅에 들어가는 판정·피해·아이템 사용 링크

단순 Markdown 원고나 세션 기획 문서는 그 자체로 Foundry 리치 텍스트가 아니다. 실제 FVTT 데이터로 변환할 때만 이 문법을 새로 조립하고 검증한다. 룰북·스탯블록 정본에 이미 확인된 인라인 문법이 있으면 임의로 일반 텍스트나 고정 숫자로 바꾸지 않고 보존한다.

## 문법의 세 층

### 1. Foundry 코어 인라인 롤

Foundry 코어는 대괄호 두 쌍 안의 주사위 공식을 해석한다.

```text
즉시 평가: [[2d6]]
지연 롤: [[/roll 1d20 + 5]]
지연 롤 축약형: [[/r 1d20 + 5]]
롤 데이터 사용: [[/r 1d20 + @abilities.str.mod]]
```

- 즉시 평가는 문맥이 풍부한 설명보다 단순 결과 표시에 적합하다.
- 지연 롤은 사용자가 링크를 눌렀을 때 굴리는 판정에 사용한다.
- D&D5e의 공격·피해·능력 판정에는 가능한 경우 코어 `[[/r ...]]`보다 해당 D&D5e 인리처를 우선한다. 시스템 판정 대화상자, 피해 유형, 활동 연결 등 D&D5e 문맥을 함께 사용할 수 있기 때문이다.

### 2. D&D5e 인리처

D&D5e 인리처는 설명의 텍스트를 시스템 판정이나 문서 사용 링크로 바꾼다.

기본 구조는 다음과 같다.

```text
[[/종류 옵션값 key=value]]{표시 라벨}
[[lookup @데이터.경로 옵션]]{대체 문구}
```

- `key=value`에서 값에 공백이 있으면 큰따옴표로 묶는다.
- `[[/item ...]]`의 이름과 `activity="..."`는 실제 아이템·활동 이름과 일치해야 한다.
- 대부분의 인리처 뒤 `{표시 라벨}`은 화면에 보일 문구를 바꾼다.
- `[[lookup ...]]{대체 문구}`의 중괄호는 표시명 변경이 아니라 값을 찾지 못했을 때 사용할 대체 문구다.

### 3. 롤 데이터 경로

`@...` 경로는 현재 설명을 소유한 액터·아이템 또는 지정한 활동이 제공하는 롤 데이터에서 값을 읽는다.

```text
@abilities.str.mod
@abilities.con.dc
@prof
@details.level
@scale.<상위 아이템 식별자>.<스케일 식별자>
@item.uses.value
```

표시 이름이나 시트의 한글 라벨을 경로에 그대로 쓰지 않는다. 식별자는 현재 문서의 `getRollData()` 결과와 D&D5e 설정값을 기준으로 확인한다.

## D&D5e 5.2.4 지원 인리처

D&D5e `5.2.4`는 다음 `[[...]]` 계열을 등록한다.

| 인리처 | 주요 용도 | 대표 예시 |
| --- | --- | --- |
| `attack` | 공격 굴림 또는 공격 활동 연결 | `[[/attack]]`, `[[/attack formula=5]]` |
| `check` | 능력·기술·도구 판정 | `[[/check ability=dex dc=15]]` |
| `skill` | `check`와 같은 판정 문법 | `[[/skill skill=prc dc=15]]` |
| `tool` | `check`와 같은 도구 판정 문법 | `[[/tool tool=thief ability=dex]]` |
| `save` | 내성 굴림 | `[[/save ability=dex dc=15]]` |
| `concentration` | 집중 내성 굴림 | `[[/concentration dc=10]]` |
| `damage` | 피해 굴림과 피해 유형 | `[[/damage 2d6 fire]]` |
| `heal`, `healing` | 치유 또는 임시 HP | `[[/heal 2d6+3]]` |
| `item` | 아이템 또는 그 활동 사용 | `[[/item 장궁]]` |
| `lookup` | 롤 데이터 값을 설명에 표시 | `[[lookup @name]]` |
| `language` | 언어 참조 표시 | `[[language common]]` |
| `award` | 경험치·화폐 보상 처리 | `[[/award ...]]` |

`award`는 세션 보상과 파티 관리용 문법이다. 일반 피트·아이템 설명에는 사용하지 않으며, 보상 자동화 요청에서 공식 Awards 가이드를 별도로 확인한 뒤 적용한다.

`&Reference[...]`, `@UUID[...]`, `@Embed[...]`도 설명에서 함께 사용할 수 있지만 `[[`로 시작하는 문법은 아니다. 서로 다른 문법을 한 종류의 변수로 취급하지 않는다.

## 공격 인리처

### 고정 공격 보정

```text
[[/attack +5]]
[[/attack formula=5]]
```

### 현재 아이템의 공격 활동 연결

```text
[[/attack]]
[[/attack activity=RLQlsLo5InKHZadn]]
```

### 확장형 표시

```text
[[/attack activity=RLQlsLo5InKHZadn format=extended]]
[[/attack extended]]
```

작성 기준:

- 수식과 `activity`를 동시에 명시하지 않는다.
- 인리처에 공격값을 생략하면 현재 아이템의 첫 공격 활동을 자동으로 찾는다.
- 공격 활동이 둘 이상이면 자동 추론에 기대지 않고 대상 활동 ID를 지정한다.
- `activity`에는 같은 아이템에 속한 공격 활동의 ID를 사용한다.
- `format=extended`는 NPC 스탯블록형 공격 문장에 적합하다.

## 판정과 내성 인리처

### 능력·기술·도구 판정

```text
[[/check ability=dex]]
[[/check skill=acr dc=20]]
[[/check ability=str skill=ath dc=15]]
[[/check tool=thief ability=int]]
[[/check activity=RLQlsLo5InKHZadn]]
```

### 내성과 집중

```text
[[/save ability=dex dc=15]]
[[/save ability=str/dex dc=20]]
[[/save activity=RLQlsLo5InKHZadn]]
[[/concentration dc=10]]
```

작성 기준:

- 능력, 기술, 도구에는 화면 표시명이 아니라 D&D5e 내부 식별자를 사용한다.
- `dc`에는 고정 숫자 또는 주사위를 포함하지 않는 확인된 공식을 사용한다.
- 설명 소유자의 능력 기반 DC를 쓰려면 `dc=@abilities.<능력>.dc`처럼 작성할 수 있다.
- 능력·기술·도구를 직접 지정하는 방식과 `activity` 연결 방식을 동시에 사용하지 않는다.
- 아무 옵션도 없는 `[[/check]]`와 `[[/save]]`는 같은 아이템의 첫 대응 활동을 자동으로 찾는다. 복수 활동에서는 ID를 지정한다.

## 피해와 치유 인리처

### 기본 피해

```text
[[/damage 2d6 fire]]
[[/damage formula="1d6 + @abilities.str.mod" type=slashing]]
```

### 평균값 표시

```text
[[/damage 2d6 radiant average]]
[[/damage formula=2d6 type=radiant average=true]]
```

### 복수 피해와 선택 피해 유형

```text
[[/damage 1d6 fire & 1d6 cold]]
[[/damage 1d10 type=bludgeoning/slashing]]
```

### 활동 연결과 치유

```text
[[/damage]]
[[/damage activity=RLQlsLo5InKHZadn]]
[[/heal 2d6+3]]
[[/healing 2d6+3]]
[[/heal 2d6 temp]]
```

작성 기준:

- 피해 공식과 `activity`를 동시에 명시하지 않는다.
- `[[/damage]]`는 현재 아이템에서 피해를 가진 첫 공격·피해·내성 활동을 찾는다.
- 복수 피해부는 `&`로 분리한다.
- 한 피해부에서 선택 가능한 피해 유형은 `/`로 분리할 수 있다.
- 피해 유형은 `fire`, `cold`, `slashing`, `bludgeoning`, `piercing`, `radiant`처럼 현재 `CONFIG.DND5E.damageTypes`에 존재하는 내부 ID를 사용한다.
- 평균 피해는 직접 고정값으로 복제하기보다 `average` 옵션으로 계산하는 방식을 우선한다.
- 설명의 수식 안에 있는 `@...` 값은 최종 클릭 사용자가 아니라 그 설명을 소유한 아이템·액터의 롤 데이터 문맥에서 해석된다.

## 아이템 사용 인리처

### 이름으로 사용

```text
[[/item 장궁]]
[[/item "치유의 물약"]]
```

### 아이템의 특정 활동 사용

```text
[[/item 장궁 activity=공격]]
[[/item "촉수" activity="구속 탈출"]]
```

### ID와 UUID 사용

```text
[[/item amUUCouL69OK1GZU]]
[[/item .amUUCouL69OK1GZU]]
[[/item Actor.p26xCjCCTQm5fRN3.Item.amUUCouL69OK1GZU]]
```

작성 기준:

- 이름 참조는 선택한 토큰 또는 할당된 액터가 같은 이름의 아이템을 가지고 있어야 한다.
- 이름이 중복되거나 번역·이름 변경 가능성이 있으면 ID 또는 상대 ID 사용을 검토한다.
- 월드 액터의 절대 UUID는 다른 월드·액터·컴펜디움 복사본으로 이식하기 어렵다.
- 피트·아이템을 여러 액터에 배포할 목적이면 같은 액터 안의 상대 ID나 이름 참조가 적합한지 먼저 판단한다.
- 활동 이름에 공백이 있으면 `activity="활동 이름"`처럼 큰따옴표로 묶는다.
- `[[/item]]`만 사용하면 현재 설명을 가진 아이템 자체를 대상으로 삼을 수 있다. 실제 사용 목적과 활동 선택 결과를 확인한다.

## 조회 인리처

`lookup`은 값을 굴리지 않고 설명에 표시한다.

```text
[[lookup @name]]
[[lookup @name lowercase]]
[[lookup @abilities.con.dc]]
[[lookup @save.dc.value activity=RLQlsLo5InKHZadn]]
[[lookup @name]]{해당 크리처}
```

옵션:

- `capitalize`: 첫 단어의 첫 글자를 대문자로 표시
- `lowercase`: 소문자로 표시
- `uppercase`: 대문자로 표시
- `activity=<ID>`: 같은 아이템의 특정 활동 롤 데이터에서 조회

작성 기준:

- `lookup`은 슬래시 없이 `[[lookup ...]]`로 작성한다.
- 경로가 없거나 찾을 수 없으면 원래 경로가 보일 수 있다.
- 중괄호의 대체 문구는 경로를 찾지 못하는 문맥에서도 문장이 깨지지 않게 할 때 사용한다.
- 활동의 값을 읽을 때에는 `activity=<ID>`를 지정하고 그 활동의 `getRollData().activity` 안에 경로가 존재하는지 확인한다.

## 자주 쓰는 롤 데이터 경로

다음 목록은 피트·아이템 설명에서 자주 쓰는 대표 경로다. 모든 액터·아이템 유형에 항상 존재하는 목록은 아니다.

### 액터 능력과 기본 수치

| 목적 | 경로 |
| --- | --- |
| 능력치 | `@abilities.str.value` 등 |
| 능력 수정치 | `@abilities.str.mod` 등 |
| 능력 기반 DC | `@abilities.str.dc` 등 |
| 숙련 보너스 | `@prof` |
| 고정 숙련 보너스 | `@prof.flat` |
| 캐릭터 전체 레벨 | `@details.level` |
| NPC 도전 등급 | `@details.cr` |
| 현재·최대 HP | `@attributes.hp.value`, `@attributes.hp.max` |
| 임시 HP | `@attributes.hp.temp` |

능력 식별자는 `str`, `dex`, `con`, `int`, `wis`, `cha`를 사용한다.

### 기술, 클래스, 자원

| 목적 | 경로 |
| --- | --- |
| 기술 총 보정 | `@skills.<기술 ID>.total` |
| 기술 수동값 | `@skills.<기술 ID>.passive` |
| 클래스 레벨 | `@classes.<클래스 식별자>.levels` |
| 주 자원 현재값 | `@resources.primary.value` |
| 주 자원 최대값 | `@resources.primary.max` |
| 주문 슬롯 현재값 | `@spells.spell1.value` 등 |
| 주문 슬롯 최대값 | `@spells.spell1.max` 등 |
| 상태 보유 여부 | `@statuses.<상태 ID>` |

기술·클래스·상태의 표시명이 아니라 실제 식별자를 확인한다. 클래스 식별자는 클래스 아이템의 Identifier 값과 일치해야 한다.

### 스케일 값

클래스, 서브클래스, 종족, 배경의 Scale Value Advancement는 다음 형태로 참조한다.

```text
@scale.<상위 아이템 식별자>.<스케일 값 식별자>
@scale.<상위 아이템 식별자>.<스케일 값 식별자>.number
@scale.<상위 아이템 식별자>.<스케일 값 식별자>.die
@scale.<상위 아이템 식별자>.<스케일 값 식별자>.faces
```

- 두 식별자는 화면 표시명이 아니라 각 문서에 저장된 Identifier다.
- 스케일 값이 주사위인지 숫자인지에 따라 하위 속성의 존재 여부가 달라진다.
- 경로를 추측하지 않고 해당 액터의 `getRollData()`에서 실제 생성값을 확인한다.

### 현재 아이템·활동 문맥

| 목적 | 경로 |
| --- | --- |
| 현재 아이템 사용 횟수 | `@item.uses.value` |
| 현재 아이템 최대 사용 횟수 | `@item.uses.max` |
| 주문 레벨 | `@item.level` |
| 클래스 아이템 레벨 | `@item.levels` |
| 현재 활동의 공격·피해 능력 수정치 | `@mod` |
| 업캐스트 등 기준 초과 단계 | `@scaling.increase` |
| 활동에서 소비한 히트 다이스 | `@consumed.hd` |

활동 전용 경로는 일반 설명을 렌더링하는 문맥에 항상 존재하지 않는다. 활동 수식에서 쓸 값과 `lookup activity=<ID>`로 표시할 값을 구분한다.

### 플래그

```text
@flags.<모듈 또는 기능이 제공한 경로>
```

`@flags.*`는 시스템·모듈·매크로가 필요에 따라 추가하는 임의 데이터다. 공식 공통 경로처럼 가정하지 않고 실제 롤 데이터에 존재하는 경우에만 사용한다.

## 데이터 문맥과 소유권

### 액터에 포함된 아이템

액터가 소유한 피트·아이템은 해당 액터의 능력치, 숙련, 클래스, 스케일 값을 참조할 수 있다. 컴펜디움 원본을 액터로 가져오면 별도 임베디드 아이템 복사본이 되므로 원본 컴펜디움 항목과 실시간으로 연결된다고 가정하지 않는다.

### 월드 또는 컴펜디움의 독립 아이템

소유 액터가 없는 독립 아이템은 액터 전용 경로를 해석할 문맥이 없을 수 있다. 이 경우 편집 화면에서 문법이 보이더라도 실제 액터에 넣은 뒤 결과가 달라질 수 있다.

### 클릭한 사용자와 데이터 소유자

설명 안 공식과 DC를 렌더링할 때 참조하는 값은 보통 설명을 소유한 액터·아이템의 데이터다. 링크를 클릭한 사용자의 캐릭터 값을 자동으로 대신 넣는다고 가정하지 않는다. 반대로 `[[/item 이름]]`의 실행 대상 선택은 선택 토큰이나 할당 액터의 영향을 받는다.

### 활동 자동 추론

`[[/attack]]`, `[[/check]]`, `[[/save]]`, `[[/damage]]`처럼 옵션을 생략하면 현재 아이템에서 첫 대응 활동을 찾는다.

- 대응 활동이 정확히 하나면 자동 추론을 사용할 수 있다.
- 대응 활동이 없으면 인리처가 변환되지 않을 수 있다.
- 대응 활동이 둘 이상이면 문장과 실제 활동이 어긋날 수 있으므로 `activity=<ID>`를 사용한다.
- 아이템을 복제·재작성한 뒤에는 활동 ID가 유지되는지 다시 확인한다.

## 피트·아이템 작성 예시

### 능력 기반 내성 DC

```text
대상은 [[/save ability=dex dc=@abilities.con.dc]]에 성공해야 합니다.
```

설명 소유 액터의 건강 기반 기능 DC를 민첩 내성 DC로 사용한다.

### 활동 기반 공격과 피해

```text
근접 무기 공격: [[/attack activity=RLQlsLo5InKHZadn]]. 명중 시 [[/damage activity=RLQlsLo5InKHZadn average]] 피해를 줍니다.
```

같은 공격 활동에서 공격과 피해를 가져온다. 실제 활동 ID로 교체해야 한다.

### 스케일 값 기반 피해

```text
추가 피해는 [[/damage formula="@scale.<상위 식별자>.<스케일 식별자>" type=radiant]]입니다.
```

꺾쇠괄호 부분은 예시 자리표시자다. 실제 Identifier를 확인하지 않은 상태로 저장하지 않는다.

### 다른 피트나 아이템 실행

```text
이 효과를 사용하면 [[/item 보호막 전개 activity="보호막 활성화"]]를 사용합니다.
```

대상 액터가 같은 이름의 아이템과 활동을 소유하는지 확인한다.

### 이름을 문장에 재사용

```text
[[lookup @name]]{이 크리처}는 턴을 시작할 때 효과를 받습니다.
```

액터 이름을 읽을 수 없으면 `이 크리처`를 사용한다.

## 작성 결정 순서

1. 설명에서 필요한 기능이 굴림, 데이터 표시, 아이템 사용 중 무엇인지 구분한다.
2. D&D5e 활동에 이미 공격·피해·판정·내성 정보가 있으면 활동 연결을 우선 검토한다.
3. 단일하고 독립적인 공식만 필요할 때 직접 공식을 사용한다.
4. 동적 값은 실제 `getRollData()`에서 경로를 확인한다.
5. 복수 활동이면 대상 활동 ID를 지정한다.
6. 이름·ID·UUID 중 배포 범위에 맞는 참조 방식을 선택한다.
7. 설명을 저장한 뒤 편집기가 문법을 링크나 값으로 변환했는지 확인한다.
8. 액터가 소유한 실제 피트·아이템에서 소유자 데이터와 활동 연결을 확인한다.

## 롤 데이터 확인 방법

현재 선택한 토큰의 액터 롤 데이터는 개발자 도구 콘솔에서 다음과 같이 확인할 수 있다.

```js
console.log(canvas.tokens.controlled[0]?.actor?.getRollData());
```

선택한 토큰이 소유한 특정 아이템은 다음과 같이 확인할 수 있다.

```js
const actor = canvas.tokens.controlled[0]?.actor;
const item = actor?.items.getName('피트 또는 아이템 이름');
console.log(item?.getRollData());
```

특정 활동의 롤 데이터는 다음과 같이 확인할 수 있다.

```js
const actor = canvas.tokens.controlled[0]?.actor;
const item = actor?.items.getName('피트 또는 아이템 이름');
const activity = item?.system.activities.get('활동 ID');
console.log(activity?.getRollData());
```

- 콘솔 출력은 현재 월드·액터·아이템·모듈 상태의 실제 결과다.
- 오른쪽 클릭 후 데이터 내보내기로 얻는 JSON에는 런타임 파생값이 없을 수 있다.
- 사용자에게 콘솔 실행을 안내할 때에는 대상 토큰 선택 여부와 GM 권한 필요 여부를 함께 설명한다.

## 오류와 금지 사항

- 확인되지 않은 `@...` 경로를 이름만 보고 만들지 않는다.
- D&D5e `5.2.4`에서 확인하지 않은 상위 버전 전용 경로를 가져오지 않는다.
- 레거시 예시의 `@data...` 또는 저장 JSON의 `system...` 경로를 현재 롤 데이터 경로로 자동 치환하지 않는다.
- `activity`와 직접 공식을 동시에 명시하지 않는다.
- 복수 활동이 있는 아이템에서 빈 `[[/attack]]`, `[[/save]]`, `[[/damage]]`를 무조건 사용하지 않는다.
- `[[/damage average]]`처럼 활동 자동 추론을 쓰는 문법을 고정 평균 숫자로 바꾸지 않는다.
- 피해 유형·능력·기술·도구 ID를 한글 표시명에서 추측하지 않는다.
- 이름 참조가 번역이나 이름 변경 뒤에도 유지된다고 가정하지 않는다.
- 컴펜디움 원본과 액터에 포함된 아이템 복사본이 실시간 동기화된다고 가정하지 않는다.
- 문법이 텍스트로 남거나 `@경로`가 그대로 표시되면 성공으로 처리하지 않는다.
- 공식 문서에 없는 명령, UUID, 활동 ID를 임의로 생성하지 않는다.
