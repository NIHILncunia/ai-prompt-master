# 세션 하이라이트 마스터 프롬프트

## 입력 자료 우선순위

- 캐릭터 외형: 아래 캐릭터 이미지 탐색 규칙에 따라 찾은 Character Reference를 우선한다.
- 사건과 장면 핵심: Highlight Card 또는 세션 로그 요약을 우선한다.
- 장소와 배경: 풍경 이미지와 `scenic_prompt.yml`을 우선한다.

## 캐릭터 이미지 탐색 규칙

등장 PC·NPC·몬스터의 외형 자료는 아래 순서로 찾는다.

1. Highlight Card의 `character_type`과 인물명으로 대상 자산 폴더를 정한다. PC는 `TRPG 데이터/7. PC/<대상>/`, NPC는 `TRPG 데이터/6. NPC/<대상>/`, 몬스터는 `TRPG 데이터/10. 몬스터/<유형>/<대상>/`이다.
2. 대상 폴더의 `<대상> 레퍼런스 시트 Vn.webp`를 최우선으로 찾는다.
3. 레퍼런스 시트가 없으면 같은 대상 폴더의 전신·초상화·토큰만 대체 자료로 사용한다.
4. 대상 또는 유형이 불명확하면 임의로 다른 폴더를 탐색해 확정하지 않고, Highlight Card에 확인 필요로 남긴다.

파일명은 Highlight Card에 기록된 인물명과 분류를 기준으로 확인하며, 확장자와 `레퍼런스 시트` 같은 접미사를 고정하지 않는다. 동명이인 또는 대상 동일성이 불명확하면 이미지를 임의로 선택하지 않고 마스터에게 확인한다.

## 기본 산출물

- 시네마틱 단일 장면을 기본으로 한다.
- 중심 인물은 보통 1~3명을 권장한다.
- 실제 사건의 핵심 감정과 행동을 장면 하나로 압축한다.

## 조립

대상·스타일·필요 시 레이아웃을 선택하되, 입력 자료의 정체성과 사건 사실을 훼손하지 않는다.

## 그림체 기준

- 확인된 캐릭터 레퍼런스가 있으면 별도 스타일 변경 지시가 없는 한 서로 호환되는 모든 제공 이미지의 그림체와 마감을 세션 하이라이트에도 보존한다.
- 핵심 등장인물의 레퍼런스 그림체가 서로 충돌하면 임의의 중간 화풍으로 혼합하지 않고 마스터에게 장면 전체에 사용할 단일 기준 그림체 하나를 확인한다.
- 기준 캐릭터 이미지가 없으면 마스터가 지정한 화풍을 사용한다. 화풍 지정도 없으면 요구사항 확인 단계에서 확인한다.
- `애니 페인팅` 또는 `붓터치 반실사`로 변경하라는 명시가 있으면 캐릭터 레퍼런스는 디자인 기준으로만 사용하고 스타일 앵커보다 먼저 참조 자리를 배정한다.
- 정식 스타일 적용 시 장면의 지배적 프레이밍을 얼굴 중심 또는 전신·행동 중심으로 분류하고, 그림체 적용 방식·선택 정식 스타일·디자인 기준 이미지 수·도구 전체 이미지 참조 한도와 함께 `../라이브러리/스타일/정식 스타일 호출 규칙.md`에 전달한다.
- 실제 생성에는 중앙 호출 규칙이 반환한 앵커 목록을 사용한다. 여러 캐릭터 레퍼런스가 참조 예산을 차지해 앵커를 줄이면 제외한 모든 활성 앵커의 전체 파일명과 각 제외 사유를 요구사항 확인서에 기록한다.
- 스타일 앵커에서는 그림체와 역할만 참조하며 앵커의 인물·의상·팔레트·포즈·카메라·배경·장면 구성을 가져오지 않는다.

## 로그 분석·설계 장면·설계 맵 연계

## 세션 분석 연계 입력 우선순위

세션 하이라이트 이미지 생성은 다음 연결을 이해해야 한다.

`Hxx → Pxx → scene_uuid → map_uuid`

- `Hxx`: 3번 로그 분석의 기본 하이라이트 선정 결과.
- `Pxx`: 실제 플레이 장면.
- `scene_uuid`: 8번 세션 제작의 영구 설계 장면 UUID.
- `map_uuid`: 8번 세션 제작의 영구 설계 맵 UUID.

실제 생성에는 2번 로그 하이라이트 추출이 정밀화한 Highlight Card를 우선 입력으로 사용한다. 분석 연계 Highlight Card가 있으면 그 안의 `analysis_highlight_id`, `play_scene_refs`, `design_scene_refs`, `design_map_refs`를 따라 근거를 확인한다.

- 사건의 실제 발생 내용은 원본 로그와 `Pxx`를 우선한다.
- 이미지화할 순간의 선정은 `Hxx`와 Highlight Card를 우선한다.
- 배경의 설계 공간은 `design_map_refs[].map_uuid`가 `confirmed`일 때 해당 설계 맵 정본을 우선한다.
- 인물 외형은 캐릭터 레퍼런스를 우선한다.
- `design_scene_refs[].scene_uuid`, `design_map_refs[].map_uuid`, `fvtt_scene_id`를 서로 다른 식별자로 취급한다.
- FVTT Scene이 없어도 확정된 설계 맵이 있으면 배경 근거로 사용할 수 있다.
- 설계 맵이 없거나 `unavailable / unmapped / uncertain`이면 로그의 환경 단서와 별도 풍경·Scene Manifest 자료를 사용하고 임의 확정하지 않는다.
