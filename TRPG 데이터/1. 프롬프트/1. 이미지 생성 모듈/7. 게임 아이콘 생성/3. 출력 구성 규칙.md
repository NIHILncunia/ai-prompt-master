# 출력 구성 규칙

## 1. 기본 출력 계약

- 게임 아이콘 다중 생성은 **3×3 슬롯 시트**를 기본 단위로 사용한다.
- 3×3 시트는 생성 도구가 반환한 **원본 이미지 해상도와 셀 구성**을 보존한다.
- 슬롯 512×512, 시트 1536×1536 같은 고정 픽셀 규격을 후처리로 강제하지 않는다.
- 생성된 3×3 이미지를 자동으로 슬롯 분할·크롭·리사이즈·재합성하지 않는다.
- 낱개 아이콘 이미지는 자동 생성·저장하지 않는다. 마스터가 명시적으로 개별 추출을 요청한 경우에만 별도 파생 작업으로 처리하며 원본 3×3 시트는 그대로 보존한다.

## 2. 슬롯 채우기 규칙

- 실제 아이콘은 좌상단부터 우측으로, 한 줄이 끝나면 다음 줄로 내려가는 **행 우선(row-major)** 순서로 채운다.
- 1~9개 요청은 3×3 시트 1장을 사용한다. 남는 슬롯이 있으면 순수 검정 빈 슬롯으로 둔다.
- 9개를 초과하면 같은 생성 배치 안에서 3×3 시트를 여러 장 사용한다.
  - 1~9개: 1장
  - 10~18개: 2장
  - 19~27개: 3장
  - 이후도 9개 단위로 추가

## 3. 배경 규격

- 실제 아이콘 슬롯은 피사체의 속성·주색·명도·발광과 조화되는 **비투명 유색 배경색 또는 비투명 유색 추상 배경면**을 셀 전체에 채운다.
- 실제 아이콘 슬롯의 순수 검정·거의 검정·차콜 기본 배경은 금지한다.
- 실제 아이콘이 없는 빈 슬롯만 순수 검정으로 둔다.
- 투명 픽셀·알파 홀·무채움 영역·의도하지 않은 빈 캔버스를 만들지 않는다.

## 4. 생성본 검수와 정본 판정

다중 생성은 다음 순서로 처리한다.

1. 3×3 시트 생성
2. 실제 이미지 전체를 기준으로 3×3 구조와 슬롯 수 확인
3. 행 우선 순서와 요청 내용 대응 확인
4. 슬롯 경계 침범·잘림·프레임·배경·텍스트 여부 확인
5. 검수용 축소 미리보기에서 128×128·64×64 상당 판독성 확인
6. 구조가 정상인 생성 이미지를 **변형 없이 최종 정본으로 채택**
7. 배치 저장 폴더에 시트 원본과 MD 인덱스 저장

- 이미지 크기가 예상과 다르다는 이유만으로 분할·리사이즈·재합성하지 않는다.
- 셀 크기가 균등하지 않거나 경계가 미세하게 어긋난 경우도 원본 시트를 재구성해 고치지 않는다. 실제 사용에 문제가 없으면 그대로 채택하고, 시각적/구조적 실패면 재생성 권고로 판정한다.
- 새 이미지 재생성은 공통 이미지 승인 절차를 다시 거친다.

## 6. 배치 폴더와 파일명

배치가 한 번 실행될 때마다 해당 상위 폴더 아래에 별도 폴더를 만든다.

### 배치 폴더명

`<YYYY MMDD> <상위 폴더명> <NN>`

예:

- `2026 0912 스킬 아이콘 01`
- `2026 0912 스킬 아이콘 02`
- `2026 0912 아이템 아이콘 01`

같은 날짜·같은 상위 폴더 안에서 `NN`은 `01`부터 2자리 순번으로 증가한다. 날짜가 바뀌거나 상위 분류가 달라지면 각각 `01`부터 다시 시작한다. 기존 폴더가 있으면 가장 큰 번호 다음 번호를 사용한다.

### 배치 내부 문서

- 반드시 배치 폴더와 같은 이름의 Markdown 문서를 1개 둔다.
- 예: `2026 0912 스킬 아이콘 01.md`
- 문서에는 최소한 다음을 기록한다.
  1. 날짜·분류·배치 번호
  2. 배치 목적과 요청 요약
  3. 저장된 이미지 파일 전체 목록
  4. 각 3×3 시트의 슬롯별 내용과 순서
  5. 검수 결과와 실패·부분 통과·채택 여부
  6. 정식 앵커 승격이나 후속 사용 등 연계 정보

### 이미지 파일명

- 한 배치에 시트가 1장뿐이면 `<배치명>.png`를 사용한다.
- 한 배치에 시트가 여러 장이면 `<배치명>-1.png`, `<배치명>-2.png`, `<배치명>-3.png`처럼 순번을 붙인다.
- 여러 장일 때는 첫 시트에도 반드시 `-1`을 붙여 전체 묶음의 번호 체계를 일관되게 유지한다.

## 7. 저장 시점

- 생성 결과가 지속 보관 대상이면 생성 직후 해당 날짜·분류의 다음 배치 번호를 판정하고 배치 폴더를 만든다.
- 시트 원본과 배치 MD를 Drive에 저장한다.
- 자가검수 결과가 나온 뒤 같은 MD를 갱신하여 검수 판정과 후속 사용 정보를 반영한다.
- 재생성으로 새 이미지가 나온 경우 기존 승인 상태를 재사용하지 않는다. 같은 논리적 배치의 수정본으로 유지할지 새 배치로 볼지는 현재 마스터 지시를 우선하며, 별도 지시가 없으면 새 생성 승인을 받은 결과는 새 배치로 기록한다.

## 8. 단일 생성

- 단일 아이콘 요청은 독립 1:1 이미지 1개를 기본으로 하며 3×3 시트로 강제 변환하지 않는다.
- 단일 결과를 지속 저장할 때도 스킬/아이템 분류에 맞는 배치 폴더와 동명 MD를 사용한다.
- 단일 이미지가 1개이면 `<배치명>.png`로 저장한다.

## 9. 최종 검증

1. 다중 결과가 의도한 3×3 구조인가.
2. 요청 수량과 슬롯 내용이 일치하는가.
3. 실제 아이콘이 행 우선 순서로 배치되었는가.
4. 빈 슬롯만 순수 검정인가.
5. 실제 슬롯의 유색 비투명 배경 계약을 지켰는가.
6. 인접 슬롯의 피사체·이펙트가 심각하게 침범하지 않는가.
7. 64×64 상당 축소에서 핵심 개념이 읽히는가.
8. 자동 분할·리사이즈·재합성·낱개 저장을 수행하지 않았는가.
9. 올바른 `22. 아이콘 생성` 하위 배치 폴더에 저장했는가.
10. 배치 폴더명·MD명·이미지명이 명명 규칙과 일치하는가.
11. 여러 시트라면 `-1`, `-2` 순번과 MD의 시트 목록이 일치하는가.
