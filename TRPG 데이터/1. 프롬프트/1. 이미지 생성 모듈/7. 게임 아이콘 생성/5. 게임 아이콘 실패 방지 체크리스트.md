# 게임 아이콘 실패 방지 체크리스트

## 사용 방법

최종 영어 프롬프트 공개 전과 생성 결과 검수 때 각각 확인한다. 문서·후처리로 고칠 수 있는 결함은 즉시 수정한다. 이미지 재생성이 필요한 결함만 수정 요구사항 확인서와 최종 영어 프롬프트를 다시 공개하고 마스터 승인 후 재생성한다.

## A. 라우팅·스타일

- [ ] 게임 UI용 아이콘 이미지 요청이다.
- [ ] 캐릭터 포트레이트·완성형 VTT 토큰·풍경·배틀맵·하이라이트가 아니다.
- [ ] 비아이템 스킬·상태 계열이면 정식 `게임 스킬 아이콘` 계약을 적용했다.
- [ ] 역할에 맞는 정식 게임 스킬 앵커를 최소 1장, 필요할 때만 최대 2장 선택했다.
- [ ] 일반 `붓터치 반실사`·`애니 페인팅`·`라인 웹툰` 앵커를 자동 혼합하지 않았다.
- [ ] 아이템·무기·장비라면 현재 아이템 계약과 해당 개발 상태를 구분했다.
- [ ] 무기 아이콘에서 속성·마법·희귀도·특수 효과가 명시되지 않았다면 일반 무기로 해석했다.
- [ ] 일반 무기에 화염·번개·마력 오라·과도한 발광을 자동 부여하지 않았다.
- [ ] 일반 무기 본체를 실사·사진풍으로 낮추지 않고 게임 아이템풍의 선명한 그래픽-페인터리 렌더링을 유지했다.
- [ ] 속성·마법 무기라면 효과를 본체 구조보다 후순위의 국소 효과로 제한했다.
- [ ] 대시·회피·도약·발놀림은 `06. 물리 기동 앵커.png`, 순간이동·위상전이는 `07. 공간 전이 앵커.png`로 분리했다.
- [ ] 속박·봉인·침묵·행동 차단은 `08. 제어·속박 앵커.png`, 저주·공포·정신 약화·오염은 `09. 저주·정신 약화 앵커.png`로 분리했다.

### A-1. 사용자 입력 의미 변환

- [ ] 사용자의 원문을 그대로 번역·전사하지 않고 의미 시드로 해석했다.
- [ ] 기능 역할, 핵심 행동/변화, 방향성, 강도, 속성/재질, 핵심 상징을 분리한 뒤 시각 언어로 다시 조립했다.
- [ ] 신체 손상·고어·잔혹 표현이 최종 프롬프트에 직접 남아 있지 않다.
- [ ] 필요한 공격성·위력은 충격파, 균열, 추상 파편, 에너지 밀도, 궤적, 압축·폭발·흡수·속박 같은 비신체적 효과로 보존했다.
- [ ] 사용자 문장의 서사적 장면 전체를 재현하지 않고 64×64에서 읽히는 단일 기호로 압축했다.
- [ ] 원소, 색, 방향, 무기 종류, 상징물처럼 실제 디자인에 필요한 명시 정보는 임의로 버리지 않았다.

## B. 캔버스·중심 대상

- [ ] 개별 아이콘은 1:1이다.
- [ ] 한 슬롯에 핵심 개념이 하나다.
- [ ] 피사체가 대체로 캔버스의 70~85% 안에서 읽힌다.
- [ ] 피사체 내부 안전 여백은 유지하되 최종 시트 셀 사이에는 어떤 거터도 만들지 않는다.
- [ ] 끝부분·불꽃·파편·무기 날·장축 끝점이 잘리지 않는다.
- [ ] 캐릭터 전신이나 복잡한 전투 장면이 핵심을 대체하지 않는다.
- [ ] 긴 물체와 투사체는 방향과 끝점이 64×64에서도 읽힌다.

## C. 프레임

- [ ] 아이콘 프레임·원형 테두리·배지 림·카드 베젤이 없다.
- [ ] 캔버스 외곽을 따라 닫힌 발광 링이 없다.
- [ ] 마법진이나 고리가 있다면 핵심 효과이며 외곽 UI 프레임이 아니다.
- [ ] VTT 토큰 프레임이 없다.

## D. 배경

- [ ] 모든 실제 아이콘 슬롯은 대상 유형에 맞는 비투명 배경면으로 캔버스 끝까지 완전히 채워졌다.
- [ ] 순수 검정 배경은 다중 3×3의 빈 슬롯에서만 사용했다.
- [ ] 스킬·상태 계열은 속성·주색·명도·발광과 조화되는 유색 추상 배경을 사용했고 순수 검정·거의 검정·차콜 기본 배경을 쓰지 않았다.
- [ ] 일반 무기는 **회색조 배경만** 사용했고 청색·갈색·녹색·보라색 등 배경 색조가 남아 있지 않다.
- [ ] 효과가 존재하는 무기는 **회색조 배경을 사용하지 않았고**, 명시된 효과와 조화되는 비회색 유색 배경을 사용했다.
- [ ] 일반 무기와 효과 무기는 배경·효과만 다르고 무기 본체의 게임 아이템풍 그림체와 디자인 품질은 같은 계열로 유지된다.
- [ ] 아이템 계열은 피사체 대비에 맞춘 흐린 색면·그라데이션·국소 안개 중 필요한 처리만 사용했다.
- [ ] 풍경·바닥·방·탁자·벽·하늘 등 환경 장면이 없다.
- [ ] 투명 픽셀·알파 홀·무채움 영역·투명 체크무늬가 없다.
- [ ] 같은 색 계열의 피사체와 배경은 명도·채도·림라이트로 분리했다.

## E. 재질·효과·판독성

- [ ] 필요한 금속·유리·가죽·목재·돌·보석·에너지 재질이 서로 구분된다.
- [ ] 모든 부분이 동일하게 발광하지 않는다.
- [ ] 전역 bloom과 과도한 렌즈 플레어가 없다.
- [ ] 연기·안개·파티클이 핵심 실루엣을 가리지 않는다.
- [ ] 신성·광휘 계열의 내부 형태가 백색 과노출로 사라지지 않는다.
- [ ] 128×128 및 64×64에서 실루엣·방향·주색이 유지된다.

## F. 텍스트·UI

- [ ] 텍스트·숫자·라벨·로고·워터마크가 없다.
- [ ] 수량 숫자나 등급 글자를 이미지 내부에 넣지 않았다.
- [ ] 완성된 모바일 앱 버튼이나 슬롯 UI로 보이지 않는다.

## G. 다중 패키징·저장

- [ ] 요청 수량과 실제 아이콘 수량이 일치한다.
- [ ] 다중 출력은 3×3 시트 단위다.
- [ ] 실제 아이콘은 좌상단부터 행 우선으로 배치했다.
- [ ] 9개 초과 시 같은 배치에서 추가 3×3 시트를 사용했다.
- [ ] 실제 아이콘이 없는 슬롯만 순수 검정이다.
- [ ] 생성된 3×3 시트를 자동 분할·크롭·리사이즈·재합성하지 않았다.
- [ ] 512×512 슬롯 또는 1536×1536 시트를 후처리로 강제하지 않았다.
- [ ] 낱개 아이콘 파일을 자동 저장하지 않았다.
- [ ] 정본은 `TRPG 데이터/22. 아이콘 생성/스킬 아이콘` 또는 `TRPG 데이터/22. 아이콘 생성/아이템 아이콘` 아래의 배치 전용 폴더에 저장했다.
- [ ] 배치 폴더명이 `<YYYY MMDD> <상위 폴더명> <NN>` 형식이다.
- [ ] 배치 폴더 내부에 동명의 `.md`가 있다.
- [ ] 시트 1장이면 `<배치명>.png`, 여러 장이면 `<배치명>-1.png`, `<배치명>-2.png` 형식이다.
- [ ] MD에 모든 이미지 파일과 시트별 3×3 슬롯 내용·검수 결과가 정리되어 있다.

## H. 최종 프롬프트 필수 요소

- [ ] `1:1 square image` 또는 동등한 정사각형 계약이 있다.
- [ ] 단일 중심 대상과 명확한 실루엣이 있다.
- [ ] 실제 슬롯 전체를 채우는 비투명 배경 계약이 있다.
- [ ] 스킬·상태 계열에는 pure black / near-black / charcoal default background 금지가 있다.
- [ ] 일반 무기 테스트에는 **grayscale background only**, no automatic magic effects, no photorealistic weapon rendering이 명시되어 있다.
- [ ] 효과 무기 테스트에는 **non-grayscale colored background**, localized effects, effects remain subordinate to weapon structure가 명시되어 있다.
- [ ] 두 분기 모두 동일한 stylized fantasy RPG inventory icon rendering을 유지한다고 명시되어 있다.
- [ ] 프레임·테두리·배지·UI 링 금지가 있다.
- [ ] 텍스트·숫자·로고 금지가 있다.
- [ ] 풍경·바닥·복잡한 환경 배경 금지가 있다.
- [ ] 과도한 bloom·파티클·미세 텍스처 금지가 있다.

## 대표 실패 수정

### 일반 무기가 모두 마법 무기처럼 보임

속성·마법·특수 효과 지시가 없다면 화염·번개·오라·마력 소용돌이·과도한 보석 발광을 제거한다. 배경을 **순수 회색조**로 되돌리고 금속·목재·가죽·뼈 같은 재질과 무기 구조를 주피사체로 돌린다. 단, 본체 그림체까지 사실적으로 낮추지 말고 게임 인벤토리 아이콘다운 선명한 그래픽-페인터리 디자인을 유지한다.

### 마법 효과가 무기 본체를 가림

효과 면적과 밝기를 줄이고 검날·룬·보석·마석·총구·지팡이 머리 등 발생 지점 근처로 제한한다. 무기 종류 실루엣과 장축 끝점이 먼저 읽혀야 한다.

### 검정 배경에 피사체가 묻힘

스킬·상태 계열은 피사체와 대비되는 유색 색면으로 바꾸고 명도·채도·선택적 림라이트로 외곽을 분리한다. 일반 무기는 순수 검정 대신 피사체와 명도 차가 나는 **회색조 배경만** 사용한다. 검정은 빈 슬롯 표식으로만 사용한다.

### 스킬 아이콘이 전투 장면이 됨

행동 전체를 서술하지 말고 결정적 상징 하나로 압축한다. 캐릭터 전신 대신 손·무기 일부·눈·심장·발자국·핵심 원소 효과처럼 작은 UI 크기에서도 읽히는 단일 기호를 사용한다.

### 사용자 원문의 과격한 표현이 프롬프트에 그대로 남음

원문을 삭제한 뒤 효과의 성질만 다시 추출한다. `신체 손상 표현 → 충격·관통·절단·압박·붕괴·흡수·속박·소멸`처럼 기능 언어로 바꾸고, 이를 균열·충격파·추상 파편·에너지 궤적·끊어진 선·흡수 흐름 같은 아이콘 기호로 재조립한다.

### 장축 투사체가 뭉개짐

진행 축과 끝점을 분명히 하고 `02. 장축 투사체 앵커.png`를 조건부 참조한다. 배경 이펙트를 줄이고 주축 주변에 명도 대비를 확보한다.

### 물리 기동이 공격 투사체처럼 보임

`06. 물리 기동 앵커.png`를 사용하고 발·부츠·발자국·잔상·위치 변화 같은 **자기 이동 단서**를 남긴다. 순수 에너지 덩어리나 창끝형 실루엣이 화면을 가로지르면 공격 투사체로 오인될 수 있으므로 피한다.

### 순간이동이 일반 대시처럼 보임

`07. 공간 전이 앵커.png`를 사용하고 서로 분리된 두 위치, 전이점, 공간 왜곡처럼 **위치 사이의 불연속성**을 보여준다. 발놀림과 속도선만으로 해결하지 않는다.

### 제어와 저주가 같은 디버프 아이콘으로 수렴함

행동 제한·속박·봉인은 `08. 제어·속박 앵커.png`, 상태 변질·공포·정신 약화·오염은 `09. 저주·정신 약화 앵커.png`를 우선한다. 제어는 수렴·압박·차단, 저주는 비대칭 변질·오염·불길한 핵심 상징을 중심으로 분리한다.

### 다중 생성이 3×3 구조를 지키지 못함

후처리 분할·재합성으로 정본을 만들지 않는다. 원본 생성 시트 자체에서 3×3 구조와 슬롯 대응이 실패했다면 시각적 실패로 판정하고 재생성 권고로 넘긴다. 새 생성은 공통 승인 절차를 다시 거친다.

### 배치 저장 폴더 또는 파일명이 누락됨

`22. 아이콘 생성/<스킬 아이콘|아이템 아이콘>/<YYYY MMDD> <상위 폴더명> <NN>/` 구조를 사용한다. 같은 이름의 MD를 만들고, 시트 1장은 `<배치명>.png`, 여러 장은 `<배치명>-1.png`, `<배치명>-2.png`로 정리한다.
