# 게임 아이콘 마스터 프롬프트

## 기본 계약

- 기본 캔버스 1:1
- 다중 생성은 **3×3 슬롯 시트**를 기본 단위로 사용한다.
- 3×3 시트는 생성 도구가 반환한 원본 해상도와 구성을 보존하며, 슬롯 512×512 또는 시트 1536×1536을 후처리로 강제하지 않는다.
- 다중 생성에서 실제 아이콘은 좌상단부터 우측으로, 한 줄이 끝나면 다음 줄로 내려가는 행 우선 순서로 채운다.
- 비어 있는 슬롯은 **순수 검정 배경**으로 둔다.
- 실제 아이콘 슬롯은 대상 유형에 맞는 **비투명 배경면**으로 캔버스 전체를 채운다.
  - 스킬·상태·UI 아이콘: 속성·주색·명도·발광과 조화되는 유색 추상 배경을 기본으로 하며 순수 검정·거의 검정·차콜 기본 배경을 금지한다.
  - 일반 아이템은 해당 아이템 계약에 맞는 비투명 배경을 사용한다.
  - **일반 무기: 회색조(grayscale) 비투명 추상 배경을 고정한다. 청색·갈색·녹색·보라색 등 색조가 느껴지는 배경을 사용하지 않는다.** 재질·실루엣 판독을 우선한다.
  - **효과가 존재하는 무기: 회색조 배경을 사용하지 않는다.** 명시된 속성·마법 성질에 맞는 비회색 유색 배경과 국소 효과를 사용한다.
- 9개를 초과하는 다중 생성은 **3×3 시트를 여러 장**으로 나누어 저장한다.
- 생성된 3×3 시트의 슬롯 구조가 정상이라면 해당 이미지 자체를 최종 정본으로 사용하고 자동 분할·리사이즈·재합성을 하지 않는다.
- 단일 핵심 개념
- 64×64에서도 식별 가능한 실루엣
- 완성형 VTT 토큰용 프레임 없음
- 아이템·소비품·재료·무기·방어구·장비는 공통 비투명 배경 계약을 사용하되 **속성·마법 효과가 명시되지 않은 일반 무기에는 마법 효과를 자동 부여하지 않는다.**
- 일반 무기는 철·강철·목재·가죽·뼈 등 재질과 구조가 먼저 읽히도록 **명도 차만 있는 회색조 추상 배경**을 사용한다. 일반 무기 배경은 색상 대비가 아니라 명도 대비로 본체를 분리한다.
- 효과가 존재하는 무기는 사용자가 속성·마법·특수 효과를 명시했거나 테스트 목적상 해당 분기를 선택한 경우에만 활성화한다. 이 분기는 **회색조가 아닌 속성색 배경**과 룬·보석·국소 발광·원소 효과를 사용할 수 있다.
- 무기 렌더링은 실사·사진풍이 아니라 **선명하고 과감한 형태, 장식적 판타지 디자인, 그래픽-페인터리 채색을 가진 게임 인벤토리 아이콘 스타일**을 사용한다. 효과가 없는 일반 무기도 같은 스타일 품질과 디자인 밀도를 유지한다.
- 아이템 배경에는 부드러운 색면, 흐린 그라데이션, 가우시안 블러, 절제된 국소 안개를 허용하되 풍경·바닥·실내 맥락은 금지
- 스킬·상태·UI 아이콘은 각 아이콘의 속성·효과와 조화되는 유색 비투명 추상 배경을 셀 전체에 채운다. 순수 검정·거의 검정·검정/차콜을 기본 배경으로 사용하는 것을 금지하고 컷아웃 친화적 가장자리 계약을 유지한다.

## 사용자 입력 해석 계약

- 사용자의 문장은 최종 이미지 프롬프트 원문이 아니라 **의도와 느낌을 파악하기 위한 의미 시드**로 취급한다.
- 사용자의 문장을 그대로 번역·전사하거나 문장 구조를 보존해 최종 영어 프롬프트에 삽입하지 않는다.
- 먼저 `기능 역할 → 행동/변화 → 방향성 → 강도 → 속성/재질 → 핵심 상징 → 분위기/색감`으로 의미를 분해한 뒤, 정식 게임 스킬 아이콘 시각 언어로 다시 조립한다.
- 과격한 신체 손상·고어·잔혹 묘사처럼 생성 실패를 유발할 수 있는 표현은 그 자체를 시각화하지 않고 **충격, 파괴력, 관통감, 압박, 붕괴, 흡수, 속박, 소멸** 같은 비신체적 효과 언어로 변환한다.
- 예를 들어 `몸을 분쇄한다`는 문장을 직접 사용하지 않고 `압도적인 충격 + 방사형 균열 + 파쇄되는 추상 물질 + 강한 충돌 에너지`처럼 재구성한다.
- `심장을 꿰뚫는다`, `목을 벤다`, `뼈를 박살낸다` 같은 표현도 인체 손상을 재현하지 않고 각각 `정밀 관통`, `결정적 참격`, `무거운 파괴 충격`의 시각적 성질만 가져온다.
- 사용자가 제공한 원소, 무기 종류, 색, 방향, 상징물처럼 실제 디자인에 필요한 구체 정보는 보존하되, 서사적 문장·욕설·과장 표현·불필요한 대상 묘사는 버린다.
- 안전화는 의미를 약화시키는 작업이 아니다. 공격의 세기와 위협도는 `에너지 밀도, 궤적, 균열, 충격파, 명암 대비, 파편, 압축/폭발 형태`로 충분히 강하게 유지한다.

## 출력 구성

- 단일 아이콘
- 개별 아이콘 세트
- 격자 시트
- 스프라이트 시트

단일 아이콘은 레이아웃 문서를 불러오지 않는다. 다중 배열에서만 필요한 레이아웃을 조립한다.
다중 출력은 **생성된 3×3 시트를 그대로 검수·보존**한다. 검수 항목은 3×3 구조, 요청 수량, 행 우선 슬롯 순서, 빈 슬롯 처리, 경계 침범, 배경 계약, 64×64 판독성이다. 픽셀 크기가 예상과 달라도 구조가 정상이면 자동 분할·리사이즈·재합성을 하지 않는다.
구조 자체가 실패한 경우 후처리로 고치지 않고 재생성 권고로 판정하며, 새 생성은 공통 승인 절차를 다시 거친다. 낱개 아이콘 추출은 마스터가 별도로 요청한 후속 작업에서만 수행한다.

## 배치 저장 계약

- 정식 배치 저장 루트: `TRPG 데이터/22. 아이콘 생성`
- 스킬 아이콘 상위 폴더: `TRPG 데이터/22. 아이콘 생성/스킬 아이콘`
- 아이템 아이콘 상위 폴더: `TRPG 데이터/22. 아이콘 생성/아이템 아이콘`
- 배치 폴더명: `<YYYY MMDD> <상위 폴더명> <NN>` (예: `2026 0912 스킬 아이콘 01`)
- 같은 날짜·같은 상위 폴더에서는 `01`, `02`, `03`처럼 2자리 번호를 순차 증가시킨다.
- 배치 내부 MD: `<배치명>.md`
- 이미지 1장: `<배치명>.png`
- 이미지 여러 장: `<배치명>-1.png`, `<배치명>-2.png`, ...
- MD에는 배치 목적, 생성 이미지 목록, 각 시트의 3×3 슬롯 내용, 검수 결과, 채택·후속 사용 정보를 기록한다.
- 정식 스타일 앵커와 개발용 개별 슬롯 이미지는 이 배치 저장소와 별개로 각 스타일·개발 경로에서 관리한다.

## 그림체 적용 경계

- 게임 아이콘 기능은 일반 인물·환경 정식 스타일의 기능성 예외다.
- 스킬·주문·액션·특성·버프·디버프·상태·속성·자원 등 비아이템 아이콘은 기능 예외 내부의 정식 `게임 스킬 아이콘` 스타일을 기본 적용한다.
- 정식 계약은 `../라이브러리/스타일/게임 스킬 아이콘.md`, 역할별 앵커는 `../라이브러리/견본/게임 스킬 아이콘/`를 사용한다.
- 아이템 계열의 신규 스타일 후보는 `게임 아이템 아이콘 스타일` 하나로 개발하며, 개발 정본은 `TRPG 데이터/20. 그림 스타일 분석/게임 아이템 아이콘 스타일/`에 둔다. 스타일 최상위 폴더에는 `dev_`를 붙이지 않고 내부 개발 자산에만 `dev_`를 사용한다.
- `게임 아이템 아이콘 스타일`은 정식 승격 전까지 런타임 자동 호출 대상이 아니다. 승격 전 아이템 아이콘은 이 문서의 공통 아이템 배경·패키징 계약을 사용한다.
- 무기 아이콘 개발에서는 `일반 무기`와 `효과가 존재하는 무기`를 같은 상위 스타일 안의 별도 검증 축으로 다룬다. 일반 무기가 기본값이며, 사용자가 별도 효과를 명시하지 않으면 화염·번개·오라·광휘를 추가하지 않는다. 일반 무기는 회색조 배경, 효과 무기는 비회색 속성 배경을 사용하되 **두 분기의 무기 본체 그림체와 디자인 품질은 동일하게 유지한다.**
- 1:1 구성, 64×64 판독성, 단일 핵심 개념, 실루엣, 아이콘과 배경의 분리 계약이 모든 표면 스타일보다 우선한다.
- 일반 정식 스타일 앵커는 자동 호출하지 않는다. `라인 웹툰풍 게임 아이콘` 요청도 라인 웹툰 01~17 앵커나 고정 영어 블록을 자동 삽입하지 않고, 판독성과 양립하는 선·색·명암 언어만 선택적으로 반영한다.
- 특정 일반 스타일 앵커의 직접 참조는 마스터가 명시적으로 요청한 경우에만 검토한다.
- 실제 예외 판정은 `../라이브러리/스타일/정식 스타일 호출 규칙.md`를 따른다.
