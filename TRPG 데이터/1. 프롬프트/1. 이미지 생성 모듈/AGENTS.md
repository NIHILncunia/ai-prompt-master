# 이미지 생성 모듈 AGENTS

## 역할

이 폴더는 프로젝트의 모든 이미지 생성 계열 요청을 라우팅하는 최상위 이미지 모듈이다.

## 기본 읽기 순서

1. 프로젝트 상위 지침
2. `0. 이미지 생성 모듈 마스터 프롬프트.md`
3. `공통/0. 이미지 생성 공통 운영 지침.md`
4. `공통/1. 이미지 생성 공통 승인 절차.md`
5. 선택된 하위 기능의 `AGENTS.md`와 0번 마스터
6. `라이브러리/스타일/정식 스타일 호출 규칙.md`에서 그림체 적용 방식과 앵커 조합 판정
7. 제공 이미지의 그림체 보존 여부 또는 선택된 정식 스타일 계약
8. `라이브러리/스타일/공통 붓터치 마감 규칙.md`의 적용 대상·예외 여부
9. 필요한 대상·레이아웃 라이브러리
10. 요구사항 확인서와 영어 프롬프트 초안 작성 후 `공통/6. 이미지 생성 프롬프트 점검 및 교정 지침.md`

하위 기능 문서에 적힌 앵커 파일명과 조합은 안내용이며 `라이브러리/스타일/정식 스타일 호출 규칙.md`의 판정을 덮어쓸 수 없다.

## 직접 준비 호출

- `포트레이트 준비`, `포트레이트 준비.`는 내부 1번 `반실사 포트레이트`로 직접 라우팅한다.
- `애니 페인팅 포트 준비`, `애니 페인팅 포트 준비.`, `애니 페인팅 포트레이트 준비`, `애니 페인팅 포트레이트 준비.`는 같은 내부 1번으로 직접 라우팅하고 선택 스타일을 `애니 페인팅`으로 바인딩한다. `애니 페인팅`은 정식 스타일명이다.
- 준비 호출이 아니더라도 이미지 요청에 `애니 페인팅` 또는 레거시 명칭 `세미리얼 애니 페인팅`이 화풍 지시로 포함되면 같은 스타일 바인딩을 적용한다. `애니 페인팅으로 전환`, `애니 페인팅 스타일`, `애니 페인팅으로 재생성/리파인`도 포함한다.
- 직접 준비 호출은 해당 기능의 처리 프로세스만 안내하며 생성·수정·외부 실행을 시작하지 않는다.
- `애니 페인팅` 또는 `붓터치 반실사`가 선택되면 해당 스타일 계약의 시각 앵커 하드 게이트를 적용하고 정식 앵커 이미지를 실제로 확인한 뒤 최종 프롬프트를 조립한다.

## 엔터티 자산과 미분류

- 설정화는 세션 진행과 직접 연관된 중요한 아이템·유물·장치·구조물 등의 디자인과 시각 설정을 확정하기 위한 이미지다.
- 모든 설정화는 가로형 16:9 또는 세로형 9:16 중 하나로 제작한다. 정사각형과 임의 비율은 설정화 산출물로 사용하지 않는다.
- 대상이 확정된 이미지는 해당 엔터티 폴더에 자산 인덱스 `.md`와 함께 보관한다. 대상 폴더는 `5. 신격`, `6. NPC`, `7. PC`, `8. 국가`, `9. 단체`, `10. 몬스터`, `12. 종족`, `13. 지역`, `14. 용종`, `15. 장소`, `18. 아이템`이다.
- 인물·NPC·PC·몬스터·신격 설정화와 초상화는 9:16, 토큰은 1:1이다. 지역·장소·아이템·기타 설정화는 16:9이며, 아이템 아이콘은 1:1이다. 국가·단체·종족은 1:1 엠블럼과 16:9 배너를 추가로 사용한다.
- 레퍼런스 시트는 같은 대상 폴더에 `<대상> 레퍼런스 시트 V1.webp` 형식으로 보관하고, 후속 시트는 V2부터 순차로 올린다.
- 대상·분류·정본 연결을 판정할 수 없는 결과만 `16. 미분류`에 보관한다. 동일 파일명의 서로 다른 이미지는 `시안/` 하위에 보존한다.
- 같은 대상의 여러 디자인 시안은 구분 가능한 파일명으로 모두 보존하며 기존 파일을 덮어쓰지 않는다. 최종 선택과 불필요한 시안 삭제는 마스터가 결정한다.
- 완성형 VTT 토큰 1:1, 캐릭터 레퍼런스 V2 고정 캔버스 등 별도의 기능 고정 계약을 가진 산출물은 이 설정화 비율 규칙의 적용 대상이 아니다.

## 핵심 원칙

- 이미지 생성 전에는 공통 승인 절차를 반드시 적용한다.
- 요구사항 확인서는 `공통/2. 요구사항 확인서 작성 규칙.md`의 `[이미지 생성 요구사항 확인서]` 15개 섹션 고정 양식을 그대로 사용한다. 번호·섹션 제목·필드명·순서는 절대 변경하지 않고, 해당하지 않는 항목도 `해당 없음`으로 유지한다. 기능별 정보는 기존 필드 값 안에 기록하며 별도 요구사항 확인 양식을 만들지 않는다.

- 요구사항 확인서와 최종 영어 프롬프트는 공통 프롬프트 점검·교정 지침의 P01~P10을 모두 통과한 뒤에만 공개한다. 실패하면 정본을 다시 읽어 자동 교정하고 처음부터 재검사한다.
- `15. 최종 해석 > 작업 가능 여부`가 `가능 — P01~P10 통과` 상태가 아니면 승인 요청 또는 생성 도구 호출을 금지한다.
- 요구사항 확인서와 최종 영어 프롬프트가 공개된 직후의 `다음`은 명시적 생성 승인으로 처리한다. 확인 절차 완료 전의 `다음`은 절차 진행으로만 처리하고, 생성 완료 후의 `다음`은 새 산출물 요청으로 보아 재승인한다.
- 생성 뒤에는 공통 자가검수로 결과를 판정한다. 결과만 제시하고 종료하지 않으며, 사용 권고 또는 재생성 권고의 근거와 `SESSION PROGRESS`를 함께 제시한다.
- 인물·NPC·PC·몬스터 이미지 작업은 생성 결과 제시에서 종료하지 않는다. 마스터가 결과를 채택하면 전신·초상화·토큰 3종 세트의 남은 산출물을 각 승인 절차에 따라 진행하고, 최종적으로 Google Drive의 분류별 정본 경로에 최초 업로드 또는 교체 업로드한다.
- 재생성 권고는 자동 재생성을 뜻하지 않는다. 수정 확인서와 최종 영어 프롬프트를 다시 공개하고 마스터의 명시적 승인을 받은 뒤에만 재생성한다.
- 기능별 고정 산출물 계약은 일반 라이브러리보다 우선한다.
- 완성형 VTT 토큰은 내부 1번 반실사 포트레이트가 소유한다. 포트레이트 전신 확정본 또는 사용자 업로드 이미지를 기준으로 캐릭터가 포함된 1:1 투명 WebP 1장을 생성한다.
- 완성형 토큰의 프레임은 내부 자동 구성 요소이며, 독립 프레임 이미지나 중앙 빈 원형을 만들지 않는다.
- 새 포트레이트는 별도 지정이 없으면 `붓터치 반실사`를 선택하고 정식 스타일 앵커와 공통 마감 블록을 적용한다.
- 캐릭터 레퍼런스 V1·V2와 세션 하이라이트는 제공 이미지가 있으면 별도 스타일 변경 지시가 없는 한 그 이미지의 그림체와 마감을 그대로 따른다. 제공 이미지가 없거나 사용자가 정식 스타일을 명시한 경우에만 해당 스타일 계약과 공통 마감 블록을 적용한다.
- 정식 스타일을 적용할 때 기능 프롬프트는 스타일별 고정 영어 그림체 블록과 공통 고정 영어 마감 블록을 문장 변경 없이 사용한다.
- 스타일 앵커는 그림체·채색·재질 표현·마감 전용이다. 앵커의 인물·의상·팔레트·포즈·카메라·배경·구성을 복제하지 않는다.
- 완성형 토큰은 포트레이트 파생물로 기준 이미지의 기존 스타일을 보존하며 캐릭터 본체를 다시 그리지 않는다.
- true top-down 배틀맵, 게임 아이콘, 양피지 지도에는 사용자가 명시하지 않는 한 공통 붓터치 마감을 적용하지 않는다.
- 이미지별 화풍에 대한 사용자의 최신 명시 지시가 공통 붓터치 마감 기본값보다 우선한다.
- **인물·NPC·PC·몬스터 이미지 작업의 기본 종료 지점은 생성이 아니라 Google Drive 저장이다.** 마스터가 저장 제외나 로컬 산출물만을 명시하지 않는 한, 생성·수정 → 검수/확정 → 최초 업로드 또는 교체 업로드까지 이어서 수행해야 완료로 본다.
- 인물 계열의 표준 이미지 세트는 `<액터>.webp` 전신, `<액터> 초상화.webp`, `<액터> 토큰.webp`의 **3종 세트**다. 마스터가 특정 산출물만 요청하거나 일부를 제외한 경우에만 범위를 축소한다. 각 이미지 생성 호출의 승인 상태는 기존 공통 승인 절차대로 서로 독립적으로 사용한다.
- 저장 분류는 설정상 역할을 우선한다. NPC는 `TRPG 데이터/6. NPC/<대상>/`, PC는 `TRPG 데이터/7. PC/<대상>/`, 몬스터는 `TRPG 데이터/10. 몬스터/<유형>/<대상>/`에 저장한다. 용종은 `TRPG 데이터/14. 용종/<유형>/<대상>/`에 두되 몬스터 자산 규칙을 그대로 따른다.
- 신규 정본이 없으면 최초 업로드한다. 같은 액터의 기존 정본이 있으면 **기존 Drive 파일 ID를 유지한 교체 업로드**를 기본으로 한다. 이미지 작업 안에서 마스터가 결과를 `픽스`, `확정`, `사용`, 다음 파생 산출물 진행 등으로 채택한 경우 저장·교체를 위해 별도의 `업로드하자` 지시를 다시 요구하지 않는다.
- NPC/PC/몬스터 분류가 자료만으로 판정되지 않을 때에만 저장 위치를 확인하며, 외형만으로 임의 분류하지 않는다.
- 인물 계열 외 일반 생성 결과도 대상이 확정되면 해당 엔터티 폴더에 저장한다. 대상이 확정되지 않은 결과만 `TRPG 데이터/16. 미분류/15. 이미지 생성 결과/`에 임시 보관한다.
