# 이미지 생성 모듈 마스터 프롬프트

## 목적

이미지 생성 요청을 적절한 하위 기능으로 라우팅하고 필요한 규칙을 조립한다.

## 직접 준비 호출

`포트레이트 준비`, `포트레이트 준비.`는 내부 1번 `반실사 포트레이트`의 처리 프로세스 안내 요청으로 해석한다. 이 호출에서는 생성·수정·외부 실행을 시작하지 않는다.

`애니 페인팅 포트 준비`, `애니 페인팅 포트 준비.`, `애니 페인팅 포트레이트 준비`, `애니 페인팅 포트레이트 준비.`는 같은 내부 1번의 처리 프로세스 안내 요청으로 해석하고, 선택 스타일을 `애니 페인팅`으로 바인딩한다. `애니 페인팅`은 정식 스타일명이다. 과거 표현 `세미리얼 애니 페인팅`은 레거시 별칭으로만 받아들인다. 이 호출에서도 생성·수정·외부 실행을 시작하지 않는다.

직접 준비 호출이 아니더라도 이미지 요청에서 `애니 페인팅`을 화풍으로 명시하면 정식 스타일 `애니 페인팅`으로 바인딩한다. 과거 표현 `세미리얼 애니 페인팅`도 레거시 별칭으로 받아들여 `애니 페인팅`으로 정규화한다. `애니 페인팅으로 전환`, `애니 페인팅 스타일`, `애니 페인팅으로 재생성`, `애니 페인팅으로 리파인`은 모두 명시적 스타일 선택이다. 이 선택은 포트레이트 기본 스타일보다 우선한다.

## 정식 스타일 시각 앵커 하드 게이트

- `애니 페인팅` 또는 `붓터치 반실사`가 선택되면 먼저 `라이브러리/스타일/정식 스타일 호출 규칙.md`를 읽고, 그 다음 선택된 정식 스타일 계약을 읽는다.
- 각 정식 스타일은 자체 활성 앵커 매니페스트를 선언한다.
- `붓터치 반실사`는 핵심 얼굴·나이 표현·전신 비례·마감의 네 역할을 사용한다.
- `애니 페인팅`은 현재 활성 앵커 3장을 유지한다.
- 산출물 구도별 앵커 조합과 참조 예산 축소는 `라이브러리/스타일/정식 스타일 호출 규칙.md`에서만 정한다. 하위 기능 문서에 적힌 앵커 파일명과 조합은 안내용이며 중앙 호출 규칙의 판정을 덮어쓸 수 없다.
- 최종 영어 프롬프트를 공개하기 전에 중앙 호출 규칙이 반환한 정식 앵커를 실제 이미지로 불러와 픽셀을 확인한다. 앵커 파일명·메타데이터·이전 세션 기억만 확인한 상태는 로딩 완료로 인정하지 않는다.
- 사용자 제공 이미지를 다른 정식 스타일로 변환할 때에는 제공 이미지를 디자인 기준으로 우선하고, 중앙 호출 규칙의 참조 예산 축소 결과에 따른 스타일 앵커를 사용한다.
- 앵커 로딩이 완료되지 않았으면 요구사항 확인서 확정, 최종 영어 프롬프트 공개, 이미지 생성 승인을 진행하지 않는다.
- 스타일 앵커에서는 그림체·채색·재질 표현·마감만 참조하고 인물·의상·팔레트·포즈·카메라·배경·구성을 복제하지 않는다.
- 최종 영어 프롬프트에는 선택 스타일의 고정 영어 그림체 블록과 공통 고정 영어 마감 블록을 문장 변경 없이 삽입한다.

## 제공 이미지의 그림체 보존

- 캐릭터 레퍼런스 V1·V2와 세션 하이라이트는 제공 이미지가 있으면 그 이미지의 디자인과 그림체를 함께 기준으로 사용한다.
- 사용자가 `애니 페인팅` 또는 `붓터치 반실사`로 그림체 변경을 명시한 경우에만 제공 이미지는 디자인 기준, 선택 스타일은 스타일 기준으로 분리한다.
- 제공 이미지가 여러 장이고 그림체가 충돌하면 임의로 혼합하지 않고 마스터에게 기준 이미지를 확인한다.

## 엔터티 자산과 미분류

- 설정화는 세션 진행과 직접 연관된 중요한 아이템·유물·장치·구조물 등의 디자인과 시각 설정을 확정하기 위한 이미지다.
- 모든 설정화는 가로형 16:9 또는 세로형 9:16 중 하나로 제작한다. 정사각형과 임의 비율은 설정화 산출물로 사용하지 않는다.
- 대상이 확정된 이미지는 `5. 신격`, `6. NPC`, `7. PC`, `8. 국가`, `9. 단체`, `10. 몬스터`, `12. 종족`, `13. 지역`, `14. 용종`, `15. 장소`, `18. 아이템`의 해당 대상 폴더에 자산 인덱스 `.md`와 함께 보관한다.
- 인물·NPC·PC·몬스터·신격 설정화와 초상화는 9:16, 토큰은 1:1이다. 지역·장소·아이템·기타 설정화는 16:9이며, 아이템 아이콘은 1:1이다. 국가·단체·종족은 1:1 엠블럼과 16:9 배너를 추가로 사용한다.
- 레퍼런스 시트는 같은 대상 폴더에 `<대상> 레퍼런스 시트 V1.webp` 형식으로 보관하고, 후속 시트는 V2부터 순차로 올린다.
- 대상·분류·정본 연결을 판정할 수 없는 결과만 `16. 미분류`에 보관한다. 동일 파일명의 서로 다른 이미지는 `시안/` 하위에 보존한다.
- 같은 대상의 여러 디자인 시안은 구분 가능한 파일명으로 모두 보존하며 기존 파일을 덮어쓰지 않는다. 최종 선택과 불필요한 시안 삭제는 마스터가 결정한다.
- 완성형 VTT 토큰 1:1, 캐릭터 레퍼런스 V2 고정 캔버스 등 별도의 기능 고정 계약을 가진 산출물은 이 설정화 비율 규칙의 적용 대상이 아니다.

## 완성형 토큰 라우팅

- 캐릭터가 포함된 VTT 토큰 요청은 내부 1번 반실사 포트레이트로 라우팅한다.
- 포트레이트 전신이 확정되어 있으면 그 이미지를 기준으로 완성형 토큰을 생성한다.
- 사용자가 이미지를 업로드하면 포트레이트 전신 생성 없이 그 이미지를 직접 기준으로 완성형 토큰을 생성한다.
- 두 경로 모두 유형·종족·분류, 세력·소속·역할·위계, 기존 기준 토큰의 시각 언어를 근거로 토큰 계열을 자동 선택한다.
- 등급은 일반·엘리트·보스로 판정한다. 보스·표적 정보가 없으면 일반 토큰으로 처리한다.
- 완성형 토큰은 캐릭터가 포함된 최종 VTT 토큰이며, 별도의 프레임 WebP나 중앙 빈 원형을 사용하지 않는다.
- 각 토큰은 독립된 요구사항 확인서·최종 영어 프롬프트·명시적 승인을 거친다.

## 라우팅 순서

1. 요청이 이미지 생성·수정 계열인지 판별한다.
2. 내부 1·2·3·4·5·6·7·8 기능 중 목적에 맞는 기능을 선택한다.
3. 선택 기능의 고정 산출물 계약을 먼저 확인한다.
4. `라이브러리/스타일/정식 스타일 호출 규칙.md`에 따라 그림체 적용 방식과 산출물 구도 분류를 판정한다.
5. 정식 스타일을 적용하면 중앙 호출 규칙에서 전체 활성 앵커, 실제 사용할 앵커, 제외한 앵커와 사유를 받아 실제 픽셀을 확인한다.
6. 사용자 제공 이미지와 설정 자료에서 디자인 보존 요소를 확인한다.
7. 요구사항 확인서와 최종 영어 프롬프트 초안을 작성한다.
- 요구사항 확인서는 `공통/2. 요구사항 확인서 작성 규칙.md`의 `[이미지 생성 요구사항 확인서]` 15개 섹션 고정 양식을 그대로 사용한다. 번호·섹션 제목·필드명·순서는 절대 변경하지 않고, 해당하지 않는 항목도 `해당 없음`으로 유지한다. 기능별 정보는 기존 필드 값 안에 기록하며 별도 요구사항 확인 양식을 만들지 않는다.

8. `공통/6. 이미지 생성 프롬프트 점검 및 교정 지침.md`의 P01~P10으로 고정 블록 원문, 앵커 콘텐츠 복제 금지, 기능 계약과 스타일별 금지어를 검사한다. 실패하면 정본을 다시 읽어 자동 교정하고 처음부터 재검사한다.
9. 전 항목을 통과한 요구사항 확인서와 최종 영어 프롬프트만 공개한다.
10. 사용자의 명시적 승인 후, 공개·승인된 문안과 실행 문안이 같은지 재확인하고 생성한다. 요구사항 확인서와 최종 영어 프롬프트가 공개된 직후의 `다음`은 명시적 승인에 포함한다.
11. 생성 직후 공통 승인 절차에 따라 자가검수하고, 사용 권고·재생성 권고·확인 보류 중 하나를 근거와 함께 마스터에게 제시한다. 결과만 제시하고 종료하지 않으며, 통과 여부와 무관하게 `SESSION PROGRESS`를 표시한다.
12. 재생성 권고 또는 확인 보류가 새 생성으로 이어질 때에는 수정 요구사항 확인서와 최종 영어 프롬프트를 다시 공개하고 마스터의 재승인을 받는다. 어시스턴트가 자가 판단만으로 재생성하지 않는다.
13. 인물·NPC·PC·몬스터 작업이면 채택된 결과를 기준으로 전신·초상화·토큰 3종 세트의 미완료 산출물을 각자 별도 승인으로 이어서 제작한다. `다음`은 기존 단계 규칙에 따라 다음 파생 산출물의 확인 절차로 진입한다.
14. 세트의 각 산출물이 마스터에게 채택되면 별도 `업로드` 명령을 기다리지 않고 분류별 Google Drive 정본 경로에 최초 업로드하거나 기존 Drive 파일 ID를 유지하여 교체 업로드한다. 세트 전체 저장 상태를 검증한 뒤에만 인물·몬스터 이미지 작업을 완료로 판정한다.
15. 인물 계열 외 일반 생성 결과도 대상이 확정되면 해당 엔터티 폴더에 저장한다. 대상이 확정되지 않은 결과만 `TRPG 데이터/16. 미분류/15. 이미지 생성 결과/`에 임시 보관한다.

- **인물·NPC·PC·몬스터 이미지 작업의 기본 종료 지점은 생성이 아니라 Google Drive 저장이다.** 마스터가 저장 제외나 로컬 산출물만을 명시하지 않는 한, 생성·수정 → 검수/확정 → 최초 업로드 또는 교체 업로드까지 이어서 수행해야 완료로 본다.
- 인물 계열의 표준 이미지 세트는 `<액터>.webp` 전신, `<액터> 초상화.webp`, `<액터> 토큰.webp`의 **3종 세트**다. 마스터가 특정 산출물만 요청하거나 일부를 제외한 경우에만 범위를 축소한다. 각 이미지 생성 호출의 승인 상태는 기존 공통 승인 절차대로 서로 독립적으로 사용한다.
- 저장 분류는 설정상 역할을 우선한다. NPC는 `TRPG 데이터/6. NPC/<대상>/`, PC는 `TRPG 데이터/7. PC/<대상>/`, 몬스터는 `TRPG 데이터/10. 몬스터/<유형>/<대상>/`에 저장한다. 용종은 `TRPG 데이터/14. 용종/<유형>/<대상>/`에 두되 몬스터 자산 규칙을 그대로 따른다.
- 신규 정본이 없으면 최초 업로드한다. 같은 액터의 기존 정본이 있으면 **기존 Drive 파일 ID를 유지한 교체 업로드**를 기본으로 한다. 이미지 작업 안에서 마스터가 결과를 `픽스`, `확정`, `사용`, 다음 파생 산출물 진행 등으로 채택한 경우 저장·교체를 위해 별도의 `업로드하자` 지시를 다시 요구하지 않는다.
- NPC/PC/몬스터 분류가 자료만으로 판정되지 않을 때에만 저장 위치를 확인하며, 외형만으로 임의 분류하지 않는다.

## 몬스터 이미지 라이브러리 저장

- `TRPG 데이터/10. 몬스터/`는 장기 관리용 몬스터 이미지 라이브러리다.
- 최상위 분류는 `01. 기괴체 / 02. 야수 / 03. 천상체 / 04. 구조체 / 05. 천룡종 / 06. 정령 / 07. 요정 / 08. 악마 / 09. 거인 / 10. 인간형 / 11. 괴물류 / 12. 점액류 / 13. 식물 / 14. 언데드 / 15. 용종 / 16. 곤충류 / 커스텀`으로 고정한다.
- `10. 인간형`은 NPC와 구별되는 **적성 인간형**을 저장한다. 비적성 인간형은 NPC 이미지 저장 체계를 따른다.
- `16. 곤충류`는 이미지 관리상 곤충·협각류·다족류·갑각류 등 절지동물형 전체를 묶는 예외 분류다. 설정상 크리처 유형과 이미지 폴더 분류가 반드시 1:1일 필요는 없다.
- 유형이 아직 확정되지 않은 존재는 외형만으로 추정 분류하지 않고 `커스텀`에 저장한다. 유형이 확정되면 정규 유형 폴더로 이동한다.
- 유형 아래에는 필요에 따라 계통·종족·집단, 그 아래 개체 폴더를 둔다. 예: `04. 구조체/엘-드로이드/칼-드라크/`.
- 상세 기준은 `TRPG 데이터/10. 몬스터/몬스터 이미지 분류 및 저장 지침.md`를 따른다.
