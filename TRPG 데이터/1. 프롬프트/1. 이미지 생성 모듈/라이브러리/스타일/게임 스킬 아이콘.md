# 게임 스킬 아이콘 정식 스타일 계약

## 1. 상태와 범위

- 상태: 정식
- 소유 기능: `7. 게임 아이콘 생성`
- 적용 계열: 스킬, 주문, 액션, 특성·패시브, 버프·디버프·상태이상, 속성·저항·취약, 자원 등 **비아이템 게임플레이 아이콘**
- 스타일 성격: 일반 인물·환경 정식 스타일과 분리된 **기능 전용 정식 스타일**
- 공통 붓터치 마감: 미적용

게임 아이콘은 중앙 스타일 체계에서 계속 기능성 예외로 분류한다. 이 문서는 그 예외 내부에서 스킬·상태 계열이 사용하는 정식 시각 계약을 소유한다. `붓터치 반실사`, `애니 페인팅`, `라인 웹툰`의 일반 정식 앵커를 게임 아이콘에 자동 혼합하지 않는다.

## 2. 기능 고정 계약

- 개별 아이콘은 1:1 정사각형이다.
- 한 슬롯에는 하나의 핵심 개념만 둔다.
- 64×64 및 128×128 축소에서 핵심 실루엣·방향·주색이 유지되어야 한다.
- 실제 아이콘 슬롯은 피사체의 속성·주색·명도·발광과 조화되는 **비투명 유색 추상 배경**을 캔버스 끝까지 채운다.
- 실제 아이콘 슬롯의 순수 검정·거의 검정·검정/차콜 기본 배경을 금지한다.
- 장소·풍경·실내·바닥·탁자 등 환경 장면을 배경으로 만들지 않는다.
- 프레임·배지 림·VTT 토큰 테두리를 기본으로 만들지 않는다.
- 다중 생성은 3×3 슬롯 시트를 기본 단위로 사용하고 행 우선으로 채운다.
- 실제 아이콘이 없는 빈 슬롯만 순수 검정으로 채운다.
- 9개를 초과하면 같은 생성 배치에서 3×3 시트를 추가한다.
- 생성된 3×3 시트는 원본 해상도와 구성을 보존하고 자동 분할·리사이즈·재합성하지 않는다.
- 낱개 슬롯 파일은 자동 저장하지 않으며, 마스터가 별도 추출을 요청한 경우에만 원본 시트를 보존한 채 파생 작업으로 만든다.

### 2.1 사용자 입력 의미 시드 처리

사용자 입력은 묘사문 자체를 그리는 지시가 아니라 **게임플레이 효과를 추출하기 위한 의미 시드**다. 최종 프롬프트는 반드시 한 번 의미 정규화를 거친다.

`사용자 원문 → 기능 역할 → 핵심 행동/변화 → 방향성 → 강도 → 속성/재질 → 핵심 상징 → 정식 아이콘 구도`

- 원문을 직역하거나 그대로 영어로 전사하지 않는다.
- 공격·방어·회복·이동·강화·약화·제어·소환 등 게임플레이 역할을 먼저 판정한다.
- 소설적 표현, 욕설, 과장, 신체 손상·고어·잔혹 표현은 최종 프롬프트의 직접 피사체가 되지 않는다.
- 이러한 표현에서 필요한 것은 잔혹성 자체가 아니라 `충격량, 관통감, 절단감, 압박감, 붕괴감, 흡수감, 속박감, 소멸감` 같은 효과의 성질이다. 이를 균열, 충격파, 에너지 궤적, 추상 파편, 끊어진 선, 압축·확산, 흡수 흐름, 봉인 구조 등 비신체적 시각 언어로 치환한다.
- 예: `몸을 분쇄한다` → `압도적 충격 + 방사형 균열 + 파쇄되는 추상 물질 + 높은 에너지 밀도`.
- 예: `피를 빨아먹는다` → `생명력 흡수 + 한 중심에서 다른 중심으로 끌려가는 적색/자홍 에너지 흐름`.
- 예: `목을 벤다` → `빠르고 결정적인 초승달형 참격 궤적 + 끊어지는 추상 선/문양`.
- 사용자가 명시한 원소, 무기 종류, 색, 방향, 상징물처럼 핵심 디자인 정보는 보존한다. 다만 앵커와 정식 스타일 계약에 맞게 크기·구도·효과 밀도를 재설계한다.
- 최종 프롬프트는 원문 재현보다 **64×64에서 즉시 읽히는 하나의 시각 기호**를 우선한다.

## 5. 최소 참조 조합

참조 이미지 수를 불필요하게 늘리지 않는다. 기본 상한은 스타일 앵커 2장이다.

- 동적 공격·베기·폭발: `01`
- 장축 투사체·창형 에너지: `01 + 02`
- 번개·빔·고에너지 방출: `01 + 03`
- 치유·신성·밝은 지원·상승형 버프: `04`
- 방어·장벽·갑주형 강화: `05`
- 대시·회피·도약·백스텝·급가속 등 물리 기동: `06`
- 순간이동·위상전이·공간 도약: `07`
- 속박·봉인·침묵·행동 차단·구속형 제어: `08`
- 저주·공포·정신 약화·오염·부정 상태: `09`
- 이동을 방해하는 둔화·중력 제어처럼 기동과 제어가 동시에 핵심: `06 + 08`
- 공간 봉쇄·차원 구속처럼 전이와 제어가 동시에 핵심: `07 + 08`
- 복합 디버프에서 제어와 정신/저주가 동시에 핵심: `08 + 09`
- 역할이 복합적이거나 판정이 애매한 비아이템 아이콘: 핵심 역할을 먼저 판정한 뒤 그 역할 앵커 1장을 우선하고, 필요한 경우에만 보조 앵커 1장을 추가한다.

명확한 역할별 앵커 하나로 충분하면 두 번째 앵커를 추가하지 않는다. 디자인 기준 이미지가 있으면 디자인 기준을 먼저 배정하고, 남은 참조 예산 안에서 위 조합을 최소화한다.

## 6. 시각 문법

- 중앙 집중형 또는 명확한 대각선 운동형 구도를 사용한다.
- 큰 형태 덩어리와 외곽 실루엣을 미세 디테일보다 우선한다.
- 고채도 속성색과 강한 명암 대비를 사용하되 절대 팔레트로 고정하지 않는다.
- 선택적 림라이트와 국소 글로우는 형태 분리를 위해 사용한다.
- 페인터리와 그래픽 렌더링 사이의 중간 밀도를 유지한다.
- 같은 색 계열의 피사체와 배경은 명도·채도·선택적 림라이트로 분리한다.
- 신성·광휘 계열은 최고광이 올라가더라도 내부 형태선과 핵심 실루엣을 보존한다.
- 효과 궤적이 피사체보다 커질 수 있지만 핵심 실루엣을 덮어서는 안 된다.

## 7. 다중 생성 검수·배치 저장

생성된 3×3 시트 자체를 최종 정본 후보로 취급한다.

`3×3 시트 생성 → 구조·수량·행 우선 순서 확인 → 경계 침범·배경 계약 확인 → 128×128·64×64 상당 축소 판독성 검수 → 원본 시트 그대로 배치 저장 → MD 인덱스 갱신`

픽셀 크기가 예상과 달라도 3×3 구조가 정상이라면 후처리 정규화하지 않는다. 자동 슬롯 분할·512 정규화·1536 재합성·낱개 저장은 사용하지 않는다. 구조적 또는 시각적 실패 때문에 새 이미지를 다시 생성하는 경우에는 공통 이미지 승인 게이트를 다시 거친다.

스킬 아이콘 정본 배치는 `TRPG 데이터/22. 아이콘 생성/스킬 아이콘` 아래 `<YYYY MMDD> 스킬 아이콘 <NN>` 폴더로 저장한다. 배치 폴더 내부에 같은 이름의 `.md`와 원본 시트를 둔다. 시트가 1장이면 `<배치명>.png`, 여러 장이면 `<배치명>-1.png`, `<배치명>-2.png` 순으로 저장한다.

## 9. 검증 근거

- 1차 6종 세트: 전체 사용 권고, 5종 강한 통과, 장축 투사체 1종 부분 판독 문제를 확인해 02 앵커의 역할을 별도 분리했다.
- 나무 계열 12종: 11/12 통과, 성공률 91.7%.
- 화염·폭발 및 다속성 테스트: 속성 색언어와 세트 일관성을 추가 확인했다.
- 5개 패키징: 3×3의 5개 실제 슬롯 + 4개 순수 검정 빈 슬롯 구조를 확인했다.
- 11개 패키징: 3×3 두 장의 9 + 2 구조를 확인했다.
- 순수 스킬 앵커 공백 3×3 테스트: `Teleport`, `Control / Restraint`, `Curse`가 각각 공간 전이·제어/속박·저주/정신 약화의 강한 후보로 판정됐다.
- 물리 기동 전용 3×3 보완 테스트: `Afterimage Movement`가 대시·회피·기동을 포괄하는 가장 범용적인 후보로 판정됐다.
- 2026-09-12의 초기 테스트 당시에는 셀 분할·512 정규화·1536 재합성을 사용했으나, 이후 운영 정책 변경으로 일반 3×3 배치에는 이 후처리를 사용하지 않는다. 당시 개별 슬롯은 앵커 승격 검증의 역사적 근거로만 유지한다.
- 현재 정식 앵커 01~09는 모두 512×512 RGB 비투명 래스터다.

### 승격 원본과 역할

- `06. 물리 기동 앵커.png`: 물리 기동 보완 테스트의 `Afterimage Movement`. 부츠·발놀림·잔상과 연속 변위를 사용하며 투사체화와 전신 캐릭터 의존을 피한다.
- `07. 공간 전이 앵커.png`: 공백 테스트의 `Teleport`. 서로 떨어진 두 위치와 공간 연결을 통해 물리 이동과 다른 전이 문법을 제공한다.
- `08. 제어·속박 앵커.png`: 공백 테스트의 `Control / Restraint`. 중심 핵을 조이는 수렴·구속 구조가 64×64에서도 명확하다.
- `09. 저주·정신 약화 앵커.png`: 공백 테스트의 `Curse`. 비대칭 룬과 오염 확산으로 일반 제어와 구분되는 부정 상태 문법을 제공한다.

### 보류 영역

`소환·현현·변형`은 현재 01·04·05 조합으로 우선 운용한다. 전용 앵커는 실제 세션 요청에서 반복적인 실패가 확인될 때만 추가한다. 정식 활성 앵커 수를 목적 없이 늘리지 않는다.
