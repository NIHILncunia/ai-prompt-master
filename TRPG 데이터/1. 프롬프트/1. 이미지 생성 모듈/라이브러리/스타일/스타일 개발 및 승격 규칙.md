# 스타일 개발 및 승격 규칙

## 1. 목적

새로운 이미지 스타일을 분석·시험할 때 처음부터 정식 스타일로 승격 가능한 구조로 개발한다.
개발 단계 산출물은 모두 `dev_` 접두사를 사용하고 정식 런타임에서는 참조하지 않는다.
확정 시에는 내용을 처음부터 다시 작성하지 않고 개발 패키지의 계약·앵커·호출 정보를 검수한 뒤 정식 위치로 복사·이름 정규화한다.

## 2. 개발 패키지 기본 구조

새 스타일 `<스타일명>`을 분석할 때 `TRPG 데이터/20. 그림 스타일 분석/<스타일명>/`을 만든다. 스타일 폴더 자체에는 `dev_` 접두사를 붙이지 않고, 내부 개발 하위 폴더와 개발 단계 자산에만 `dev_`를 사용한다.

```text
<스타일명>/
├─ dev_문서/
│  ├─ dev_스타일 계약.md
│  ├─ dev_앵커 매니페스트.md
│  └─ dev_승격 체크리스트.md
├─ dev_분석/
│  ├─ dev_스타일 분석.md
│  └─ dev_시안 판정 이력.md
├─ dev_프롬프트 블록/
│  ├─ 00. 블록 조립 규칙.md
│  ├─ 01. 기본 스타일 블록.md
│  ├─ 02. 인물 블록.md
│  ├─ 03. 연령·체형 블록.md
│  ├─ 04. 표정·눈매 블록.md
│  ├─ 05. 판타지 형태 블록.md
│  ├─ 06. 환경 공간감 블록.md
│  ├─ 07. 재질 블록.md
│  ├─ 08. 광원·대기 블록.md
│  ├─ 09. 기후·계절 블록.md
│  └─ 10. 제외 조건 블록.md
├─ dev_앵커/
├─ dev_견본 레퍼런스/
└─ dev_시안 레퍼런스/
```

스타일에 필요하지 않은 블록은 삭제하지 않고 `해당 없음` 또는 비활성으로 남긴다. 이렇게 해야 승격 시 어떤 축을 검토했는지 알 수 있다.

## 3. 프롬프트 블록 원칙

스타일 분석용 프롬프트는 거대한 단일 프롬프트 하나로 관리하지 않는다.
프롬프트를 독립 블록으로 나누고 각 블록이 소유하는 역할을 고정한다.

- `01 기본 스타일`: 선화·채색·명암·형태 단순화·표면 마감 등 스타일의 핵심 언어
- `02 인물`: 얼굴·손·머리카락·인체 표현
- `03 연령·체형`: 나이, 신장, 골격, 근육량, 체지방 분포 등
- `04 표정·눈매`: 기본 눈 설계와 순간 감정 표현
- `05 판타지 형태`: 비인간 두상·귀·뿔·비늘·털·갑각 등
- `06 환경 공간감`: 전경·중경·원경, 원근, 거리별 정보량
- `07 재질`: 피부·천·가죽·금속·목재·석재·유리·자연물
- `08 광원·대기`: 주광·역광·야간·안개·색온도·시정거리
- `09 기후·계절`: 비·눈·바람·젖음·건조·계절 변화
- `10 제외 조건`: 스타일 이탈 요소와 금지 렌더링

각 블록은 단독 테스트가 가능해야 하며 다른 블록의 역할을 불필요하게 중복하지 않는다.
스타일의 최종 고정 영어 블록은 개발 블록을 검증한 뒤 `dev_스타일 계약.md`에서 정식 형태로 조립한다.

## 4. 앵커 개발 원칙

- 개발 앵커는 모두 `dev_앵커/`에 둔다.
- 번호는 개발 중에도 `01`, `02`, `03`처럼 연속 번호를 사용한다.
- 실패·대체 시안을 번호 체계에 억지로 남기지 않는다. 실패 이미지는 `dev_시안 레퍼런스/`와 `dev_시안 판정 이력.md`에 보존한다.
- 실제 승격 대상으로 확정된 앵커만 `dev_앵커/`에 남긴다.
- `dev_앵커 매니페스트.md`에는 번호, 파일명, 역할, 핵심/조건부/전문/환경 구분, 호출 조건을 기록한다.
- 앵커는 스타일 역할만 소유하고 캐릭터 정체성·의상·팔레트·포즈·카메라·장면 구성을 소유하지 않는다.

## 5. 분석 단계

1. 견본 수집 → `dev_견본 레퍼런스/`
2. 시각 축 분해 → `dev_분석/dev_스타일 분석.md`
3. 프롬프트를 블록 단위로 작성
4. 기본 시안 생성 → `dev_시안 레퍼런스/`
5. 시안별 사용 권고 / 재생성 권고 / 확인 보류 판정을 `dev_분석/dev_시안 판정 이력.md`에 기록
6. 반복 테스트로 각 표현 축의 허용 범위 확정
7. 확정 이미지만 `dev_앵커/`로 승격
8. `dev_문서/dev_앵커 매니페스트.md` 번호를 빈칸 없이 재정렬
9. `dev_문서/dev_스타일 계약.md`에 최종 고정 영어 블록·앵커 역할·마감 정책을 조립
10. `dev_문서/dev_승격 체크리스트.md` 통과 후 정식 스타일로 복사

## 6. 정식 승격 규칙

승격은 재작성 작업이 아니라 복사·정규화 작업이어야 한다. 개발 자산의 정본 위치는 끝까지 `TRPG 데이터/20. 그림 스타일 분석/<스타일명>/`이며, 정식 런타임 자료만 이미지 생성 모듈 라이브러리로 복사한다.

- `dev_문서/dev_스타일 계약.md` → `라이브러리/스타일/<스타일명>.md`
- `dev_앵커/` → `라이브러리/견본/<스타일명>/`
- `dev_문서/dev_앵커 매니페스트.md`의 역할·조합 → 중앙 `정식 스타일 호출 규칙.md`에 등록
- 필요한 경우 이미지 모듈 루트 AGENTS·마스터와 해당 기능 라우터에 스타일명만 연결
- `dev_프롬프트 블록/`은 개발 근거로 보존하되 정식 런타임에서 직접 호출하지 않는다.
- `dev_분석/dev_스타일 분석.md`, `dev_분석/dev_시안 판정 이력.md`도 개발 기록으로 보존한다.

정식 승격 전에는 `dev_` 경로와 파일을 이미지 생성 런타임에서 자동 참조하지 않는다.

## 7. 승격 완료 조건

- 스타일 정체성과 금지 영역이 명확하다.
- 고정 영어 스타일 블록이 완성되어 있다.
- 공통 붓터치 마감 사용 여부가 명시되어 있다.
- 핵심 앵커와 조건부 앵커가 구분되어 있다.
- 앵커 번호가 빈칸 없이 연속이다.
- 인물·환경 등 필요한 표현 축의 검증이 끝났다.
- 프롬프트 블록 간 역할 중복이 정리되어 있다.
- 실패 시안은 정식 앵커 폴더에서 제거되어 있다.
- 중앙 호출 규칙에 넣을 최소 조합이 정리되어 있다.
- 기능성 예외와 충돌 여부를 확인했다.
