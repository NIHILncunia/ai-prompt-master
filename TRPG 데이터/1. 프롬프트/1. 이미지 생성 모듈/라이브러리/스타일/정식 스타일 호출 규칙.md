# 정식 스타일 호출 규칙

## 목적과 적용 범위

이 문서는 이미지 생성 모듈 내부 1~8번 기능이 그림체 적용 방식을 하나로 판정하고, 선택한 정식 스타일의 활성 앵커와 참조 예산을 일관되게 호출하는 단일 정본이다. 기능 문서는 이 문서가 반환한 앵커 조합을 사용하며, 앵커 파일명·조합·참조 예산을 자체 정본으로 다시 정하지 않는다.

## 입력 계약

- 그림체 적용 방식
- 선택 정식 스타일
- 대상 유형
- 주 프레이밍
- 디자인 기준 이미지 수
- 도구 전체 이미지 참조 한도

## 출력 계약

- 스타일별 전체 활성 앵커
- 실제 사용할 앵커
- 제외한 앵커와 제외 사유
- 고정 영어 그림체 블록 적용 여부
- 공통 고정 영어 마감 블록 적용 여부

## 그림체 적용 방식

생성 프롬프트를 조립하기 전에 아래 셋 중 하나만 선택한다. 둘 이상의 방식을 혼합하지 않는다.

1. 제공 이미지 그림체 보존
2. 정식 스타일 적용
3. 사용자 지정 스타일·기능성 예외

캐릭터 레퍼런스 V1·V2와 세션 하이라이트는 제공 이미지가 있고 별도 스타일 변경 지시가 없으면 `제공 이미지 그림체 보존`을 선택한다. 이 방식에서는 정식 스타일 앵커, 고정 영어 그림체 블록, 공통 고정 영어 마감 블록을 자동으로 삽입하지 않는다.

`정식 스타일 적용`에서는 선택 스타일의 활성 앵커 실제 픽셀을 확인하고, 선택 스타일의 고정 영어 그림체 블록을 한 번만 원문 그대로 삽입한다. `공통 붓터치 마감 규칙.md`의 고정 영어 마감 블록은 선택 스타일 계약이 적용을 선언한 경우에만 그림체 블록 바로 뒤에 한 번 삽입한다. `붓터치 반실사`와 `애니 페인팅`은 공통 붓터치 마감 블록을 적용하고, `라인 웹툰`은 자체 고정 영어 그림체 블록 안에서 선화·2~3단 셀식 명암·재질·표면 마감이 완결되므로 공통 붓터치 마감 블록을 적용하지 않는다. 선택 스타일이 마감 역할 앵커를 선언한 경우 해당 마감 앵커를 참조 예산 때문에 제외할 수 없으며, 로딩 완료·파일명·메타데이터·이전 기억으로 실제 픽셀 확인을 대체하지 않는다.

`사용자 지정 스타일·기능성 예외`에서는 사용자 명시 스타일 또는 기능 계약을 우선한다. true top-down 배틀맵·게임 아이콘·양피지 지도는 일반 인물·환경 정식 스타일보다 기능 전용 스타일과 판독성 계약을 우선한다. true top-down 배틀맵과 양피지 월드 지도는 일반 정식 스타일 앵커를 자동 적용하지 않는다. 게임 아이콘도 `붓터치 반실사`·`애니 페인팅`·`라인 웹툰` 등 일반 정식 스타일의 자동 적용 대상이 아니지만, 기능 예외 내부에 승격된 정식 `게임 스킬 아이콘` 계약은 비아이템 스킬·주문·액션·특성·버프·디버프·상태·속성·자원 아이콘에 기본 적용한다. 이 기능 전용 계약은 `게임 스킬 아이콘.md`와 `../견본/게임 스킬 아이콘/` 01~09 앵커가 소유하며, 역할별 최소 1장·필요 시 최대 2장만 호출한다. 사용자가 라인 웹툰풍 게임 아이콘을 명시해도 게임 스킬 기능 계약은 유지하고 작은 크기에서 유지되는 선명한 구조선·평면 색 분리·제한된 셀식 명암만 설명형으로 반영하며 라인 웹툰 01~17 앵커와 고정 영어 블록은 자동 삽입하지 않는다. 배틀맵·월드 지도에서 특정 일반 스타일 앵커를 직접 참조하라는 명시 지시가 있을 때에만 개별 참조를 검토한다. 풍경 생성은 `6. 풍경 생성/라이브러리/풍경 앵커 호출 규칙.md`의 전용 05~09 앵커를 장소에 맞게 최소 조합으로 사용하며 인물 앵커를 적용하지 않는다. 완성형 VTT 토큰은 확정 기준 이미지의 그림체를 보존하고 캐릭터 재렌더링용 앵커를 적용하지 않는다.

## 개발 스타일 격리

- 개발 스타일의 유일한 정본 위치는 `TRPG 데이터/20. 그림 스타일 분석/<스타일명>/`이다. 다른 개발 저장 위치는 사용하지 않는다.
- 스타일 최상위 폴더에는 `dev_` 접두사를 붙이지 않으며, `dev_스타일 계약`, `dev_프롬프트 블록`, `dev_앵커`, `dev_견본 레퍼런스`, `dev_시안 레퍼런스` 등 내부 개발 자산에만 `dev_`를 사용한다.
- `TRPG 데이터/20. 그림 스타일 분석`의 개발 패키지는 정식 스타일이 아니다. 정식 승격 후에도 개발 기록은 런타임 자동 호출 대상으로 사용하지 않는다.
- `dev_스타일 계약`, `dev_프롬프트 블록`, `dev_앵커`, `dev_견본 레퍼런스`, `dev_시안 레퍼런스`는 이미지 생성 런타임에서 자동 호출하지 않는다.
- 개발 스타일은 `스타일 개발 및 승격 규칙.md`의 승격 체크리스트를 통과하고 마스터가 확정한 뒤에만 이 문서의 `스타일별 전체 활성 앵커`와 기본/조건부 조합에 등록한다.
- 승격 전 테스트에서 개발 앵커를 사용할 때에도 해당 테스트 세션의 명시적 개발 작업 안에서만 직접 참조하며, 일반 이미지 요청에 개발 자산을 확산하지 않는다.

## 스타일별 전체 활성 앵커

### 붓터치 반실사

정본 경로: `../견본/붓터치 반실사/`

- `01. 핵심 얼굴 앵커.webp` — 얼굴 그림체: 얼굴 평면 단순화, 눈·코·입 설계, 머리카락 덩어리, 비사진적 얼굴 조형
- `02. 나이 표현 앵커.webp` — 연령 표현: 두개골 대비 얼굴 비율, 하안부 길이, 목·어깨, 연령별 인상과 노화 표현
- `03. 전신 앵커.webp` — 전신 비례: 머리 대비 신장, 몸통·팔다리 비율, 연령별 체형, 전신 실루엣
- `04. 마감 앵커.webp` — 최종 마감: 구아슈 + 아크릴 혼합형 불투명 채색, 초점별 붓터치 밀도, 명암, 경계, 재질 분리와 표면 처리
- `05. 인간 외형 다양성 앵커.webp` — 보조 인간 다양성: 서로 다른 성인 인간의 피부색·얼굴 골격·이목구비·머리카락 질감·체격을 하나의 회화 언어로 처리하는 기준
- `06. 감정·표정 앵커.webp` — 보조 감정·표정: 한 인물의 정체성을 유지한 채 눈·눈썹·입·얼굴 긴장으로 감정을 분리하는 기준
- `07. 판타지 종족 형태 앵커.webp` — 보조 판타지 종족: 귀·뿔·엄니·비늘·털 등 비인간 해부와 표면 재질을 동일한 회화 언어로 처리하는 기준

01~04는 기본 조합을 구성하는 핵심 앵커다. 05~07은 요청 내용이 직접 해당할 때만 추가하는 조건부 보조 앵커다. 보조 앵커는 기본 호출에 자동으로 넣지 않으며, 사용 시에는 해당 파일의 실제 픽셀을 확인하고 앵커 콘텐츠를 복제하지 않는다.

## 라인 웹툰 기본 조합

### 인물 기본 조합

- 얼굴·흉상: `01 + 04`
- 반신·전신: `03 + 04`

### 라인 웹툰 조건부 인물 조합

- 연령 표현이 핵심: 해당 기본 조합 + `02`

- 기본 눈매 설계가 핵심: 해당 기본 조합 + `07`
- 동일 인물의 감정·표정 연기가 핵심: 해당 기본 조합 + `08`
- 비인간 판타지 종족의 두상·귀·뿔·엄니·비늘·털·깃털·갑각 등 형태 표현이 핵심: 해당 기본 조합 + `09`
- 특정 성인 여성 체형의 정면·측면 일관성이 핵심: 관련 목적에 한해 `10 + 11` 또는 `10 + 12` 전문 참고 조합을 추가

### 라인 웹툰 환경 조합

라인 웹툰 환경 요청은 `04. 라인 마감 앵커.png`를 기본 환경 마감 앵커로 유지하고, 아래 13~17 중 장소의 실제 위험과 직접 맞는 앵커만 최소 조합으로 추가한다. `이미지 생성 모듈/라이브러리/견본/풍경 앵커/`의 기존 05~09 회화 환경 앵커와 라인 웹툰 13~17을 자동 혼합하지 않는다.

- 넓은 실외·도시 전경·광역 지형: `04 + 13`
- 자연 지형·숲·계곡·수변: `04 + 13 + 14`
- 근접 자연 재질이 핵심이고 광역 원근이 중요하지 않음: `04 + 14`
- 건축 외관·정착지 전경: `04 + 13 + 15`
- 실내·건축 재질이 핵심: `04 + 15`
- 넓은 실내의 공간감과 건축 재질이 모두 핵심: `04 + 13 + 15`
- 시간대·광원 방향·색온도·안개/시정거리 변화가 핵심: 위 장소 조합 + `16`
- 비·눈·바람·습기·계절·적설·결빙 등 환경 물리 상태가 핵심: 위 장소 조합 + `17`

13~17을 한 요청에 모두 자동 삽입하지 않는다. 예를 들어 자연 풍경의 낮 장면이면 04+13+14로 충분하고, 같은 자연 풍경에 겨울 적설이 핵심이면 17을 추가한다. 대기·광원과 기후·계절이 모두 핵심일 때에만 16과 17을 함께 사용한다.

라인 웹툰은 그림체 적용 방식의 세 중앙 모드 원칙을 그대로 따른다. 제공 이미지가 있고 명시적 정식 스타일 변환 요청이 없으면 `제공 이미지 그림체 보존`을 적용한다. 명시적으로 라인 웹툰을 선택한 경우에만 위 앵커 조합과 `라인 웹툰.md`의 고정 영어 그림체 블록을 적용한다. 라인 웹툰에는 `공통 붓터치 마감 규칙.md`의 고정 영어 마감 블록을 삽입하지 않는다.

## 참조 예산 우선순위

1. 디자인 기준 이미지
2. 마감 앵커
3. 주 구도 앵커
4. 명시 요구와 직접 맞는 조건부 보조 앵커
5. 나이 표현 앵커(독립 나이 표현 앵커를 선언한 스타일에 한함)
6. 남은 핵심·보조 앵커

도구 전체 이미지 참조 한도 때문에 전체 활성 앵커를 모두 사용할 수 없으면 위 순서로 자리를 배정한다. 주 구도 앵커는 얼굴 중심일 때 핵심 얼굴 앵커, 전신 중심일 때 전신 앵커다. 명시 연령이 미성년·고령이거나 연령 오차가 핵심 위험이면 독립 나이 표현 앵커를 선언한 스타일에서만 해당 나이 앵커를 우선한다. 명시 감정·인간 다양성·비인간 종족이 핵심 위험이면 선택 스타일의 해당 조건부 앵커를 우선한다. 붓터치 반실사에서는 06·05·07, 라인 웹툰에서는 08·05·09가 각각 감정·인간 얼굴 다양성·비인간 종족 역할을 맡는다. 단, 마감 앵커는 제외하지 않으며 일반적인 경우 주 구도 앵커를 우선한다. 애니 페인팅은 02 전신 앵커 안에 연령별 체형 기준이 내장되어 있으며 독립 나이 표현 앵커가 없으므로, 이 예외를 적용하지 않는다. 라인 웹툰 환경 요청에서는 디자인 기준 이미지 다음에 04 라인 마감, 광역 장면이면 13 공간감, 그 다음 실제 위험과 직접 맞는 14~17 순으로 예산을 배정한다. 축소하면 요구사항 확인서에 실제 사용할 앵커, 제외한 앵커, 각 제외 사유를 기록한다.

## 제공 이미지 보존과 기능성 예외

제공 이미지 그림체 보존은 제공 이미지의 디자인과 그림체를 함께 기준으로 삼는다. 사용자가 정식 스타일 변환을 명시한 경우에만 제공 이미지를 디자인 기준으로 유지하고 선택 정식 스타일을 적용한다.

반실사 포트레이트의 신규 전신·흉상은 정식 스타일 호출을 사용한다. 캐릭터 레퍼런스 V1·V2와 세션 하이라이트의 신규 생성 또는 명시적 스타일 변환은 중앙 호출 규칙을 사용한다. 풍경은 기본적으로 `6. 풍경 생성/라이브러리/풍경 앵커 호출 규칙.md`의 기존 전용 05~09 환경 앵커를 사용한다. 단, 마스터가 `라인 웹툰`을 명시적으로 선택한 풍경은 정식 라인 웹툰 환경 모드로 판정하고 `../견본/라인 웹툰/`의 04 + 13~17 최소 조합과 라인 웹툰 고정 영어 그림체 블록을 사용하며 공통 붓터치 마감은 적용하지 않는다. 이 경우 기존 풍경 05~09와 라인 웹툰 13~17을 자동 혼합하지 않는다. 배틀맵·게임 아이콘·월드 지도는 정식 스타일 앵커 자동 적용 금지의 기능성 예외다. 배틀맵과 게임 아이콘은 라인 웹툰 01~17 전체와 고정 영어 그림체 블록을 자동 적용하지 않으며, 해당 기능의 판독성 계약과 양립하는 표면 언어만 설명형으로 반영한다. 월드 지도도 라인 웹툰 01~17과 고정 영어 그림체 블록을 자동 적용하지 않고, 양피지 카토그래피·해안선·지형·수계·라벨·바다 여백 계약을 우선하며 카토그래피와 양립하는 그래픽 속성만 설명형으로 반영한다.

## 앵커 콘텐츠 복제 금지

모든 정식 스타일 앵커는 스타일 역할만 소유한다. 앵커의 인물 정체성·성별·종족·얼굴 생김새·헤어스타일·의상·색상·포즈·표정·카메라·배경·장면 구성은 참조하거나 복제하지 않는다. 제공 이미지가 있는 경우에도 앵커는 그림체와 역할만 담당하고, 제공 이미지는 정체성과 디자인 기준을 담당한다.

## 요구사항 확인서 기록

정식 스타일을 적용하는 요구사항 확인서에는 그림체 적용 방식, 선택 정식 스타일, 디자인 기준 이미지, 산출물 구도 분류, 스타일별 전체 활성 앵커, 실제 사용할 앵커, 참조 예산 때문에 제외한 앵커와 사유, 앵커 실제 픽셀 확인 여부, 고정 영어 그림체 블록 원문 적용 여부, 공통 고정 영어 마감 블록의 적용 또는 미적용 여부와 그 근거를 기록한다.
