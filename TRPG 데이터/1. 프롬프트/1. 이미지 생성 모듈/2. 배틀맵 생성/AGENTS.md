# 2. 배틀맵 생성 AGENTS

## 역할

탑뷰 전투용 배틀맵 생성 기능을 담당한다.

## 읽기 순서

1. 상위 `../AGENTS.md`
2. 상위 `../0. 이미지 생성 모듈 마스터 프롬프트.md`
3. `0. 배틀맵 생성 마스터 프롬프트.md`
4. `../공통/1. 이미지 생성 공통 승인 절차.md`
5. `1. 배틀맵 공통 지침.md`
6. `2. 격자 및 칸 수 규칙.md`
7. `3. 지형 표현 규칙.md`
8. `4. 실내 배틀맵.md` 또는 `5. 실외 배틀맵.md`

상위 모듈의 공통 붓터치 마감 적용 대상·자동 예외와 이미지 승인 하드 게이트를 먼저 판정한다. true top-down 배틀맵은 공통 붓터치 마감의 자동 적용 예외다.

## 그림체 적용 경계

- 그림체 적용 방식은 사용자 지정 스타일·기능성 예외다.
- 정식 스타일 앵커는 종류를 불문하고 자동으로 불러오지 않는다. `라인 웹툰`의 01~17 인물·형태·환경 앵커도 배틀맵에는 자동 적용하지 않는다.
- true top-down 시점, 이동 가능 영역, 엄폐물, 통로, 고저차, 격자/칸 수 등 기능 전용 판독성·시점·레이아웃 계약이 모든 스타일 계약보다 우선한다.
- 사용자가 `라인 웹툰풍 배틀맵`처럼 스타일을 명시해도 `정식 스타일 적용`으로 전환하지 않고 `사용자 지정 스타일·기능성 예외`를 유지한다. 이때 선명한 구조선, 평면 색 분리, 제한된 셀식 명암처럼 기능 계약과 양립하는 표면 언어만 설명형 스타일 요소로 반영하고, 라인 웹툰 고정 영어 블록이나 01~17 앵커를 자동 삽입하지 않는다.
- 사용자가 특정 스타일 앵커 이미지를 직접 참조하라고 명시한 경우에만 기능 계약과 충돌하지 않는 범위에서 개별 참조를 검토하고 요구사항 확인서에 공개한다.
- 실제 예외 판정은 `../라이브러리/스타일/정식 스타일 호출 규칙.md`를 따른다.

## 핵심 계약

- 플레이 가독성 우선
- 탑뷰 유지
- 격자/칸 수 요구가 있으면 반드시 반영
- 이미지 생성은 공통 승인 절차를 적용하고 마스터의 명시적 승인을 받은 뒤에만 실행한다.

## 공용 맵 저장

- 확정 배틀맵은 `11. 맵/<환경>/`에 `<map_code>_<map_title>_맵.webp`로 저장한다.
- 먼저 같은 공간의 `map_uuid`와 기존 자산을 찾고, 새 공간일 때만 새 공용 맵 문서와 UUID를 만든다.
- 별도 그리드 이미지는 만들거나 저장하지 않는다.
