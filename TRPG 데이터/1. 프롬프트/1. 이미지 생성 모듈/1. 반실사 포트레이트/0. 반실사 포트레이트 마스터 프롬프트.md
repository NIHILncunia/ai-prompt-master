# 반실사 포트레이트 마스터 프롬프트

## 목적

단일 대상의 포트레이트를 선택된 스타일 계약에 따라 제작한다. 기본 스타일은 `붓터치 반실사`이며, 사용자가 `애니 페인팅` 또는 `라인 웹툰`을 선택하면 해당 정식 스타일을 적용한다. 과거 표현 `세미리얼 애니 페인팅`은 레거시 별칭으로만 받아들인다. 전신 확정본 또는 사용자 업로드 이미지를 기준으로 동일 개체의 완성형 VTT 토큰을 생성한다.

## 스타일 선택과 별칭

- 별도 스타일 지정이 없으면 `../라이브러리/스타일/붓터치 반실사.md`를 기본 스타일로 사용한다.
- `애니 페인팅`과 `라인 웹툰`은 정식 스타일명이다. 과거 표현 `세미리얼 애니 페인팅`은 레거시 별칭으로만 받아들여 `애니 페인팅`으로 정규화한다.
- `애니 페인팅 포트 준비` 계열 직접 호출은 `../라이브러리/스타일/애니 페인팅.md`, `라인 웹툰 포트 준비` 계열 직접 호출은 `../라이브러리/스타일/라인 웹툰.md`를 선택한다.
- 직접 준비 호출이 아니더라도 요청 본문에 `애니 페인팅`, `세미리얼 애니 페인팅`, `라인 웹툰` 또는 해당 스타일로의 전환·재생성·리파인이 화풍 지시로 포함되면 해당 정식 스타일을 선택한다.
- 선택 스타일은 사용자가 다른 스타일을 명시하기 전까지 해당 포트레이트 작업의 전신·흉상에 유지한다.
- `애니 페인팅`, `붓터치 반실사`, `라인 웹툰` 모두 먼저 `../라이브러리/스타일/정식 스타일 호출 규칙.md`에 그림체 적용 방식과 산출물 구도 분류를 전달하고, 반환된 앵커 조합을 사용한다.
- 신규 얼굴·흉상·반신·전신의 실제 조합과 참조 예산 축소는 중앙 호출 규칙이 선택 스타일별로 결정한다. 라인 웹툰은 정식 01~09 인물 앵커와 필요한 경우 10~12 전문 체형 참고를 사용한다.
- 최종 영어 프롬프트 확정 전에 중앙 호출 규칙이 반환한 앵커의 실제 이미지 픽셀을 확인한다.
- 앵커 로딩이 완료되지 않으면 최종 영어 프롬프트를 확정하거나 생성 승인 단계로 넘어가지 않는다.
- 기존 이미지를 정식 스타일로 변환하는 요청에서는 원본의 캐릭터 디자인을 기준으로 보존하되 원본 그림체는 보존 대상에서 제외하고 선택 스타일로 재해석한다.
- 정식 스타일을 적용하는 최종 영어 프롬프트에는 해당 스타일의 고정 영어 그림체 블록을 문장 변경 없이 넣는다. 공통 고정 영어 마감 블록은 스타일 계약이 적용을 선언한 경우에만 넣으며, 라인 웹툰에는 삽입하지 않는다.
- 요구사항 확인서와 최종 영어 프롬프트 초안은 `../공통/6. 이미지 생성 프롬프트 점검 및 교정 지침.md`의 P01~P10을 통과한 뒤에만 공개·승인한다.
- 완성형 VTT 토큰은 캐릭터 본체를 재생성하지 않으므로 기준 이미지의 기존 스타일을 그대로 사용하며 새 스타일 변환을 수행하지 않는다.

## 고정 산출물 계약

```text
인물·NPC·PC·몬스터 기본 세트
전신 9:16 1장
→ 전신 확정 및 저장
→ 확정 전신 기반 초상화 9:16 1장
→ 초상화 확정 및 저장
→ 확정 전신 기반 완성형 VTT 토큰 1:1 1장
→ 토큰 확정 및 저장
→ 전신·초상화·토큰 3종 Drive 저장 검증

사용자 업로드 이미지
→ 요청 범위에 따라 전신 정본 채택 또는 직접 토큰 파생
→ 인물 계열 표준 세트 작업이면 부족한 전신·초상화·토큰을 순차 보완
```

- 업로드 이미지 기반 토큰은 전신 생성·확정을 선행하지 않는 직접 경로다.
- 모든 완성형 토큰은 캐릭터를 포함한 최종 WebP 한 장이며, 프레임은 자동 구성 요소다.
- 토큰 계열은 유형·설정·역할·위계·기준 토큰 시각 언어를 근거로 자동 선택한다.
- 일반·엘리트·보스는 프레임 본체 두께를 같게 유지하고 장식 밀도·보스 표적성으로 구분한다.
- 보스·표적 정보가 없으면 일반 토큰으로 처리한다.
- 캐릭터 본체는 새로 그리거나 재생성하지 않는다.
- **인물·NPC·PC·몬스터 이미지 작업의 기본 종료 지점은 생성이 아니라 Google Drive 저장이다.** 마스터가 저장 제외나 로컬 산출물만을 명시하지 않는 한, 생성·수정 → 검수/확정 → 최초 업로드 또는 교체 업로드까지 이어서 수행해야 완료로 본다.
- 인물 계열의 표준 이미지 세트는 `<액터>.webp` 전신, `<액터> 초상화.webp`, `<액터> 토큰.webp`의 **3종 세트**다. 마스터가 특정 산출물만 요청하거나 일부를 제외한 경우에만 범위를 축소한다. 각 이미지 생성 호출의 승인 상태는 기존 공통 승인 절차대로 서로 독립적으로 사용한다.
- 저장 분류는 설정상 역할을 우선한다. NPC는 `TRPG 데이터/6. NPC/<대상>/`, PC는 `TRPG 데이터/7. PC/<대상>/`, 몬스터는 `TRPG 데이터/10. 몬스터/<유형>/<대상>/`에 저장한다. 용종은 `TRPG 데이터/14. 용종/<유형>/<대상>/`에 두되 몬스터 자산 규칙을 그대로 따른다.
- 신규 정본이 없으면 최초 업로드한다. 같은 액터의 기존 정본이 있으면 **기존 Drive 파일 ID를 유지한 교체 업로드**를 기본으로 한다. 이미지 작업 안에서 마스터가 결과를 `픽스`, `확정`, `사용`, 다음 파생 산출물 진행 등으로 채택한 경우 저장·교체를 위해 별도의 `업로드하자` 지시를 다시 요구하지 않는다.
- NPC/PC/몬스터 분류가 자료만으로 판정되지 않을 때에만 저장 위치를 확인하며, 외형만으로 임의 분류하지 않는다.

## 파일명 규칙

- 전신 확정본: `<액터>.webp`
- 초상화: `<액터> 초상화.webp`
- 완성형 VTT 토큰: `<액터> 토큰.webp`
- 접미가 없는 기본 액터 파일명은 전신을 뜻한다. 전신 이미지에는 `전신`, `포트레이트 전신` 같은 별도 접미사를 붙이지 않는다.

## 기본 흐름

1. 대상 분류와 종족·신체 구조를 확인한다.
2. 선택 스타일과 산출물 구도를 중앙 호출 규칙에 전달하고, 반환된 앵커 조합을 실제 이미지로 로드한다.
3. 기준 이미지를 판정한다. 확정 전신이 있으면 전신을, 사용자가 업로드한 이미지를 토큰 기준으로 요청하면 업로드 이미지를 사용한다.
4. 유형·설정·역할·위계와 기준 토큰을 근거로 계열·등급을 자동 판정한다.
5. 완성형 토큰 요구사항 확인서와 최종 영어 프롬프트를 제시한다.
6. 승인 후 캐릭터는 재생성하지 않고 크롭·배치·마스킹·미세 보정·프레임 합성으로 1:1 VTT 토큰을 생성한다.
7. 캐릭터 포함 여부, 투명도, 원형 프레임, 계열·등급 일관성을 검수한다.
8. 인물·NPC·PC·몬스터 작업에서 결과가 채택되면 해당 산출물을 분류별 Drive 정본에 최초 업로드 또는 동일 ID 교체 업로드한다.
9. 기본 세트 범위라면 다음 미완료 산출물의 승인 절차로 이어가고, 3종 모두 저장되었는지 재검증한 뒤 종료한다.
