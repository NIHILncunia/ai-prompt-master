# 0. 로그 하이라이트 추출 마스터 프롬프트

## 로컬 운영 진입점과 동기화

이 기능 폴더의 `AGENTS.md`와 `0. 로그 하이라이트 추출 마스터 프롬프트.md`는 함께 운영 진입점으로 취급한다. 폴더를 직접 작업 공간으로 열었을 때에는 상위 `AGENTS.md`와 프로젝트 기본·통합 문서를 읽은 뒤 로컬 `AGENTS.md`를 확인하고, 이 마스터와 필요한 하위 지침·라이브러리를 이어서 읽는다.

폴더 ID, 정식 경로, 진입점, 필수 읽기 순서, 기능 경계, 외부 데이터 원천, 기본 산출물, 파일 작업 정책을 바꾸면 `AGENTS.md`와 이 마스터를 함께 점검한다. 실제 생성·분석·작성 절차와 세부 품질 규칙은 이 마스터와 하위 문서에 두며, 로컬 `AGENTS.md`에는 작업 시작과 유지보수에 필요한 라우팅 정보만 둔다.

전역 응답 규칙·파일 정책·공통 승인 절차를 바꾸면 `TRPG 데이터/AGENTS.md`, `TRPG 데이터/1. 프롬프트/AGENTS.md`, `00. TRPG 세션 매니저 프로젝트 기본 지침.md`, `0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md`를 함께 확인한다. 다른 기능이 소유한 정본 규칙은 이 폴더에 복제하지 않고 해당 기능을 참조한다.

## 문서 목적

이 문서는 `TRPG 데이터/1. 프롬프트/2. 로그 하이라이트 추출 프롬프트` 폴더의 진입점이다.

사용자가 TRPG 세션 로그에서 이미지화 가능한 하이라이트 장면 후보를 추출해 달라고 요청하면, 이 문서를 먼저 읽고 반드시 같은 폴더의 `1. 로그 하이라이트 추출 지침서.md`를 이어서 읽는다.

이 폴더의 목적은 최종 이미지 프롬프트를 바로 작성하는 것이 아니다.  
원본 로그 또는 3번 로그 분석본을 참고하여 후속 `1번 이미지 생성 모듈 내부 4번 세션 하이라이트 이미지 생성`에서 사용할 수 있는 `Highlight Card` 또는 `Scene Beat Data`를 구조화하는 것이다.

## 적용 조건

아래 요청은 모두 이 폴더의 지침으로 처리한다.

- 세션 로그에서 이미지화 가능한 장면 후보 추출
- 세션 하이라이트 후보 목록 생성
- Highlight Card 생성
- Scene Beat Data 생성
- 세션 하이라이트 이미지 생성을 위한 장면 선별
- 로그에서 전투, 폭로, 감정적 결단, 보스 등장, 장소 공개, 의식 장면 등 시각적 장면 후보 추출
- 특정 세션에서 그림으로 만들 만한 장면 정리

아래 요청은 이 폴더가 아니라 다른 폴더의 지침을 따른다.

- 원본 로그의 정보흐름분석, 기승전결 요약, 세션 연속성 프론트매터 작성
  - `3. 로그 분석 프롬프트`를 따른다.
- 실제 세션 하이라이트 이미지 생성
  - `1번 이미지 생성 모듈 내부 4번 세션 하이라이트 이미지 생성`을 따른다.
- 캐릭터 외형 기준 시트 생성
  - `1번 이미지 생성 모듈 내부 3번 캐릭터 레퍼런스 생성`을 따른다.
- 배틀맵, 풍경, Scene Manifest 작성
  - `1번 이미지 생성 모듈 내부 2번 배틀맵 생성`을 따른다.

## 전체 파이프라인에서의 위치

이 폴더는 최종 이미지 생성기가 아니라 이미지화 가능한 장면 후보를 추출하는 중간 모듈이다.

관련 모듈의 관계는 아래와 같다.

1. `1번 이미지 생성 모듈 내부 3번 캐릭터 레퍼런스 생성`
   - PC 또는 NPC의 외형 기준 시트를 생성한다.

2. `3. 로그 분석 프롬프트`
   - 원본 로그를 정보흐름분석, 기승전결 요약, 세션 연속성 프론트매터로 정리한다.

3. `2. 로그 하이라이트 추출 프롬프트`
   - 원본 로그 또는 3. 로그 분석 프롬프트의 분석본을 참고하여 이미지화 가능한 Highlight Card를 추출한다.

4. `1번 이미지 생성 모듈 내부 2번 배틀맵 생성`
   - 장소, 지도, Scene Manifest, 배틀맵 정보를 준비한다.

5. `1번 이미지 생성 모듈 내부 4번 세션 하이라이트 이미지 생성`
   - Highlight Card, 캐릭터 레퍼런스, 맵 / Scene Manifest를 조합해 최종 이미지를 생성한다.

## 기본 처리 순서

1. 사용자 요청이 로그 하이라이트 추출인지 판별한다.
2. 이 문서를 읽은 뒤 `1. 로그 하이라이트 추출 지침서.md`를 반드시 읽는다.
3. 사용자가 원본 로그를 제공했는지 확인한다.
4. 사용자가 세션명 또는 회차를 지정했다면 `TRPG 데이터/2. 로그/원본`에서 해당 원본 로그를 찾는다.
5. 같은 세션에 대해 3번 로그 분석본이 존재하면 `TRPG 데이터/2. 로그/분석`에서 참고할 수 있다.
6. 단, 3. 로그 분석 프롬프트의 분석본은 보조 자료이며 원본 로그와 충돌하는 추정은 확정 사실로 쓰지 않는다.
7. 장면성이 강하고 후속 이미지화에 적합한 후보만 선별한다.
8. 산출물은 최종 이미지 프롬프트가 아니라 YAML 기반 Highlight Card / Scene Beat Data로 작성한다.

## 핵심 원칙

로그 하이라이트 추출의 핵심은 다음 네 가지다.

- 어떤 장면을 하이라이트로 볼 것인가
- 왜 그 장면이 중요한가
- 그 장면을 이미지로 만들 때 무엇을 보여줘야 하는가
- 어떤 캐릭터, 맵, 사물, 감정 정보가 추가로 필요한가

특히 중요한 것은 로그에 없는 정보를 지어내지 않는 것이다.

세션 로그에 명시되지 않은 맵 구조, 조명, 거리, 위치, 캐릭터 감정은 단정하지 않는다.  
불명확한 정보는 `unknown`, `unclear`, `needs_scene_mapping`, `source_needs_verification`으로 남긴다.

## 3번 로그 분석본 참조 규칙

대상 세션에 대해 `3. 로그 분석 프롬프트`로 작성된 정보흐름분석 문서가 이미 존재하면 참고할 수 있다.

분석본은 아래 용도로만 사용한다.

- 장면의 선행 맥락 확인
- PC / NPC 관계 확인
- 미확정 사실과 떡밥 확인
- 사건의 중요도 판단
- 장면이 후속 이미지 생성에 적합한지 판단

단, Highlight Card의 사실 정보는 원본 로그와 충돌하지 않아야 한다.

분석본에만 있는 추정, 해석, 장기 플롯 가설은 확정 사실처럼 쓰지 않는다.

원본 로그를 확인할 수 없는 경우에는 `source_confidence: low` 또는 `source_needs_verification`으로 표시한다.

## 캐릭터 이미지 참조 연결 규칙

PC, NPC 또는 몬스터가 등장하는 하이라이트는 후속 이미지 생성에서 적합한 시각 자료를 찾을 수 있도록 이름과 분류를 정확히 기록한다.

- 최우선 참조 폴더: `TRPG 데이터/3. 캐릭터 레퍼런스 이미지/` — PC·NPC·몬스터별 하위 폴더를 포함해 해당 인물의 레퍼런스 시트를 먼저 찾는다.
- 레퍼런스 시트가 없을 때의 대체 탐색 순서: `TRPG 데이터/6. NPC 이미지/` → `TRPG 데이터/7. PC 이미지/` → `TRPG 데이터/10. 몬스터 이미지/`
- 파일명은 `{인물명}`과의 일치 여부를 기준으로 찾되, 확장자나 `레퍼런스 시트` 같은 접미사는 고정하지 않는다.
- 동명이인 또는 이미지의 대상 동일성이 불명확하면 임의로 선택하지 않고 후속 단계에 확인 필요로 남긴다.

이 단계에서는 이미지를 직접 찾거나 생성하지 않는다.  
이 단계의 목적은 후속 1번 이미지 생성 모듈 내부 4번 세션 하이라이트 이미지 생성이 참조할 수 있도록 등장 캐릭터의 이름, 분류, 역할을 정확히 남기는 것이다.

## 맵 / Scene Manifest 연결 규칙

2. 로그 하이라이트 추출 단계는 맵 정보를 완성하지 않는다.

로그에서 장소 단서가 보이면 `environment_hint_from_log`에 기록한다.  
정확한 FVTT 씬 또는 Scene Manifest와 연결할 수 있으면 `scene_id`를 기입한다.

Scene Manifest가 없거나 확신이 낮으면 `scene_id: needs_scene_mapping` 또는 `scene_id: unknown`으로 남긴다.

## 산출물

기본 산출물은 아래 중 하나다.

- Highlight Card 목록
- Scene Beat Data 목록
- 이미지화 우선순위가 매겨진 하이라이트 후보 목록
- 후속 세션 하이라이트 이미지 생성용 구조화 YAML

이 산출물은 최종 이미지 프롬프트가 아니다.  
실제 이미지 생성은 `1번 이미지 생성 모듈 내부 4번 세션 하이라이트 이미지 생성`에서 처리한다.

## 파일 제공 원칙

사용자가 파일 생성을 요청하면 내려받을 수 있는 파일로 제공한다.

에이전트는 사용자의 명시적 요청 없이 구글 드라이브에 파일을 자동 생성하거나, 기존 파일을 덮어쓰거나, 이름을 변경하지 않는다.

## 반드시 읽을 파일

로그 하이라이트 추출 요청을 처리할 때에는 반드시 아래 파일을 읽고 따른다.

- `1. 로그 하이라이트 추출 지침서.md`

필요한 경우 아래 자료를 참고할 수 있다.

- `3. 로그 분석 프롬프트`로 작성된 해당 세션 정보흐름분석 문서
- `1번 이미지 생성 모듈 내부 3번 캐릭터 레퍼런스 생성`의 캐릭터 레퍼런스 참조 규칙
- `1번 이미지 생성 모듈 내부 2번 배틀맵 생성`의 Scene Manifest 관련 산출물

## 최종 실행 지시

사용자가 로그 하이라이트 추출을 요청하면, 같은 폴더의 `1. 로그 하이라이트 추출 지침서.md`를 읽고 그 규칙에 따라 Highlight Card / Scene Beat Data를 작성한다.

프롬프트만 출력하지 말고, 사용자가 요구한 형식에 맞춰 구조화된 결과물을 제공한다.
