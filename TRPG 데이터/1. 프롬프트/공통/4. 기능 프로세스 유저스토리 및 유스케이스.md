# 기능 프로세스 유저스토리 및 유스케이스

## 1. 목적과 적용 범위

이 문서는 TRPG 세션 매니저의 프롬프트 흐름이 실제 운영 규칙대로 작동하는지 검증하기 위한 공통 유저스토리와 유스케이스 정본이다.

대상은 다음 기능 전체다.

1. 이미지 생성 모듈과 내부 8개 기능
2. 로그 하이라이트 추출
3. 로그 분석
4. 룰북 관련 요청
5. 설정 관련 요청
6. Foundry VTT 관련 요청
7. 창작 지원 제작기
8. 세션 제작
9. 집필 데이터 체크
10. 기능 간 복합 파이프라인
11. 전역 라우팅, Drive 저장, `다음`, 자료 충돌과 누락 처리

이 문서는 실제 산출물을 생성하는 지침이 아니다. 기능의 입력·라우팅·자료 탐색·승인·저장·후속 전환이 올바른지 점검할 때 사용한다.

## 2. 고정 전제

모든 유스케이스는 다음 전역 정책을 전제로 판정한다.

- 웹 GPT의 프로젝트 최상위 정본은 Google Drive `TRPG 데이터` 루트의 `PROJECT AGENTS YYYY MMDD.md` 형식 문서 중 가장 최신의 유효한 날짜형 파일이다.
- 실질 작업을 시작하기 전에 선택한 프로젝트 에이전트의 기준일을 `프로젝트 에이전트 기준일: YYYY-MM-DD (PROJECT AGENTS YYYY MMDD.md)` 형식으로 명시한다.
- 날짜 없는 `PROJECT AGENTS.md`, 프로젝트 소스 사본, 오래된 로컬 파일, 캐시 ID는 최신 날짜형 Drive 정본과 실제 폴더 구조보다 우선하지 않는다.
- 지속 보관 데이터의 생성·수정은 생성·수정 직후 Drive 직접 생성·업로드·갱신을 먼저 시도한다. 이후 검수·확정으로 내용이 바뀌면 같은 정본 파일을 다시 갱신한다.
- Drive 직접 반영이 실패할 때만 같은 상대 경로와 원래 파일명을 보존한 ZIP을 제공한다.
- 비데이터성 채팅 응답·준비 안내·검토 의견은 자동 저장하지 않으며, 마스터가 업로드·저장·반영을 요청했을 때 Drive 직접 업로드를 시도한다.
- `다음`은 언제나 직전에 제시된 현재 단계의 결과를 확정하고 다음 정의된 프로세스로 즉시 진행하라는 뜻이다.
- `다음`은 필수 절차를 생략하지 않는다. 직전에 확정할 결과가 없다면 현재 절차의 다음 필수 단계로 진행한다.
- 새 기능 또는 점검 흐름의 첫 요청은 기능·절차 안내와 `시작할까요?` 확인을 먼저 제시한다. 그 안내 뒤의 `다음`·`시작`·`진행`은 표시된 범위를 확정하고 절차를 개시한다.
- 근거 없이 판정할 수 없는 대상명·저장 경로·공개 수준은 발명하지 않는다. 가능한 범위까지 진행하고 정확한 차단 지점만 표시한다.

## 3. 표기와 판정 방법

- **유저스토리**는 마스터가 얻고자 하는 사용자 가치다.
- **유스케이스**는 유저스토리를 만족시키기 위한 하나의 검증 가능한 처리 경로다.
- 각 유스케이스는 사전조건, 사용자 입력, 시스템 처리, 기대 결과, 금지 동작으로 검증한다.
- P0는 기능을 사용할 수 없게 만드는 핵심 경로, P1은 주요 분기, P2는 희귀하지만 회귀 위험이 큰 예외다.
- 동일한 의도를 가진 자연어 표현은 별도 케이스가 아니라 같은 유스케이스의 입력 변형으로 처리한다.

## 5. 이미지 생성 유저스토리와 유스케이스

### US-I01 — 검토 가능한 이미지 생성과 후속 산출물

마스터로서, 이미지 요청마다 요구사항과 최종 프롬프트를 확인하고, 전신·초상화·토큰·변형을 독립된 산출물로 제어하고 싶다.

3. 이미지의 확인·생성·재승인 상태와 모든 기능의 `다음` 전이가 일관됐다.
4. 지속 보관 데이터는 Drive 직접 저장을 먼저 시도했고, 결과를 확인했다.
5. Drive 실패 시에만 경로와 파일명을 보존한 ZIP을 제공했다.
6. 근거 없는 사실·경로·공개 수준·외형·공식 수치를 발명하지 않았다.
7. SESSION PROGRESS에 실제 완료·차단 지점·다음 작업을 정확히 기록했다.
8. 정식 스타일 요청은 중앙 스타일 호출 규칙·실제 앵커 픽셀·스타일별 마감 정책과 일치하고, 기능성 예외는 정식 스타일 자산을 자동 호출하지 않았다.
9. 신규 스타일 개발 자산은 `TRPG 데이터/20. 그림 스타일 분석/<스타일명>/` 한 곳에만 존재하고 스타일 최상위 폴더에는 `dev_`가 없으며, 정식 승격 전 일반 런타임과 격리되고 승격은 체크리스트 통과와 마스터 확정 뒤 복사·정규화 방식으로 수행됐다.
