## 역할

- 그 밖의 이미지 생성·수정·재구성 요청에서 공용 태그나 종족 자료가 필요한 경우

## 산출물 계약 책임 분리

공통 폴더는 공용 데이터 접근 절차를 관리한다. 승인 상태는 이미지 생성 모듈 공통 폴더의 승인 정본이 관리한다.

출력 수, 단일 뷰·다중 뷰, 스프라이트, 시트 구성 여부는 각 기능 마스터가 결정한다. 공통 규칙을 이유로 레퍼런스 시트나 아이콘 스프라이트의 고유 레이아웃을 금지하지 않는다.

이미지 모듈 내부 1번 반실사 포트레이트의 전신·초상화 분리는 해당 로컬 마스터와 실행 파일이 정의한다. 공통 승인 절차는 각 모드의 승인을 분리하고 완료 후 승인 상태를 소모하는 역할만 담당한다.

## 프로세스 검증 문서

- 기능 흐름, 유저스토리, 유스케이스, 라우팅, Drive 저장, `다음` 처리, 회귀 점검 요청에서는 `4. 기능 프로세스 유저스토리 및 유스케이스.md`와 `5. 기능 프로세스 검증 및 교정 지침.md`을 함께 읽는다.
- 9번 집필 데이터 체크에서는 기능 폴더의 `AGENTS.md`와 마스터 프롬프트, `1. 과제 호출 및 원문 기록 지침.md`, `2. 문체 분석 및 프로필 갱신 지침.md`, `3. 과제 데이터베이스 선택 지침.md`을 읽는다. 장르·주제·장면 소재 데이터, 과제 이력, 원문, 문체 프로필은 `TRPG 데이터/19. 집필 데이터`를 정본으로 한다.
- `프로세스 점검.`은 점검을 곧바로 시작하는 명령이 아니다. 먼저 전역, 이미지 내부 8개 기능, 로그, 룰북, 설정, FVTT, 창작 지원, 세션 제작, 집필 데이터 체크, 복합 파이프라인의 점검 흐름을 전부 나열하고 전체 P0 점검을 시작할지 묻는다. 대상·UC ID가 붙으면 해당 범위와 의존 흐름만 안내한 뒤 시작 여부를 묻는다.
- 새 기능·점검 흐름의 첫 응답은 기능명, 목적·대표 산출물, 주요 단계, 필요한 입력·선행 자료, 연결 기능을 안내하고 `시작할까요?`를 물어야 한다. 이미 시작한 흐름 안의 실행 명령에는 이 안내를 반복하지 않는다.
- 이 문서들은 일반 기능 실행의 세부 산출물 계약을 대체하지 않는다. 실제 기능 규칙은 선택된 기능의 AGENTS·마스터·하위 지침이 소유한다.
- 검증에서 전역 정책과 하위 기능 문서가 충돌하면, Drive 최신 정본의 전역 `최우선 실행·저장·진행 정책`을 우선하고 영향 진입 문서를 함께 교정한다.

## 동기화 원칙

- 이미지 승인 정본의 위치는 `../1. 이미지 생성 모듈/공통/1. 이미지 생성 공통 승인 절차.md`다. 이 폴더의 동명 문서는 기존 참조를 위한 안내 문서이며 활성 정책을 소유하지 않는다.
- 승인 상태·첫 응답·재승인·공통 확인 양식이 바뀌면 이미지 생성 모듈 공통 문서와 모든 적용 기능의 `AGENTS.md`와 마스터 프롬프트를 점검한다.
- 기능별 화풍·비율·구도·산출 수량은 각 기능이 소유한다. 공통 폴더에 세부 규칙을 중복 정의하지 않는다.
- 전역 응답 규칙이나 파일 정책이 바뀌면 TRPG 데이터 루트·프롬프트 루트 `AGENTS.md`, 프로젝트 기본 지침, 통합 마스터도 함께 갱신한다.

## 파일 작업 원칙

- 지속 보관 데이터의 생성·수정은 Drive 직접 생성·업로드·갱신을 먼저 시도한다.
- 준비 안내·조회·검토처럼 비데이터 결과는 자동 저장하지 않으며, 마스터가 업로드·저장·반영을 요청하면 Drive 직접 업로드를 먼저 시도한다.
- Drive 직접 반영이 실패했을 때만 원래 적용 경로와 파일명을 보존한 ZIP을 제공한다.
