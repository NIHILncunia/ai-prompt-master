# 몬스터 스탯블록 출력 템플릿

## 출력 형식

- 모든 스탯블록은 반드시 `text` 타입의 코드블럭 안에 담아서 제공합니다.
- 코드블럭 시작은 반드시 ```` ```text ```` 형식으로 작성합니다.
- 코드블럭 시작을 단순한 ```` ``` ```` 형식으로 작성하지 않습니다.
- 아래의 스탯블록 템플릿 양식을 줄바꿈과 띄어쓰기까지 정확하게 지켜서 작성합니다.
- 각 데이터별로 3단계 제목을 포함합니다.
- 창작/조정 데이터 생성 시 출력 순서는 반드시 아래와 같습니다.
  1. 참고 몬스터 명시
  2. `### 원본 데이터`
  3. 원본 몬스터 스탯블록 `text` 코드블럭
  4. `### 메인 스탯블록`
  5. 창작/조정 몬스터의 영문 스탯블록과 LOCALIZATION JSON을 합친 Import Package `text` 코드블럭
  6. `### 한국어 번역`
  7. 능력 및 액션의 일반 한국어 번역 `text` 코드블럭
  8. 미확인 항목이 있을 때만 `### 적용 확인`에 해당 항목과 확인할 내용을 기록
- 공식 데이터만 출력하는 경우에는 `### 원본 데이터` 제목을 쓰지 않고, 요청받은 몬스터 이름을 3단계 제목으로 사용한 뒤 같은 Import Package와 `### 한국어 번역`을 제공합니다. 단순 규칙 조회나 마스터가 다른 출력 형식을 명시한 요청은 그 범위를 따릅니다.
- 한 패키지는 몬스터 한 마리만 담습니다. `===STATBLOCK===`와 `===LOCALIZATION===`는 각각 한 번, 독립된 줄에 배치합니다. 원본 데이터와 일반 번역·출처·적용 확인은 패키지 밖에 둡니다.
- 원본 데이터 블록과 STATBLOCK 영역에서 한글은 몬스터 이름에만 허용합니다. LOCALIZATION 영역의 한글 이름·설명에는 이 제한을 적용하지 않습니다.
- 원본 데이터와 STATBLOCK 영역의 Size, Type, Alignment, 수치, 능력명, 설명, 피해 유형, 상태 이상, 감각, 언어는 영어로 작성합니다.
- 코드블럭 내부에서는 마크다운 표를 사용하지 않습니다.
- 값이 없는 필드는 `Damage Resistances -`처럼 필드명 뒤에 `-`를 씁니다. 아래 대괄호 자리표시는 실제 값으로 교체하고 `Melee/Ranged`, `reach/range` 같은 선택지는 해당 공격에 맞는 하나로 정리합니다.
- `TRAITS`와 `ACTIONS`는 항상 포함합니다.
- `BONUS ACTIONS`와 `REACTIONS`는 해당 능력이 존재할 때만 포함합니다.
- `LEGENDARY ACTIONS`와 `MYTHIC ACTIONS`는 해당 몬스터에게 존재할 때만 포함합니다.
- 스탯블록 출력이 끝난 후, 그 아래에 별도의 `text` 코드블럭을 생성하여 각 Trait, Action, Bonus Action, Reaction, Legendary Action, Mythic Action에 대한 한국어 번역을 제공합니다.
- 창작/조정 데이터의 한국어 번역은 메인 스탯블록의 능력 및 액션을 대상으로 합니다.
- 한국어 번역의 능력명과 행동명은 반드시 `한글명 (English Name)` 형식으로 작성합니다.
- FVTT용 한글 이름·설명은 LOCALIZATION으로 제공합니다. 일반 번역 아래 별도 FVTT 번역 블록을 중복 출력하지 않습니다.
- LOCALIZATION의 형식·키 매칭·인라인 문법·예외 처리·검증 범위는 [몬스터 스탯블록 지침](<../2. 몬스터 스탯블록 지침.md>)을 따릅니다.
- 원본 데이터의 번역이 필요한 경우에는 `Original Data Translation` 항목을 별도로 추가합니다.

## 메인 스탯블록 템플릿

아래 블록 전체가 매크로에 넣을 Import Package입니다. 구성을 설명하기 위한 자리표시자 템플릿이며 그대로 임포트하는 시험 데이터가 아닙니다. 능력이 없는 선택 섹션은 STATBLOCK과 LOCALIZATION 양쪽에서 제거하고 JSON 쉼표를 정리합니다. 참조용 기반 몬스터 원본은 이 블록에 넣지 않습니다.

```text
===STATBLOCK===
[Monster Name]
Size Type, Typically Alignment

Armor Class [AC number] ([armor type or natural armor])
Hit Points [HP number] ([Hit Dice + Constitution bonus])
Speed [land speed] ft., [fly/swim/climb speed] ft.

STR DEX CON INT WIS CHA
[score]([modifier]) [score]([modifier]) [score]([modifier]) [score]([modifier]) [score]([modifier]) [score]([modifier])

Saving Throws [ability + total modifier]
Skills [skill + total modifier]
Damage Vulnerabilities [damage type]
Damage Resistances [damage type]
Damage Immunities [damage type]
Condition Immunities [condition]
Senses [sense and range] ft., Passive Perception [number]
Languages [languages]
Challenge [CR number] ([XP number] XP)
Proficiency Bonus +[PB number]

TRAITS
[Trait Name]. [Trait description]

ACTIONS
Multiattack. [Multiattack description]

[Attack Name]. Melee/Ranged Weapon Attack: +[modifier] to hit, reach/range [range] ft., [number] target. Hit: [average damage] ([damage dice + modifier]) [damage type] damage.
[Action Name]. [Action description]

BONUS ACTIONS
[Bonus Action Name]. [Bonus action description]

REACTIONS
[Reaction Name]. [Reaction description]

LEGENDARY ACTIONS
The [monster name] can take [number] legendary actions, choosing from the options below. Only one legendary action option can be used at a time and only at the end of another creature's turn. The [monster name] regains spent legendary actions at the start of its turn.

[Legendary Action Name] (Costs X Actions). [Description]

MYTHIC ACTIONS
If the [monster name]'s [Mythic Trait Name] trait has activated in the last hour, it can use the options below as legendary actions.

[Mythic Action Name] (Costs X Actions). [Description]

===LOCALIZATION===
{
  "actorName": "[최종 한글 몬스터 이름]",
  "items": {
    "[Trait Name]": {
      "name": "[한글 특성명]",
      "description": "[특성 전체의 한글 설명. 기존 인라인 명령과 참조 보존]"
    },
    "Multiattack": {
      "name": "다중공격",
      "description": "[원문의 공격 횟수와 조합을 번역하고 최종 한글 Item 이름으로 참조]"
    },
    "[Attack Name]": {
      "name": "[한글 공격명]",
      "description": "[근접 또는 원거리] 무기 공격: [[/attack]], [원문 도달거리 또는 사거리], [원문 대상]. 명중 시 [[/damage average]] 피해를 줍니다. [추가 효과가 있으면 전체 번역]"
    },
    "[Action Name]": {
      "name": "[한글 행동명]",
      "description": "[행동 전체의 한글 설명. 기존 인라인 명령과 참조 보존]"
    },
    "[Bonus Action Name]": {
      "name": "[한글 추가 행동명]",
      "description": "[추가 행동 전체의 한글 설명. 기존 인라인 명령과 참조 보존]"
    },
    "[Reaction Name]": {
      "name": "[한글 반응 행동명]",
      "description": "[반응 행동 전체의 한글 설명. 기존 인라인 명령과 참조 보존]"
    },
    "[Legendary Action Name]": {
      "name": "[한글 전설 행동명]",
      "description": "[전설 행동의 비용과 전체 한글 설명. 실제 생성 Item 이름과 자동화 확인 필요]"
    },
    "[Mythic Action Name]": {
      "name": "[한글 신화 행동명]",
      "description": "[신화 행동의 조건·비용과 전체 한글 설명. 실제 생성 Item 이름과 자동화 확인 필요]"
    }
  }
}
```

LOCALIZATION의 키는 자리표시자를 실제 생성 Item의 영문 이름으로 교체합니다. 재충전·비용 같은 접미사 처리 결과를 추정하지 않습니다. 전설·신화 행동은 구조상 선택 항목을 보여 주는 것이며 실환경 자동화 검증 완료를 뜻하지 않습니다.

## LOCALIZATION 작성 예시

아래 JSON은 생성 Item 이름이 `Longbow`임을 확인한 단일 공격과 다중공격의 부분 예시입니다. 완성 패키지에서는 해당 몬스터의 모든 번역 대상과 합쳐 `===LOCALIZATION===` 뒤에 넣고, 별도 코드펜스는 넣지 않습니다. 새로운 공식 몬스터 데이터가 아닙니다.

```json
{
  "actorName": "검증용 추적자",
  "items": {
    "Multiattack": {
      "name": "다중공격",
      "description": "검증용 추적자는 [[/item 장궁]]으로 두 번 공격합니다."
    },
    "Longbow": {
      "name": "장궁",
      "description": "원거리 무기 공격: [[/attack]], 사거리 150/600피트, 대상 하나. 명중 시 [[/damage average]] 피해를 줍니다."
    }
  }
}
```

일반 한국어 번역에서는 같은 공격을 `장궁 (Longbow)`으로 표기하고 원문의 공격 보정·피해식·피해 유형을 읽을 수 있게 번역합니다. LOCALIZATION은 Activity를 참조하는 인라인 명령을 사용합니다.

## 전달 전 확인

- 메인 패키지의 두 마커와 JSON을 확인합니다. JSON에는 주석·후행 쉼표·중복 키·추가 코드펜스가 없어야 합니다.
- STATBLOCK의 능력·행동, 일반 번역, LOCALIZATION의 키와 한글 이름을 대조합니다. 템플릿 자리표시자는 모두 실제 내용으로 바꿉니다.
- 기계 데이터는 STATBLOCK에 유지하고 LOCALIZATION에는 이름·설명만 둡니다. `description`은 전체 설명을 대체하므로 조건과 추가 효과를 누락하지 않습니다.
- `[[/item ...]]`의 최종 대상과 기타 기존 명령·UUID를 확인합니다. 새 `[[...]]` 명령, `@...` 롤 데이터 경로와 활동 연결은 6번 FVTT 기능의 `2. 피트 및 아이템 인라인 문법과 변수 사용 가이드.md`에 따라 검증합니다. 미확인 키·미번역 설명·주문 등 미검증 자동화는 패키지 밖의 `### 적용 확인`에 구체적으로 기록합니다.
- 코드블록의 내용을 한 번 복사해 `스탯블록 임포터`에 붙여넣을 수 있는지 확인합니다. 이번 문서의 형식 검증만으로 새 몬스터의 SBI 파싱과 실전 동작까지 검증됐다고 표현하지 않습니다.
