# 몬스터 스탯블록 지침

## 1. 기본 원칙

- 공식 데이터 출력: 사용자가 룰북에 존재하는 스탯블록을 요구할 경우, 확인된 원본 데이터를 기준으로 제공합니다.
- 창작/조정 데이터 생성: 사용자가 룰북에 없는 새로운 스탯블록 생성을 원할 경우, 요구사항에 가장 부합하는 근사치 데이터를 생성합니다.
- 창작/조정 데이터 생성 시 반드시 룰북에 존재하는 기반 몬스터를 참고합니다.
- 창작/조정 데이터 생성 시 사용자에게 어떤 몬스터를 참고했는지 명시하고, 원본 몬스터의 스탯블록도 함께 제공합니다.
- 기반 몬스터의 원본 스탯블록을 확인하지 못한 경우에는 원본 데이터를 임의로 작성하지 않습니다. 이 경우 추가 검색을 진행하거나, 확인 불가 사유를 명시합니다.
- 사용자가 일반 몬스터, 정예 몬스터, 보스 몬스터를 지정하면 아래 명중 보정 최소 기준을 반드시 적용합니다.
  - 일반 몬스터: 명중 보정 +7 이상
  - 정예 몬스터: 명중 보정 +9 이상
  - 보스 몬스터: 명중 보정 +11 이상

## 2. 출력 레이아웃

- 스탯블록의 실제 출력 순서, `text` 코드블록, 필드 구성, 공백, 영문 표기, 한국어 번역 블록은 [템플릿/몬스터 스탯블록 출력 템플릿.md](<템플릿/몬스터 스탯블록 출력 템플릿.md>)를 정확히 따릅니다.
- FVTT 임포트용 스탯블록 레이아웃은 임의로 바꾸지 않습니다.

### Import Package 기본 출력

- 메인 스탯블록은 `===STATBLOCK===` 다음에 SBI용 스탯블록, `===LOCALIZATION===` 다음에 한글화 JSON을 넣은 하나의 `text` 코드블록으로 제공합니다. 마커는 각각 정확히 한 번, 독립된 줄에 이 순서로 씁니다.
- 몬스터 한 마리당 패키지 하나를 작성합니다. 코드블록 전체를 기존 `스탯블록 임포터` 매크로의 입력창에 한 번 붙여넣는 형식입니다. 순수 SBI 입력창에는 STATBLOCK 영역만 사용합니다.
- 창작/조정의 기반 몬스터 원본은 패키지 밖의 별도 블록으로 제공합니다. 실제 임포트 대상인 메인 스탯블록만 패키지에 넣습니다.
- STATBLOCK 영역은 기존 SBI 레이아웃과 영문 필드·능력명·설명·수치를 유지합니다. 한글은 몬스터 이름에만 허용합니다. 공격 보정·피해식·DC·재충전·사용 횟수도 이 영역에 온전히 적습니다.
- 일반 `한국어 번역`은 패키지 아래 별도 `text` 코드블록으로 유지합니다. 모든 Trait, Action, Bonus Action, Reaction, Legendary Action, Mythic Action을 번역하고 이름은 `한글명 (English Name)`으로 씁니다.
- 기존 별도 `FVTT 한국어 번역`의 역할은 패키지 안의 LOCALIZATION으로 통합합니다. 기본 출력에 같은 FVTT 번역을 다시 복제하지 않습니다. 마스터가 수동 편집용 번역을 요청한 경우에만 별도 제공합니다.

### LOCALIZATION JSON

- 최상위는 `actorName`과 `items`를 가진 JSON 객체입니다. `actorName`은 최종 한글 Actor 이름, `items`는 영문 Item 이름을 키로 하는 객체입니다. 번역할 Item이 없으면 `items`는 빈 객체로 둡니다.
- 각 Item 값은 `name`과 `description`을 가진 객체로 작성합니다. `name`은 한글 Item 이름, `description`은 FVTT에서 사용할 한글 설명 문자열입니다. 일반 번역의 한글명과 동일하게 쓰며 영문 병기는 일반 번역에 둡니다.
- 키는 SBI가 생성하는 Item의 영문 이름과 일치시킵니다. `TRAITS`, `ACTIONS` 같은 섹션 제목이나 번역 이름을 키로 쓰지 않습니다. 기존 실환경 시험에서 `Cold Breath (Recharge 5–6)`와 `Recovery (1/Day)`는 각각 `Cold Breath`, `Recovery`로 생성됐습니다. 다른 접미사도 모두 제거된다고 추정하지 않습니다.
- 매크로의 대소문자·공백 정규화에 의존해 키를 대충 쓰지 않습니다. 앞뒤 공백 제거·연속 공백 통합·소문자 변환 후에도 영문 키는 유일해야 합니다. 같은 이름의 Item 여러 개를 이름 키만으로 구별할 수 있다고 가정하지 않습니다.
- 한글 Item 이름도 같은 Actor 안에서 참조 대상을 구분할 수 있어야 합니다. 다중공격 등에서 쓰는 이름과 `name`을 맞춥니다.
- 큰따옴표를 사용하고 문자열 내부의 따옴표·역슬래시·줄바꿈은 JSON 규칙에 맞게 이스케이프합니다. 주석, 후행 쉼표, 중복 키, `null`, 배열, 문자열 단독 Item 값은 출력하지 않습니다. 코드블록 안에는 JSON을 감싼 추가 코드펜스나 JSON 뒤의 설명을 넣지 않습니다.
- 모든 의도된 능력·행동의 번역 대응을 확인합니다. SBI가 별도로 추가한 장비·주문 Item은 실제 생성 이름과 설명을 확인한 경우에만 매핑합니다. 제목처럼 Item으로 생성되지 않는 문구는 억지로 키를 만들지 않습니다.
- 매칭이나 설명 보존을 확인할 수 없는 항목은 패키지 밖의 `### 적용 확인`에 원문명·미확인 이유·확인할 내용을 적습니다. 설명을 안전하게 번역할 수 없으면 해당 Item의 `description`을 생략해 생성 설명을 보존할 수 있습니다. 이는 예외이며 일반 번역은 제공하고 FVTT 설명이 미번역 상태임을 명시합니다.
- LOCALIZATION은 이름·설명용 데이터입니다. Activity, 피해식, 내성, 사용 횟수, Effect, UUID 등 기계 데이터를 수정하는 필드를 추가하지 않습니다. 수치 조정은 STATBLOCK에 반영합니다.

### FVTT 설명과 참조 보존

- `description`은 기존 설명 전체를 대체합니다. 공격 뒤의 추가 효과, 조건, 제한, 후속 문장을 빠뜨리지 않습니다. 일반 번역과 의미·사거리·대상·횟수가 같아야 합니다.
- FVTT가 계산하는 공격 보정과 피해값은 `[[/attack]]`, `[[/damage average]]`를 유지합니다. LOCALIZATION에서 고정 숫자로 바꾸지 않습니다. 반대로 SBI가 읽는 STATBLOCK의 숫자를 이 명령으로 바꾸지 않습니다.
- 확인된 단일 무기 공격의 표준 설명은 다음과 같습니다. 해당 공격의 사거리와 대상 수를 실제 데이터에 맞춰 씁니다.

| 유형 | LOCALIZATION의 description |
| --- | --- |
| 원거리 | `원거리 무기 공격: [[/attack]], 사거리 150/600피트, 대상 하나. 명중 시 [[/damage average]] 피해를 줍니다.` |
| 근접 | `근접 무기 공격: [[/attack]], 도달거리 5피트, 대상 하나. 명중 시 [[/damage average]] 피해를 줍니다.` |

- `[[/damage average]]` 뒤에 피해 유형을 중복해서 덧붙이지 않습니다. 복수 피해·복수 Activity에는 단일 공격 패턴을 일괄 적용하지 않고 실제 생성 설명과 연결을 확인합니다.
- 기존 설명에 있는 `[[/r ...]]`, `@UUID[...]`, `&Reference[...]`와 기타 인라인 명령의 실제 식별자·인자·구조를 보존합니다. 자료에 없는 명령이나 UUID는 만들지 않습니다.
- 단순 Item 이름 참조는 `[[/item Longbow]]`를 `[[/item 장궁]]`처럼 최종 이름과 맞춥니다. 현 매크로의 단순 이름 치환을 사용할 수 있으나 최종 참조 대상도 확인합니다. 인자·라벨이 붙은 복잡한 참조까지 자동 치환된다고 가정하지 않습니다.
- 기존 인라인 문법을 넘어서 새 `[[...]]` 명령을 조립하거나 `@...` 롤 데이터 경로·활동 ID를 확정해야 하면 6번 FVTT 기능의 `2. 피트 및 아이템 인라인 문법과 변수 사용 가이드.md`를 적용합니다. 룰북 근거가 없는 동적 경로나 활동 연결을 이 단계에서 임의로 만들지 않습니다.
- 인라인 명령이 없는 서술형 능력은 일반 번역의 내용을 사용합니다. 기존 명령이 있는 설명은 일반 문장으로 덮어 지우지 않습니다.

### 적용 확인과 검증 범위

- 기준 실환경은 Foundry 13.351 / dnd5e 5.2.4 / SBI 2.3.10과 FormData 반환 오류를 수정한 기존 `스탯블록 임포터`입니다. 다른 버전의 동작을 동일하게 보장하지 않습니다.
- 2026-09-05 시험에서 Actor·prototypeToken 이름, Item 이름·설명, 단순 Item 링크, attack/damage 연결과 장궁 실제 굴림을 확인했습니다. 내성·피해·재충전·일일 사용 데이터는 생성과 보존을 확인한 범위입니다.
- 시험한 Actor.system과 Activity·피해·내성·Uses·Effect 내용에는 전후 차이가 없었으나, 한글화한 Item에 빈 `flags.dnd5e.riders.activity`가 추가됐습니다. 전체 데이터가 완전히 불변이라고 표현하지 않습니다.
- 주문·Cast Activity·주문 UUID, 내용이 있는 Active Effect, 전설·신화·소굴 행동 비용, 복수 피해·Activity, 복잡한 링크, 실제 대상 내성·피해 적용·자원 회복은 별도 확인 대상입니다. JSON 형식 검사 통과와 실환경 자동화 검증을 구분합니다.
- 실제 임포트를 요청받으면 생성 Actor와 Item을 확인하고 미매칭 키·SBI importIssues·한글 이름·설명·인라인 연결·기계 데이터를 점검합니다. Actor 이름이 이미 같으면 현 매크로의 이름 변경 분기가 생략될 수 있으므로 prototypeToken 이름도 확인합니다.
- 매칭 경고나 생성 후 오류가 나면 이미 만들어진 Actor의 상태부터 확인합니다. 같은 패키지를 무조건 다시 실행해 Actor를 중복 생성하지 않습니다.
- 근거: [실환경 검증 보고서](<../../docs/superpowers/reports/2026-09-05-fvtt-sbi-ko-live-test.md>). 문서 작성만으로 서버 접속이나 미검증 기능의 시험을 완료했다고 기록하지 않습니다.

## 3. 창작/조정 스탯블록 작성 기준

- CR은 요청값을 우선합니다.
- 요청값이 없을 경우 기반 몬스터의 CR과 의도된 전투 역할을 기준으로 산정합니다.
- HP, AC, 명중 보정, 평균 피해량은 요청 CR에 맞게 조정합니다.
- 피해 유형, 저항, 면역, 상태 면역은 몬스터 콘셉트에 맞게 조정하되 과도하게 누적하지 않습니다.
- 일반 몬스터는 복잡한 라운드 전환, 전용 전장 규칙, 다단계 페이즈를 넣지 않습니다.
- 정예 몬스터는 전투 중 1~2개의 차별화된 전술 요소를 허용합니다.
- 보스 몬스터는 Legendary Actions 또는 Mythic Actions를 사용할 수 있으나, 사용자가 보스를 요청하지 않았다면 포함하지 않습니다.
- 사용자가 특정 피해 유형을 동시에 입히는 몬스터를 요청한 경우, 공격 피해식에 각 피해 유형을 분리해 표기합니다.
- 예: `Hit: 9 (1d8 + 5) bludgeoning damage plus 7 (2d6) fire damage and 7 (2d6) cold damage.`
- 같은 공격에 여러 피해 유형이 포함될 경우, 각 피해 유형별 평균값과 주사위를 명확히 분리합니다.
