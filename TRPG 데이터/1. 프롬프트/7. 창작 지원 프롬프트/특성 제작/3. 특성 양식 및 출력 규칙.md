# 3. 특성 양식 및 출력 규칙

## 목적

이 문서는 특성의 기본 양식과 요청 유형별 출력 형식을 정의한다.

모든 특성은 종류와 대분류를 필수로 기록한다. 소분류와 태그는 검색·관리 또는 기능 이해에 필요할 때 추가한다.

## 1. 표준 양식

```md
### 특성명

**종류:** 크리처 특성 / 효과 특성 / 로어 특성  
**대분류:** 해당 종류의 대분류 하나  
**소분류:** 필요한 경우 최대 두 개  
**태그:** 필요한 경우 기입

**로어적 설명:**  
특성이 세계관 안에서 의미하는 성질, 힘, 작용 또는 위치를 1~2문단으로 설명한다.

**기능적 설명:**  
D&D에서 실제로 적용되는 기능을 명확히 설명한다.
```

대분류는 하나만 지정한다. 복합 특성이 여러 대분류에 걸치면 핵심 역할을 기준으로 하나를 선택하고, 나머지는 소분류나 태그로 기록한다.

서로 독립적으로 적용되는 기능이라면 별도의 특성으로 분리한다.

## 2. 공용 태그 필드

모든 크리처 특성·효과 특성·로어 특성은 하나의 `태그` 필드를 사용한다.

```text
태그: 강화 / 이로운 / 지속 / 화염
태그: 반응 / 긴 휴식 / 축복 / 천상체
태그: 비공개 / 과거 / 비밀 / 복선
```

태그 그룹은 검색용 분류일 뿐 출력 필드를 나누는 기준이 아니다. `태그`, `태그`, `발동 태그`, `획득 태그`, `태그`처럼 별도의 필드로 분리하지 않는다.

태그는 특성 종류와 크리처 유형에 관계없이 실제 내용을 설명할 때 사용할 수 있다. 표준 표기와 태그 그룹은 `../../공통/라이브러리/공용 태그 사전.md`를 따른다.

특정 크리처 유형을 전제로 하는 특성에는 다음 선택 필드를 추가할 수 있다.

```md
**대상 크리처 유형:** 구조체 > 기계 생명계  
**태그:** 인간형 기계체 / 독립 시민 / 기계 생명
```

`대상 크리처 유형`은 유형 대분류와 중분류의 정식 경로이며 태그를 대신하지 않는다.

## 3. 크리처 특성 작성 규칙

기능적 설명에는 해당 크리처가 지속적으로 보유하는 효과나 사용할 수 있는 능력을 기록한다.

필요한 경우 다음 정보를 포함한다.

- 발동 조건
- 행동 종류
- 사거리와 대상
- 공격 또는 내성 굴림
- 피해와 상태
- 지속 시간
- 사용 횟수
- 휴식 또는 재충전
- 종료 조건

## 4. 효과 특성 작성 규칙

효과 특성은 무엇을 변화시키는지를 대분류로 삼고, 어떻게 변화시키는지를 태그로 기록한다.

필요한 경우 다음 요소를 포함한다.

- 적용 대상
- 지속 시간
- 중첩 여부
- 해제 또는 종료 조건
- 단계 변화
- 이로운·해로운·중립 여부
- 즉시·지속·반복·누적 여부

## 5. 로어 특성 작성 규칙

로어 특성은 이야기에서 대상이 어떤 존재인지 이해할 수 있는 정보를 제공한다.

기능이 없는 로어 특성에 임의의 판정 보너스를 부여하지 않는다. 실제 규칙 효과가 필요하면 별도의 크리처 특성 또는 효과 특성을 작성한다.

## 6. 단순 특성 축약형

```md
- **화염 저항**
  - 종류: 크리처 특성
  - 대분류: 방어·내성
  - 소분류: 피해 저항
  - 태그: 상시
  - 로어: 이 특성을 지닌 존재는 불꽃과 고열로 인한 손상을 효과적으로 견딜 수 있다.
  - 기능: 화염 피해에 저항을 가진다.
```

사용자가 코드블록 목록을 요청하면 이 형식을 우선한다.

## 7. 효과 특성 축약형

```md
- **화염 내성 강화**
  - 종류: 효과 특성
  - 대분류: 방어·내성
  - 소분류: 내성 단계
  - 태그: 강화 / 단계 상승
  - 태그: 이로운 / 지속
  - 로어: 대상이 불꽃과 고열로 인한 손상을 견디는 능력을 강화한다.
  - 기능: 지속 시간 동안 대상의 화염 내성 단계를 한 단계 상승시킨다.
```

## 8. 복합 특성

여러 규칙 효과가 있는 특성은 기능적 설명을 불릿으로 분리한다.

복수 효과가 하나의 이름과 콘셉트로 자연스럽게 묶이지 않으면 별도의 특성으로 분리한다.

관리 데이터에서는 복합 특성이 호출하는 효과 특성을 별도 항목으로 등록할 수 있다.

## 9. 특성 세트 출력

특성 세트는 먼저 한 문장 콘셉트를 제시한 뒤 종류별로 나눈다.

세트 검수 시에는 대분류 분포를 확인한다. 같은 대분류의 비슷한 특성만 반복되고 핵심 콘셉트 축이 누락되지 않았는지 점검한다.

## 10. D&D 규칙 문장

D&D용 기능은 가능한 한 공식 용어를 사용한다.

권장 표현:

- `화염 피해에 저항을 가진다.`
- `지혜 내성 굴림에 실패하면 공포 상태가 된다.`
- `자신의 다음 턴이 끝날 때까지 지속된다.`
- `긴 휴식을 마치면 사용 횟수를 모두 회복한다.`
- `대상을 최대 10피트 밀어낸다.`
- `이 효과는 같은 이름의 효과와 중첩되지 않는다.`

피해야 할 표현:

- 방어력이 많이 오른다.
- 확률적으로 발동한다.
- 잠시 유지된다.
- 강한 피해를 준다.
- 적을 멀리 날려 보낸다.

## 11. 수치가 미정인 초안

수치를 확정할 근거가 부족하면 변수형, 조정 표기형 또는 선택안형을 사용한다.

## 12. 로어 문단 규칙

- 기본 1문단
- 기원과 작용을 함께 설명해야 하면 2문단
- 문단당 하나의 중심 내용
- 같은 기능을 다른 말로 반복하지 않음
- 첫 문장에서 특성의 핵심을 파악할 수 있게 작성
- 상위 특성은 확정 설정을 사용해 충분히 확장 가능
- 단순 특성은 장대한 기원이나 외형을 임의로 추가하지 않음

## 13. 출력 언어

- 기본 출력은 한국어다.
- D&D 고유 용어가 필요한 경우 한국어 뒤에 영문을 병기할 수 있다.
- 다른 AI에게 전달할 프롬프트를 요청한 경우에만 해당 프롬프트를 영어로 작성한다.
- 특성명은 사용자가 영문을 요구하지 않는 한 한국어를 기본으로 한다.

## 14. 완성 특성 라이브러리 문서 형식

`라이브러리/`에는 실제 작업에서 조회하고 재사용할 검수 완료 특성군만 저장한다.

### 파일명

문서의 범위를 직접 드러내는 이름을 사용한다.

```text
[주제] 특성 라이브러리.md
```

예시:

```text
기본 피해 관련 특성 라이브러리.md
몬스터 유형 관련 특성 라이브러리.md
상태 이상 관련 효과 특성 라이브러리.md
```

### 문서 기본 구조

```md
# 문서명

> 문서의 목적과 사용 범위

## 문서 정보

- 특성 종류
- 적용 대상 또는 범위
- 포함된 특성 수
- 공통 규칙 또는 전제

## 공통 규칙

여러 특성에 반복 적용되는 단계, 중첩, 종료, 우선순위 규칙을 기록한다.

## 주제별 특성

### 특성명

**종류:**  
**대분류:**  
**소분류:**  
**태그:**

**로어적 설명:**  
내용

**기능적 설명:**  
내용

## 검수 결과

- 종류별 특성 수
- 중복 검수 결과
- 공통 규칙 적용 여부
```

### 작성 원칙

- 하나의 문서는 하나의 명확한 주제나 공통 규칙 체계를 다룬다.
- 공통 단계·중첩·우선순위 규칙은 문서 앞부분에서 한 번 정의한다.
- 각 특성은 문서 밖으로 분리해도 종류·분류·기능을 이해할 수 있어야 한다.
- 공통 규칙을 참조하더라도 개별 기능적 설명에서 실제 단계 변화나 효과를 생략하지 않는다.
- 같은 이름의 특성을 여러 라이브러리 문서에 중복 등록하지 않는다.
- 기능이 같은 특성을 표현만 바꾸어 별도 항목으로 만들지 않는다.
- 설정 전용 특성과 범용 특성이 섞이면 문서를 분리하거나 적용 범위를 명시한다.
- 문서 하단에는 특성 수와 검수 결과를 기록한다.

### 예시 문서와의 구분

`5. 특성 제작 예시.md`는 형식과 분류 판단을 설명하는 참고 문서다. 실제 완성 특성의 검색·재사용·중복 판정은 `라이브러리/`에 저장된 문서를 기준으로 한다.
