# 7번 창작 지원의 특성 제작기 프롬프트 적용 안내

## 문서 상태

이 문서는 `7. 창작 지원 프롬프트/특성 제작`의 정식 적용 안내입니다.

특성 종류, 대분류·소분류, 공용 태그, 크리처 유형 규격, 출력 양식과 밸런스 규칙은 이 문서 체계를 기준으로 운용합니다.

현재 버전은 `1.4`입니다.

## 폴더 구조

```text
7. 창작 지원 프롬프트/특성 제작/
├─ 0. 특성 제작 마스터 프롬프트.md
├─ 1. 특성 제작 지침서.md
├─ 2. 특성 종류 및 분류 체계.md
├─ 3. 특성 양식 및 출력 규칙.md
├─ 4. 특성 품질 검수 체크리스트.md
├─ 5. 특성 제작 예시.md
├─ 공통 라이브러리/공용 태그 사전.md (조건부 참조)
├─ 라이브러리/크리처 유형 표준 규격.md
├─ 라이브러리/크리처 유형 대분류-중분류 인덱스.md
├─ README.md
└─ 라이브러리/
   └─ 기본 피해 관련 특성 라이브러리.md
```

## 기능 목적

7번 창작 지원의 특성 제작기는 다음 세 종류의 특성을 독립적으로 제작하고 관리합니다.

1. 크리처 특성
2. 효과 특성
3. 로어 특성

D&D에서 실제 사용할 수 있는 기능적 설명과 작품 안에서 자연스럽게 읽히는 로어적 설명을 함께 작성합니다.

크리처 특성을 설계할 때 평범한 인간, 자연 생물, 천상 주민, 기계 시민, 자율 병기, 생체병기, 영체, 언데드, 천룡종과 용종을 같은 분류 문법으로 설명할 수 있도록 크리처 유형 규격을 함께 참조합니다.

## 분류 체계의 분리

특성 분류와 크리처 유형 분류는 서로 다른 체계입니다.

```text
특성 분류:
종류 → 대분류 → 소분류 → 공용 태그

크리처 유형 분류:
유형 대분류 → 기원·계통 중분류 → 공용 태그
```

특성 대분류는 특성이 무엇을 설명하거나 변화시키는지를 나타냅니다. 크리처 유형 대분류는 대상이 어떤 존재인지를 나타냅니다. 두 체계를 같은 필드에 혼합하지 않습니다.

## 공용 태그 운용

모든 크리처 특성·효과 특성·로어 특성과 모든 크리처 유형은 같은 태그 사전을 사용합니다.

- 종류별 전용 태그 필드를 사용하지 않습니다.
- 최종 출력 필드명은 `태그`로 통일합니다.
- 발동, 획득, 작동, 외형, 존재 기반, 지성, 사회, 역할, 속성, 서사와 위상 태그를 함께 사용할 수 있습니다.
- 태그 그룹은 검색 편의를 위한 분류이며 사용 제한이 아닙니다.
- 표준 표기와 동의어 정규화는 `../../공통/라이브러리/공용 태그 사전.md`를 따릅니다.

## 크리처 유형 규격

`라이브러리/크리처 유형 표준 규격.md`는 다음 15개 유형 대분류를 사용합니다.

```text
이형체
야수
천상체
구조체
천룡종
정령
요정
악마
거인
인간형
괴수
점액괴물
식물
언데드
용종
```

- D&D의 `Dragon` 유형은 룩스테라에서 `천룡종`에 대응합니다.
- 용종은 천룡종이 아닌 생물이 용성에 적응하여 형질과 생태가 변한 지상 생물입니다.
- 기계 생명, 로봇, 안드로이드와 자율 병기는 구조체입니다.
- 구조체도 시민·상인·학자·예술가와 같은 사회적 역할을 가질 수 있습니다.
- 생물학적 존재가 기계를 이식받은 사이보그는 원래 유형을 유지하고 `기계 개조` 태그를 사용합니다.
- 천상 세계에서 태어날 때부터 천상체인 일반 주민은 `천상체 > 천상 태생계`로 분류합니다.

## 대분류-중분류 인덱스

`라이브러리/크리처 유형 대분류-중분류 인덱스.md`는 크리처 유형의 정식 경로를 별도로 관리합니다.

역할, 직업, 외형, 속성, 크기와 성장 위상은 중분류로 만들지 않습니다. 이러한 정보는 공용 태그로 관리합니다.

## 완성 특성 라이브러리 운용

`라이브러리/`는 검수 완료된 완성 특성군을 주제별 Markdown 문서로 누적하는 데이터 영역입니다.

특성 제작·개편·분류·세트 구성 작업은 먼저 이 폴더의 파일 목록과 관련 문서를 확인합니다. 기존 특성이 요청을 충족하면 재사용하고, 기능이 실질적으로 같은 특성을 이름만 바꾸어 중복 제작하지 않습니다.

현재 등록된 완성 문서는 다음과 같습니다.

```text
라이브러리/기본 피해 관련 특성 라이브러리.md
```

### 예시 문서와 완성 데이터의 구분

- `5. 특성 제작 예시.md`: 작성법·분류·경계 사례를 보여 주는 참고 문서
- `라이브러리/`: 실제 작업에서 검색·재사용하는 검수 완료 특성 문서

예시 문서는 라이브러리 검색을 대신하지 않으며, 두 위치에 같은 이름이 있으면 `라이브러리/`의 최신 완성 문서를 우선합니다.

## 라우팅 핵심

- 공식 룰북의 기존 피쳐 확인: 4번
- 세계관 정본 문서 작성·수정: 5번
- 신규 특성 설계·분류·윤문·세트 구성: 7번 창작 지원의 특성 제작기
- 독립된 능력·스킬·권능의 전체 구조 제작: 7번 창작 지원의 능력 제작기
- 클래스·직업·전직·하위 클래스 제작: 7번 창작 지원의 클래스 제작기
- 특성 아이콘 이미지: 1번 이미지 생성 모듈 내부 7번
- 특성의 FVTT 자동화: 6번

## 적용 원칙

Google Drive에는 직접 생성하거나 덮어쓰지 않습니다.

압축 파일을 내려받아 사용자가 직접 적용합니다.

## 변경 이력

### 1.4

- 7번 창작 지원의 능력 제작기와 7번 창작 지원의 클래스 제작기 기능의 경계를 추가했습니다.
- 패시브 여부가 특성과 능력의 경계 기준이 아님을 명시했습니다.
- 독립 능력 전체 구조는 7번 창작 지원의 능력 제작기, 대상에게 부착하는 짧은 특성 단위는 7번 창작 지원의 특성 제작기로 구분했습니다.
- 클래스 전체 구조는 7번 창작 지원의 클래스 제작기, 클래스가 부여하는 재사용 특성은 7번 창작 지원의 특성 제작기로 구분했습니다.
- 공용 태그 사전의 사용 범위를 능력 데이터와 클래스 데이터까지 확장했습니다.

### 1.3

- 평범한 인간부터 기계 생명·인공 생명·병기·영체까지 설명하는 크리처 유형 15종 규격을 추가했습니다.
- D&D의 드래곤 유형을 `천룡종`으로 명시하고 `용종`과 분리했습니다.
- `천상체 > 천상 태생계`를 추가하여 천사가 아닌 천상 문명의 토착 주민을 분류할 수 있게 했습니다.
- 트랜스포머형 기계 종족, 로봇, 안드로이드, 독립 인공지능과 자율 병기를 구조체로 분류하는 기준을 추가했습니다.
- 사이보그는 생물학적 존재 기반이 유지되는 동안 원래 크리처 유형을 유지하도록 경계를 확정했습니다.
- 모든 특성 종류와 크리처 유형이 같은 태그 사전을 사용하도록 태그 필드를 통합했습니다.
- 기존 `기본 피해 관련 특성 라이브러리.md`의 작동·운용 태그 필드도 단일 `태그` 필드로 변환했습니다.
- 발동·작동·외형·존재 기반·지성·사회·역할·속성·서사·위상 태그를 `../../공통/라이브러리/공용 태그 사전.md`에서 관리하도록 분리했습니다.
- 크리처 유형의 대분류·중분류를 `라이브러리/크리처 유형 대분류-중분류 인덱스.md`로 별도 색인화했습니다.
- 역할과 직업은 기원 중분류로 만들지 않고 공용 태그로 관리하도록 확정했습니다.

### 1.2

- `7. 창작 지원 프롬프트/특성 제작/라이브러리/`를 검수 완료 특성군의 정식 저장 위치로 추가했습니다.
- 특성 제작 전에 관련 라이브러리 문서를 조회하고, 기존 특성의 재사용·변형·신규 제작 여부를 판정하도록 절차를 갱신했습니다.
- 동일한 이름이나 실질적으로 같은 기능의 특성을 중복 생성하지 않는 규칙을 추가했습니다.
- 반복 재사용 가능한 완성 특성군의 등록 기준과 주제별 문서 형식을 확정했습니다.
- `5. 특성 제작 예시.md`는 작성법 참고용, `라이브러리/`는 실제 완성 데이터용으로 역할을 분리했습니다.
- 첫 완성 데이터로 `라이브러리/기본 피해 관련 특성 라이브러리.md`를 등록했습니다.

### 1.1

- 특성 관리 구조를 `종류 → 대분류 → 소분류 → 태그`의 네 단계로 확장했습니다.
- 종류와 대분류는 하나만 지정하고, 소분류와 태그로 복합적인 성질을 보완하도록 규칙을 확정했습니다.
- 로어 특성 대분류 8종, 크리처 특성 대분류 13종, 효과 특성 대분류 13종을 추가했습니다.
- 효과 특성은 무엇을 변화시키는지를 대분류로 삼고, 부여·제거·강화·약화 등의 작동 방식을 태그로 관리하도록 정리했습니다.
- 표준 출력 양식, 검수 체크리스트와 예시 라이브러리에 새 분류 필드를 반영했습니다.

### 1.0

- 7번 창작 지원의 특성 제작기 기능을 정식 기능으로 추가했습니다.
- 크리처 특성·효과 특성·로어 특성의 최상위 분류를 확정했습니다.
- 특성명, 종류, 선택적 분류, 로어적 설명, 기능적 설명을 표준 양식으로 채택했습니다.
- 상위 라우터 3종에 7번 창작 지원의 특성 제작기 진입점과 독립 라우팅 규칙을 반영했습니다.
- 초안 및 패치 안내 형식을 제거하고 정규 `.md` 문서로 승격했습니다.
- 이후 개정에서는 이 README를 교체하지 않고 변경 이력을 누적 갱신합니다.
