# 4. 특성 품질 검수 체크리스트

## 사용 방법

특성을 출력하기 전에 각 항목을 점검한다.

중대한 오류가 하나라도 있으면 수정한 뒤 다시 검수한다.

## 1. 종류 검수

- [ ] 크리처 특성·효과 특성·로어 특성 중 하나로 분류했는가?
- [ ] 분류 기준이 발동 시간이 아니라 소유 관계인가?
- [ ] 크리처 특성은 크리처에게 지속적으로 귀속되는가?
- [ ] 효과 특성은 능력·아이템·상태·환경이 적용하는 효과인가?
- [ ] 로어 특성은 규칙 효과를 임의로 암시하지 않는가?
- [ ] 하나의 특성에 서로 다른 소유 관계가 섞였다면 분리했는가?

## 2. 대분류·소분류 검수

- [ ] 해당 종류에 맞는 대분류를 하나만 지정했는가?
- [ ] 대분류는 특성의 출처가 아니라 핵심 역할을 기준으로 선택했는가?
- [ ] 효과 특성은 무엇을 변화시키는지를 대분류로 삼았는가?
- [ ] 강화·약화·부여·제거 같은 작동 방식은 대분류가 아니라 태그로 기록했는가?
- [ ] 소분류가 대분류의 범위 안에 있는가?
- [ ] 소분류를 과도하게 늘리지 않았는가?
- [ ] 대분류가 두 개 이상 필요하다면 특성 분리를 검토했는가?
- [ ] 같은 특성이 여러 대분류에 중복 등록되지 않았는가?

## 3. 공용 태그 검수

- [ ] 모든 종류에서 필드명을 `태그`로 통일했는가?
- [ ] 태그가 발동·획득·작동·외형·존재 기반·사회·역할·서사·위상 정보를 실제로 보완하는가?
- [ ] 특성 종류나 크리처 유형을 이유로 적용 가능한 태그를 부당하게 제한하지 않았는가?
- [ ] 태그가 대분류·소분류와 같은 의미를 불필요하게 반복하지 않는가?
- [ ] 태그가 종류와 대분류 판정을 대신하지 않는가?
- [ ] 동일한 개념의 태그를 다른 표현으로 중복 생성하지 않았는가?
- [ ] `../../공통/라이브러리/공용 태그 사전.md`의 표준 표기와 일치하는가?
- [ ] 새로운 태그가 필요하다면 기존 태그 조합으로 표현할 수 없는지 확인했는가?

## 4. 이름 검수

- [ ] 이름과 핵심 기능이 연결되는가?
- [ ] 직접 기능형은 이름만으로 기능을 파악할 수 있는가?
- [ ] 고유명형은 확정된 설정과 연결되는가?
- [ ] 이름이 실제 기능보다 지나치게 거창하거나 사소하지 않은가?
- [ ] 비슷한 이름의 특성과 구별되는가?

## 5. 로어 검수

- [ ] 로어적 설명이 1~2문단 안에서 핵심을 전달하는가?
- [ ] 첫 문장에서 특성의 의미를 파악할 수 있는가?
- [ ] 한국어 문장이 자연스럽게 읽히는가?
- [ ] 의미가 불분명한 추상어를 남용하지 않았는가?
- [ ] 불필요한 수식과 장식을 제거했는가?
- [ ] 특성명이나 확정 설정에 없는 신체·외형·기원을 임의로 추가하지 않았는가?
- [ ] 상위 특성은 필요한 세계관 설정을 충분히 설명하는가?
- [ ] 로어가 기능보다 강한 효과를 암시하지 않는가?
- [ ] 규칙에 없는 부가 효과를 사용할 수 있는 것처럼 쓰지 않았는가?

## 6. 기능 검수

- [ ] D&D 규칙으로 해석이 갈리지 않는가?
- [ ] 대상과 발동 조건이 필요한 경우 명시했는가?
- [ ] 행동 종류가 필요한 경우 명시했는가?
- [ ] 수치, 사거리, 지속 시간이 필요한 경우 명시했는가?
- [ ] 공격 또는 내성 굴림이 필요한 경우 기준을 명시했는가?
- [ ] 사용 횟수와 회복 조건이 필요한 경우 명시했는가?
- [ ] 중첩과 종료 조건이 중요한 경우 명시했는가?
- [ ] 공식 규칙 확인이 필요한 부분은 4번 자료로 검증했는가?
- [ ] 근거가 부족한 정밀 수치를 임의로 확정하지 않았는가?

## 7. 이름·로어·기능 통합 검수

- [ ] 세 요소가 같은 특성을 설명하는가?
- [ ] 이름에서 기대한 효과가 기능에 존재하는가?
- [ ] 로어에서 설명한 작용이 기능에 반영되는가?
- [ ] 기능에 있는 핵심 효과가 로어에서 완전히 누락되지 않았는가?
- [ ] 단순한 특성을 불필요하게 초월적 능력으로 확장하지 않았는가?
- [ ] 상위 특성의 격을 지나치게 평범한 설명으로 축소하지 않았는가?

## 8. 특성 세트 검수

- [ ] 특성 목록만으로 대상의 콘셉트를 유추할 수 있는가?
- [ ] 각 특성이 서로 다른 역할을 담당하는가?
- [ ] 같은 대분류의 비슷한 기능을 반복하지 않았는가?
- [ ] 핵심 전투 방식이 드러나는가?
- [ ] 방어·생존 방식이 드러나는가?
- [ ] 필요한 경우 약점·비용·제약이 드러나는가?
- [ ] 로어 특성이 정체성과 세계관적 위치를 보강하는가?
- [ ] 기능과 관계없는 범용 보너스를 무작정 추가하지 않았는가?
- [ ] 대분류 분포가 콘셉트에 필요한 축을 적절히 포함하는가?

## 9. 라이브러리 등록 검수

- [ ] `라이브러리/`에서 동일한 이름의 특성을 먼저 검색했는가?
- [ ] 이름이 다르더라도 실질적으로 같은 기능의 특성이 존재하는지 확인했는가?
- [ ] 기존 특성을 재사용하거나 변형하는 것으로 해결할 수 없는가?
- [ ] 변형 특성이라면 원본과의 기능 차이가 명확한가?
- [ ] 반복 재사용할 수 있는 완성 특성인가?
- [ ] 일회성 초안이나 작성 예시를 완성 라이브러리에 섞지 않았는가?
- [ ] 라이브러리 문서의 주제와 파일명이 실제 범위를 드러내는가?
- [ ] 공통 단계·중첩·우선순위·종료 규칙이 필요한 경우 문서 앞부분에 정의했는가?
- [ ] 각 특성이 공통 규칙을 참조하면서도 독립적으로 이해 가능한가?
- [ ] 같은 특성이 여러 라이브러리 문서에 중복 등록되지 않았는가?
- [ ] 특성명·분류·태그가 기존 라이브러리 체계와 충돌하지 않는가?
- [ ] 공식 규칙과 세계관 정본을 라이브러리 문서가 임의로 대체하지 않는가?
- [ ] 문서 하단에 종류별 특성 수와 검수 결과를 기록했는가?

## 10. 크리처 유형 연동 검수

- [ ] 대상이 크리처라면 상위 유형 대분류를 하나만 판정했는가?
- [ ] 중분류가 역할이나 직업이 아니라 기원·계통·발생 기반을 나타내는가?
- [ ] 외형·존재 기반·지성·사회·역할·위상은 공용 태그로 분리했는가?
- [ ] 구조체·사이보그, 천룡종·용종, 야수·괴수, 언데드·영혼 정착 구조체의 경계를 확인했는가?
- [ ] `라이브러리/크리처 유형 표준 규격.md`의 정의와 일치하는가?
- [ ] `라이브러리/크리처 유형 대분류-중분류 인덱스.md`의 정식 경로를 사용했는가?
- [ ] 유형 정보만으로 모든 개체에게 동일한 특성을 자동 부여하지 않았는가?

## 11. 최종 판정

다음 네 문장에 모두 답할 수 있어야 한다.

- 무엇을 의미하는지 알 수 있다.
- 어떻게 작동하는지 이해할 수 있다.
- 어디에 분류하고 검색해야 하는지 알 수 있다.
- 한국어 문장으로 자연스럽게 읽힌다.
