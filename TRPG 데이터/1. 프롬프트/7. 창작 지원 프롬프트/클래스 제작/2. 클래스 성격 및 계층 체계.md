# 2. 클래스 성격 및 계층 체계

## 목적

이 문서는 클래스가 작품 안에서 어떤 종류의 구조인지, 다른 클래스와 어떤 관계를 맺는지를 정의한다.

## 1. 클래스 성격

### 기본 클래스

독립적인 출발점이 되는 클래스다.

### 하위 클래스

특정 상위 클래스의 핵심 구조를 계승하면서 일부 원천·역할·능력·테마를 전문화한다.

### 전직 클래스

기존 클래스에서 조건을 만족해 이동하는 클래스다. 반드시 더 강한 것은 아니며 역할이 달라질 수 있다.

### 상위 클래스

기존 클래스의 숙련과 권한을 확장하는 고단계 클래스다. 작품 내 등급 체계가 있을 때 사용한다.

### 히든 클래스

일반적인 획득 경로가 공개되지 않았거나 희귀 조건을 요구하는 클래스다.

### 복합 클래스

둘 이상의 클래스 원형이 동등하게 결합된 독립 클래스다.

### 사회 직업

전투 능력보다 사회적 노동·제도·역할이 중심인 클래스다.

### 전문직

특정 기술·지식·생산·연구 분야를 전문화한 클래스다.

### 전투 스타일

독립 직업보다 싸우는 방식과 전술을 정의하는 클래스 구조다.

### 아키타입

구체적인 직업보다 반복되는 서사적·기능적 인물형을 나타낸다.

### 칭호형 클래스

업적·권위·운명·사회적 인정으로 획득하는 클래스다.

### 혈통 클래스

특정 혈통이나 선천적 계보를 통해 획득하는 클래스다.

### 종족 전용 클래스

특정 종족의 생리·문화·기관을 전제로 하는 클래스다.

### 조직 전용 클래스

교단·길드·국가·군대·비밀결사의 교육과 권한을 통해 획득하는 클래스다.

### 시스템 클래스

세계의 시스템, 상태창, 계약 장치와 같은 외부 체계가 부여·관리하는 클래스다.

## 2. 계층 관계

### 직접 상위 클래스

실제로 이 클래스가 파생된 부모 클래스다.

```text
비스트 마스터 → 레인저
화염술사 → 마법사
```

### 조합 원형

클래스의 설계와 기능에 결합된 원형이다. 직접 상위 클래스와 다르다.

```text
마검사 → 검사 / 마법사
성기사 → 기사 / 성직자
```

### 하위 클래스

이 클래스에서 파생되는 세부 클래스 목록이다.

### 전직 대상

현재 클래스에서 조건을 충족하면 이동할 수 있는 클래스다.

### 선행 클래스

현재 클래스를 획득하기 위해 필요한 이전 클래스다.

### 연관 클래스

기능·테마·사회적 역할이 유사하거나 경쟁하는 클래스다.

### 대체 클래스

같은 역할을 다른 기술 원천과 방식으로 수행하는 클래스다.

### 반대 클래스

가치관·원천·역할·사회적 지위가 구조적으로 대립하는 클래스다.

## 3. 관계 우선순위

클래스 관계는 다음 질문으로 판정한다.

1. 실제로 특정 클래스에서 파생되었는가?
2. 작품 안에서 전직 절차가 존재하는가?
3. 단지 두 클래스의 이미지를 조합한 것인가?
4. 같은 역할을 다른 방식으로 수행하는가?
5. 단순히 이름이나 테마가 비슷한가?

## 4. 복수 관계

하나의 클래스는 다음 관계를 동시에 가질 수 있다.

```md
- 클래스 성격: 전직 클래스 / 복합 클래스
- 직접 상위 클래스: 검사
- 조합 원형: 검사 / 마법사
- 선행 클래스: 검사 또는 마법사
- 전직 대상: 마도검성
```

클래스 성격이 둘 이상일 경우 가장 중요한 성격을 앞에 둔다.

## 5. 획득 관계

클래스 획득 방식은 계층 관계와 별도 필드로 기록할 수 있다.

```text
자연 획득
교육
수련
전직
계승
혈통 발현
계약
조직 임명
시스템 부여
업적 달성
신분 획득
유물 선택
각성
강제 변질
```

## 6. 상실·변경 관계

```text
자발적 포기
전직으로 대체
권한 박탈
계약 파기
조직 추방
능력 상실
혈통 봉인
기억 소실
신분 박탈
사망 후 소멸
```

## 7. 금지 사항

- 조합 원형을 직접 상위 클래스로 기록하지 않는다.
- 상위 클래스를 무조건 강한 클래스의 수식어로 사용하지 않는다.
- 하위 클래스와 전직 클래스를 같은 의미로 사용하지 않는다.
- 사회 직업을 비전투라는 이유만으로 불완전한 클래스로 취급하지 않는다.
- 특정 종족의 생리와 문화 전체를 종족 전용 클래스 문서에서 새로 정의하지 않는다.
