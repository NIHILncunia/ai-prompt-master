# 8. 클래스 양식 및 출력 규칙

## 목적

이 문서는 클래스 데이터를 일관된 형식으로 작성하고 요청 목적에 따라 출력 깊이를 조절하는 규칙을 정의한다.

## 1. 정식 데이터형

```md
# 클래스명

## 기본 정보

- 한 줄 정의:
- 클래스 성격:
- 직접 상위 클래스:
- 조합 원형:
- 하위 클래스:
- 전직 대상:
- 선행 클래스:
- 연관 클래스:
- 적용 세계:

## 구조

- 핵심 수행 유형:
- 테마:
- 기술 원천:
- 주 기능 포지션:
- 보조 기능 포지션:
- 활동 범위:
- 전투 포지션:
- 전투 거리:
- 대표 전투 수단:

## 운용

- 자원관리:
- 제약·한계:
- 획득 방식:
- 상실·변경 조건:
- 사회적 역할:
- 태그:

## 설명

클래스의 정체성, 수행 방식, 원천, 역할과 세계관적 위치를 2~4문단으로 설명한다.

## 대표 능력

- 능력명
  - 역할:
  - 획득 관계:
  - 정본:
  - 상태:

## 관련 특성

- 특성명
  - 종류:
  - 정본:

## 계층 및 전직

상위·하위·전직 관계가 있을 때만 작성한다.

## 비고

설정 확정 여부, 연결 문서와 주의점을 기록한다.
```

## 2. 간략 카드형

```md
# 클래스명

- 한 줄 정의:
- 클래스 성격:
- 핵심 수행 유형:
- 기술 원천:
- 주 기능 포지션:
- 활동 범위:
- 사회적 역할:
- 대표 능력:
```

여러 클래스 후보를 비교하거나 세계관 문서에 짧게 소개할 때 사용한다.

## 3. 브레인스토밍형

```md
## 설계 방향

- 기본안:
- 변주안 1:
- 변주안 2:
- 핵심 선택 기준:
```

브레인스토밍 결과를 정식 문서로 승격할 때에는 폐기 후보와 설계 과정은 제거한다.

## 4. 계층형

```md
# 클래스 계통명

- 기본 클래스:
  - 하위 클래스:
  - 전직 클래스:
    - 상위 클래스:
```

각 클래스에는 한 줄 정의, 핵심 수행 유형과 관계 유형을 함께 기록한다.

## 5. 필드 생략 규칙

- 직접 상위 클래스가 없으면 `없음`으로 기록한다.
- 조합 원형이 없으면 생략할 수 있다.
- 비전투 클래스는 전투 포지션·전투 거리·대표 전투 수단을 생략하거나 `없음`으로 기록한다.
- 자원이 없는 클래스는 `없음`으로 기록한다.
- 하위 클래스와 전직 관계가 없으면 계층 및 전직 섹션을 생략할 수 있다.
- 대표 능력이 미작성 상태면 이름과 한 줄 개념만 기록한다.

## 6. 설명 문단 규칙

### 첫 문단

클래스 성격, 핵심 수행 유형, 테마와 기술 원천을 바탕으로 정체성을 설명한다.

### 둘째 문단

주 기능·활동 범위·자원과 실제 수행 방식을 설명한다.

### 셋째 문단

제약·한계와 사회적 역할, 조직·세계 안의 위치를 설명한다.

### 넷째 문단

필요할 때만 하위 클래스, 전직과 확장 가능성을 설명한다.

## 7. 문장 규칙

- 필드 값을 그대로 나열하는 문장만 반복하지 않는다.
- 클래스가 실제로 무엇을 하는지 첫 문단에서 드러낸다.
- 전투 수단과 사회적 역할을 클래스의 전체 정체성으로 오인하지 않는다.
- 설정에 없는 길드·국가·계급·역사를 임의로 추가하지 않는다.
- 비전투 클래스를 전투 능력이 없다는 이유로 결핍된 구조처럼 서술하지 않는다.
- `만능`, `최강`, `무적` 같은 표현은 실제 범위와 제약이 확정된 경우에만 사용한다.

## 8. 파일명 규칙

정식 클래스 데이터 파일명은 클래스명을 그대로 사용한다.

```text
클래스명.md
```

동일 이름의 다른 클래스가 실제로 존재하면 다음처럼 범위를 구분한다.

```text
클래스명 - 세계명.md
클래스명 - 조직명.md
```

임의 번호와 의미 없는 접두어를 붙이지 않는다.
