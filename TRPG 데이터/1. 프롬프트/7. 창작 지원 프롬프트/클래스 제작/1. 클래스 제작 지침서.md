# 1. 클래스 제작 지침서

## 목적

이 문서는 클래스·직업·전직·아키타입을 실제로 분석하고 설계하며 정식 데이터로 작성하는 절차를 정의한다.

완성된 클래스는 다음 질문에 답할 수 있어야 한다.

- 어떤 종류의 클래스인가?
- 무엇에서 파생되거나 무엇을 조합했는가?
- 주로 무엇을 수행하는가?
- 어떤 지식·수련·권한을 원천으로 삼는가?
- 어떤 역할과 활동 범위를 가지는가?
- 무엇을 관리하고 어떤 한계를 가지는가?
- 세계관 안에서 어떤 직업·신분·조직적 위치를 가지는가?
- 어떤 능력을 대표적으로 사용하거나 습득하는가?

## 1. 요청 유형 판정

### 클래스 요청

다음 요소 중 둘 이상이 중심이면 7번 창작 지원의 클래스 제작기로 처리한다.

- 직업·클래스명
- 상위·하위·전직 관계
- 핵심 역할과 수행 영역
- 기술·지식·권한의 원천
- 대표 능력 목록
- 자원과 운용 한계
- 사회적 역할과 세계관적 위치
- 획득·전직·선행 조건

### 능력 요청

하나의 기술·스킬·주문·권능의 세부 구조가 중심이면 7번 창작 지원의 능력 제작기로 보낸다.

### 특성 요청

클래스에 붙는 짧은 성질·효과·칭호·이력 단위가 중심이면 7번 창작 지원의 특성 제작기로 보낸다.

### 설정 요청

개별 클래스가 아니라 세계 전체의 직업 제도, 길드 구조, 교육 체계, 사회 계급과 역사 자체가 중심이면 5번으로 보낸다.

## 2. 선행 자료 조회

1. `인덱스/클래스 인덱스.md`에서 동일·유사 클래스를 검색한다.
2. `클래스 데이터/`에서 같은 수행 유형과 원천을 가진 클래스를 확인한다.
3. 특정 세계관에 종속되면 5번 정본을 확인한다.
4. 종족 전용 클래스라면 공통 종족 데이터를 확인한다.
5. 대표 능력이 이미 존재하면 능력 제작기 데이터와 연결한다.
6. 클래스가 부여하는 공통 특성이 있으면 7번 창작 지원의 특성 제작기 라이브러리를 확인한다.
7. 결과를 재사용·변형·파생·융합·신규 제작 중 하나로 판정한다.

## 3. 클래스 성격 판정

클래스의 제도적·서사적 성격을 먼저 정한다.

```text
기본 클래스
하위 클래스
전직 클래스
상위 클래스
히든 클래스
복합 클래스
사회 직업
전문직
전투 스타일
아키타입
칭호형 클래스
혈통 클래스
종족 전용 클래스
조직 전용 클래스
시스템 클래스
```

클래스 성격은 강함의 등급이 아니다. 작품 안에서 어떤 방식으로 획득되고 다른 클래스와 어떤 관계를 가지는지를 설명한다.

## 4. 계층 관계 판정

다음 관계를 서로 구분한다.

- 직접 상위 클래스: 실제로 파생된 부모 클래스
- 조합 원형: 설계상 결합된 클래스 또는 역할 계통
- 하위 클래스: 이 클래스에서 파생되는 세부 클래스
- 전직 대상: 이 클래스에서 이동할 수 있는 클래스
- 선행 클래스: 획득에 필요한 클래스
- 연관 클래스: 유사하거나 경쟁하는 클래스
- 대체 클래스: 동일한 역할을 다른 방식으로 수행하는 클래스

예시:

```text
마검사
- 직접 상위 클래스: 없음
- 조합 원형: 검사 / 마법사
- 선행 클래스: 설정에 따라 검사 또는 마법사
```

조합 원형을 직접 상위 클래스로 기록하지 않는다.

## 5. 핵심 수행 유형

클래스가 주로 무엇을 수행하는지 `대분류 - 중분류`로 기록한다.

예시:

```text
전투 - 검술
탐사 - 추적
사회 - 교섭
제작 - 연금
정보 - 시스템 침투
지휘 - 군세 통솔
```

핵심 수행 유형은 1개를 기본으로 하되 복합 클래스는 2~3개까지 사용할 수 있다. 가장 중요한 유형을 앞에 둔다.

## 6. 테마

테마는 클래스의 미학, 상징, 분위기와 반복 키워드다.

- 구조를 결정하지 않는다.
- 3~10개를 권장한다.
- 핵심적인 키워드부터 기록한다.
- 수행 유형·기술 원천과 같은 값을 기계적으로 반복하지 않는다.

## 7. 기술 원천

기술 원천은 클래스 전체의 숙련·지식·권한·혈통·장비가 어디에서 비롯되는지를 나타낸다.

예시:

```text
자체 수련
무기 숙련
마법 이론
신앙
맹세
자연 교감
혈통
장비
데이터
조직 교리
상업 네트워크
```

개별 능력의 세부 원천과 다르다. 클래스가 `신앙`을 원천으로 삼더라도 각 능력은 성력·기도·성물·맹세처럼 다른 세부 원천을 가질 수 있다.

## 8. 기능 포지션

주 기능 포지션은 클래스가 대상·조직·서사 안에서 주로 제공하는 기능이다.

```text
공격
방어
지원
회복
통제
지휘
소환
탐사
정보
제작
생산
교섭
관리
운송
연구
복합
```

보조 기능 포지션은 필요할 때 0~3개를 기록한다.

전투 클래스라면 별도 `전투 포지션`을 선택 필드로 기록할 수 있다.

```text
딜러
탱커
브루저
서포터
힐러
컨트롤러
커맨더
서머너
스카우트
스페셜리스트
```

## 9. 활동 범위

활동 범위는 클래스가 주로 영향을 미치는 거리·규모·사회적 범위를 나타낸다.

```text
자기 자신
접촉
근거리
중거리
원거리
초장거리
영역
지역
조직
도시
국가
세계
네트워크
차원
복합
```

전투 클래스에 필요하면 별도 `전투 거리`를 기록할 수 있다.

## 10. 대표 전투 수단

대표 전투 수단은 선택 필드다.

```text
검술
궁술
격투
총기
주문
신성 권능
소환체
기계 병기
직접 공격 수단 없음
```

비전투 클래스에 억지 공격 수단을 만들지 않는다.

## 11. 자원관리

자원은 다음 성격으로 분류한다.

- 소모 자원
- 축적 자원
- 유지 자원
- 용량 자원
- 사회 자원
- 권한 자원
- 환경 자원

자원이 없으면 `없음`으로 기록한다. 클래스의 모든 활동을 하나의 수치 자원으로 억지 환원하지 않는다.

## 12. 제약·한계

제약은 클래스의 구조적 한계, 획득 조건, 사회적 부담과 운용상 취약성을 나타낸다.

- 전투 한계
- 사회적 제약
- 법적 제약
- 윤리적 금기
- 신분 제한
- 환경 의존
- 장비 의존
- 원천 의존
- 학습 난이도
- 획득 조건
- 정신적·신체적 부담
- 조직적 의무

권장 개수는 1~6개지만 의미가 없다면 `없음`으로 기록할 수 있다.

## 13. 사회적 역할

사회적 역할은 클래스가 세계 안에서 맡는 직업적·문화적·제도적 위치다.

예시:

```text
기사
용병
사제
연구자
상인
외교관
장인
행정관
범죄자
유랑자
```

사회적 역할은 핵심 수행 유형과 다르다.

```text
핵심 수행 유형: 사회 - 교섭
사회적 역할: 상인 / 외교관
```

## 14. 대표 능력 연결

클래스는 대표 능력을 3~8개까지 기록할 수 있다.

각 능력에는 다음을 기록한다.

- 능력명
- 클래스 안에서의 역할
- 습득 또는 사용 조건
- 7번 창작 지원의 능력 제작기 정본 능력 파일

능력 문서가 없으면 `개념만 확정`으로 표시한다.

## 15. 클래스와 특성 연결

클래스가 공통으로 부여하는 짧은 특성은 다음처럼 연결한다.

```text
클래스: 성기사
대표 능력: 신성 강타 → 7번 창작 지원의 능력 제작기
공통 특성: 맹세의 구속 / 신성 감응 → 7번 창작 지원의 특성 제작기
```

클래스 문서 안에 특성의 전체 기능을 중복 작성하지 않는다.

## 16. 비전투 클래스

비전투 클래스도 다음 요소를 동일하게 설계한다.

- 핵심 수행 유형
- 기술 원천
- 기능 포지션
- 활동 범위
- 자원관리
- 제약·한계
- 사회적 역할
- 대표 능력

예시:

```text
상인
- 핵심 수행 유형: 사회 - 교섭 / 관리 - 거래망
- 주 기능 포지션: 교섭
- 활동 범위: 조직 / 도시
- 대표 전투 수단: 직접 공격 수단 없음
```

## 17. 세계관 적용

세계관 종속 클래스를 작성할 때에는 다음을 구분한다.

- 정본으로 확인된 제도와 역사
- 사용자가 이번 요청에서 확정한 내용
- 클래스 구조상 필요한 보수적 추론
- 선택 가능한 제안

클래스 설명을 풍부하게 보이게 하려고 기존에 없는 국가·길드·교단·법을 임의로 확정하지 않는다.

## 18. 정식 데이터 등록

다음 조건을 충족하면 `클래스 데이터/` 등록 대상으로 본다.

- 클래스 성격과 계층 관계가 확정되었다.
- 핵심 수행 유형과 기술 원천이 구분된다.
- 기능 포지션과 사회적 역할이 구분된다.
- 자원과 제약이 실제 클래스 구조와 연결된다.
- 대표 능력과 특성의 연결이 정리되었다.
- 관련 종족·조직·세계 설정과 모순되지 않는다.
- 인덱스 중복 검수를 통과했다.

## 19. 최종 검수 순서

1. 클래스인지 능력·특성·설정인지 확인한다.
2. 클래스 성격과 계층 관계를 확인한다.
3. 핵심 수행 유형·테마·기술 원천이 중복되지 않는지 확인한다.
4. 주 기능·활동 범위·자원·제약이 실제 운용을 설명하는지 확인한다.
5. 사회적 역할이 전투 포지션을 대신하지 않는지 확인한다.
6. 대표 능력을 7번 창작 지원의 능력 제작기 데이터와 중복 작성하지 않았는지 확인한다.
7. 기존 클래스와 이름·구조가 중복되지 않는지 확인한다.
8. 세계관 정본에 없는 정보를 임의로 확정하지 않았는지 확인한다.
