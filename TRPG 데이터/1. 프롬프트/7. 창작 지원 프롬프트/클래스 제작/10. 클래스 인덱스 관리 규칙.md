# 10. 클래스 인덱스 관리 규칙

## 목적

클래스 인덱스는 완성 클래스 데이터의 검색, 중복 방지, 계층 추적과 능력·종족·세계 연결을 위한 색인이다.

인덱스는 클래스 정본을 대체하지 않는다. 세부 내용은 연결된 클래스 데이터에서 확인한다.

## 1. 필수 필드

```text
클래스명
한 줄 정의
클래스 성격
직접 상위 클래스
조합 원형
하위 클래스
전직 대상
핵심 수행 유형
기술 원천
주 기능 포지션
활동 범위
대표 능력
관련 종족
관련 조직
적용 세계
정본 파일
상태
```

## 2. 상태 값

```text
확정
검토 중
초안
봉인
폐기
통합됨
대체됨
```

정식 인덱스에는 기본적으로 확정 클래스만 기록한다.

## 3. 중복 판정

다음 항목을 비교한다.

- 이름이 같은가?
- 한 줄 정의가 실질적으로 같은가?
- 핵심 수행 유형과 기술 원천이 같은가?
- 사회적 역할만 다른 동일 구조인가?
- 기존 클래스의 하위·전직·조직 전용 변형인가?
- 세계만 다르고 보편 구조는 같은가?

판정 결과:

- 재사용
- 세계별 구현
- 하위 클래스
- 전직 클래스
- 조직 전용 변형
- 종족 전용 변형
- 복합·융합 클래스
- 신규 클래스

## 4. 이름 충돌

동일 이름이지만 다른 클래스라면 다음 순서로 구분한다.

1. 적용 세계
2. 조직
3. 종족
4. 클래스 성격

```text
기사 — 룩스테라
기사 — 엘드로스
```

정본 클래스명 자체에 의미 없는 번호를 붙이지 않는다.

## 5. 계층 인덱싱

다음 관계는 양방향으로 연결한다.

- 직접 상위 ↔ 하위 클래스
- 현재 클래스 ↔ 전직 대상
- 현재 클래스 ↔ 선행 클래스
- 조합 원형 ↔ 복합 클래스
- 클래스 ↔ 대표 능력
- 클래스 ↔ 관련 종족
- 클래스 ↔ 관련 조직

## 6. 세계별 데이터

공용으로 재사용 가능한 클래스 구조와 세계 고유 제도를 구분한다.

```text
공용 클래스 데이터
- 수행 구조와 보편 분류를 관리

세계 전용 클래스 데이터
- 고유 명칭, 획득 제도, 조직, 역사와 사회적 위치를 관리
```

세계 전용 클래스가 공용 구조를 참조하더라도 설명 전체를 복제하지 않는다.

## 7. 갱신 절차

1. 기존 인덱스에서 이름과 구조를 검색한다.
2. 신규·재사용·하위·전직·변형 여부를 판정한다.
3. 클래스 데이터 문서를 작성하거나 갱신한다.
4. 인덱스 항목을 추가·수정한다.
5. 계층 관계와 대표 능력 링크를 확인한다.
6. 대체·통합된 기존 문서의 상태를 갱신한다.
7. 파일명과 실제 경로를 검증한다.

## 8. 표준 인덱스 형식

```md
| 클래스명 | 한 줄 정의 | 성격 | 상위 | 조합 원형 | 수행 유형 | 원천 | 포지션 | 활동 범위 | 적용 세계 | 정본 |
|---|---|---|---|---|---|---|---|---|---|---|
```

복잡한 계층과 전직 관계는 표 아래 별도 섹션으로 정리한다.
