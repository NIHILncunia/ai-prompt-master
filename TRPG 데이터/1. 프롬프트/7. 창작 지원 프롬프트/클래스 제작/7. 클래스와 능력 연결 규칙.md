# 7. 클래스와 능력 연결 규칙

## 목적

이 문서는 클래스 제작기 데이터가 능력 제작기 데이터와 특성 제작기 데이터를 중복 없이 연결하는 방법을 정의한다.

## 1. 데이터 역할

```text
클래스
- 여러 능력·특성·역할·자원과 성장 방향을 묶는 구조

능력
- 하나의 이름과 작동 구조를 가진 독립 기능

특성
- 대상에게 부착하거나 반복 재사용하는 짧은 성질·효과·이력 단위
```

## 2. 클래스 문서의 대표 능력 필드

클래스 문서에는 대표 능력 3~8개를 권장한다.

각 능력은 다음 형식으로 기록한다.

```md
- 능력명
  - 역할: 클래스 안에서 담당하는 기능
  - 획득 관계: 기본 보유 / 수련 / 선택 / 전직 / 계약 / 장비
  - 정본: `7. 창작 지원 프롬프트/능력 제작/능력 데이터/능력명.md`
  - 상태: 확정 / 개념만 확정 / 후보
```

## 3. 능력 데이터가 없는 경우

클래스를 설계하면서 대표 능력 이름과 한 줄 개념을 먼저 만들 수 있다.

```md
- 별빛 항법
  - 역할: 별과 차원 흐름을 읽어 항로를 계산한다.
  - 정본: 미작성
  - 상태: 개념만 확정
```

사용자가 능력의 세부 구조를 요구하면 7번 창작 지원의 능력 제작기에서 정식 능력 문서로 확장한다.

## 4. 클래스 전용 변형 능력

기존 능력을 클래스 전용으로 변형할 때에는 원본을 복제하지 않는다.

```md
- 원본 능력: 화염창
- 클래스 변형: 적염 기사단식 화염창
- 차이: 검을 매개로 사용 / 근거리 관통에 특화
- 원본 정본: 능력 데이터/화염창.md
```

차이가 이름과 설명뿐이고 구조가 같다면 별도 능력 문서를 만들지 않고 클래스별 표현으로 처리한다.

## 5. 상위·하위 클래스의 능력 계승

하위·전직 클래스는 다음을 구분한다.

- 계승 능력
- 강화 능력
- 대체 능력
- 신규 능력
- 상실 능력
- 선택 능력

예시:

```md
## 능력 계승

- 계승: 표적 추적
- 강화: 특수 사격 → 왕실 저격술
- 신규: 지휘관 사살
- 상실: 야생 교감
```

능력의 완전한 진화 관계는 능력 제작기 계보에도 반영한다.

## 6. 클래스와 특성 연결

클래스가 공통으로 부여하는 짧은 성질과 효과는 특성 제작기을 참조한다.

```md
## 관련 특성

- 중갑 숙련
  - 종류: 크리처 특성
  - 정본: `7. 창작 지원 프롬프트/특성 제작/라이브러리/...`

- 왕실 임명
  - 종류: 로어 특성
  - 정본: 미작성
```

클래스 문서에 필요한 요약은 적을 수 있지만 특성의 전체 로어와 기능을 반복하지 않는다.

## 7. 종족 전용 클래스

종족 전용 클래스는 다음 관계를 기록한다.

- 요구 종족
- 요구 생리·기관
- 문화적 획득 경로
- 종족 전용 능력
- 종족 제한의 이유

종족 자체의 생리와 문화는 공통 종족 데이터을 참조한다.

## 8. 조직 전용 클래스

조직 전용 클래스는 다음을 기록한다.

- 요구 조직
- 임명·교육·계약 절차
- 부여 권한
- 조직 전용 능력
- 탈퇴·추방 시 상실 요소

조직의 역사와 제도는 5번 설정 정본을 참조한다.

## 9. 양방향 링크

가능하면 다음 연결을 양쪽 문서에 기록한다.

```text
클래스 → 대표 능력
능력 → 관련 클래스

클래스 → 관련 특성
특성 → 관련 클래스 또는 적용 대상
```

링크가 양방향이라고 해서 본문을 복제하지 않는다.

## 10. 충돌 처리

### 클래스 설명과 능력 정본이 다를 때

- 최신 사용자 지시를 확인한다.
- 능력 자체의 구조는 7번 창작 지원의 능력 제작기 정본을 우선한다.
- 클래스에서만 달라지는 운용은 클래스 전용 변형으로 기록한다.

### 세계관 설정과 클래스 문서가 다를 때

- 5번 정본을 확인한다.
- 클래스 문서가 정본을 임의로 덮어쓰지 않는다.
- 사용자가 변경을 확정하면 5번 반영안과 클래스 제작기 문서를 함께 갱신한다.

## 11. 금지 사항

- 클래스 문서 안에 모든 능력의 전체 구조를 반복하지 않는다.
- 능력 문서 안에 클래스 전체 설명을 반복하지 않는다.
- 이름만 다른 동일 능력을 클래스별로 무한 복제하지 않는다.
- 정본 없는 능력을 확정 데이터처럼 링크하지 않는다.
- 대표 능력 목록만으로 클래스의 역할과 원천 설명을 대체하지 않는다.
