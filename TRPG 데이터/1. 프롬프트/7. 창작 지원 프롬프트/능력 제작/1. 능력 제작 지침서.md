# 1. 능력 제작 지침서

## 목적

이 문서는 능력을 실제로 분석하고 설계하며 정식 데이터로 작성하는 절차를 정의한다.

완성된 능력은 이름만 멋있는 설정이 아니라 다음 질문에 답할 수 있어야 한다.

- 무엇에 개입하는가?
- 작품 안에서 어떤 체계로 인식되는가?
- 어떤 힘과 매개를 사용하는가?
- 어떤 방식으로 작동하는가?
- 어떤 형태로 발현되는가?
- 대상에게 어떤 결과를 남기는가?
- 언제 작동하고 얼마나 유지되는가?
- 무엇을 지불하며 어떤 위험을 가진가?
- 다른 능력과 어떤 관계를 가지는가?

## 1. 요청 유형 판정

먼저 사용자가 만들고자 하는 데이터의 중심을 판정한다.

### 능력 요청

다음 요소 중 둘 이상을 설계하려는 경우 능력 제작기 요청으로 본다.

- 고유한 능력명
- 원천과 작동 원리
- 발현 형태와 결과 효과
- 발동·지속 방식
- 비용·리스크
- 하위 기능
- 자동화·독립성
- 진화·파생·계승 관계

### 특성 요청

대상에게 부착할 짧은 성질, 상태, 효과, 이력 또는 반복 재사용 가능한 모듈이 중심이면 7번 창작 지원의 특성 제작기로 보낸다.

### 설정 요청

능력 하나가 아니라 세계 전체의 마법 체계, 초능력 발생 원리, 신성 권능의 우주론, 능력자 사회 제도와 역사 자체가 중심이면 5번으로 보낸다.

### 클래스 요청

여러 능력과 역할을 묶는 직업·클래스·전직·아키타입의 구조가 중심이면 7번 창작 지원의 클래스 제작기로 보낸다.

## 2. 선행 자료 조회

정식 능력 제작 전에 다음 순서로 기존 자료를 확인한다.

1. `인덱스/능력 인덱스.md`에서 동일·유사 이름을 찾는다.
2. `능력 데이터/`에서 같은 원천·작동·효과를 가진 능력을 찾는다.
3. 특정 세계관에 종속되면 5번에서 관련 정본을 확인한다.
4. 특정 종족의 능력이면 공통 종족 데이터를 확인한다.
5. 특정 클래스의 대표 능력이면 클래스 제작기 데이터와 연결 관계를 확인한다.
6. 동일하거나 실질적으로 대체 가능한 데이터가 있으면 재사용·변형·신규 제작을 판정한다.

## 3. 능력의 독립성 판정

다음 조건을 많이 충족할수록 독립된 능력 데이터로 작성한다.

- 작품 안에서 고유한 이름으로 불린다.
- 하나 이상의 명확한 기능을 가진다.
- 사용 또는 작동 조건이 있다.
- 원천·비용·리스크가 존재한다.
- 다른 능력으로 진화하거나 파생될 수 있다.
- 하위 기능을 포함한다.
- 능력 자체가 사회적 평가나 상징성을 가진다.
- 특정 인물 외의 사용자에게도 계승·복제·전수될 수 있다.

단순히 `불에 강함`, `밤눈이 밝음`, `귀족임`처럼 짧은 성질만 설명하면 특성으로 처리하는 편이 적절하다.

## 4. 설계 순서

### 4.1 구성 방식

능력이 하나의 기능인지, 여러 기능의 묶음인지, 내부 운영 규칙을 가진 체계인지 판정한다.

- 단일형
- 복합형
- 체계형

### 4.2 권한 성격

능력이 단순 기능인지, 특정 영역의 규칙을 지배하는 권능인지, 사용자의 능력을 관리하는 시스템인지 판정한다.

- 일반형
- 권능형
- 시스템형

### 4.3 계보 관계

다른 능력과의 관계를 판정한다.

- 독립형
- 파생형
- 진화형
- 계승형
- 융합형
- 분기형
- 퇴화형
- 봉인형

### 4.4 층위

능력이 실제로 개입하는 세계의 층위를 정한다.

- 물질층
- 생명층
- 정신층
- 정보층
- 관계층
- 개념층
- 초월층
- 메타층
- 혼성층

### 4.5 표현 권역

작품 속 인물과 독자가 이 능력을 어떤 체계로 인식하는지 정한다.

- 마도형
- 육체형
- 기예형
- 정신형
- 초상형
- 기술형
- 신성형
- 주술형
- 계약형
- 상징형
- 이계형
- 생체형
- 병장형
- 의례형
- 혼성형

### 4.6 원천

능력이 무엇에서 힘을 얻고 무엇을 매개로 움직이는지 정한다.

원천은 표현 권역과 다르다. 마법처럼 보이는 능력도 실제 원천은 혈액·기억·계약·별빛일 수 있다.

### 4.7 작동 계통

능력이 대상이나 세계에 어떤 방식으로 개입하는지 동사형으로 정한다.

예: 방출, 구현, 강화, 제어, 간섭, 감지, 이동, 전이, 소환, 흡수, 봉인, 변환, 복제, 강제, 조성, 회복, 박탈.

### 4.8 발현 형태

능력이 어떤 모양, 현상, 매체 또는 인터페이스로 드러나는지 정한다.

예: 투사체, 광선, 파동, 장벽, 영역, 오라, 표식, 무기화, 신체변형, 접촉, 시선, 음성, 의식, 매개체, 소환체, 무형.

### 4.9 결과 효과

능력 사용 후 실제로 무엇이 달라지는지 정한다.

예: 피해, 회복, 강화, 약화, 구속, 이동, 탐지, 은신, 생성, 소멸, 변형, 복제, 차단, 부여, 박탈, 교란, 확정, 왜곡.

### 4.10 운용 메타

다음 항목을 필요한 만큼 기록한다.

- 대상
- 발동 방식
- 지속 방식
- 비용
- 리스크
- 자동화 수준
- 독립성
- 권한 범위
- 태그

## 5. 구조 축 중복 방지

다음 항목을 같은 뜻으로 반복하지 않는다.

```text
표현 권역: 기술형
원천: 전력
작동 계통: 방출
발현 형태: 광선
결과 효과: 피해
태그: 기계 / 과열 / 정밀
```

잘못된 예시:

```text
표현 권역: 기술형
원천: 기술
작동 계통: 레이저
발현 형태: 피해
결과 효과: 방출
태그: 기술 / 방출 / 광선 / 피해
```

`레이저`처럼 여러 축을 동시에 암시하는 표현은 가장 중요한 축에 배치하고 다른 축은 보편어로 분해한다.

## 6. 패시브와 자동 능력

패시브는 독립된 능력 종류가 아니라 발동 방식이다.

- 상시: 별도의 조건 없이 지속 작동
- 조건반응: 특정 조건을 감지하면 작동
- 자동 발동: 능력 또는 시스템이 판단하여 실행
- 피격 반응: 공격받을 때 작동
- 환경 반응: 특정 장소·시간·현상에서 작동
- 누적 해방: 자원이 쌓이면 작동

패시브 능력도 비용·리스크·하위 기능·진화 관계를 가질 수 있다.

## 7. 비용과 리스크

비용은 의도적으로 지불하거나 소모하는 것이고, 리스크는 사용 후 발생할 수 있는 불이익이다.

```text
비용: 마력
리스크: 과부하

비용: 기억
리스크: 자아 균열

비용: 없음
리스크: 없음
```

강한 능력에 반드시 비용과 리스크를 모두 붙여야 하는 것은 아니다. 대신 제약, 발동 조건, 권한 범위와 사회적 결과 중 무엇이 능력을 제한하는지 확인한다.

## 8. 복합 능력 처리

하나의 이름 아래 서로 독립적인 기능이 둘 이상이면 복합형 이상을 검토한다.

하위 능력은 다음 조건에서 분리한다.

- 작동 계통이 다르다.
- 발현 형태가 다르다.
- 결과 효과가 다르다.
- 독립적으로 사용하거나 봉인할 수 있다.
- 다른 능력으로 파생될 수 있다.

체계형 능력은 하위 기능을 단순히 보유하는 것을 넘어 호출·조합·자동 실행·최적화·자원 배분·권한 위임과 같은 통합 규칙을 가진다.

## 9. 권능형 능력 처리

권능형은 강한 능력의 동의어가 아니다.

다음 조건 중 하나 이상이 핵심일 때 권능형을 사용한다.

- 특정 영역의 규칙을 정의하거나 강제한다.
- 대상의 자격과 권한을 판정한다.
- 이름·죽음·계약·시간·운명 같은 개념의 소유권을 행사한다.
- 일반적인 작동 절차보다 상위 권한이 결과를 우선한다.

권능형에는 반드시 권한 범위, 적용 조건, 예외와 반대 권한을 기록한다.

## 10. 지성형·시스템형 능력

지성형 능력은 자동화 수준과 독립성을 별도로 판정한다.

- 자동화 수준은 얼마나 사용자 대신 판단하고 실행하는가를 나타낸다.
- 독립성은 도구·보조지성·관리자·대행자·공존인격·잠식형 중 어디에 가까운지를 나타낸다.
- 독립된 육체와 사회적 행위 능력이 있다면 능력이 아니라 별도 크리처일 수 있다.

세부 규칙은 `5. 지성형·시스템형 능력 처리 규칙.md`를 따른다.

## 11. 세계관 적용

세계관 종속 능력을 작성할 때에는 다음을 구분한다.

- 정본으로 확인된 원천과 법칙
- 사용자가 이번 요청에서 확정한 내용
- 구조상 필요한 보수적 추론
- 선택 가능한 제안

확정되지 않은 신격·기관·역사·조직을 능력 설명을 풍부하게 보이게 하기 위해 임의로 추가하지 않는다.

## 12. 정식 데이터 등록

다음 조건을 충족하면 `능력 데이터/` 등록 대상으로 본다.

- 이름과 구조가 확정되었다.
- 각 구조 축의 의미가 중복되지 않는다.
- 비용·리스크·제약이 모순되지 않는다.
- 하위 능력과 계보 관계가 정리되었다.
- 관련 설정·종족·클래스와의 연결이 확인되었다.
- 인덱스 중복 검수를 통과했다.
- 사용자가 정식 데이터로 확정했거나 반복 재사용성이 명확하다.

브레인스토밍 후보와 폐기안은 정식 데이터 폴더에 등록하지 않는다.

## 13. 최종 검수 순서

1. 능력인지 특성·설정·클래스인지 다시 확인한다.
2. 구성 방식·권한 성격·계보 관계가 서로 다른 축으로 기록되었는지 확인한다.
3. 층위부터 결과 효과까지 구조가 한 흐름으로 읽히는지 확인한다.
4. 발동·지속·비용·리스크가 실제 작동과 일치하는지 확인한다.
5. 하위 능력을 설명문 안에 숨기지 않았는지 확인한다.
6. 능력명과 설명이 같은 범위의 기능을 나타내는지 확인한다.
7. 기존 능력과 중복되지 않는지 확인한다.
8. 세계관 정본에 없는 정보를 임의로 확정하지 않았는지 확인한다.
