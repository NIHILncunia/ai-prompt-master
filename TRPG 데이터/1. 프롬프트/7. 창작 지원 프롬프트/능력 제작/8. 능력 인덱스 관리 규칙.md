# 8. 능력 인덱스 관리 규칙

## 목적

능력 인덱스는 완성 능력 데이터의 검색, 중복 방지, 계보 추적과 세계별 연결을 위한 색인이다.

인덱스는 능력 문서의 정본 내용을 대체하지 않는다. 세부 사실은 반드시 연결된 능력 데이터에서 확인한다.

## 1. 필수 인덱스 필드

```text
능력명
한 줄 정의
구성 방식
권한 성격
계보 관계
층위
표현 권역
주요 원천
주요 작동 계통
주요 결과 효과
관련 능력
관련 클래스
관련 종족
적용 세계
정본 파일
상태
```

## 2. 상태 값

```text
확정
검토 중
초안
봉인
폐기
통합됨
대체됨
```

정식 인덱스에는 기본적으로 `확정` 데이터만 기록한다. 검토 중 데이터를 관리해야 하면 상태를 명시하고 정본과 섞이지 않도록 구분한다.

## 3. 중복 판정

다음 항목을 비교한다.

- 이름이 같은가?
- 한 줄 정의가 실질적으로 같은가?
- 층위·작동 계통·결과 효과가 같은가?
- 비용과 제약만 다른 변주인가?
- 기존 능력의 파생·진화·하위 기능인가?
- 세계만 다르고 보편 구조는 같은가?

판정 결과:

- 재사용: 기존 데이터 그대로 사용
- 변주: 같은 능력의 운용 변형으로 기록
- 파생: 상위 능력과 계보 연결
- 세계별 구현: 공용 구조와 세계 전용 표현을 분리
- 신규: 독립 능력으로 등록

## 4. 이름 충돌

동일 이름이지만 다른 능력인 경우 다음 순서로 구분한다.

1. 적용 세계
2. 능력 계통
3. 대표 사용자 또는 조직

```text
심안 — 룩스테라
심안 — 엘드로스
```

정본 능력명 자체에 불필요한 번호를 붙이지 않는다.

## 5. 세계별 데이터

공용으로 재사용 가능한 구조와 세계 고유 설정을 구분한다.

```text
공용 능력 데이터
- 보편 구조와 분류를 관리

세계 전용 능력 데이터
- 고유 원천, 명칭, 역사, 사용자와 사회적 의미를 관리
```

세계 전용 능력이 공용 구조를 참조하더라도 설명 전체를 복제하지 않는다.

## 6. 계보 인덱싱

다음 관계는 양방향으로 연결한다.

- 상위 능력 ↔ 하위 능력
- 기원 능력 ↔ 파생 능력
- 진화 전 ↔ 진화 후
- 융합 원본 ↔ 융합 능력
- 분기 원점 ↔ 분기 능력
- 클래스 ↔ 대표 능력

## 7. 갱신 절차

1. 기존 인덱스에서 이름과 구조를 검색한다.
2. 신규·재사용·변주·파생 여부를 판정한다.
3. 능력 데이터 문서를 작성하거나 갱신한다.
4. 인덱스 항목을 추가·수정한다.
5. 관계형 필드를 양쪽 문서에서 확인한다.
6. 대체·통합된 기존 문서의 상태를 갱신한다.
7. 링크와 파일명이 실제 경로와 일치하는지 확인한다.

## 8. 표준 인덱스 형식

```md
| 능력명 | 한 줄 정의 | 구성 | 권한 | 계보 | 층위 | 표현 권역 | 작동 | 효과 | 적용 세계 | 정본 |
|---|---|---|---|---|---|---|---|---|---|---|
```

복잡한 계보는 표 아래 별도 섹션으로 정리한다.
