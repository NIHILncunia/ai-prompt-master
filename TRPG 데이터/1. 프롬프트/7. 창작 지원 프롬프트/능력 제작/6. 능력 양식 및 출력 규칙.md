# 6. 능력 양식 및 출력 규칙

## 목적

이 문서는 능력 데이터를 일관된 형식으로 작성하고, 요청 목적에 따라 출력 깊이를 조절하는 규칙을 정의한다.

## 1. 정식 데이터형

```md
# 능력명

## 기본 정보

- 한 줄 정의:
- 구성 방식: 단일형 / 복합형 / 체계형
- 권한 성격: 일반형 / 권능형 / 시스템형
- 계보 관계: 독립형 / 파생형 / 진화형 / 계승형 / 융합형 / 분기형 / 퇴화형 / 봉인형
- 상위 능력: 없음 또는 능력명
- 하위 능력: 없음 또는 능력명 목록
- 관련 능력: 없음 또는 능력명 목록
- 관련 클래스: 없음 또는 클래스명 목록
- 관련 종족: 없음 또는 종족명 목록
- 적용 세계: 공용 또는 세계·시리즈명

## 구조

- 대표 구조: `[층위/표현 권역:원천] - [작동 계통] - [발현 형태] -> [결과 효과]`
- 층위:
- 표현 권역:
- 원천:
- 작동 계통:
- 발현 형태:
- 결과 효과:
- 대상:

## 운용

- 발동 방식:
- 지속 방식:
- 비용:
- 리스크:
- 제약:
- 자동화 수준:
- 독립성:
- 권한 범위:
- 태그:

## 설명

능력의 정체성, 작동 원리, 사용 양상과 세계관적 의미를 2~4문단으로 설명한다.

## 하위 능력

복합형·체계형일 때만 작성한다.

### 하위 능력명

- 구조:
- 역할:
- 발동 방식:
- 지속 방식:
- 비용:
- 리스크:
- 설명:

## 계보 및 변화

진화·파생·계승·융합 관계가 있을 때만 작성한다.

- 이전 능력:
- 계승 기능:
- 사라진 기능:
- 재해석된 기능:
- 신규 기능:
- 변화 조건:

## 비고

설정 확정 여부, 연결 문서와 주의점을 기록한다.
```

## 2. 브레인스토밍형

정식 필드에 앞서 다음을 추가할 수 있다.

```md
## 설계 방향

- 기본안:
- 변주안 1:
- 변주안 2:
- 핵심 선택 기준:
```

브레인스토밍형은 후보를 비교하는 용도다. 사용자가 하나를 확정하면 폐기 후보와 설계 과정은 정식 데이터 문서에서 제거한다.

## 3. 간략 목록형

여러 능력을 비교하거나 후보 목록을 만들 때 사용한다.

```md
- 능력명: [한 줄 정의] [구성 방식 / 층위 / 작동 계통 / 결과 효과]
```

예시:

```md
- 공간 절단: 지정한 공간의 연속성을 끊어 대상을 분리한다. [단일형 / 개념층 / 간섭 / 절단]
- 자동 방벽: 위협을 감지해 보호 장벽을 자동 전개한다. [체계형 / 물질층·정보층 / 구현 / 차단]
```

## 4. 계보형

능력의 변화 관계가 중심일 때 사용한다.

```md
# 능력 계보명

- 기원 능력:
  - 파생 능력:
    - 진화 능력:
    - 분기 능력:
```

각 항목에는 한 줄 정의, 계승 기능과 변화 조건을 함께 기록한다.

## 5. 출력 생략 규칙

- 해당하지 않는 필드는 `없음`으로 쓰거나 섹션을 생략할 수 있다.
- 단일형 능력에는 하위 능력 섹션을 강제로 만들지 않는다.
- 독립형 능력에는 계보 및 변화 섹션을 강제로 만들지 않는다.
- 도구형 능력에는 인격 설명을 추가하지 않는다.
- 비용과 리스크가 없으면 억지로 대가를 만들지 않는다.

## 6. 문장 규칙

- 첫 문장에서 능력의 핵심을 파악할 수 있게 한다.
- 구조 필드를 설명문에 기계적으로 반복하지 않는다.
- 작동 원리와 결과를 구분하여 서술한다.
- 능력에 없는 신격·조직·역사를 임의로 추가하지 않는다.
- 화려한 수식보다 능력의 실제 작동을 우선한다.
- `무조건`, `절대`, `모든 것` 같은 표현은 권한 범위와 예외가 확정된 경우에만 사용한다.

## 7. 고유명과 내부 분류

작품 안에서 `특성`, `스킬`, `권능`, `가호`, `고유 기술`로 불리더라도 내부 데이터 종류가 능력이면 7번 창작 지원의 능력 제작기 형식을 사용한다.

```md
- 표시 분류: 고유 스킬
- 내부 데이터 종류: 능력
```

사용자에게 보여줄 필요가 없으면 내부 데이터 종류는 비고에만 기록할 수 있다.

## 8. 파일명 규칙

정식 능력 데이터 파일명은 능력명을 그대로 사용한다.

```text
능력명.md
```

동명이인이 아니라 동명 능력이 실제로 둘 이상 존재하면 다음처럼 범위를 구분한다.

```text
능력명 - 세계명.md
능력명 - 계통명.md
```

임의 번호와 의미 없는 접두어를 붙이지 않는다.
