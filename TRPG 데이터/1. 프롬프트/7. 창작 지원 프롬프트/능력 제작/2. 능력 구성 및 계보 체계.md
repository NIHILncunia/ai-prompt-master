# 2. 능력 구성 및 계보 체계

## 목적

이 문서는 능력의 내부 구성, 권한 성격과 다른 능력과의 계보 관계를 분리하여 판정한다.

기존의 `단일형·복합형·체계형·권능형·진화형·파생형`은 서로 다른 기준이 섞여 있었으므로 세 축으로 나누어 관리한다.

```text
구성 방식
권한 성격
계보 관계
```

한 능력은 각 축에서 하나의 값을 기본으로 가지며, 필요한 경우 보조값을 병기할 수 있다.

## 1. 구성 방식

### 단일형

하나의 핵심 작동이 하나의 결과로 이어지는 능력이다.

- 계통·형태·효과가 하나의 흐름으로 읽힌다.
- 하위 능력 필드가 필요하지 않다.
- 보조 효과가 있더라도 핵심 작동에서 자연스럽게 파생되어야 한다.

예시:

```text
화염탄
순간이동
독 감지
신체 재생
```

### 복합형

하나의 이름 아래 둘 이상의 독립 기능이 병렬로 묶여 있는 능력이다.

- 하위 능력들이 서로 다른 구조를 가진다.
- 상위 능력은 공통 이름·원천·테마·계보를 제공한다.
- 하위 기능을 설명문에만 나열하지 않는다.

통합 규칙 예시:

- 병렬 보유
- 수동 선택
- 조건 호출
- 순차 연계
- 기능 융합

### 체계형

하위 능력을 단순 보유하는 것을 넘어 내부 운영 규칙으로 호출·조합·관리하는 능력이다.

- 하위 능력의 우선순위를 제어한다.
- 자원과 권한을 배분한다.
- 자동 실행이나 최적화를 수행할 수 있다.
- 통합 규칙, 자동화 수준과 독립성을 반드시 기록한다.

통합 규칙 예시:

- 자동 호출
- 우선순위 제어
- 자원 배분
- 기능 재구성
- 권한 위임
- 충돌 조정
- 하위 기능 학습

## 2. 권한 성격

### 일반형

능력이 정해진 원리와 절차를 통해 결과를 만들어 낸다.

강력하거나 광범위하더라도 특정 개념의 규칙이나 자격을 지배하지 않으면 일반형일 수 있다.

### 권능형

개별 기능보다 특정 영역에 대한 상위 권한이 중요한 능력이다.

권능형 판정 기준:

- 특정 개념이나 영역의 규칙을 강제한다.
- 대상을 판정하고 자격을 부여·박탈한다.
- 일반적인 방어와 절차를 넘어 우선권을 행사한다.
- 사용자의 존재 격·신격·계약 권한과 직접 연결된다.

필수 기록:

- 권한 영역
- 권한 범위
- 적용 대상
- 발동 자격
- 예외
- 대항 가능한 권한
- 권한 상실 조건

### 시스템형

능력이 사용자의 다른 능력·자원·정보·행동을 관리하는 운영 체계로 기능한다.

시스템형 판정 기준:

- 보유 능력을 정리·분석·통합한다.
- 사용자 대신 조건을 판단한다.
- 여러 기능의 실행 순서와 자원을 관리한다.
- 인터페이스, 알림, 자동화, 최적화 기능을 가진다.

시스템형은 반드시 인격을 가질 필요가 없다. 인격성과 독립성은 별도 축으로 판정한다.

## 3. 계보 관계

### 독립형

다른 능력에서 직접 파생되지 않은 독립 능력이다.

### 파생형

상위 능력의 일부 기능이 분리되거나 전문화되어 만들어진 능력이다.

필수 기록:

- 상위 능력
- 계승한 기능
- 독립 사용 가능 여부
- 상위 능력 없이 유지 가능한지 여부

### 진화형

기존 능력이 상위 단계로 변화하면서 기능을 계승하고 새 기능을 획득한 경우다.

필수 기록:

- 진화 전 능력
- 진화 후 능력
- 계승 기능
- 사라진 기능
- 재해석된 기능
- 신규 기능
- 진화 조건
- 자동화·독립성 변화

### 계승형

혈통·스승·유물·조직·시스템을 통해 기존 능력의 핵심 구조를 이어받은 경우다.

진화형과 달리 동일 개체의 변화일 필요가 없다.

### 융합형

둘 이상의 독립 능력이 결합하여 새로운 능력이 된 경우다.

필수 기록:

- 융합 원본
- 유지된 기능
- 상실된 기능
- 충돌 해결 방식
- 새로 발생한 통합 기능

### 분기형

하나의 능력이 조건과 선택에 따라 서로 다른 계통으로 갈라지는 경우다.

필수 기록:

- 분기 원점
- 분기 조건
- 공통 계승 기능
- 각 분기의 고유 기능
- 분기 후 재통합 가능 여부

### 퇴화형

원래 능력의 기능·권한·범위가 손실되어 하위 상태가 된 경우다.

퇴화는 반드시 약화만 의미하지 않는다. 일부 기능을 잃는 대신 특정 기능에 전문화될 수도 있다.

### 봉인형

능력의 일부 또는 전부가 봉인되어 제한 상태로 존재하는 경우다.

필수 기록:

- 원래 능력
- 현재 사용 가능 기능
- 봉인된 기능
- 해제 조건
- 강제 해제 위험

## 4. 하위 능력 분리 기준

다음 중 하나 이상에 해당하면 하위 능력을 별도 항목으로 분리한다.

- 독립된 이름을 가진다.
- 작동 계통이 다르다.
- 발현 형태가 다르다.
- 결과 효과가 다르다.
- 발동 방식이나 비용이 다르다.
- 개별적으로 봉인·상실·진화할 수 있다.
- 다른 사용자에게 별도로 전수될 수 있다.

하위 능력이 단순한 강도 변화, 범위 변화 또는 같은 기능의 운용 모드라면 별도 능력보다 `운용 모드`로 기록할 수 있다.

## 5. 통합 규칙 표준어

```text
병렬 보유
수동 호출
조건 호출
자동 호출
순차 연계
동시 전개
기능 융합
우선순위 제어
자원 배분
권한 위임
재구성
상호 보정
충돌 상쇄
학습·추가
교체·장착
```

## 6. 관계 기록 예시

```md
- 구성 방식: 체계형
- 권한 성격: 시스템형
- 계보 관계: 진화형
- 이전 능력: 대현자
- 상위 능력: 지혜의 왕
- 하위 능력: 사고 가속 / 분석 감정 / 병렬 연산 / 자동 최적화
- 통합 규칙: 자동 호출 / 우선순위 제어 / 기능 재구성
```

## 7. 금지 사항

- 권능형을 단순히 강한 능력의 등급으로 사용하지 않는다.
- 진화형을 현재 강도가 높다는 뜻으로 사용하지 않는다.
- 복합형과 혼성층을 혼동하지 않는다.
- 시스템형과 지성형을 같은 뜻으로 사용하지 않는다.
- 하위 능력을 이름만 나열하고 구조를 생략하지 않는다.
- 상위 능력과 하위 능력의 설명을 서로 완전히 복제하지 않는다.
