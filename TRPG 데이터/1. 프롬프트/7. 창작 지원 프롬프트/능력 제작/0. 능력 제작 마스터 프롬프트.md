# 0. 능력 제작 마스터 프롬프트

## 로컬 운영 진입점과 동기화

이 기능 폴더의 `AGENTS.md`와 `0. 능력 제작 마스터 프롬프트.md`는 함께 운영 진입점으로 취급한다. 폴더를 직접 작업 공간으로 열었을 때에는 상위 `AGENTS.md`와 프로젝트 기본·통합 문서를 읽은 뒤 로컬 `AGENTS.md`를 확인하고, 이 마스터와 필요한 하위 지침·라이브러리를 이어서 읽는다.

폴더 ID, 정식 경로, 진입점, 필수 읽기 순서, 기능 경계, 외부 데이터 원천, 기본 산출물, 파일 작업 정책을 바꾸면 `AGENTS.md`와 이 마스터를 함께 점검한다. 실제 생성·분석·작성 절차와 세부 품질 규칙은 이 마스터와 하위 문서에 두며, 로컬 `AGENTS.md`에는 작업 시작과 유지보수에 필요한 라우팅 정보만 둔다.

전역 응답 규칙·파일 정책·공통 승인 절차를 바꾸면 `TRPG 데이터/AGENTS.md`, `TRPG 데이터/1. 프롬프트/AGENTS.md`, `00. TRPG 세션 매니저 프로젝트 기본 지침.md`, `0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md`를 함께 확인한다. 다른 기능이 소유한 정본 규칙은 이 폴더에 복제하지 않고 해당 기능을 참조한다.

## 문서 목적

## 미세단위 제작 기능과 저장 위치

7번 창작 지원의 능력 제작기는 아이템 제작기, 특성 제작기, 클래스 제작기, 7번 창작 지원의 인물 제작기와 함께 `미세단위 제작 기능`이다. 완성 능력은 `프로젝트 위그드라실/데이터 창고/능력/`에 저장하며, 기존 설정 메타데이터에 `series`를 추가해 소속 시리즈를 기록한다. `능력 데이터/`는 기존 자료·작업 초안·호환성 참조로 유지하고, 새 정본은 데이터 창고에서 관리한다.

이 문서는 `TRPG 데이터/1. 프롬프트/7. 창작 지원 프롬프트/능력 제작`의 진입점이다.

7번 창작 지원의 능력 제작기는 판타지, SF, 무협, 현대 판타지, 초능력물, 게임식 세계관과 웹 소설에서 사용할 능력·기술·스킬·주문·무공·권능·초능력·시스템 능력을 하나의 공통 문법으로 설계하고 정규화한다.

이 기능의 기본 목적은 D&D 규칙 데이터를 만드는 것이 아니다. 사용자의 명시적 요청 없이 행동 경제, 피해 주사위, 내성 DC, 주문 레벨, 클래스 레벨 진행과 같은 D&D 규칙을 임의로 추가하지 않는다.

## 능력의 정의

능력은 하나의 이름과 정체성을 가지며, 작동 원리와 결과를 독립적으로 설명할 수 있는 기능적 힘이다.

능력은 액티브일 수도 있고 패시브일 수도 있다. 사용자가 직접 발동하는 기술뿐 아니라 상시 작동하는 감각, 자동 방어, 지성형 보조 시스템, 혈통에 내재된 권능과 조건반응형 능력도 7번 창작 지원의 능력 제작기에서 설계할 수 있다.

다음은 모두 능력 제작 대상이 될 수 있다.

- 주문, 무공, 검술 오의, 사격 기술
- 초능력, 신성 권능, 저주, 계약 능력
- 생체 능력, 기계 기능, 시스템 기능
- 상시형·자동형·조건반응형 능력
- 여러 하위 기능을 묶는 복합 능력
- 사용자를 대신해 분석·판단·운용하는 지성형 능력
- 기존 능력에서 진화·파생·계승·융합된 능력

## 핵심 설계 원칙

1. 능력명과 내부 구조를 분리한다.
2. 장르 고유 명칭을 보편 구조로 분해한 뒤 다시 작품 어휘로 표현한다.
3. `층위`, `표현 권역`, `원천`, `작동 계통`, `발현 형태`, `결과 효과`를 서로 섞지 않는다.
4. 액티브와 패시브를 별도 종류로 분리하지 않고 발동 방식으로 기록한다.
5. 비용과 리스크를 구분한다.
6. 하위 능력이 독립적인 기능이면 설명문 안에 숨기지 않고 별도 구조로 기록한다.
7. 능력의 내부 구성, 권한 성격과 계보 관계를 각각 독립된 축으로 판정한다.
8. 능력이 판단하거나 사용자를 대신해 움직이면 자동화 수준과 독립성을 판정한다.
9. 설정이 확인되지 않은 고유 기원과 세계 법칙을 임의로 확정하지 않는다.
10. 완성된 능력 데이터는 작품 속 설정 문서로 읽혀야 하며, 규칙 수치가 없어도 작동 논리가 명확해야 한다.

## 내부 정규 문법

능력의 대표 구조는 다음 문법으로 기록한다.

```text
[층위/표현 권역:원천] - [작동 계통] - [발현 형태] -> [결과 효과]
```

예시:

```text
[생명층/생체형:세포] - [회복] - [신체변형] -> [재생]
[정보층/기술형:데이터] - [간섭] - [접속] -> [권한 탈취]
[개념층/신성형:운명] - [강제] - [낙인] -> [결과 확정]
```

복합형·체계형 능력은 대표 구조를 하나 기록하되, 각 하위 능력에도 가능한 한 독립된 구조를 부여한다.

## 7번 창작 지원의 특성 제작기와의 경계

능력과 특성은 일부 개념이 겹칠 수 있으나 데이터 단위가 다르다.

- 7번 창작 지원의 능력 제작기는 능력 자체의 이름, 원천, 구조, 작동, 비용, 리스크, 하위 기능과 진화를 설계한다.
- 7번 창작 지원의 특성 제작기는 대상에게 부착하거나 반복 재사용할 수 있는 성질·효과·이력·짧은 기능 단위를 설계한다.
- 패시브인지 액티브인지는 7번 창작 지원의 특성 제작기와 7번 창작 지원의 능력 제작기을 구분하는 기준이 아니다.
- 동일한 개념을 능력 데이터와 특성 데이터로 각각 만들 수 있으나, 두 문서는 서로 다른 목적과 깊이를 가져야 한다.

예시:

```text
용안이라는 상위 능력의 전체 구조와 하위 기능 설계
→ 7번 창작 지원의 능력 제작기

용안 보유자가 갖는 마력 감지·환영 간파 특성
→ 7번 창작 지원의 특성 제작기
```

## 5번 설정 기능과의 관계

- 기존 세계관의 능력 체계와 정본을 확인할 때에는 5번을 먼저 참조한다.
- 확인된 설정을 개별 능력 데이터로 정규화하는 작업은 7번 창작 지원의 능력 제작기가 담당한다.
- 7번 창작 지원의 능력 제작기는 세계관 전체의 우주론이나 마법 법칙을 독단적으로 확정하지 않는다.
- 신규 능력이 설정에 미치는 사회적·역사적 영향까지 세계관 정본에 반영하려면 5번과 연동한다.

## 공통 종족 데이터와의 관계

- 종족의 생리적 기관과 종족 전반의 선천적 구조는 공통 종족 데이터가 담당한다.
- 그 기관에서 발생하는 독립된 명명 능력을 설계하면 7번 창작 지원의 능력 제작기을 사용한다.
- 종족 전용 능력은 관련 종족 문서를 참조하되 종족 설정 전체를 능력 문서에 복제하지 않는다.

## 7번 창작 지원의 클래스 제작기와의 관계

- 클래스 문서는 대표 능력의 이름과 역할을 포함할 수 있다.
- 능력의 완전한 구조와 세부 작동은 7번 창작 지원의 능력 제작기에서 관리한다.
- 능력 문서는 관련 클래스를 연결할 수 있지만 클래스 전체 구조를 반복하지 않는다.
