# 프롬프트 이중 계통 흐름 무결성 감사 보고서

## 결론

`1. 프롬프트`에는 기존 기능 계통과 신규 `1. 이미지 생성 모듈` 계통이 함께 존재한다. 두 계통을 분리해 판정한 결과, **기존 계통의 물리적 연결은 보존되어 있으며 루트 라우터에서 신규 이미지 모듈로 비활성화하는 전환 상태는 정상**이다. 반면 **신규 이미지 생성 모듈은 폴더 골격과 내부 문서가 갖춰졌지만, 상위 지침의 잘못된 경로와 산출물 계약 충돌 때문에 현재 흐름을 완전히 정상으로 판정할 수 없다.**

## 확인 범위와 방법

- 범위: `1. 프롬프트` 하위 Markdown 318개, `AGENTS.md` 34개, 0번 마스터 33개.
- 대상: 프롬프트 루트 AGENTS, 프로젝트 기본 지침, 통합 마스터, 공통 지침, 기존 1~15번 기능, 신규 이미지 모듈 및 내부 1~8번, 창작 지원 하위 제작기, 보관 계통.
- 검증: 실제 파일 존재, 표준 Markdown 링크, 문서에 적힌 명시 경로, AGENTS→마스터→실행 문서 읽기 순서, 호출 번호·승인 게이트·산출물 계약·상위 운영 규칙을 대조했다.
- Markdown 링크: 내부 링크 4건은 모두 유효했다. 룰북 템플릿에서 처음 검출된 12건의 `[[modifier]]`는 링크가 아니라 스탯블록 자리표시자이므로 결함에서 제외했다.

| 보관/애니 포트레이트 | 정상 제외 | 루트 AGENTS가 `보관`을 활성 목록에서 제외한다. 보관 폴더는 현재 라우팅 대상이 아니다. |

## 정상 신호

1. **전환기 분리 라우팅이 명시되어 있다.** `1. 프롬프트/AGENTS.md`는 목표 1~8번 체계, 실제 구 번호 매핑, 구 이미지 기능의 비활성화를 함께 명시한다. 따라서 기존 이미지 폴더가 물리적으로 남은 사실 자체는 실패가 아니다.
2. **신규 이미지 모듈의 내부 1~8번은 모두 실재한다.** 각 기능은 0번 마스터·AGENTS·README를 보유한다. 신규 계통에서 파일 자체가 없어 실행이 중단되는 사례는 발견하지 못했다.
3. **공통 승인 게이트는 신규 구조와 연결되어 있다.** 신규 모듈 AGENTS의 읽기 순서, 공통 운영 지침, 승인 절차는 상위 → 공통 → 선택 기능 → 라이브러리의 흐름을 일관되게 제시한다.
4. **기존 일반 기능은 기본 골격이 보존되어 있다.** 최상위 15개 기능 폴더와 창작 지원의 5개 하위 제작기는 모두 필수 진입 문서를 갖춘다. `공통/종족 데이터`와 `보관`은 데이터/보관 성격이므로 0번 마스터 부재가 결함이 아니다.

## 결함

### C-01 — 상위 이미지 승인 경로가 두 번 중첩됨

- 심각도: 높음
- 증거:
  - `00. TRPG 세션 매니저 프로젝트 기본 지침.md:24,52,268`
  - `0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md:24,77,232`
- 잘못된 경로: `1. 이미지 생성 모듈/1. 이미지 생성 모듈/공통/1. 이미지 생성 공통 승인 절차.md`
- 실제 경로: `1. 이미지 생성 모듈/공통/1. 이미지 생성 공통 승인 절차.md`
- 영향: 이미지 생성의 최우선 하드 게이트에서 존재하지 않는 경로를 먼저 지시한다. 같은 문서의 뒤쪽에는 올바른 경로도 있으나, 상위 규칙을 위에서부터 적용하면 잘못된 경로로 멈출 수 있다.
- 최소 조치: 두 상위 문서의 6개 중첩 경로를 실제 경로로 통일한다.

### C-02 — 신규 포트레이트 고정 파이프라인과 단일 실행 모드 규칙이 충돌함

- 심각도: 높음
- 신규 계약:
  - `1. 이미지 생성 모듈/1. 반실사 포트레이트/0. 반실사 포트레이트 마스터 프롬프트.md:5-34`
  - 전신 9:16 → 전신 확정 → 동일 개체 흉상 9:16.
- 충돌 규칙:
  - `00. TRPG 세션 매니저 프로젝트 기본 지침.md:316`
  - `0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md:931`
  - 위 두 문장은 전신 1장 또는 초상화 1장만 생성하고, 둘 다 필요하면 독립 요청으로 처리하라고 지시한다.
- 영향: 신규 내부 1번으로 진입한 요청도 상위 문서의 단일 모드 규칙을 따라 흉상 단계를 생략하거나, 반대로 신규 마스터를 따라 고정 파이프라인을 강제할 수 있다.
- 최소 조치: 현재 정본 계약을 하나로 확정한다. 현행 신규 모듈을 정본으로 유지한다면 두 상위 문서의 단일 모드 문장을 고정 파이프라인과 각 단계별 별도 승인으로 교체한다.

### C-03 — 신규 내부 5~8번 AGENTS가 직접 진입점을 완성하지 못함

- 심각도: 중간
- 증거:
  - `1. 이미지 생성 모듈/5. 토큰 프레임 생성/AGENTS.md`
  - `1. 이미지 생성 모듈/6. 풍경 생성/AGENTS.md`
  - `1. 이미지 생성 모듈/7. 게임 아이콘 생성/AGENTS.md`
  - `1. 이미지 생성 모듈/8. 월드 지도 생성/AGENTS.md`
- 관찰: 네 파일은 역할 한 줄만 있고 0번 마스터·필수 실행 문서·공통 승인 절차의 읽기 순서가 없다. 직접 해당 하위 폴더에서 시작할 경우 폴더 AGENTS가 얇은 라우터 역할을 수행하지 못한다.
- 영향: 상위 모듈을 항상 경유할 때는 보완되지만, 해당 폴더가 독립 진입점인 프로젝트 운영 계약에는 맞지 않는다.
- 최소 조치: 각 AGENTS에 `0번 마스터 → 공통 승인 절차 → 해당 실행 규칙 → 필요한 라이브러리` 순서를 명시한다.

### C-04 — 최상위 AGENTS의 Drive 접근 시작 문구가 하위 기본 지침과 반대됨

- 심각도: 중간
- 증거:
  - `TRPG 데이터/AGENTS.md:34-36`은 Drive 자료 참조 시 `구글 드라이브에 접근을 시도합니다.`로 시작하라고 지시한다.
  - `1. 프롬프트/00. TRPG 세션 매니저 프로젝트 기본 지침.md:58-59`은 Codex에서 로컬 동기화 Markdown을 직접 읽고 그 문구를 쓰지 말라고 지시한다.
- 영향: 이미지가 아닌 일반 TRPG 요청도 최상위와 하위 지침의 어느 쪽을 적용할지 흔들린다.
- 최소 조치: 최상위 AGENTS를 현행 Codex 로컬 경로 정책에 맞추거나, 환경별 분기 규칙을 한 문장으로 명확히 통일한다.

## 경고 및 정리 대상

### W-01 — 기존 이미지 폴더는 비활성화됐지만, 각 폴더 내부에는 이관/비활성 안내가 없음

루트 AGENTS는 기존 이미지 8개 폴더를 신규 작업 진입점으로 쓰지 말라고 명시한다. 그러나 각 기존 폴더의 AGENTS·README에는 이관 사실이나 신규 모듈 경로가 없다. 경로를 직접 열거나 파일명을 검색해 시작하는 경우 구 규칙을 현행으로 오인할 수 있다.

이것은 기존 파일을 역사 자료로 보존한다는 전제에서는 정상이나, 직접 진입 가능성까지 차단하려면 각 구 이미지 폴더의 AGENTS 또는 README에 짧은 비활성 안내를 추가해야 한다.

### W-02 — 전환기 기능 수 표현이 일치하지 않음

`00. TRPG 세션 매니저 프로젝트 기본 지침.md:75`는 프롬프트 루트를 “1번부터 19번까지의 기능”으로 소개한다. 반면 프롬프트 루트 AGENTS의 목표 활성 체계는 8개다. 이는 물리적 구 번호가 남아 있는 전환기에는 설명 가능한 역사 정보지만, `준비` 명령의 출력 범위와 활성 기능 수를 혼동시킬 수 있다.

### W-03 — 신규 포트레이트 마스터의 라이브러리 경로 표기가 상대 기준을 생략함

`1. 이미지 생성 모듈/1. 반실사 포트레이트/0. 반실사 포트레이트 마스터 프롬프트.md:10-11`의 `라이브러리/...`는 모듈 루트를 기준으로 해석하면 실제 파일과 연결된다. 다만 같은 폴더의 AGENTS는 `../라이브러리/...`를 사용하므로, 하위 폴더 기준으로 읽으면 경로 기준이 다르게 보인다. 현재는 파일 누락이 아니며, 기준 경로 표기만 통일하는 편이 안전하다.

## 기존 계통의 단절 해석

기존 이미지 폴더에서는 끊어진 Markdown 링크를 발견하지 못했다. 이 결과는 “기존 것이 끊어져야 정상”이라는 기대와 다르지만, 현재 전환 설계에서는 **파일을 끊어 놓는 방식이 아니라 루트 라우터가 신규 진입을 금지하는 방식**을 채택한 것으로 해석해야 한다.

따라서 기존 계통의 보존된 연결은 정상이며, 판단 기준은 링크 단절이 아니라 다음 두 가지다.

1. 루트 라우터가 신규 이미지 요청을 신규 모듈로 보낸다.
2. 신규 모듈이 스스로 완결된 실제 경로와 상충하지 않는 계약을 제공한다.

첫째는 충족한다. 둘째는 C-01·C-02·C-03 때문에 아직 충족하지 못한다.

## 권장 처리 순서

1. C-02에서 포트레이트 계약 정본을 확정한다.
2. C-01의 잘못된 공통 승인 경로 6건을 수정한다.
3. C-03의 내부 5~8번 AGENTS를 최소 라우터 규격으로 보완한다.
4. C-04와 W-02의 최상위·기본·통합 문서 표현을 동기화한다.
5. 기존 이미지 폴더에 비활성 안내를 넣을지 결정한다. 이는 기능 수정이 아니라 오진 방지용 안내이며, 별도 승인 범위로 다룬다.

## 감사 한계

이번 감사는 문서의 실제 존재·명시 경로·라우팅·규칙 충돌을 대상으로 했다. 이미지 생성 도구 호출이나 외부 서비스 실행은 하지 않았고, 프롬프트 원본은 수정하지 않았다.
