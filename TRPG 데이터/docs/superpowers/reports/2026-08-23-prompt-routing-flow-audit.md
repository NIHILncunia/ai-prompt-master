# 프롬프트 지침 흐름 감사 보고서

## 판정 결과

- 판정: 수정 필요
- 범위: `TRPG 데이터` 루트부터 `1. 프롬프트`의 활성 1~8 기능, 이미지 모듈 내부 1~8 기능, 창작 지원 하위 제작기 진입 문서
- 방식: 읽기 전용 정적 추적. 파일을 수정하지 않았다.
- 기준: 현재 활성 1~8 번호 체계, 상위에서 하위로 이어지는 필수 읽기 순서, 이미지 승인 하드 게이트, 실제 존재하는 로컬 경로

## 현재 정본 흐름

```text
TRPG 데이터/AGENTS.md
  → 1. 프롬프트/AGENTS.md
    → 활성 기능 1~8의 AGENTS.md
      → 각 기능의 0. 마스터 프롬프트
        → 마스터가 지정한 실행 지침·라이브러리·템플릿
```

이미지 기능은 위 흐름에 더해 다음 경로를 일관되게 사용해야 한다.

```text
1. 이미지 생성 모듈
  → 공통 승인 절차
  → 내부 기능 1~8의 AGENTS.md와 마스터
  → 요구사항 확인서와 최종 영어 프롬프트
  → 마스터의 명시적 승인
  → 생성
```

## 확인된 문제

### P0 — 이미지 공통 승인 절차가 두 정본 경로로 분기됨

- 근거 경로
  - `1. 프롬프트/AGENTS.md:67`은 `1. 프롬프트/공통/1. 이미지 생성 공통 승인 절차.md`를 먼저 읽도록 한다.
  - 이미지 모듈의 내부 기능은 `1. 프롬프트/1. 이미지 생성 모듈/공통/1. 이미지 생성 공통 승인 절차.md`를 읽도록 한다.
- 문제
  - 두 파일은 같은 이름과 역할을 가지지만 SHA-256이 서로 다르다.
  - 프롬프트 루트의 공통 문서는 포트레이트 흉상을 두상·흉상·상반신 중 하나로 취급한다. 이미지 모듈 공통 문서는 `전신 확정 → 동일 개체 흉상 9:16`이라는 현재 고정 계약과 결과 저장 규칙을 가진다.
  - 따라서 루트 지침을 따라 시작하면 최신 포트레이트 승인 계약과 저장 절차를 건너뛸 수 있다.
- 영향
  - 이미지 생성 하드 게이트의 단일 정본 원칙이 깨지고, 포트레이트 승인 단계가 이전 계약으로 되돌아갈 수 있다.
- 권장 조치
  - 이미지 모듈 내부의 공통 승인 절차를 단일 정본으로 확정한다.
  - 프롬프트 루트와 기존 `공통` 폴더의 모든 진입 참조를 그 경로로 통일하거나, 구 공통 문서를 명시적으로 폐기·리디렉션한다.

### P1 — 로그 하이라이트·로그 분석의 재번호 이전 참조가 현재 2·3번 흐름을 뒤집음

- 기대 라우팅
  - 2번: 로그 하이라이트 추출
  - 3번: 로그 분석
  - 1번 이미지 생성 모듈 내부 4번: 세션 하이라이트 이미지 생성
- 근거 경로
  - `2. 로그 하이라이트 추출 프롬프트/AGENTS.md:13, 28-29`
  - `2. 로그 하이라이트 추출 프롬프트/0. 로그 하이라이트 추출 마스터 프롬프트.md:56, 71, 116, 120`
  - `2. 로그 하이라이트 추출 프롬프트/1. 로그 하이라이트 추출 지침서.md:25, 183, 247, 319, 376, 409, 413, 430, 444`
  - `3. 로그 분석 프롬프트/AGENTS.md:29`
  - `3. 로그 분석 프롬프트/0. 로그 분석 마스터 프롬프트.md:77, 83, 85`
  - `3. 로그 분석 프롬프트/1. 로그 분석 지침서.md:456, 459-460`
  - `0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md:432-434`
- 문제
  - `6번 분석본`, `4번 하이라이트 추출`, `5번 이미지 생성`이 현행 번호와 혼용된다.
  - `6번 분석본`은 6개 파일, `4번 하이라이트`는 5개 파일, `5번 이미지 생성`은 2개 파일에서 발견됐다.
  - 일부 문서는 같은 처리 순서 안에서 `3번 로그 분석본`과 `6번 분석본`을 함께 사용해 자기모순을 만든다.
- 영향
  - 로그 분석을 FVTT로, 하이라이트 추출을 과거 4번으로, 최종 이미지 생성을 과거 5번으로 해석할 위험이 있다.
- 권장 조치
  - 위 세 표현을 현재 경로 기반 명칭으로 일괄 교체한다. 번호만 쓰지 말고 `3. 로그 분석 프롬프트`, `2. 로그 하이라이트 추출 프롬프트`, `1번 이미지 생성 모듈 내부 4번`을 함께 표기한다.

### P1 — 통합 마스터의 TRPG 자문 파이프라인이 FVTT와 로그 분석 번호를 서로 바꿈

- 근거 경로: `1. 프롬프트/0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md:900-907`
- 문제
  - `FVTT 구현 방식 설계 → 3번`, `세션 로그와 플레이 흐름 확인 → 6번`으로 기록돼 있다.
  - 현행 체계에서는 각각 `6번 FVTT`, `3번 로그 분석`이어야 한다.
- 영향
  - 통합 마스터를 기준으로 자문 요청을 처리하면 기능 3과 6이 반대로 라우팅된다.
- 권장 조치
  - 파이프라인을 `FVTT 구현 방식 설계 → 6번`, `세션 로그와 플레이 흐름 확인 → 3번`으로 정정한다.

### P1 — 창작 지원 하위 제작기 3곳의 상위 문서 상대 경로가 실제로 존재하지 않음

- 근거 경로
  - `7. 창작 지원 프롬프트/특성 제작/AGENTS.md:18-19`
  - `7. 창작 지원 프롬프트/능력 제작/AGENTS.md:18-19`
  - `7. 창작 지원 프롬프트/클래스 제작/AGENTS.md:18-19`
- 문제
  - 세 문서가 `../00. TRPG 세션 매니저 프로젝트 기본 지침.md`, `../0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md`를 상위 문서로 적는다.
  - 해당 상대 경로는 `1. 프롬프트/7. 창작 지원 프롬프트/`에서 찾게 되지만 실제 파일은 `1. 프롬프트/`에 있다.
- 영향
  - 하위 제작기에서 직접 시작하면 필수 상위 규칙 두 개를 찾지 못한다.
- 권장 조치
  - 상대 경로를 `../../00. TRPG 세션 매니저 프로젝트 기본 지침.md`, `../../0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md`로 고치거나, 절대 프로젝트 상대 경로 표기로 통일한다.

### P2 — 룰북·설정·FVTT 마스터의 이미지 라우팅 범위가 내부 1~8 구조를 축소 표기함

- 근거 경로
  - `4. 룰북 관련 요청 프롬프트/0. 룰북 관련 요청 마스터 프롬프트.md:48-49`
  - `5. 설정 관련 요청 프롬프트/0. 설정 관련 요청 마스터 프롬프트.md:84-85`
  - `6. FVTT 관련 요청 프롬프트/0. FVTT 관련 요청 마스터 프롬프트.md:50-51`
- 문제
  - 세 문서가 이미지 요청을 `1~5번 이미지 관련 기능`으로 보낸다고 적는다.
  - 현재 이미지는 최상위 1번 모듈 내부 1~8 기능이며, 풍경·게임 아이콘·월드 지도 6~8이 이 표현에서 빠진다.
- 영향
  - 아이콘·풍경·지도 요청이 이미지 모듈에 포함되는지 불명확해진다.
- 권장 조치
  - `1번 이미지 생성 모듈의 목적에 맞는 내부 1~8 기능`으로 바꾸고, 필요하면 대표 사례만 괄호로 든다.

### P2 — 이미지 내부 기능을 직접 열었을 때 상위 모듈 지침이 읽기 순서에 없음

- 근거 경로: `1. 이미지 생성 모듈/1~8` 각 하위 기능의 `AGENTS.md`
- 문제
  - 내부 기능은 자신의 마스터와 공통 승인 절차는 읽도록 하지만, 상위 `1. 이미지 생성 모듈/AGENTS.md`와 모듈 마스터를 읽기 순서에 넣지 않는다.
  - 이번에 추가한 공통 붓터치 마감 기본값은 모듈 AGENTS에 있으므로, 하위 폴더에서 직접 시작하면 적용 여부 판단을 건너뛸 수 있다.
- 영향
  - 정상적인 루트 진입에서는 문제가 없지만, 하위 기능 폴더를 직접 작업 공간으로 열 때 최신 공통 정책이 누락될 수 있다.
- 권장 조치
  - 내부 1~8 AGENTS의 첫 단계에 상위 모듈 AGENTS와 모듈 마스터 확인을 추가한다. 공통 승인 절차의 단일 정본화와 함께 처리한다.

### P2 — 공통 폴더의 종족 자료 경로 표기가 실제 폴더명과 다름

- 근거 경로: `1. 프롬프트/공통/AGENTS.md:11`
- 문제
  - 문서는 공통 종족 자료를 `데이터/`로 적지만 실제 폴더는 `종족 데이터/`다.
- 영향
  - 공통 시각 자료나 종족 규칙을 찾는 흐름에서 존재하지 않는 디렉터리를 먼저 탐색한다.
- 권장 조치
  - `종족 데이터/`로 정정한다.

## 정상 확인 범위

- 루트 `AGENTS.md`의 활성 최상위 기능 1~8 목록과 실제 직계 폴더 1~8은 일치한다.
- 이미지 모듈 내부 1~8 폴더와 모듈 AGENTS의 목록은 일치한다.
- 이미지 모듈 내부 1~8 기능은 모두 공통 승인 절차를 읽기 순서에 포함한다.
- 세션 제작 8번은 루트부터 자신의 마스터·기본 지침·양식·품질 검수까지의 읽기 순서를 명시한다.
- 기능 4·5·6의 기본 경계와 7번 창작 지원의 상위 모듈 경계는 현재 번호 체계와 대체로 일치한다.

## 권장 수정 순서

1. 이미지 공통 승인 절차를 단일 정본으로 통합하고 루트 참조를 수정한다.
2. 로그 2·3번, 통합 마스터의 재번호 이전 참조를 현재 경로 기준으로 일괄 정비한다.
3. 창작 지원 하위 제작기 3곳의 상대 경로를 복구한다.
4. 이미지 라우팅 축약 표현·직접 진입 흐름·공통 종족 자료 경로를 보완한다.
5. 각 수정 뒤 루트 → 기능 → 마스터 → 필수 하위 문서의 재추적 검증을 실행한다.
