## 요청과 수행 범위

사용자가 지정 서버 접속 및 기존 매크로 테스트를 직접 요청했다. 기존 매크로 이름은 `스탯블록 임포터`다. 보조마스터1의 하단 바 1페이지에는 로그 저장 매크로만 보여 매크로 디렉터리에서 기존 임포터를 열었다. 매크로를 새로 만들지 않았다.

첨부 ZIP의 시작 프롬프트는 인계 자료로 구분했다. 이번에 사용한 테스트 데이터는 ZIP 07번 예시 및 이를 확장한 기술 검증용 데이터다. 공식 몬스터 데이터 또는 설정 정본으로 채택하지 않았다.

## 발견 오류와 최종 변경

입력창 자체는 열렸으나 임포트 시 `TypeError: fd.get is not a function`으로 Actor 생성 전에 중단됐다. 입력창 반환값을 FormData로 가정한 것이 원인이다.

최종 변경은 `DialogV2.input`의 `ok.callback`에서 `new FormData(button.form)`을 명시적으로 반환하도록 한 것이다. 그 외 임포터 로직은 유지했다.

- 서버 원본을 로컬 백업했다.
- 중간 수정본에서 괄호 누락을 구문 검사와 Foundry 저장 검증이 탐지했다. 해당 저장은 거부됐으며 괄호 보정 후 재검증했다.
- 최종 수정본의 비동기 JavaScript 구문 검사 통과.
- 실제 저장 후 다시 편집기를 열어 복사한 코드와 로컬 최종 수정본이 정확히 일치함을 확인했다.
- 전후 비교용 임시 계측은 제거했다. 최종 서버 코드에는 입력 반환값 수정만 남았다.

## 전후 데이터 비교 해석

비교 대상은 Actor.system, Actor.effects, 전체 Embedded Item 데이터다. 허용 변경인 Item.name과 Item.system.description.value, 갱신 메타데이터인 Item._stats는 비교에서 제외했다. Actor 및 prototypeToken 이름은 별도로 결과를 확인했다.

전체 비교의 첫 boolean 값은 false였다. 경로별 차이를 추적한 결과 한글화한 Item 5개에 `flags.dnd5e.riders.activity: []`가 추가된 것뿐이었다. 이는 임포터 수정 코드에서 직접 쓰는 필드가 아니다. 이 초기화의 구체적인 훅 소유자는 이번 시험에서 추적하지 않았다.

Activity, 피해, Save, Uses, Actor.system, Effect 내용에는 전후 차이가 없었다. 따라서 핵심 기계 데이터는 보존됐으나 모든 필드가 완전히 불변이라고 표현해서는 안 된다.
