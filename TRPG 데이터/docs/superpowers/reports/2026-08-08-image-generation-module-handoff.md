## 4. 확정된 핵심 결정

### 4-1. 상위 번호

프로젝트 전체 `1번`은 앞으로:

`1. 이미지 생성 모듈`

로 통합한다.

### 4-2. 이미지 모듈 내부 1번

`1. 반실사 포트레이트`

로 확정한다.

### 4-3. 반실사 포트레이트 고정 계약

```text
전신 9:16 1장
→ 사용자/작업 흐름에서 전신 확정
→ 확정 전신을 기준으로 흉상 9:16 1장
```

흉상은 신규 디자인이 아니라 전신의 동일 캐릭터를 기반으로 한다.

### 4-4. 반실사 스타일

신규 반실사 포트레이트 스타일 방향:

- 현실적 반실사
- 고급 붓터치
- 회화적 표면감
- 일러스트 분위기
- 과도한 포토리얼/AAA 3D CGI 렌더링 지양

과거 1번 기능의 `photorealistic cinematic 3D CGI` 중심 제약은 신규 스타일과 충돌하므로 그대로 이관하지 않는다.

### 4-5. 레이아웃 개념

레이아웃은 모든 이미지 기능에 강제되는 공통 축이 아니다.

**필요한 기능에서만 참조하는 선택형 조립 모듈**로 정의한다.

예:
- 단일 아이콘 → 레이아웃 참조 불필요
- 16개 아이콘 4x4 → `4x4` 레이아웃 참조
- 스프라이트 시트 → 특수 레이아웃 참조

포트레이트와 캐릭터 레퍼런스처럼 자체 고정 출력 계약이 있는 기능은 일반 레이아웃 라이브러리를 참조하지 않는다.

## 5. 신규 이미지 모듈 내부 기능 권장 번호

현재 권장안:

```text
1. 이미지 생성 모듈
├─ 1. 반실사 포트레이트
├─ 2. 배틀맵 생성
├─ 3. 캐릭터 레퍼런스 생성
├─ 4. 세션 하이라이트 이미지 생성
├─ 5. 토큰 프레임 생성
├─ 6. 풍경 생성
├─ 7. 게임 아이콘 생성
└─ 8. 월드 지도 생성
```

이 내부 번호는 현재 설계 기준 권장안이며, 실제 기존 기능 분석에서 통합/분리 필요성이 새로 발견되지 않는 한 그대로 사용한다.

## 6. 기존 기능 매핑

현재 이미지 병합 대상:

```text
기존 1번  포트레이트
기존 2번  배틀맵
기존 3번  캐릭터 레퍼런스 시트
기존 5번  세션 하이라이트 이미지
기존 10번 토큰 프레임
기존 12번 풍경 일러스트
기존 13번 게임 아이콘
기존 14번 월드 지도
```

신규 내부 번호와 대응:

```text
기존 1  → 신규 1-1
기존 2  → 신규 1-2
기존 3  → 신규 1-3
기존 5  → 신규 1-4
기존 10 → 신규 1-5
기존 12 → 신규 1-6
기존 13 → 신규 1-7
기존 14 → 신규 1-8
```

`4. 로그 하이라이트 추출`은 이미지 생성 기능이 아니므로 통합 대상에서 제외한다.

## 8. 조립 모델

최종 프롬프트는 다음 부품을 조립한다.

```text
공통 이미지 규칙
+ 기능 계약
+ 대상 규칙
+ 스타일 규칙
+ 필요 시 레이아웃 규칙
+ 견본/레퍼런스
+ 사용자 요구사항
```

레이아웃은 선택적이다.

예:

```text
게임 아이콘
+ 플랫 아이콘
+ 4x4 레이아웃
+ 지역 아이콘 16종
```

반실사 포트레이트:

```text
반실사 포트레이트
+ 휴머노이드
+ 붓터치 반실사
+ 전신 9:16 고정 계약
+ 사용자 외형 요구
```

## 11. 아직 확정하지 않은 사항

다음은 실제 구현 전에 추가 확인 가능하다.

- 배틀맵의 기본 캔버스 비율을 단일 기본값으로 고정할지 여부
- 세션 하이라이트의 기본 비율
- 토큰 프레임의 기본 출력 크기
- 게임 아이콘의 세부 스타일 목록 최종 범위
- 월드 지도의 기본 해상도/비율
- 레이아웃 라이브러리를 어디까지 초기 제공할지

이 항목들은 기능 자체의 구조를 흔들지 않으므로 실제 하위 기능 작성 단계에서 결정해도 된다.

## 12. 비이미지 기능 번호

전체 기능 재번호는 아직 완료하지 않았다.

원칙만 확정:

- 신규 전체 1번 = 이미지 생성 모듈
- 기존 이미지 번호들은 독립 최상위 번호에서 제거
- 나머지 활성 비이미지 기능은 이후 실제 활성 목록을 재확인한 후 2번부터 연속 재번호하는 방향 우선

과거 번호를 기억으로 추정하지 않는다.
현재 Drive 구조를 다시 확인한 뒤 최종 번호표를 작성한다.
