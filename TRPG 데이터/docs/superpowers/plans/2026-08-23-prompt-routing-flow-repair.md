# Prompt Routing Flow Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 활성 1~8 기능 체계에 맞춰 이미지 승인 정본, 로그 연계 번호, 창작 지원 상대 경로, 이미지 직접 진입 흐름을 복구한다.

**Architecture:** 이미지 승인 절차는 이미지 생성 모듈 내부 공통 문서를 단일 정본으로 삼고, 프롬프트 루트와 기존 공통 폴더에서는 그 문서로만 연결한다. 기능 간 참조는 현행 번호와 현재 폴더명을 함께 사용하며, 각 하위 기능은 상위 모듈의 진입 규칙을 먼저 읽는다.

**Tech Stack:** Markdown, PowerShell, ripgrep, 로컬 동기화 TRPG 데이터 문서 체계

**Spec:** [`2026-08-23-prompt-routing-flow-repair-design.md`](../specs/2026-08-23-prompt-routing-flow-repair-design.md)

## Global Constraints

- 이미지 승인 절차의 유일한 정본은 `1. 프롬프트/1. 이미지 생성 모듈/공통/1. 이미지 생성 공통 승인 절차.md`다.
- 기존 `1. 프롬프트/공통/1. 이미지 생성 공통 승인 절차.md`는 삭제하지 않고, 활성 정본이 아닌 안내 문서로 전환한다.
- 2번은 로그 하이라이트 추출, 3번은 로그 분석, 6번은 FVTT다.
- 최종 세션 하이라이트 이미지는 `1번 이미지 생성 모듈 내부 4번 세션 하이라이트 이미지 생성`이 담당한다.
- 이미지 모듈 내부 1~8의 개별 출력 계약·화풍·화면비는 변경하지 않는다.
- 활성 최상위 기능 1~8과 이미지 내부 기능 1~8의 폴더 구성은 변경하지 않는다.
- 모든 변경은 Markdown 문서로만 수행하며, 파일 삭제·이동·외부 업로드를 수행하지 않는다.
