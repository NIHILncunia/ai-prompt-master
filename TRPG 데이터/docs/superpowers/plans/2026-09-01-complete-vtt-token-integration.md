# 완성형 VTT 토큰 통합 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 독립 5번 토큰 프레임 기능을 제거하고, 포트레이트 전신 확정본과 사용자 업로드 이미지를 기준으로 완성형 VTT 토큰 PNG 1장을 생성하는 체계로 통합한다.

**Architecture:** 이미지 생성 모듈 내부 1번 반실사 포트레이트가 완성형 토큰의 유일한 소유 기능이 된다. 전신 기반·업로드 기반 경로는 같은 승인·자동 계열 선택·일반/엘리트/보스 프레이밍·검수 계약으로 합류하며, 프레임은 내부 시각 규칙으로만 남는다.

**Tech Stack:** Markdown 지침 문서, PowerShell 정적 검색, 로컬 Google Drive 동기화 작업 폴더

**Spec:** `docs/superpowers/specs/2026-09-01-complete-vtt-token-integration-design.md`

## Global Constraints

- 내부 5번 `토큰 프레임 생성` 기능과 하위 마스터·지침·템플릿·라이브러리·예시·개발 자료를 모두 제거한다.
- 내부 기능 번호는 `1·2·3·4·6·7·8`로 유지하고, 6·7·8번을 재번호하지 않는다.
- 결과물은 캐릭터가 포함된 1:1 투명 완성형 VTT 토큰 PNG 1장뿐이다. 빈 프레임 PNG와 중앙 `#FFFFFF` 빈 원형 계약은 남기지 않는다.
- 포트레이트 전신 확정본과 사용자 업로드 이미지는 각각 독립적으로 토큰 생성에 진입한다.
- 캐릭터 본체는 재생성·재디자인하지 않으며, 원본 형상을 바꾸지 않는 크롭·배치·마스킹·블렌딩·미세 보정만 허용한다.
- 토큰 계열은 유형·종족·분류, 세력·소속·역할·위계, 기준 토큰의 시각 언어로 자동 선택한다. 마스터의 명시 지시는 항상 우선한다.
- 등급은 일반·엘리트·보스로 구분한다. 프레임 본체 두께는 공통이며, 장식 밀도와 보스 표적성으로만 위계를 표현한다.
- 보스·표적 정보가 없으면 일반 토큰으로 처리한다.
- 모든 이미지 생성은 요구사항 확인서·최종 영어 프롬프트·마스터의 명시적 승인을 거친다.
- 현재 작업 폴더는 Git 저장소가 아니므로 커밋을 시도하지 않는다. `git diff --check`는 `.git`이 존재하는 경우에만 실행한다.

**Interfaces:**

- Consumes: 확정 전신 이미지 또는 사용자 업로드 이미지, 유형·설정·역할 정보, 기존 기준 토큰과 계열 프로필
- Produces: 두 입력 경로가 공유하는 완성형 토큰 계약과 계열 프로필 자동 선택 규칙

- [ ] **Step 1: 기존 완성형 토큰 지침과 토큰 프레임 지침에서 이관할 규칙을 분류한다.**

  유지 대상은 원형 프레임, 재질·색상·문양·장식·외곽 실루엣, 균형, 캐릭터 가림 방지다. 삭제 대상은 빈 중앙 마스크, `#FFFFFF` 요구, 별도 프레임 PNG, 프레임 전용 입력 모드다.

- [ ] **Step 2: `4. 완성형 토큰 생성 지침.md`를 두 입력 경로의 단일 정본으로 갱신한다.**

  포트레이트 전신 확정본 경로와 사용자 업로드 이미지 직접 경로를 별도 진입으로 명시한다. 업로드 경로에서는 단일 대상 식별, 원형 배치 가능성, 최소 정리의 허용 범위를 정한다. 두 경로의 출력은 `<대상명> 토큰.png`, `캐릭터` 저장 경로, 1:1 투명 PNG 1장으로 통일한다.

- [ ] **Step 3: 일반·엘리트·보스의 공통 프레임 폭과 차등 장식 규칙을 추가한다.**

  일반은 최소 장식, 엘리트는 뚜렷한 문양·보석·제한적 외곽 장식, 보스는 가장 높은 장식 밀도와 대칭적 표적 표현을 사용한다. 보스 표적 표현은 조준선·UI 마커가 아닌 프레임 주변의 표식·대비·장식 구조만으로 구성한다. 등급이 없으면 일반으로 처리한다.

- [ ] **Step 4: 계열 프로필 운영 지침을 생성한다.**

  프로필 필드를 계열명, 기준 토큰, 적용 유형, 프레임 공통 두께, 색상, 재질, 문양, 외곽 실루엣, 대칭, 등급별 장식 밀도, 보스 표적 표현, 금지 요소로 고정한다. 유형·종족·분류 → 세력·소속·역할·위계 → 시각 일치도 순으로 자동 선택하고, 일치 계열이 없거나 충돌하면 새 기본 계열을 만든다. 기존 캐릭터 본체 요소를 복제하지 않는 규칙을 명시한다.

- [ ] **Step 5: 포트레이트 공통 지침의 보존·금지 규칙을 새 계약과 일치시킨다.**

  확정 전신 또는 업로드 원본의 얼굴·신체·의상·장비·대표 색·실루엣을 보존하고, 캐릭터 재생성·재디자인·빈 프레임 결과를 금지한다.

- [ ] **Step 6: 핵심 기능 문서를 정적 점검한다.**

  Run:

  ```powershell
  rg -n '포트레이트 전신 확정본|사용자 업로드 이미지|일반|엘리트|보스|토큰 계열|#FFFFFF|빈 프레임' '1. 프롬프트/1. 이미지 생성 모듈/1. 반실사 포트레이트'
  ```

  Expected: 두 입력 경로와 세 등급·계열 규칙은 새 지침에서 확인되고, `#FFFFFF`와 빈 프레임은 금지 항목에서만 확인된다.
