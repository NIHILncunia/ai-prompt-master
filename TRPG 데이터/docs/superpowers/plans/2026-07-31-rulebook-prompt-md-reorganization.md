# 7번 룰북 프롬프트 Markdown 정리 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 루트의 룰북 관련 Markdown 3개를 7번 기능으로 이관하고, 지침과 산출물 템플릿을 분리한다.

**Architecture:** 7번 폴더의 0번 마스터와 1번 일반 지침서는 요청 분류와 공통 절차를 맡는다. 2번·3번은 몬스터 작업의 세부 규칙, `템플릿/`은 최종 출력 레이아웃, 9999번은 룰북 소유 현황 색인을 맡는다.

**Tech Stack:** Markdown, PowerShell, ripgrep

## Global Constraints

- Google Drive의 파일·폴더·문서는 수정하지 않는다.
- `드라켄하임 오염 룰 정리.md`와 19번 기능의 상위 등록은 이번 작업 범위에서 제외한다.
- FVTT 임포트용 스탯블록 `text` 코드블록의 필드 순서, 공백, 영문 표기, 섹션 구성, 번역 블록 형식은 변경하지 않는다.
- Git 커밋·푸시는 사용자가 명시적으로 요청하기 전에는 수행하지 않는다.

### Task 1: 룰북 자료와 템플릿 경계 구성

**Files:**
- Create: `1. 프롬프트/7. 룰북 관련 요청 프롬프트/2. 몬스터 스탯블록 지침.md`
- Create: `1. 프롬프트/7. 룰북 관련 요청 프롬프트/3. 룰북 몬스터 리스트업 지침.md`
- Create: `1. 프롬프트/7. 룰북 관련 요청 프롬프트/9999. D&D 룰북 소유 리스트.md`
- Create: `1. 프롬프트/7. 룰북 관련 요청 프롬프트/템플릿/몬스터 스탯블록 출력 템플릿.md`
- Create: `1. 프롬프트/7. 룰북 관련 요청 프롬프트/템플릿/룰북 몬스터 리스트업 출력 템플릿.md`
- Delete: `지침 - D&D 5.5 몬스터 스탯블록 생성 및 출력.md`
- Delete: `지침 - 룰북 몬스터 리스트업.md`
- Delete: `D&D 룰북 소유 리스트.md`

**Interfaces:**
- Consumes: 기존 루트의 스탯블록 지침, 몬스터 목록 지침, 룰북 소유 목록
- Produces: 7번 기능 안에서 직접 참조 가능한 규칙·템플릿·색인 파일

- [ ] **Step 1: 이동 전 스탯블록 레이아웃 기준을 추출한다.**

  `지침 - D&D 5.5 몬스터 스탯블록 생성 및 출력.md`의 세 개 `text` 코드블록을 각각 별도 문자열로 읽는다. 첫 번째는 원본 스탯블록, 두 번째는 메인 스탯블록, 세 번째는 한국어 번역 템플릿이다.

- [ ] **Step 2: 템플릿 문서를 만든다.**

  `템플릿/몬스터 스탯블록 출력 템플릿.md`에 세 `text` 코드블록을 내용 변경 없이 넣는다. `템플릿/룰북 몬스터 리스트업 출력 템플릿.md`에는 다음 목록 레이아웃만 둔다.

  ```md
  - 몬스터 이름(영어 이름) / 크기 / 유형 / 스탯블록(O/X)
  ```

- [ ] **Step 3: 세부 지침과 색인을 이관한다.**

  `2. 몬스터 스탯블록 지침.md`에는 기본 원칙, 출력 조건, 창작·조정 기준, 최종 검수만 둔다. 레이아웃을 요구하는 항목은 `템플릿/몬스터 스탯블록 출력 템플릿.md`를 참조하도록 바꾼다. `3. 룰북 몬스터 리스트업 지침.md`에는 목적, 탐색·분석·출력 절차, 항목 판정 규칙만 두고 레이아웃은 목록 템플릿으로 분리한다. 보유 목록은 내용 변경 없이 `9999. D&D 룰북 소유 리스트.md`로 이관한다.

- [ ] **Step 4: 루트 원본을 제거한다.**

  세 새 문서와 두 템플릿의 내용을 확인한 뒤, 루트의 원본 세 파일을 삭제한다.

- [ ] **Step 5: 레이아웃 보존을 검증한다.**

  원본에서 미리 추출한 세 `text` 코드블록과 새 스탯블록 템플릿의 세 코드블록을 `Compare-Object`로 비교한다. 기대 결과는 차이 없음이다.

### Task 2: 7번 기능의 조건부 읽기와 경로 참조 갱신

**Files:**
- Modify: `1. 프롬프트/7. 룰북 관련 요청 프롬프트/AGENTS.md`
- Modify: `1. 프롬프트/7. 룰북 관련 요청 프롬프트/0. 룰북 관련 요청 마스터 프롬프트.md`
- Modify: `1. 프롬프트/7. 룰북 관련 요청 프롬프트/1. 룰북 관련 요청 지침서.md`

**Interfaces:**
- Consumes: Task 1의 새 파일명과 `템플릿/` 경로
- Produces: 요청 유형별로 필요한 문서를 정확히 읽는 7번 기능 진입점

- [ ] **Step 1: 7번 AGENTS의 자료 위치와 읽기 규칙을 갱신한다.**

  룰북 원문은 `TRPG 데이터/0. 룰북`, 보유 현황은 같은 폴더의 `9999. D&D 룰북 소유 리스트.md`라고 명시한다. 기본 읽기 순서는 0번 마스터와 1번 일반 지침서까지만 유지하고, 스탯블록·목록·보유 확인 요청에 각각 2번·3번·9999번을 조건부로 추가한다.

- [ ] **Step 2: 7번 마스터의 직접 참조를 교체한다.**

  루트의 `D&D 룰북 소유 리스트` 참조를 `9999. D&D 룰북 소유 리스트.md`로, 루트 스탯블록 지침 참조를 `2. 몬스터 스탯블록 지침.md`로 바꾼다. 몬스터 목록 요청에는 `3. 룰북 몬스터 리스트업 지침.md`와 해당 템플릿을 읽는다고 추가한다.

- [ ] **Step 3: 7번 일반 지침서의 중복 레이아웃을 제거한다.**

  커스텀 스탯블록 섹션의 기존 루트 파일명을 2번 지침과 템플릿 경로로 교체한다. `룰북 몬스터 리스트업` 섹션의 Markdown 표와 그 출력 규칙은 3번 지침 및 목록 템플릿 참조로 대체한다. 탐색, 수록 여부, 출처 판정 규칙은 유지한다.

- [ ] **Step 4: 7번 범위에서 끊어진 참조가 없는지 검증한다.**

  `rg -n '지침 - D&D 5.5 몬스터 스탯블록 생성 및 출력|지침 - 룰북 몬스터 리스트업|TRPG 데이터/D&D 룰북 소유 리스트' '1. 프롬프트/7. 룰북 관련 요청 프롬프트'`를 실행한다. 기대 결과는 0건이다.

**Interfaces:**
- Consumes: Task 1의 `9999. D&D 룰북 소유 리스트.md`
- Produces: 7번 기능의 실제 보유 현황 위치를 가리키는 상위 진입점

- [ ] **Step 1: 모든 루트 경로 표현을 새 경로로 바꾼다.**

  `D&D 룰북 소유 리스트.md`의 루트 참조와 `TRPG 데이터/D&D 룰북 소유 리스트` 문자열을 `TRPG 데이터/1. 프롬프트/7. 룰북 관련 요청 프롬프트/9999. D&D 룰북 소유 리스트.md`로 교체한다. 프롬프트 루트 AGENTS의 Markdown 링크는 `7. 룰북 관련 요청 프롬프트/9999. D&D 룰북 소유 리스트.md`를 가리키게 한다.

- [ ] **Step 2: 전체 참조와 파일 위치를 검증한다.**

  `rg -n '지침 - D&D 5.5 몬스터 스탯블록 생성 및 출력|지침 - 룰북 몬스터 리스트업|TRPG 데이터/D&D 룰북 소유 리스트' --glob '*.md' .`를 실행해 기존 경로가 0건인지 확인한다. `Test-Path`로 새 파일 다섯 개와 루트 원본 세 파일의 부재를 함께 확인한다.

- [ ] **Step 3: Markdown 구조를 최종 검수한다.**

  변경된 모든 Markdown 파일에서 제목 레벨, 코드 펜스 짝, 링크 대상의 존재 여부를 확인한다. 스탯블록 템플릿의 세 `text` 코드블록이 존재하고, `git diff --check`가 가능하면 공백 오류도 확인한다.
