# 창작 지원 모듈 통합 및 기능 번호 재편 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 아이템·특성·능력·클래스·인물 제작을 11번 창작 지원 프롬프트로 통합하고, 남은 활성 기능을 연속 번호로 정리한다.

**Architecture:** 11번은 공통 라우팅과 관계 규격을 담당하고, 다섯 제작기는 내부 폴더에서 전문 규칙을 유지한다. 완성 데이터는 기존 데이터 창고 유형별 저장 구조를 유지하며, 데이터 간 연결은 `data_id`, `relations`, `effect_rules`로 기록한다.

**Tech Stack:** Markdown, YAML frontmatter, PowerShell, ripgrep

## Global Constraints

- 사용자 호칭과 모든 운영 문서는 한국어를 사용한다.
- 최상위 11번 명칭은 `창작 지원 프롬프트`다.
- 이전 번호·이전 경로·이전 번호 별칭은 최종 운영 문서에 남기지 않는다.
- `준비 11번`은 활성 제작기와 크리처 예정 제작기를 함께 표시한다.
- 하위 호출은 `11번 <제작기명> 준비.`만 사용한다.
- 공용 태그 사전의 정본은 `1. 프롬프트/공통/라이브러리/공용 태그 사전.md`이며 복제하지 않는다.
- 데이터 창고의 아이템·특성·능력·클래스·인물 폴더는 유지한다.
- 기존 설정 정본의 `uuid`는 유지하고, 새 창작 데이터 참조에는 `data_id`를 사용한다.
- 특성·능력 단계는 소=1, 중=2, 대=3, 특대=4이며 5 이상 표시는 특대+다.
- Google Drive 또는 GitHub에는 직접 쓰지 않는다. 이 작업은 동기화된 로컬 Markdown에만 적용한다.
- 현재 작업 루트는 Git 저장소가 아니므로 커밋 단계는 수행하지 않는다.
