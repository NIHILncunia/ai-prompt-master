# TRPG 프롬프트 표준화 1단계 및 시범 이관 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 상위 구조 규약을 고정하고 7번 룰북 및 19번 세션 제작 기능을 표준 구조로 이관한다.

**Architecture:** 상위 문서는 표준 구조와 예외·동기화 원칙을 기록한다. 7번과 19번은 AGENTS를 얇은 라우터로 유지하면서 README·라이브러리·템플릿·개발 자료를 각 책임에 맞게 배치한다.

**Tech Stack:** Markdown, PowerShell, ripgrep

## Global Constraints

- 정식 프롬프트 루트는 `TRPG 데이터/1. 프롬프트`다.
- Google Drive의 파일·폴더·문서는 직접 수정하지 않는다.
- 프로젝트 위그드라실의 설정 정본은 공통 라이브러리에 복제하지 않는다.
- `9999. D&D 룰북 소유 리스트.md`는 실행 순서에 포함되지 않는 색인·레지스트리이며 숫자 문서의 연속 번호 규칙에서 제외한다.
- AGENTS에는 라우팅, 조건부 읽기 대상, 의존성, 기능 경계, 동기화 범위만 둔다.
- 비정규 파일은 삭제하지 않고 `개발 자료/` 또는 단계 산출물 목록으로 보존한다.
- Git 커밋·푸시는 사용자가 명시적으로 요청하기 전에는 수행하지 않는다.

### Task 1: 표준 규약과 이관 기준선 고정

**Files:**
- Modify: `드라이브 프롬프트 폴더 구조 개편.md`
- Modify: `AGENTS.md`
- Modify: `1. 프롬프트/AGENTS.md`
- Modify: `1. 프롬프트/00. TRPG 세션 매니저 프로젝트 기본 지침.md`
- Modify: `1. 프롬프트/0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md`
- Create: `docs/superpowers/reports/2026-07-31-prompt-standardization-baseline.md`

**Interfaces:**
- Consumes: `docs/superpowers/specs/2026-07-31-prompt-folder-standardization-execution-design.md`
- Produces: 7번·19번이 참조할 수 있는 표준 구조, 번호 예외, 파일 보존 규약

- [ ] **Step 1: 이동 전 기준선을 기록한다.**

  1~19번과 공통 폴더의 `AGENTS.md`, `README.md`, 0번 마스터, `라이브러리/`, `템플릿/` 존재 여부를 표로 기록한다. 7번의 `9999. D&D 룰북 소유 리스트.md`, 19번의 `검증 보고서.md`와 `상위 문서 등록 및 동기화 수정 지침.md`를 별도 항목으로 기록한다.

- [ ] **Step 2: 설계서의 경로·예외·정본 경계를 보정한다.**

  `드라이브 프롬프트 폴더 구조 개편.md`에서 `TRPG 데이터/프롬프트`를 `TRPG 데이터/1. 프롬프트`로 고친다. 7번의 `9999` 색인은 연속 실행 문서가 아니라는 예외, AGENTS의 얇은 라우터 책임, 설정 정본 비복제 원칙, 비정규 파일 보존 원칙을 명시한다.

- [ ] **Step 3: 상위 라우터에 표준 구조 원칙을 등록한다.**

  루트 AGENTS·프롬프트 루트 AGENTS·프로젝트 기본 지침·통합 마스터에 다음을 일관되게 기록한다: 0번은 마스터, 1번 이후는 연속 실행 문서, `README.md`는 사람용, `라이브러리/`는 재사용 자료, `템플릿/`은 산출물 레이아웃, `9999`는 색인 예외, 구조 변경 시 상위 문서와 기능 진입점을 함께 점검한다.

- [ ] **Step 4: 규약 반영을 검증한다.**

  네 상위 문서와 설계서에서 `1. 프롬프트`, `9999`, `README.md`, `라이브러리/`, `템플릿/`, `정본` 키워드를 확인한다. `TRPG 데이터/프롬프트/`라는 이전 경로가 없고, `1번부터 19번` 표기가 유지되는지 검사한다.

### Task 2: 7번 룰북 기능을 표준 구조로 완성

**Files:**
- Create: `1. 프롬프트/7. 룰북 관련 요청 프롬프트/README.md`
- Create: `1. 프롬프트/7. 룰북 관련 요청 프롬프트/라이브러리/`
- Modify: `1. 프롬프트/7. 룰북 관련 요청 프롬프트/AGENTS.md`
- Modify: `1. 프롬프트/7. 룰북 관련 요청 프롬프트/0. 룰북 관련 요청 마스터 프롬프트.md`

**Interfaces:**
- Consumes: 기존 0~3번 실행 문서, `9999. D&D 룰북 소유 리스트.md`, `템플릿/`
- Produces: 표준 구조를 충족하는 룰북 기능의 시범 사례

- [ ] **Step 1: README를 작성한다.**

  README에는 기능 개요, 적용 대상, 주요 사용 사례, 파일 구성, 숫자 문서 적용 순서, 기능 전용 라이브러리, 공통 라이브러리 의존성, 템플릿, 입력 자료, 출력 결과, 관련 기능, 유지보수 주의사항을 둔다. 현재 기능 전용 라이브러리와 공통 라이브러리 의존성이 없음을 명시한다.

- [ ] **Step 2: 빈 라이브러리 폴더를 만든다.**

  `라이브러리/`을 만들고 파일을 넣지 않는다. 이 폴더는 미래의 룰북 기능 전용 재사용 자료만 수용하며, 룰북 원문과 보유 목록은 이 폴더로 옮기지 않는다.

- [ ] **Step 3: AGENTS와 0번 마스터의 역할을 정리한다.**

  AGENTS에는 기본·조건부 읽기 순서, 9999 색인 예외, 템플릿 선택, 9번 FVTT·8번 설정과의 경계, 상위 문서 동기화 조건만 둔다. 0번 마스터에는 요청 분류별 0~3번·9999·템플릿의 조건부 적용 순서를 둔다. README를 필수 실행 문서로 지정하지 않는다.

- [ ] **Step 4: 7번 구조를 검증한다.**

  `AGENTS.md`, `README.md`, `0. 룰북 관련 요청 마스터 프롬프트.md`, `라이브러리/`, `템플릿/`의 존재를 확인한다. 실행 문서가 0·1·2·3이고, `9999. D&D 룰북 소유 리스트.md`만 예외로 남았는지 확인한다. 스탯블록 템플릿의 `text` 코드블록 수가 3인지 검사한다.

### Task 3: 19번 세션 제작 기능을 표준 구조로 완성

**Files:**
- Create: `1. 프롬프트/19. 세션 제작 프롬프트/README.md`
- Create: `1. 프롬프트/19. 세션 제작 프롬프트/라이브러리/`
- Create: `1. 프롬프트/19. 세션 제작 프롬프트/개발 자료/`
- Move: `1. 프롬프트/19. 세션 제작 프롬프트/검증 보고서.md` to `1. 프롬프트/19. 세션 제작 프롬프트/개발 자료/검증 보고서.md`
- Move: `1. 프롬프트/19. 세션 제작 프롬프트/상위 문서 등록 및 동기화 수정 지침.md` to `1. 프롬프트/19. 세션 제작 프롬프트/개발 자료/상위 문서 등록 및 동기화 수정 지침.md`
- Move: `1. 프롬프트/19. 세션 제작 프롬프트/8. 세션 제작 예시 라이브러리.md` to `1. 프롬프트/19. 세션 제작 프롬프트/8. 세션 제작 예시.md`
- Modify: `1. 프롬프트/19. 세션 제작 프롬프트/AGENTS.md`
- Modify: `1. 프롬프트/19. 세션 제작 프롬프트/0. 세션 제작 마스터 프롬프트.md`
- Modify: every Markdown file that directly references one of the three moved files

**Interfaces:**
- Consumes: 기존 0~8번 세션 제작 문서와 `템플릿/`
- Produces: 숫자 문서·예시·검수·비정규 자료가 분리된 세션 제작 기능의 시범 사례

- [ ] **Step 1: 직접 참조를 먼저 목록화한다.**

  세 이동 대상 파일명으로 `rg -n --glob '*.md'`를 실행해 참조 파일과 줄을 목록화한다. 이 목록을 기준선 보고서에 추가한다.

- [ ] **Step 2: README와 빈 라이브러리를 만든다.**

  README는 7번과 같은 공통 목차를 사용하되, 입력 자료에 룩스테라 정본·세션 로그 분석본·기존 세션 아크를, 출력 결과에 단일 세션 Markdown·연속 아크 개요·ZIP을 기록한다. `라이브러리/`은 비어 있는 기능 전용 재사용 자료 공간으로 만든다.

- [ ] **Step 3: 예시와 비정규 파일을 분리한다.**

  `8. 세션 제작 예시 라이브러리.md`를 `8. 세션 제작 예시.md`로 바꾼다. 검증 보고서와 상위 문서 등록 지침은 `개발 자료/`로 이관해 실행 순서에서 제외한다. 내용은 변경하지 않는다.

- [ ] **Step 4: AGENTS와 0번 마스터를 갱신한다.**

  AGENTS에는 0~8번 실행 문서의 조건부 읽기와 템플릿 선택, 6번 로그 분석·7번 룰북·8번 설정·9번 FVTT와의 경계, 개발 자료 비필수 원칙을 기록한다. 0번 마스터에는 예시 8번과 템플릿·검수 7번을 필요한 경우 읽는 순서를 추가한다.

- [ ] **Step 5: 19번 구조와 참조를 검증한다.**

  실행 문서가 0~8번 연속인지, README·라이브러리·템플릿·개발 자료가 존재하는지 확인한다. 원래 비정규 파일 경로와 `8. 세션 제작 예시 라이브러리.md` 참조가 0건인지 검사한다. 새 경로의 파일 세 개가 존재하는지 확인한다.

### Task 4: 시범 단계 종합 검증과 다음 이관 기준 확정

**Files:**
- Create: `docs/superpowers/reports/2026-07-31-prompt-standardization-pilot-verification.md`

**Interfaces:**
- Consumes: Tasks 1~3의 기준선, 표준 구조, 파일 이동 결과
- Produces: 다음 기능군 이관에 재사용할 검증 보고서와 이관 기준

- [ ] **Step 1: 구조 검증을 실행한다.**

  7번과 19번 각각에 `AGENTS.md`, `README.md`, 0번 마스터, `라이브러리/`, `템플릿/`이 있는지 확인한다. 19번에는 `개발 자료/`도 있는지 확인한다.

- [ ] **Step 2: 참조·번호 검증을 실행한다.**

  모든 Markdown에서 7번의 이전 루트 경로와 19번의 이전 비정규 파일 경로를 검색한다. 7번은 0·1·2·3과 9999 예외, 19번은 0~8 연속 번호를 만족하는지 확인한다.

- [ ] **Step 3: 보고서를 작성한다.**

  변경 파일, 이동 파일, 새 구조, 검증 명령과 결과, 보류된 공통 라이브러리 후보, 다음 기능군에 적용할 체크리스트를 보고서에 기록한다.

- [ ] **Step 4: 로컬 ZIP 대상 목록을 확인한다.**

  7번과 19번의 전체 폴더와 변경된 상위 문서를 포함하는 ZIP 대상 목록을 작성한다. ZIP 생성은 시범 단계 검증이 통과한 뒤에만 수행한다.
