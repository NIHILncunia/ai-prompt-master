# 완성형 VTT 토큰 통합 설계

## 목적

내부 5번 `토큰 프레임 생성` 단독 기능을 완전히 제거한다. 캐릭터가 포함된 완성형 VTT 토큰만 제공하며, 프레임은 독립 산출물이 아니라 토큰 내부에서 자동 구성한다.

새 체계는 다음 두 경로를 지원한다.

```text
포트레이트 전신 확정본
  → 유형·계열·등급 자동 판정
  → 자동 프레이밍
  → 완성형 VTT 토큰 PNG 1장

사용자 업로드 이미지
  → 대상·유형·계열·등급 자동 분석
  → 최소 정리·원형 배치·자동 프레이밍
  → 완성형 VTT 토큰 PNG 1장
```

## 기능 경계

- 완성형 토큰은 이미지 생성 모듈 내부 1번 `반실사 포트레이트`가 소유한다.
- 포트레이트 전신 기반 토큰은 전신 확정 뒤의 후속 산출물이다.
- 업로드 이미지 기반 토큰은 전신 생성을 선행하지 않는 직접 진입 경로다.
- 두 경로 모두 캐릭터가 포함된 1:1 투명 PNG 1장만 제공한다.
- 캐릭터 본체는 새로 생성·재디자인하지 않는다. 크롭, 확대·축소, 위치 이동, 가장자리 블렌딩, 마스킹, 원본 형상을 바꾸지 않는 미세 보정만 허용한다.
- 프레임은 원형 배치와 장식 규칙의 내부 처리이며, 빈 프레임 PNG나 중앙 빈 원형 마스크는 제공하지 않는다.

## 공통 산출물·승인·검수 계약

### 산출물

- 캐릭터를 포함한 1:1 정사각형 완성형 VTT 토큰 PNG 1장
- 원형 토큰 바깥 투명 배경
- 파일명: `<대상명> 토큰.png`
- 저장 위치: `15. 이미지 생성 결과/캐릭터/`

### 승인

토큰은 전신·초상화·다른 토큰의 승인 상태를 재사용하지 않는다. 생성 전에 한국어 요구사항 확인서와 최종 영어 프롬프트를 공개하고, 마스터의 명시적 승인을 받아야 한다.

확인서에는 기준 이미지, 대상 유형, 자동 적용 계열, 적용 등급, 프레임의 색·재질·문양·장식 밀도, 단일 PNG 산출물 계약을 기록한다.

### 검수

- 캐릭터가 토큰에 실제 포함되어 있음
- 프레임 본체가 기하학적으로 완전한 원형임
- 원형 바깥 영역이 투명함
- 캐릭터의 핵심 식별 요소가 프레임에 과도하게 가려지지 않음
- 자동 적용 계열과 등급의 시각 규칙이 일치함
- 중앙 `#FFFFFF` 빈 원형, 별도 프레임 출력, 캐릭터 없는 결과가 없음

## 일반·엘리트·보스 등급

프레임 본체의 두께는 일반·엘리트·보스에서 동일하게 유지한다. 위계는 프레임 폭이 아니라 장식의 밀도와 표적성으로 구분한다.

| 등급 | 판정 | 시각 규칙 |
| --- | --- | --- |
| 일반 | 등급 정보가 없거나 일반으로 명시 | 대표 색·재질을 반영한 절제된 링과 최소 문양 |
| 엘리트 | 엘리트·정예·강화 개체로 명시 | 같은 두께의 링에 더 뚜렷한 문양·보석·제한적 외곽 장식 |
| 보스 | 보스·중간보스·최종보스·표적·토벌 대상으로 명시 | 같은 두께의 링에 가장 높은 장식 밀도, 대칭적 위계 장식, 강한 대비의 표적 표현 |

- 보스 표적성은 캐릭터를 덮는 조준선이나 UI 마커가 아니라, 프레임 주변의 대칭적 표식·대비색·위협성 있는 장식 구조로 표현한다.
- 보스·표적 정보가 없으면 자동 추론하지 않고 일반 토큰으로 생성한다.
- 일반 몬스터를 임의로 엘리트나 보스처럼 표현하지 않는다.

## 토큰 계열 프로필

빈 프레임 파일 대신 기준 완성형 토큰 이미지와 Markdown 계열 프로필을 함께 보관한다.

```text
토큰 계열
├─ 기준 완성형 토큰 PNG
└─ 계열 프로필 Markdown
   ├─ 계열 정체성과 적용 유형
   ├─ 프레임 공통 두께
   ├─ 주·보조 색상과 재질
   ├─ 문양·장식·외곽 실루엣
   ├─ 일반·엘리트·보스 장식 밀도
   ├─ 보스 표적 표현
   └─ 캐릭터 본체에 적용 금지인 요소
```

- 계열 프로필은 `1. 반실사 포트레이트/라이브러리/토큰 계열 프로필 운영 지침.md`에서 관리한다.
- 새 대상은 유형·종족·분류, 세력·소속·역할·위계, 기준 토큰의 시각 언어 순으로 기존 계열을 자동 선택한다.
- 같은 유형의 계열이 여러 개면 세력·지역·역할·시각 일치도가 가장 높은 계열을 선택한다.
- 일치하는 계열이 없거나 충돌하면 새 기본 계열로 생성하고, 해당 결과를 이후 재사용 가능한 기준으로 보관한다.
- 마스터의 명시적 계열·색·분위기 지시는 자동 선택보다 우선한다.
- 계열 규칙은 프레임 시각 언어만 재사용하며, 기존 캐릭터의 얼굴·의상·장비·포즈·실루엣을 새 대상에 복제하지 않는다.

## 5번 기능 제거와 문서 이관

### 삭제

`1. 이미지 생성 모듈/5. 토큰 프레임 생성/`과 하위 마스터·지침·템플릿·라이브러리·예시·개발 자료를 모두 제거한다.

다음 내용은 삭제하고 이관하지 않는다.

- 중앙 `#FFFFFF` 빈 원형 및 Inner Mask 계약
- 중앙 영역 침범 금지에 기반한 빈 프레임 계약
- 별도 프레임 PNG 출력
- 프레임 전용 입력 모드와 출력 템플릿

### 이관

다음 내용은 완성형 토큰 지침으로 이관한다.

- 재질·색상·문양·장식·외곽 실루엣의 해석 어휘
- 프레임의 완전한 원형과 시각 균형
- 캐릭터 가림 방지
- 일반·엘리트·보스의 장식 밀도
- 보스 표적성

### 번호 정책

- 내부 5번은 결번으로 둔다.
- 기존 내부 6·7·8번의 번호와 폴더명은 변경하지 않는다.
- 활성 기능 목록은 `1·2·3·4·6·7·8`로 표기한다.

## 실행 전제와 검증 기준

구현은 별도 실행 계획 승인 뒤에만 시작한다. 실행 완료 전에는 다음을 검증한다.

- 활성 문서와 폴더에서 독립 5번 토큰 프레임 경로·빈 프레임 계약이 제거됨
- 내부 기능 번호는 `1·2·3·4·6·7·8`로 유지됨
- 두 입력 경로가 같은 완성형 토큰 산출물 계약에 도달함
- 유형 기반 계열 자동 선택과 일반·엘리트·보스 규칙이 상위·공통·포트레이트 문서에서 일치함
- `git diff --check`와 활성 Markdown 경로·참조 검색을 통과함
