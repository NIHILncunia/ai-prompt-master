# 게임 스킬 아이콘 정규 스타일 이식 및 아이템 아이콘 확장 설계

## 목적

개발 완료 수준의 `게임 스킬 아이콘 스타일`을 7번 게임 아이콘 기능의 기능 전용 정식 스타일로 승격하고, 일반 정식 스타일과 기능성 예외의 경계를 유지한 채 호출 체계에 연결한다. 승격 완료 후 무기 아이콘, 그다음 장비 아이콘을 별도 하위 스타일로 개발한다.

## 확정 설계

- 일반 인물·환경 정식 스타일의 자동 적용 예외는 유지한다.
- 예외 내부에 `게임 스킬 아이콘` 기능 전용 정식 스타일을 등록한다.
- 정식 계약은 `라이브러리/스타일/게임 스킬 아이콘.md`가 소유한다.
- 정식 앵커는 검증된 512×512 자체 생성 결과 5장을 역할별로 정규화한다.
- 동적 공격·장축 투사체·고에너지 발광·치유 지원·방어 재질의 다섯 역할을 사용한다.
- 역할별 최소 1장, 필요할 때만 2장까지 참조한다.
- 스킬·상태 계열 실제 슬롯은 유색 비투명 추상 배경을 사용하고 검정·차콜 기본 배경을 금지한다.
- 다중 패키징은 3×3, 512 슬롯, 1536 시트, 0px 접합, 빈 슬롯 순수 검정으로 고정한다.
- 아이템 계열은 동일 패키징·배경 기반을 공유하되 무기·장비별 실루엣 계약을 별도 개발한다.

## 검증 기준

- 정식 계약과 정식 앵커 5개가 존재한다.
- 개발 앵커와 정식 앵커의 해시가 일치한다.
- 런타임 문서에서 개발 경로를 직접 참조하지 않는다.
- 스킬·상태 계열에 회색/검정 무광 기본 배경이라는 구형 규칙이 남지 않는다.
- 1·5·9·11개 패키징이 3×3 정책으로 계산 가능하다.
- 일반 정식 스타일과 게임 스킬 전용 스타일의 호출 경계가 명확하다.
- Markdown 경로와 코드 펜스가 유효하다.

## 후속 범위

스킬 아이콘 승격이 검증된 뒤 무기 아이콘 스타일 개발 패키지를 시작하고, 무기 안정화 뒤 장비 아이콘으로 확장한다. 실제 신규 테스트 이미지 생성은 공통 15섹션 승인 게이트를 적용한다.
