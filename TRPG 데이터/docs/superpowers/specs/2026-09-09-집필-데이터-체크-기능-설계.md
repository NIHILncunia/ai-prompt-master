# 집필 데이터 체크 기능 설계

## 목적

마스터의 소설 원문과 장면 묘사 원문을 지속적으로 축적하고, 매 제출마다 관찰 가능한 문체 특성을 분석·갱신하여 이후의 집필 요청에 적용한다. 이 기능은 첨삭, 평가, 수정본 관리가 아니라 **과제 제시 → 원문 기록 → 문체 프로필 갱신**을 담당한다.

## 범위와 비범위

### 범위

- 소설 과제: 장르와 주제만 제시하며, 마스터는 5,000자 이상의 원문을 작성한다.
- 장면 묘사 과제: 한 장면을 간결히 제시하며, 마스터가 자유롭게 묘사 원문을 작성한다.
- 장르·주제·장면 소재 데이터베이스를 근거로 과제 다양성을 관리한다.
- 원문을 그대로 보관하고, 매 제출마다 공통·소설·장면 묘사 문체 프로필을 갱신한다.
- 룩스테라 장면과 범용 창작 장면은 동등한 확률로 무작위 선택한다. 룩스테라가 선택되면 현재 설정 정본만 근거로 사용한다.

### 비범위

- 원문 첨삭, 윤문, 점수 평가, 리라이트, 수정본 버전 관리.
- 원문에 없는 특성을 사실처럼 프로필에 추가하는 일.
- 프로젝트 소스 사본의 수정 또는 이를 정본으로 취급하는 일.
- keyword_management_system.xlsx 원본 자체의 수정.

## 저장 구조

```text
TRPG 데이터
├─ 1. 프롬프트
│  └─ 9. 집필 데이터 체크 프롬프트
│     ├─ AGENTS.md
│     ├─ 0. 집필 데이터 체크 마스터 프롬프트.md
│     ├─ 1. 과제 호출 및 원문 기록 지침.md
│     ├─ 2. 문체 분석 및 프로필 갱신 지침.md
│     └─ 3. 과제 데이터베이스 선택 지침.md
└─ 19. 집필 데이터
   ├─ 0. 집필 데이터 운영 지침.md
   ├─ 1. 장르 데이터베이스.md
   ├─ 2. 주제 데이터베이스.md
   ├─ 3. 장면 소재 데이터베이스.md
   ├─ 4. 과제 이력.md
   ├─ 5. 문체 프로필.md
   └─ 원문
      ├─ 소설
      └─ 장면 묘사
```

`9. 집필 데이터 체크 프롬프트`는 라우팅과 실행 규칙만 소유한다. 과제 목록, 원문, 과제 이력, 문체 프로필은 `19. 집필 데이터`가 정본으로 소유한다.

## 호출과 상태 전이

| 호출 | 처리 |
| --- | --- |
| `집필 데이터 체크.` | 기능 목적, 과제 유형, 기록·분석·저장 절차를 설명하고 시작 여부를 확인한다. |
| `집필 데이터 체크 소설.` | 장르 1개와 주제 1개를 공개한다. 개요·줄거리·인물·문체 조건은 추가하지 않는다. |
| `집필 데이터 체크 장면 묘사.` | 장면 1개를 간결하게 공개한다. |
| `집필 데이터 제출.` | 현재 발급 과제와 함께 제공된 원문을 새 파일로 보관하고 문체 프로필을 갱신한다. |
| `문체 프로필.` | 누적 프로필, 유형별 근거 수, 최근 갱신일, 적용 가능 범위를 공개한다. |

새 기능 흐름의 첫 호출은 전역 정책에 따라 안내 후 시작 승인을 받는다. 이미 발급된 과제에 대한 제출·조회 호출에서는 시작 안내를 반복하지 않는다. `다음`은 직전 과제를 확정하고 다음 정의 단계로 진행한다.

## 과제 데이터 모델

### 장르

각 장르 항목은 `genre_id`, 명칭, 계층(`핵심 장르`·`하위 장르`·`융합 장르`), 상위 장르, 서사 매체 적합성, 선택 상태, 원본 근거를 가진다. 소설이 아닌 게임·음악·미술·방송 형식은 장르 후보에서 제외하며, 서사 전제·클리셰는 하위 장르 또는 보조 태그로 분리한다.

### 주제

각 주제 항목은 `theme_id`, 명칭, 주제 축, 핵심 갈등, 적용 가능한 장르, 원본 근거를 가진다. 감정·가치·심리·관계·사회 구조·철학·생존·변화·상실·성장과 같은 축을 분리한다. 단순 사물·의상·도구 키워드는 주제에 넣지 않고 장면 소재 후보로만 사용한다.

### 장면 소재

장면 소재 항목은 `scene_id`, 공간·시간·관계·갈등·전환·정서 축과 원본 근거를 가진다. 실제 과제는 이 축들을 조합해 한 문장 또는 한 단락의 장면으로 변환한다. 마스터에게 내부 태그 묶음을 노출하지 않는다.

### 원본 키워드 정규화

keyword_management_system.xlsx는 문자열 중복 제거가 완료된 원본 후보 집합으로만 사용한다. 정규화 과정은 다음을 만족한다.

1. 원본 키워드, 테마명, 상위 카테고리, 키워드 경로를 추적 가능하게 보존한다.
2. 한 키워드가 복수 의미를 가지면 하나로 삭제하지 않고 목적별 복수 레코드 또는 보조 태그로 분리한다.
3. `문화·장르`의 영화·게임·음악·미술 용어는 소설 장르 여부를 별도로 판정한다.
4. 키워드가 장르가 아닌 전제, 세계관 요소, 서사 장치, 주제, 장면 소재이면 해당 유형으로 이동한다.
5. 신규로 보강한 항목은 `원본 근거: 신규 보강`으로 표기해 원본 항목과 구분한다.

## 과제 선택 규칙

- 소설 과제는 활성 장르 1개와 활성 주제 1개만 공개한다.
- 장면 묘사는 범용·룩스테라 풀을 균등 무작위로 선택한다.
- 동일한 장르·주제 조합은 전체 후보가 소진되기 전 다시 발급하지 않는다.
- 최근 5개 과제와 같은 핵심 장르, 주제 축, 장면 갈등 축은 우선순위를 낮춘다.
- 과제 이력에는 과제 ID, 유형, 공개 문구, 내부 선택 ID, 발급 시각, 범위, 상태(`발급`·`제출 완료`)를 기록한다.
- 미제출 과제는 문체 프로필의 근거로 사용하지 않는다.

## 원문과 문체 프로필

원문 파일은 과제 ID, 과제 유형, 발급 문구, 제출 시각, 글자 수, 원문 본문으로 구성한다. 원문은 보관 뒤 수정·정리·축약하지 않는다. 제출마다 원문 파일을 새로 만들며, 수정본 관계를 만들지 않는다.

`5. 문체 프로필.md`는 다음 세 계층을 가진다.

1. 공통 문체: 문장 호흡, 시점 운용, 서술 거리, 어휘 경향, 감각 묘사, 정보 공개 방식, 대화 비중 등 모든 원문에서 관찰되는 특성.
2. 소설 문체: 5,000자 이상 소설 원문에서만 관찰되는 장면 전개, 단락 구성, 갈등 축적, 전환 방식.
3. 장면 묘사 문체: 장면 묘사 원문에서만 관찰되는 공간 제시, 인물 동선, 정서 전환, 긴장 연출 방식.

모든 프로필 항목에는 근거 원문 ID와 관찰 상태(`반복 관찰`·`초기 관찰`)를 기록한다. 원문 한 편만으로는 보편적 습관이라고 단정하지 않는다. 이후 마스터가 문체 적용을 요청하면 대상 산출물의 유형에 맞는 계층을 우선하고, 공통 문체를 보조로 적용한다.

## 저장·오류 처리·검증

- 과제 이력, 원문, 문체 프로필, 데이터베이스 갱신은 지속 보관 데이터이므로 생성·수정 직후 Drive에 직접 반영하고 재조회로 확인한다.
- Drive 직접 반영이 실패한 경우에만 상대 경로를 보존한 ZIP을 제공한다.
- 현재 과제가 없거나 제출 유형이 맞지 않으면 원문을 추측하여 저장하지 않고 정확한 누락 상태만 안내한다.
- 룩스테라 장면에 필요한 설정 근거가 부족하면 범용 장면을 임의 대체하지 않고, 근거 가능한 룩스테라 범위에서 다시 선택한다.
- 검증은 호출어 라우팅, 과제 발급 정보, 원문 무변형 보존, 과제 이력 상태 전이, 프로필 근거 연결, Drive 저장 재조회를 포함한다.
