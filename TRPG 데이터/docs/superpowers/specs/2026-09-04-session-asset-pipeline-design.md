# 세션 제작 자산 통합 파이프라인 설계

## 상태

- 사용자 승인 완료
- 대상 기능: `TRPG 데이터/1. 프롬프트/8. 세션 제작 프롬프트`
- 목적: 세션 설계에서 실제 플레이용 장면을 확정한 뒤 배틀맵, NPC·몬스터 스탯블록, 이미지와 토큰까지 연속 제작하고, FVTT 데이터 변환은 6번 기능에 유지한다.

## 1. 목표

세션 제작 기능의 완료 기준을 GM 문서 작성에서 끝내지 않고, 실제 FVTT 플레이 준비에 필요한 시각 자산과 스탯 데이터를 준비하는 단계까지 확장한다.

세션 제작 기능은 다음을 담당한다.

- 세션 이야기와 장면 설계
- 능력 체크·내성 체크와 실제 진행 묘사
- 토큰을 배치할 장면을 기준으로 필요한 맵 산정
- 장면별 맵 할당과 맵 재사용 판단
- 맵의 논리 크기와 그리드 수 설계
- 기존 배틀맵 이미지 기능을 통한 배틀맵 제작
- NPC·몬스터 역할과 외형·행동 정보 설계
- 필요 스탯블록 판정
- 기존 스탯블록 재사용 또는 전용 스탯블록 제작
- 기존 이미지 기능을 통한 NPC·몬스터 이미지 제작
- 세션에 등장하는 NPC·몬스터의 VTT용 토큰 제작
- 세션 자산 전체 연결 검수

다음은 세션 제작 기능에서 만들지 않는다.

- Foundry VTT Actor 데이터
- Foundry VTT Scene 데이터
- Journal 데이터
- Compendium 데이터
- FVTT 임포트용 JSON
- 모듈·팩 데이터 변환

위 항목은 기존 6번 FVTT 관련 요청 기능의 책임으로 유지한다.

## 2. 전체 제작 순서

세션 제작의 표준 순서는 다음과 같다.

`한 줄 이야기 → 핵심 이야기 골격 → 핵심 사건 흐름 → 장면 목록 → 장면별 파일 생성 → 장면 기능 확장·묘사 → 맵 산정·할당 → 배틀맵 설계·제작 → NPC·몬스터 목록 확정 → 스탯 정책 판정 → 전용 대상 컨셉 확인 → 스탯블록 제작 → 이미지 제작 → 토큰 제작 → 조우·자산 연결 검증 → 세션 패키지 완료`

맵과 NPC·몬스터 자산은 장면 기능과 실제 묘사가 충분히 정리된 후에 설계한다. 장면이 아직 바뀔 가능성이 큰 상태에서 맵이나 스탯블록을 먼저 만들지 않는다.

## 3. 맵 산정 원칙

### 3.1 배틀맵의 의미

여기서 배틀맵은 전투 전용 지도가 아니다.

토큰을 배치해 위치, 거리, 이동, 공간 관계를 표현할 가치가 있는 장면이라면 전투가 없어도 맵 대상으로 본다.

예:

- 전투 지역
- 도시 광장
- 회의실
- 여관
- 유적
- 비공정 내부
- 구조·호위 구역
- 탐사 공간
- 추적·도주 구간
- NPC 다수가 배치되는 사회적 장면

단순 전환, 짧은 대화, 장소 배치가 의미 없는 장면은 맵을 만들지 않는다.

### 3.2 맵 개수 산정

장면 수와 맵 수를 1:1로 맞추지 않는다.

- 같은 장소를 공유하면 하나의 맵을 여러 장면에서 재사용할 수 있다.
- 한 장면의 공간이 지나치게 넓거나 성격이 다른 구역으로 나뉘면 여러 맵을 할당할 수 있다.
- 기존 맵을 재사용할 수 있으면 신규 제작을 줄인다.
- 필요 없는 맵을 만들지 않되, 전투가 없다는 이유만으로 맵을 생략하지 않는다.

### 3.3 맵 설계 정보

각 맵에는 다음을 기록한다.

- 맵 번호와 이름
- 사용 장면
- 신규 제작 / 기존 맵 재사용 여부
- 맵 목적
- 장소와 시점
- 가로형 / 세로형 / 정방형
- 논리 그리드 가로 칸 수
- 논리 그리드 세로 칸 수
- 권장 이미지 가로·세로 비율과 해상도
- 주요 구조물
- 출입 지점
- 토큰 활동 범위
- 고저차
- 엄폐물
- 이동 제약
- 조우·이벤트 특수 구역
- 생성 상태 및 결과 이미지 참조

그리드 크기와 이미지 규격은 장면의 규모, 참여자 수, 이동 거리, 원거리 전투 가능성, 공간 밀도와 기존 배틀맵 기능의 출력 제약을 기준으로 시스템이 적절한 수준으로 정한다. 사용자가 별도로 지정한 경우 그 값을 우선한다.

이미지 자체에 격자를 그릴지 여부는 기존 배틀맵 이미지 기능의 지침을 따른다. 세션 제작 문서의 그리드 수는 FVTT에서 사용할 논리 그리드 설계값이다.

## 4. 장면별 맵 할당

`02. [세션 이름] 장면 목록.md`에는 각 장면의 `맵` 참조를 추가한다.

예:

`장면 01 → 맵 01 불타는 시가지`

맵이 없는 장면은 `없음`으로 명시할 수 있다.

`맵/00. 맵 목록.md`를 맵 자산의 기준 원장으로 사용한다. 이 파일에서 신규·재사용 여부, 사용 장면, 그리드 크기, 이미지 제작 상태를 추적한다.

## 5. NPC·몬스터 제작 원칙

### 5.1 목록 확정

장면과 맵이 확정된 뒤 세션에서 실제로 등장하거나 토큰을 올려야 하는 NPC·몬스터를 목록으로 확정한다.

모든 맵 배치 NPC와 몬스터는 기본적으로 토큰 제작 대상이다.

주요 시각 자료가 필요한 인물·몬스터는 이미지 제작 대상이기도 하다.

### 5.2 스탯블록 필요성 판정

각 대상은 다음 중 하나로 분류한다.

1. `스탯블록 불필요`
2. `기존 스탯블록 재사용`
3. `전용 스탯블록 제작`

일반 NPC는 세션 역할에 맞는 기존 NPC 스탯블록을 재사용할 수 있다. 예를 들어 일반 경비, 병사, 사제, 상인, 용병 등은 적절한 기존 스탯을 우선 검토한다.

사용자가 중요하다고 강조한 NPC, 고유 전투 능력이 필요한 NPC, 이야기상 특별한 능력이 중요한 NPC는 자동으로 평범한 기존 스탯블록에 치환하지 않는다. 전용 제작 여부를 사용자에게 확인한다.

몬스터는 새로 전용 제작하는 경우 기본적으로 `일반 / 정예 / 보스` 분류를 확인한다. 이미 사용자가 분류를 명시했다면 다시 묻지 않는다.

### 5.3 전용 제작 전 질문

전용 스탯블록을 만들기 전에는 이미 제공된 정보가 없는 항목만 질문한다.

핵심 질문은 다음과 같다.

- 어떤 전투·운용 컨셉을 원하는가
- 몬스터라면 일반·정예·보스 중 어느 등급인가
- NPC라면 고유 전투 능력이 필요한가, 기존 NPC 스탯으로 충분한가

질문은 한 번에 하나의 결정 단위로 한다. 사용자가 이미 컨셉·등급·능력 방향을 제공했다면 재질문하지 않는다.

## 6. 스탯블록 자료 원칙

특정 룰 시스템의 실제 스탯블록을 작성하거나 기존 스탯블록을 고를 때에는 4번 룰북 기능과 현재 인덱싱된 룰북 자료를 확인한다.

- 기존 스탯블록 재사용: 출처와 사용할 스탯블록명을 기록한다.
- 전용 스탯블록 제작: 사용자 승인 컨셉과 난이도 분류를 기준으로 작성한다.
- NPC와 몬스터 모두 스탯블록이 필요할 수 있다.
- 스탯블록은 별도 Markdown 파일로 저장한다.

## 7. 이미지와 토큰 제작

세션 제작 기능은 자산의 필요성과 디자인 요구사항을 확정한 뒤 기존 이미지 생성 기능으로 실제 이미지를 제작한다.

### 배틀맵

- 이미지 생성 모듈의 배틀맵 기능 지침을 사용한다.
- 세션 문서에 확정된 맵 목적, 공간 구조, 그리드 수를 입력으로 사용한다.

### NPC·몬스터 이미지

- 대상 분류에 맞는 이미지 기능을 사용한다.
- 기존 세션 NPC 설계에서 확정한 외형·장비·분위기를 입력으로 사용한다.

### 토큰

- 세션 맵에 배치되는 NPC·몬스터는 기본적으로 토큰 제작 대상이다.
- 토큰 제작은 기존 토큰 이미지 기능의 규칙을 따른다.
- 전투 여부와 관계없이 맵에 올라가는 NPC는 토큰을 준비한다.

이미지 기능의 승인 절차와 해상도·비율·스타일 규칙은 세션 제작 기능에서 복제하지 않고 해당 이미지 기능 지침을 따른다.

## 8. 표준 세션 폴더 구조

```text
[세션 이름] 기획/
├─ 01. [세션 이름] 시나리오.md
├─ 02. [세션 이름] 장면 목록.md
├─ 장면/
│  ├─ 01. [장면명].md
│  └─ ...
├─ 맵/
│  ├─ 00. 맵 목록.md
│  ├─ 01. [맵명].md
│  └─ ...
├─ NPC 및 몬스터/
│  ├─ 00. NPC 및 몬스터 목록.md
│  ├─ [NPC명].md
│  ├─ [NPC명] 스탯블록.md           # 필요 시
│  ├─ [몬스터명].md
│  ├─ [몬스터명] 스탯블록.md        # 필요 시
│  └─ ...
└─ 조우/
   ├─ 00. 조우 목록.md
   ├─ [조우명].md
   └─ ...
```

기존 `03. [세션 이름] 등장인물 및 몬스터.md`와 `04. [세션 이름] 조우 설계.md`는 새 세션부터 각각 `NPC 및 몬스터/00. NPC 및 몬스터 목록.md`, `조우/00. 조우 목록.md`의 인덱스 역할로 전환한다. 파일명 호환이 필요하면 기존 03·04 파일을 인덱스로 유지하고 하위 폴더 상세 문서를 참조하게 한다. 기존 세션은 자동 이관하지 않는다.

## 9. 파일 책임

- `01. 시나리오`: 이야기 상위 구조
- `02. 장면 목록`: 장면 순서와 맵 참조의 기준 원장
- `장면/`: 실제 플레이 운영 단위
- `맵/00. 맵 목록`: 맵 자산 기준 원장
- `맵/NN. 맵명`: 맵별 설계 정보
- `NPC 및 몬스터/00. 목록`: 등장 대상과 자산·스탯 상태 기준 원장
- `NPC 및 몬스터/개별 파일`: 공통 프로필·외형·행동·세션 역할
- `NPC 및 몬스터/* 스탯블록`: 실제 룰 시스템 스탯
- `조우/00. 조우 목록`: 조우 인덱스
- `조우/개별 파일`: 조우 전문 운용

같은 내용을 여러 파일에 복제하지 않고 참조한다.

## 10. 모호성 처리

다음 상황에서는 임의로 중요한 결정을 확정하지 않고 사용자에게 묻는다.

- 맵이 필요한지 여부에 따라 플레이 방식이 크게 달라지는 경우
- 맵 규모가 서로 다른 두 설계 방향으로 갈리는 경우
- 주요 NPC의 전용 스탯블록 제작 필요성이 애매한 경우
- 몬스터의 일반·정예·보스 분류가 정해지지 않은 경우
- 전용 스탯블록의 전투 컨셉이 비어 있는 경우
- 이미지 디자인이 설정상 여러 방향으로 갈리는 경우

단순한 그리드 크기, 적절한 맵 비율, 일반 NPC의 기존 스탯 후보 같은 사소한 기술 선택은 시스템이 합리적으로 정할 수 있다.

## 11. 완료 기준

세션 제작 완료 시 다음 상태를 확인한다.

- 장면 구조와 묘사가 확정됨
- 필요한 맵이 모두 산정됨
- 각 장면의 맵 참조가 정리됨
- 필요한 배틀맵 이미지가 준비됨
- 세션에 등장하는 NPC·몬스터 목록이 확정됨
- 각 대상의 스탯 정책이 결정됨
- 필요한 스탯블록 파일이 준비됨
- 필요한 NPC·몬스터 이미지가 준비됨
- 맵에 배치되는 NPC·몬스터의 토큰이 준비됨
- 조우가 장면·맵·스탯블록을 올바르게 참조함
- FVTT 데이터 변환 대상 목록이 명확함

이 완료 기준 이후의 실제 Foundry VTT 데이터 변환은 6번 기능으로 넘긴다.
