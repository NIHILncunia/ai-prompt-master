# 이미지 생성 모듈 상세 실행 명세서

## 1. 문서 목적

이 문서는 `1. 이미지 생성 모듈` 통합 설계를 실제 파일 구조로 구현하기 위한 파일·폴더 단위 실행 명세서다.

이 문서는 다음 문서를 전제로 한다.

- `specs/2026-08-08-image-generation-module-design.md`
- `plans/2026-08-08-image-generation-module-plan.md`

설계 문서가 구조 원칙과 기능 철학을 정의하고, 실행 계획이 작업 순서를 정의한다면, 이 문서는 **각 단계에서 실제로 어떤 파일을 만들고 어떤 역할을 부여할지**를 정한다.

이 문서를 기준으로 다른 세션에서도 같은 구조를 재현할 수 있어야 한다.

---

      ├─ README.md

      │  ├─ README.md
      │  ├─ 0. 이미지 생성 공통 운영 지침.md
      │  ├─ 1. 이미지 생성 공통 승인 절차.md
      │  ├─ 2. 요구사항 확인서 작성 규칙.md
      │  ├─ 3. 사용자 이미지 분석 및 보존 규칙.md
      │  ├─ 4. 외부 시각 자료 탐색 규칙.md

      │
      ├─ 라이브러리/
      │  ├─ 스타일/
      │  ├─ 대상/
      │  ├─ 레이아웃/
      │  └─ 견본/
      │

각 기존 기능의 규칙을 분석하여 `보존 / 재작성 / 폐기 / 공통 승격`으로 분류한 뒤 신규 구조에 다시 작성한다.

## 4. 상위 모듈 파일 명세

### 4-1. `AGENTS.md`

역할:
- 이미지 요청의 최상위 라우터
- 읽기 순서 안내
- 하위 기능 경계 안내
- 공통/라이브러리 참조 규칙 안내
- 상위 메인 지침 동기화 조건 안내

반드시 포함:
- 상위 기능 번호: 1번
- 하위 기능 1~8번 목록
- 공통 승인 절차 우선 규칙
- 기능별 고정 계약 우선 규칙
- 선택형 레이아웃 참조 원칙
- 스타일·대상 라이브러리 참조 원칙
- 이미지 생성 전 사용자 승인 필수 규칙
- 이미지 기능 개편 시 갱신 대상 문서

포함하지 않을 것:
- 개별 기능의 세부 프롬프트
- 개별 레이아웃의 실제 규칙
- 스타일 묘사 원문

### 4-2. `README.md`

역할:
- 사람용 구조 안내

반드시 포함:
- 모듈 개요
- 하위 기능 목록
- 고정 계약형 / 준고정 계약형 / 가변 계약형 설명
- 공통 폴더 역할
- 라이브러리 역할
- 기본 사용 예시
- 유지보수 주의사항

### 4-3. `0. 이미지 생성 모듈 마스터 프롬프트.md`

역할:
- 이미지 요청을 하위 기능으로 분류
- 필요한 공통 규칙·라이브러리·기능 파일 조합
- 최종 요구사항 확인서와 영어 프롬프트 조립

필수 라우팅 흐름:

```text
요청 수신
→ 이미지 기능 판별
→ 기능 고정 계약 확인
→ 대상 규칙 선택
→ 스타일 규칙 선택
→ 필요 시 레이아웃 선택
→ 견본/레퍼런스 확인
→ 충돌 검사
→ 요구사항 확인서
→ 최종 영어 프롬프트
→ 사용자 승인
→ 생성
```

기능 계약과 사용자 요구가 충돌하면 무리하게 조립하지 않는다.
다른 하위 기능이 더 적합한 경우 재라우팅한다.

## 5. 공통 폴더 명세

### `0. 이미지 생성 공통 운영 지침.md`
공통 규칙의 목차와 적용 순서를 정의한다.

### `1. 이미지 생성 공통 승인 절차.md`
기존 공통 승인 절차를 이 위치의 정본으로 이관한다.

핵심:
- 첫 생성 전 요구사항 확인
- 최종 영어 프롬프트 공개
- 명시적 승인 이후 생성
- 새 시안이면 재승인
- 승인 상태는 동일 생성 배치에만 유효

### `2. 요구사항 확인서 작성 규칙.md`
확인서의 표준 필드를 정의한다.

권장 필드:
- 기능
- 대상
- 출력 계약
- 스타일
- 레이아웃
- 배경/환경
- 포즈/상태
- 보존 요소
- 금지 요소
- 참고 자료
- 생성 수량

사용하지 않는 필드는 생략 가능하게 한다.

### `3. 사용자 이미지 분석 및 보존 규칙.md`
사용자 제공 이미지가 있을 때:
- 무엇을 유지할지
- 무엇을 변경할지
- 정체성·외형·장비·색상·형태 보존 우선순위
를 정의한다.

### `4. 외부 시각 자료 탐색 규칙.md`
종족/고유 개체/설정 문서가 외형 자료를 지정할 때 탐색 순서를 정의한다.

### `5. 생성 후 검수 및 재생성 규칙.md`
생성 결과가 요구사항과 일치하는지 비교하고, 재생성 시 어떤 조건에서 다시 승인받는지 정의한다.

## 6. 라이브러리 명세

## 6-1. 스타일

초기 권장 파일:

```text
라이브러리/스타일/
├─ 붓터치 반실사.md
├─ 플랫 아이콘.md
├─ 실루엣 아이콘.md
├─ 라인 아이콘.md
└─ 양피지 지도.md
```

`붓터치 반실사.md`는 현재 반실사 포트레이트의 정식 스타일 계약이다.

핵심:
- 현실적 반실사
- 고급 붓터치
- 회화적 표면감
- 3D CGI 게임 렌더링처럼 보이는 방향 금지
- 과도한 포토리얼보다 일러스트적 붓터치 우선

## 6-2. 대상

초기 권장 파일:

```text
라이브러리/대상/
├─ 휴머노이드.md
├─ 짐승·동물형.md
├─ 크리처형.md
├─ 용종.md
└─ 기계형.md
```

각 파일은 형태·신체 구조·실루엣 해석만 담당한다.
스타일은 정의하지 않는다.

## 6-3. 레이아웃

초기 권장 구조:

```text
라이브러리/레이아웃/
├─ 격자/
│  ├─ 2x2.md
│  ├─ 2x3.md
│  ├─ 2x4.md
│  ├─ 3x3.md
│  └─ 4x4.md
├─ 분할/
│  ├─ 좌우 2분할.md
│  └─ 상하 2분할.md
└─ 특수/
   ├─ 스프라이트 시트.md
   └─ 정보 패널 포함.md
```

레이아웃 문서가 담당할 것:
- 슬롯 수
- 행/열
- 슬롯 크기 균등 여부
- 간격
- 잘림 방지
- 슬롯 침범 금지
- 캔버스 전체 배치

레이아웃 문서가 담당하지 않을 것:
- 인물 외형
- 아이콘 화풍
- 몬스터 종류
- 배경 설정
- 세계관 정보

## 6-4. 견본

권장 구조:

```text
라이브러리/견본/
├─ 스타일/
├─ 대상/
└─ 레이아웃/
```

견본은 역할을 명시한다.
하나의 이미지를 모든 목적의 견본으로 사용하지 않는다.

## 7. 하위 1번 — 반실사 포트레이트 상세 명세

최종 구조:

```text
1. 반실사 포트레이트/
├─ AGENTS.md
├─ README.md
├─ 0. 반실사 포트레이트 마스터 프롬프트.md
├─ 1. 반실사 포트레이트 공통 지침.md
├─ 2. 전신 생성 지침.md
├─ 3. 흉상 생성 지침.md
└─ 개발 자료/
```

### 고정 출력 계약

반실사 포트레이트는 다음 파이프라인을 기본 계약으로 한다.

```text
전신 9:16 1장
→ 전신 확정
→ 확정 전신 기반 흉상 9:16 1장
```

전신:
- 세로 9:16
- 단일 대상
- 머리부터 발끝까지 보여야 함
- 발/무기/장식의 불필요한 잘림 금지

흉상:
- 세로 9:16
- 앞서 확정된 전신 이미지를 기준 자료로 사용
- 동일 캐릭터 정체성 유지
- 의상·장비·색상·얼굴·장식 임의 변경 금지
- 독립 신규 디자인 생성 금지
- 확대·재구도는 허용하되 기존 전신 디자인을 우선

이 기능은 일반 레이아웃 모듈을 참조하지 않는다.
고정 계약 자체가 레이아웃 역할을 한다.

- 내부 초상 영역 확보
- VTT에서 읽히는 명확한 외곽 구조

일반 레이아웃 모듈 의존도는 낮다.

## 13. 하위 7번 — 게임 아이콘 상세 명세

```text

├─ AGENTS.md
├─ README.md

└─ 개발 자료/
```

가장 대표적인 조립형 기능으로 정의한다.

선택 가능한 출력 구성:
- 단일 아이콘
- 복수 아이콘
- 격자 시트

- 플랫
- 실루엣

```text

+ 지역 아이콘 16종
```

레이아웃을 지정하지 않은 단일 아이콘 요청에는 레이아웃 라이브러리를 호출하지 않는다.

## 15. 조립 충돌 규칙

우선순위:

1. 사용자 최신 명시 지시
2. 기능 고정 계약
3. 기능 전용 규칙
4. 대상 규칙
5. 스타일 규칙
6. 레이아웃 규칙
7. 일반 기본값

단, 사용자의 최신 지시가 기능의 정체성을 바꿀 정도라면 그 기능 안에서 억지로 처리하지 않고 적절한 다른 기능으로 라우팅한다.

예:
- `반실사 포트레이트를 4x4로 16명 생성`은 기존 반실사 포트레이트 고정 계약과 맞지 않는다.
- 이런 요청은 추후 다중 캐릭터 시트/바리에이션 기능이나 하이라이트·아이콘 계열의 가변 레이아웃 기능으로 재라우팅하는 것이 안전하다.

## 18. 금지 사항

- 기존 이미지 기능 폴더를 그대로 신규 폴더 아래로 이동하지 않는다.
- 기존 포트레이트의 3D CGI 중심 스타일 제약을 신규 반실사 스타일에 복사하지 않는다.
- 모든 기능에 `대상/스타일/레이아웃` 폴더를 기계적으로 강제하지 않는다.
- 레이아웃 문서에 대상/스타일 규칙을 섞지 않는다.
- 같은 규칙을 여러 하위 기능에 복제하지 않는다.
- 아직 최종 번호가 확정되지 않은 비이미지 기능을 임의로 재번호하지 않는다.
