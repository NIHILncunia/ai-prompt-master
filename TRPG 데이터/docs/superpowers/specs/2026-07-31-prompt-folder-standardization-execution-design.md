# TRPG 프롬프트 폴더 표준화 단계별 실행 설계

## 목표

`1. 프롬프트`의 1~19번 기능과 `공통`을 표준 구조로 이관하되, 경로·참조·기능 규칙을 안전하게 보존한다.

## 적용 경로와 구조

- 정식 프롬프트 루트는 `TRPG 데이터/1. 프롬프트`다.
- 모든 번호 기능은 `AGENTS.md`, `README.md`, `0. 기능명 마스터 프롬프트.md`, 연속된 실행 문서, `라이브러리/`, `템플릿/`을 가진다.
- `9999. D&D 룰북 소유 리스트.md`는 실행 순서에 포함되지 않는 색인·레지스트리다. 숫자 문서의 연속 번호 규칙에서 제외한다.

## 책임 경계

- `AGENTS.md`는 라우팅, 조건부 읽기 대상, 의존성, 기능 경계, 동기화 범위를 기록하는 얇은 운영 문서다.
- `README.md`는 사람용 구조·사용 안내다.
- 0번과 연속 번호 문서는 실행 규칙과 필수 검수를 맡는다.
- `라이브러리/`는 재사용 자료, `템플릿/`은 최종 산출물의 레이아웃만 맡는다.
- 프로젝트 위그드라실의 설정 정본은 공통 라이브러리에 복제하지 않는다. 공통 라이브러리에는 기능 운영에 필요한 검증된 공유 자료만 둔다.

## 단계

1. 표준 규약을 상위 문서와 설계서에 반영한다.
2. 7번과 19번을 시범 표준화하고 각 기능의 링크·번호·필수 구조를 검증한다.
3. 이미지 계열, 데이터·규칙 계열, 공통을 기능군 단위로 이관한다.
4. 전체 참조·번호·필수 파일·비정규 파일을 검증하고 로컬 ZIP을 만든다.

## 보존과 되돌림

- 각 단계 시작 전 인벤토리와 경로 이관표를 만든다.
- 파일을 이동·이름 변경하기 전 모든 직접 참조를 찾고, 단계 종료 시 이전 경로 참조가 없는지 검사한다.
- 비정규 파일은 삭제하지 않고 `개발 자료/` 또는 단계 산출물 목록으로 보존한다.
- 각 단계는 다음 단계로 넘어가기 전에 구조·링크·번호 검증을 통과해야 한다.

## 범위 제외

- Google Drive의 파일·폴더·문서는 직접 수정하지 않는다.
- 정본 설정 자료의 내용 통합·복제는 이번 구조 표준화에서 수행하지 않는다.
