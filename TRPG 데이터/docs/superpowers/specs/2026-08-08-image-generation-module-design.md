# 이미지 생성 모듈 통합 설계

## 1. 목적

이 문서는 현재 분산되어 있는 이미지 관련 기능을 `1. 이미지 생성 모듈`로 통합하기 위한 구조 설계안이다.

핵심 목표는 다음과 같다.

- 이미지 관련 기능을 하나의 상위 기능으로 통합한다.
- 각 하위 기능의 성격 차이를 유지한다.
- 공통 규칙은 상위에서 공유한다.
- 기능별 특화 규칙은 하위 모듈에서 독립적으로 관리한다.
- 스타일, 대상, 레이아웃을 조립식으로 참조할 수 있도록 한다.
- 포트레이트처럼 고정 계약이 필요한 기능은 고정 파이프라인으로 운영한다.

---

## 2. 최상위 번호 체계

```text
1. 이미지 생성 모듈
├─ 0. 이미지 생성 모듈 마스터 프롬프트.md
├─ AGENTS.md
├─ README.md
├─ 공통/
├─ 라이브러리/
├─ 1. 반실사 포트레이트/
├─ 2. 배틀맵 생성/
├─ 3. 캐릭터 레퍼런스 생성/
├─ 4. 세션 하이라이트 이미지 생성/
├─ 5. 토큰 프레임 생성/
├─ 6. 풍경 생성/
├─ 7. 게임 아이콘 생성/
└─ 8. 월드 지도 생성/
```

상위 `1번`은 이미지 관련 요청 전체의 진입점이다.

하위 번호는 이미지 생성 모듈 내부의 서브 기능 번호다.

---

## 3. 공통 운영 원칙

### 3-1. 공통 계층이 담당할 것

`공통/`은 다음 규칙을 담당한다.

- 승인 절차
- 요구사항 확인서 양식
- 사용자 제공 이미지 분석 및 보존 규칙
- 종족/개체/대상 시각 자료 탐색 규칙
- 생성 후 검수 및 수정 절차
- 시리즈 이미지의 일관성 유지 규칙

### 3-2. 라이브러리 계층이 담당할 것

`라이브러리/`는 재사용 가능한 조립형 규칙을 관리한다.

```text
라이브러리/
├─ 스타일/
├─ 대상/
├─ 레이아웃/
└─ 견본/
```

- `스타일/` : 붓터치 반실사, 플랫 아이콘, 양피지 지도 등
- `대상/` : 휴머노이드, 짐승·동물형, 크리처형, 용종, 기계형 등
- `레이아웃/` : 2x4, 4x4, 분할 화면, 스프라이트 시트 등
- `견본/` : 스타일·대상·레이아웃 견본 관리

레이아웃은 모든 기능의 필수 요소가 아니라 **필요한 기능에서만 참조하는 선택형 모듈**로 본다.

## 4. 하위 기능별 권장 구성

## 4-1. 1. 반실사 포트레이트

### 성격

- 고정 계약형 기능
- 현재 가장 많이 사용하는 대표 기능
- 내부 1번으로 두는 것이 적절함

### 출력 계약

1단계: 전신 1장
- 세로 9:16
- 단일 인물
- 머리부터 발끝까지 전신이 보여야 함

2단계: 흉상 1장
- 세로 9:16
- 1단계에서 확정된 전신 이미지를 기준으로 생성
- 캐릭터 디자인, 의상, 장식, 색상은 유지
- 독립 신규 캐릭터 생성처럼 해석하지 않음

### 내부 구조

```text
1. 반실사 포트레이트/
├─ AGENTS.md
├─ README.md
├─ 0. 반실사 포트레이트 마스터 프롬프트.md
├─ 1. 반실사 포트레이트 공통 지침.md
├─ 2. 전신 생성 지침.md
├─ 3. 흉상 생성 지침.md
└─ 개발 자료/
```

### 조립 규칙

- 필수 참조: `라이브러리/스타일/붓터치 반실사.md`
- 필요 시 참조: `라이브러리/대상/*.md`
- 일반적으로 레이아웃 참조 불필요

---

## 4-2. 2. 배틀맵 생성

### 성격

- 준고정 계약형 기능
- 탑뷰, 지형, 격자, 칸 수, 전투 활용성을 중심으로 함

### 출력 계약

- 풍경과 별개로 전투용 탑뷰 맵 생성
- 기본적으로 격자를 포함함
- 배경 미술보다 전장 가독성을 우선

### 가변 요소

- 가로형/세로형/정사각형
- 격자 크기
- 칸 수
- 실내/실외/특수 지형

### 내부 구조

```text
2. 배틀맵 생성/
├─ AGENTS.md
├─ README.md
├─ 0. 배틀맵 생성 마스터 프롬프트.md
├─ 1. 배틀맵 공통 지침.md
├─ 2. 격자 및 칸 수 규칙.md
├─ 3. 지형 표현 규칙.md
├─ 4. 실내 배틀맵.md
├─ 5. 실외 배틀맵.md
└─ 개발 자료/
```

### 조립 규칙

- 대상 모듈보다는 지형 규칙을 우선
- 레이아웃은 `정사각형`, `가로형`, `세로형` 같은 맵 전용 규칙을 참조
- 스타일은 배틀맵 전용 규칙을 기본으로 함

---

## 4-3. 3. 캐릭터 레퍼런스 생성

### 성격

- 고정 계약형 기능
- 캐릭터 설정 참조용 시트
- 정보 전달과 일관성을 중시

### 출력 계약

현재 체계를 기준으로 다음 요소를 기본 구조로 권장한다.

- 16:9 기준 레퍼런스 시트
- 바이오 영역
- 흉상
- 정면
- 후면
- 키 정보

필요 시 대상에 맞춘 세부 차이는 둘 수 있으나 큰 출력 골격은 고정한다.

### 내부 구조

```text
3. 캐릭터 레퍼런스 생성/
├─ AGENTS.md
├─ README.md
├─ 0. 캐릭터 레퍼런스 마스터 프롬프트.md
├─ 1. 캐릭터 레퍼런스 공통 지침.md
├─ 2. 레퍼런스 시트 구성 규칙.md
├─ 3. 바이오/정보 영역 규칙.md
└─ 개발 자료/
```

### 조립 규칙

- 필수 참조: 대상 모듈
- 필수 참조: 스타일 모듈
- 일반적인 레이아웃 모듈보다는 `레퍼런스 시트 구성 규칙`이 고정 레이아웃 역할 수행

---

## 4-4. 4. 세션 하이라이트 이미지 생성

### 성격

- 가변 계약형 기능
- 장면 연출, 분위기, 정보 강조를 모두 고려해야 함
- 레이아웃 참조가 필요한 대표 기능

### 출력 계약

고정 단일 양식으로 묶기보다 다음 하위 유형을 두는 것이 적절하다.

- 단일 장면형
- 인물 중심 장면형
- 단체 장면형
- 정보 포함 하이라이트형

### 내부 구조

```text
4. 세션 하이라이트 이미지 생성/
├─ AGENTS.md
├─ README.md
├─ 0. 세션 하이라이트 마스터 프롬프트.md
├─ 1. 세션 하이라이트 공통 지침.md
├─ 2. 단일 장면형.md
├─ 3. 인물 중심형.md
├─ 4. 단체 장면형.md
├─ 5. 정보 포함형.md
└─ 개발 자료/
```

### 조립 규칙

- 대상, 스타일, 레이아웃 참조를 모두 활용할 수 있음
- 필요 시 2인 대치, 군상, 정보 패널 레이아웃 등을 호출

---

## 4-5. 5. 토큰 프레임 생성

### 성격

- 고정 계약형 기능
- 사용 목적이 명확함
- 기능 폭이 넓지 않음

### 출력 계약

- 원형 또는 지정된 프레임 형태
- 토큰 사용성을 우선
- 캐릭터/적/중립 등의 구분 체계를 지원할 수 있음

### 내부 구조

```text
5. 토큰 프레임 생성/
├─ AGENTS.md
├─ README.md
├─ 0. 토큰 프레임 마스터 프롬프트.md
├─ 1. 토큰 프레임 공통 지침.md
├─ 2. 프레임 유형 규칙.md
└─ 개발 자료/
```

### 조립 규칙

- 레이아웃 모듈 의존도 낮음
- 프레임 유형, 색상 체계, 장식 체계 위주로 조립

---

## 4-6. 6. 풍경 생성

### 성격

- 준고정 계약형 기능
- 단일 장면 일러스트 중심
- 배틀맵의 전단계 소스로도 활용될 수 있음

### 출력 계약

- 일반적으로 단일 풍경 이미지
- 장소성, 분위기, 원근감, 조명, 계절감 등을 중시

### 내부 구조

```text
6. 풍경 생성/
├─ AGENTS.md
├─ README.md
├─ 0. 풍경 생성 마스터 프롬프트.md
├─ 1. 풍경 생성 공통 지침.md
├─ 2. 실내 풍경.md
├─ 3. 실외 풍경.md
├─ 4. 특수 환경 풍경.md
└─ 개발 자료/
```

### 조립 규칙

- 필요 시 스타일 참조
- 레이아웃 참조는 일반적으로 불필요
- 환경·구도 중심

## 4-7. 7. 게임 아이콘 생성

### 성격

- 가변 계약형 기능
- 레이아웃과 스타일 조립의 활용도가 가장 큼

### 출력 계약

고정 단일 양식으로 묶지 않는다.

지원 형태 예시:
- 단일 아이콘
- 복수 아이콘
- 격자 배열
- 스프라이트 시트

지원 스타일 예시:
- 플랫
- 실루엣
- 라인
- 일러스트형

### 내부 구조

```text
7. 게임 아이콘 생성/
├─ AGENTS.md
├─ README.md
├─ 0. 게임 아이콘 마스터 프롬프트.md
├─ 1. 게임 아이콘 공통 지침.md
├─ 2. 아이콘 스타일 규칙.md
├─ 3. 출력 구성 규칙.md
├─ 4. 지도/UI/자원용 아이콘 분기.md
└─ 개발 자료/
```

### 조립 규칙

- 스타일 모듈 필수
- 레이아웃 모듈 자주 사용
- 기능 내에서 `4x4`, `2x4`, `스프라이트 시트` 등을 호출 가능

---

## 4-8. 8. 월드 지도 생성

### 성격

- 준고정 계약형 기능
- 정보 구조와 시각 표현이 모두 중요함
- 포트레이트와 매우 다른 별도 분야

### 출력 계약

- 양피지 또는 지도 전용 스타일
- 지형, 해안선, 국가 구역, 주요 지명, 범례 등의 표현
- 대륙 전도, 지역도, 약도 등의 하위 용도 지원

### 내부 구조

```text
8. 월드 지도 생성/
├─ AGENTS.md
├─ README.md
├─ 0. 월드 지도 마스터 프롬프트.md
├─ 1. 월드 지도 공통 지침.md
├─ 2. 양피지 스타일 규칙.md
├─ 3. 라벨링 및 표기 규칙.md
├─ 4. 전도/지역도 분기.md
└─ 개발 자료/
```

### 조립 규칙

- 지도 전용 스타일 강제
- 필요 시 레이아웃이 아니라 지도 전용 구조 규칙을 사용
- 일반 레이아웃 모듈과는 구분하는 편이 좋음

---

## 5. 레이아웃 모듈 설계 원칙

레이아웃 모듈은 모든 기능의 필수 계층이 아니다.

필요한 기능에서만 다음처럼 참조한다.

```text
라이브러리/레이아웃/
├─ 격자/
│  ├─ 2x2.md
│  ├─ 2x3.md
│  ├─ 2x4.md
│  ├─ 3x3.md
│  └─ 4x4.md
├─ 분할/
│  ├─ 좌우 2분할.md
│  └─ 상하 2분할.md
└─ 특수/
   ├─ 스프라이트 시트.md
   └─ 정보 패널 포함.md
```

레이아웃 문서는 다음만 정의한다.

- 슬롯 수
- 행렬 구조
- 요소 간 간격
- 잘림 금지 규칙
- 배치 질서
- 정보 패널 존재 여부

레이아웃 문서에 스타일, 대상, 주제 내용은 넣지 않는다.

---

## 6. 조립 순서

최종 프롬프트 조립 순서는 다음을 권장한다.

1. 이미지 기능 선택
2. 기능의 고정 계약 로드
3. 대상 규칙 로드
4. 스타일 규칙 로드
5. 필요한 경우 레이아웃 규칙 로드
6. 견본/참조 자료 로드
7. 사용자 요구사항 적용
8. 충돌 검사
9. 요구사항 확인서 작성
10. 최종 영어 프롬프트 조립

---

## 7. 충돌 우선순위

규칙 충돌 시 다음 우선순위를 적용한다.

1. 기능의 고정 계약
2. 기능 전용 규칙
3. 대상 규칙
4. 스타일 규칙
5. 레이아웃 규칙
6. 사용자 세부 요구사항

사용자 요구가 기능 고정 계약과 충돌하면, 현재 기능에서 처리하지 않고 적절한 다른 하위 기능으로 라우팅한다.

---

## 8. 결론

현재 기준으로 가장 안정적인 구조는 다음과 같다.

- 상위 1번을 `이미지 생성 모듈`로 통합한다.
- 내부 1번은 `반실사 포트레이트`로 둔다.
- 포트레이트는 `전신 9:16 1장 → 전신 기반 흉상 9:16 1장`의 고정 계약으로 운영한다.
- 나머지 기능은 성격에 따라 고정 계약형과 가변 계약형으로 나눈다.
- 레이아웃은 필수 축이 아니라 선택형 조립 모듈로 운영한다.
- 스타일, 대상, 레이아웃, 견본을 재사용 가능한 라이브러리로 분리한다.
