# 프롬프트 이중 계통 흐름 무결성 감사 설계

## 목적

`1. 프롬프트`의 모든 지침 문서를 현행 파일 기준으로 대조하여, 호출부터 세부 지침까지의 흐름이 실제로 이어지는지 판정한다.

## 감사 경계

두 계통을 서로 독립적으로 판정한다.

1. **기존 기능 계통**: 루트의 기존 1~15번 기능과 공통 지침. 신규 이미지 모듈로 이관되었거나 폐기 예정인 경로의 단절은 즉시 결함으로 보지 않는다. 문서가 그 상태를 명시하고 신규 경로를 안내하는지로 판정한다.
2. **신규 이미지 생성 모듈 계통**: `1. 이미지 생성 모듈`과 내부 1~8번 기능. 이 계통은 현재 진행 중인 정식 이관 대상이므로, 상위 진입점·공통 절차·하위 기능·필수 참조가 실제 파일로 이어지지 않으면 결함이다.

## 판정 기준

- **정상**: 요청을 해당 계통의 실제 진입점으로 라우팅할 수 있고, 지시된 필수 문서가 존재하며, 상위·하위 규칙의 역할과 우선순위가 모순되지 않는다.
- **의도된 단절**: 기존 계통의 경로가 더는 정본이 아니지만, 이관 상태·후속 경로·사용 제한이 명시되어 있다.
- **경고**: 현행 실행에는 막힘이 없으나 중복된 진입점, 오래된 번호, 불명확한 적용 범위로 오판 위험이 있다.
- **결함**: 신규 계통의 필수 링크·경로·호출 규칙·승인 게이트·문서 참조가 없거나 상충하여 실행 경로를 확정할 수 없다.

## 검증 방법

1. `AGENTS.md`, 루트 마스터, 각 기능 0번 마스터, 실행 지침, README와 공통 문서를 목록화한다.
2. Markdown 상대 링크와 코드 블록의 파일 경로를 실제 파일 시스템과 대조한다.
3. 호출어, 기능 번호, 읽기 순서, 승인 규칙, 파일 산출물 정책, 정본 접근 규칙을 추출해 계통별로 비교한다.
4. 신규 이미지 모듈은 상위 → 공통 → 내부 기능 → 라이브러리/템플릿의 필수 연결을 추적한다.
5. 기존 기능은 끊긴 참조를 이관 의도·현재 레지스트리·신규 경로 안내와 함께 해석한다.
6. 결과를 증거 경로와 함께 보고서에 남기고, 레지스트리의 공식 상태를 갱신한다.
