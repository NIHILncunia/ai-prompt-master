# 캐릭터 레퍼런스 V2 내부 5번 이관 설계

## 목표

이미지 생성 모듈의 `캐릭터 레퍼런스 V2 생성`을 내부 9번에서 내부 5번으로 이관하고, 9번 기능·폴더·활성 라우팅을 제거한다.

## 확정 결정

1. 이미지 모듈 내부 활성 번호는 연속된 `1·2·3·4·5·6·7·8`로 한다.
2. 내부 5번은 `캐릭터 레퍼런스 V2 생성`이 소유한다.
3. 기존 `9. 캐릭터 레퍼런스 V2 생성` 폴더의 7개 Markdown 문서는 내용과 상대 구조를 유지한 채 `5. 캐릭터 레퍼런스 V2 생성`으로 이관한다.
4. 내부 5번은 과거 독립 토큰 프레임 기능을 복원하지 않는다. 완성형 VTT 토큰은 계속 내부 1번 반실사 포트레이트가 소유한다.
5. 기존 내부 3번은 V1 16:9 캐릭터 레퍼런스 기능으로 유지한다.
6. V2 명시 요청은 내부 5번으로 라우팅한다.
7. 내부 3번과 5번의 캐릭터 레퍼런스 시트는 모두 `TRPG 데이터/3. 캐릭터 레퍼런스 이미지/`에 저장한다.

## 활성 문서 동기화 범위

- 전역 `준비` 호출 지침
- 루트 및 프롬프트 루트 AGENTS
- 프로젝트 기본 지침과 통합 마스터
- 이미지 모듈 AGENTS·마스터·README·공통 승인 절차
- 공통, 룰북, 설정, FVTT의 이미지 기능 연계 문구
- V2 기능 폴더의 제목과 상위 참조

## 기록 보존 원칙

- 9번으로 추가됐던 기존 설계·실행 계획·검증 보고서는 당시 이력을 보존한다.
- 새 이관 작업의 설계·실행 계획·검증 보고서가 내부 5번의 현재 정본 상태를 명시적으로 대체한다.
- 과거 토큰 프레임 제거 작업은 그대로 보존하며, 새 내부 5번이 토큰 프레임을 뜻하지 않는다는 점을 새 기록에 명시한다.

## 성공 기준

- `1. 이미지 생성 모듈`의 번호 폴더는 정확히 1~8이다.
- `9. 캐릭터 레퍼런스 V2 생성` 폴더는 존재하지 않는다.
- 활성 라우팅 문서에서 V2 요청은 내부 5번으로만 안내한다.
- 활성 문서에 `내부 5번은 결번`, `내부 9번`, `9. 캐릭터 레퍼런스 V2 생성`이 남지 않는다.
- V1·V2 저장 경로와 이미지 승인 절차가 유지된다.

## 비범위

- V1과 V2의 시각 계약·해상도·레이아웃·파일명 규칙은 바꾸지 않는다.
- 완성형 VTT 토큰의 입력·출력·승인 정책은 바꾸지 않는다.
- 역사 문서의 당시 사실을 삭제하거나 재작성하지 않는다.
