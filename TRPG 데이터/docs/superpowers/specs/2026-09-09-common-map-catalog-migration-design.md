# 공용 맵 카탈로그 전환 설계

## 상태

- 설계 확정
- 실행 계획: 미작성
- 물리 자산 이관·이름 변경·기존 파일 삭제: 미실행

## 1. 목적과 범위

`11. 맵 이미지`와 세션 패키지 안에 흩어진 맵 문서·풍경·전술맵을 `11. 맵` 공용 카탈로그로 통합한다. 모든 맵은 재사용 여부나 최초 제작 세션과 무관하게 공용 카탈로그에만 물리적으로 보관한다.

이 작업은 다음을 포함한다.

1. 기존 3개 공용 후보 이미지와 `섬에서 전해진 바람 상편 2`의 4개 세션 전술맵을 6개 공용 맵 항목으로 정리한다.
2. 세션 패키지에서 개별 맵 문서·이미지를 제거하고, 장면과 세션 맵 목록이 `map_uuid`로 공용 맵을 참조하도록 바꾼다.
3. 공용 맵 문서에는 공간 고유 정보를, 세션 장면 문서에는 해당 플레이의 사건·토큰·배치를 둔다.

이 설계는 이미지 재생성, 이미지 내용 변경, 논리 그리드 임의 추정, 기존 역사 문서의 경로 표현 일괄 수정은 포함하지 않는다.

## 2. 공용 카탈로그 구조

```text
11. 맵/
├─ 비공정/
│  ├─ M_AIRSHIP001_오리진 비공정.md
│  └─ M_AIRSHIP001_오리진 비공정_풍경.webp
├─ 동굴/
│  ├─ M_CAVE001_수정 동굴.md
│  ├─ M_CAVE001_수정 동굴_풍경.webp
│  └─ M_CAVE001_수정 동굴_맵.webp
├─ 도시/
│  ├─ M_CITY001_도시 전투 구역.md
│  ├─ M_CITY001_도시 전투 구역_맵.webp
│  ├─ M_CITY002_도시 외곽 진입로.md
│  └─ M_CITY002_도시 외곽 진입로_맵.webp
└─ 성소/
   ├─ M_SHRINE001_검은 사수의 왼팔 성소.md
   ├─ M_SHRINE001_검은 사수의 왼팔 성소_맵.webp
   ├─ M_SHRINE002_성소 외곽 회랑 및 격리 구역.md
   └─ M_SHRINE002_성소 외곽 회랑 및 격리 구역_맵.webp
```

- 환경 분류 폴더 아래에는 Markdown, 풍경, 전술맵을 평면으로 함께 둔다. 풍경과 전술맵을 분리하는 하위 폴더는 만들지 않는다.
- 공용 맵 이름에는 특정 지역명을 넣지 않는다. 지역명은 세션 장면과 서술 문맥에서만 사용한다.
- 이미지 파일의 `_풍경`과 `_맵` 접미사는 역할을 나타낸다. 전술맵이 아직 없는 항목에 빈 파일이나 자리표시자를 만들지 않는다.
- 별도 그리드 이미지는 만들지 않는다. 논리 그리드는 맵 문서에만 기록한다.

## 3. 식별자·상태·재사용 규칙

```yaml
document_type: 공용 맵
map_uuid: 변경 불가 UUID
map_code: 변경 가능 코드
map_title: 지역명을 제외한 공간명
environment: 환경 분류명
map_status: 초안 | 사용 가능 | 사용 중지
logical_grid: 30 × 20 | 미확정
reuse_notes: 재사용 조건 또는 없음
assets:
  - 파일명과 역할
```

- `map_uuid`는 영구 참조값이다. 코드, 제목, 파일명, 환경 폴더가 바뀌어도 변경하지 않는다.
- `map_code`는 사람이 읽는 코드이며 현재 `M_<환경 영문명><순번>` 형식을 사용한다. 환경 분류와 정렬이 바뀌면 변경할 수 있다.
- 모든 세션·로그 분석·하이라이트 참조의 기준은 `map_uuid`다. `map_code`나 물리 경로를 참조 식별자로 쓰지 않는다.
- 논리 그리드가 있는 맵의 가로·세로는 각각 5의 배수다. 아직 검증하지 않은 값은 추정하지 않고 `미확정`으로 둔다.
- `초안`은 자산이나 구상은 있으나 공간 구조 또는 논리 그리드가 완결되지 않은 항목이다. `사용 가능`은 세션에서 바로 참조할 수 있는 공간 문서와 자산 구성이 갖춰진 항목이다. `사용 중지`는 보존하되 신규 세션에서 선택하지 않는 항목이다.
- 모든 맵은 공용 카탈로그에 있으므로 `세션 전용` 상태나 별도 재사용 이력은 만들지 않는다. 실제 사용 이력은 각 세션의 `map_uuid` 참조로 추적한다.

## 4. 초기 공용 맵 원장

| 환경 | map_code | map_title | map_uuid | 초기 상태 | 현재 자산 |
| --- | --- | --- | --- | --- | --- |
| 비공정 | `M_AIRSHIP001` | 오리진 비공정 | `e313df92-ace1-4f56-908c-88b0bea70240` | 초안 | 풍경 1개 |
| 동굴 | `M_CAVE001` | 수정 동굴 | `c63e022b-5794-4b1a-a925-f70af4f72439` | 초안 | 풍경 1개, 전술맵 1개 |
| 도시 | `M_CITY001` | 도시 전투 구역 | `f64579ed-12a1-4c24-a3c4-c675b9695fea` | 사용 가능 | 전술맵 1개 |
| 도시 | `M_CITY002` | 도시 외곽 진입로 | `c0350d55-2d40-419c-83ea-ef2785dd8e0f` | 사용 가능 | 전술맵 1개 |
| 성소 | `M_SHRINE001` | 검은 사수의 왼팔 성소 | `8060cb5a-0e2b-4ee5-b41d-82fa2c008bca` | 사용 가능 | 전술맵 1개 |
| 성소 | `M_SHRINE002` | 성소 외곽 회랑 및 격리 구역 | `38289b6a-e3c2-492d-a4f1-31a50db793de` | 사용 가능 | 전술맵 1개 |

수정 동굴의 풍경과 전술맵은 같은 공간의 한 쌍이므로 하나의 `map_uuid`와 `map_code`를 공유한다. 오리진 비공정은 비공정 자체를 독립 공간 항목으로 관리하며, 이후 내부·갑판 등 구조적으로 독립된 전술맵을 만들면 새 `map_uuid`를 부여하고 필요하면 원본 비공정 맵과의 파생 관계를 기록한다.

## 5. 세션 문서와 공용 맵 문서의 소유 경계

| 정보 | 정본 소유 위치 |
| --- | --- |
| 공간의 구조, 출입구, 논리 그리드, 이미지, 재사용 제약 | 공용 맵 문서 |
| 장면의 목표, 전투 목적, 등장 토큰, 배치, 사건 진행 | 세션 장면 문서 |
| 장면별 `map_uuid` 배정과 사용 방식 | 세션의 `맵 목록`, 각 장면의 `사용 맵` |

`섬에서 전해진 바람 상편 2`의 개별 맵 문서에는 공간 고유 정보와 이번 세션 전용 운용 정보가 함께 있다. 이관 시 공간 정보는 해당 공용 맵 문서로 옮기고, 베르카스 전투·수상한 마법사 격리·혼탁함을 먹는 돌 회수·보호전의 토큰과 사건 정보는 관련 장면 문서에 남긴다. 세션 패키지에는 개별 맵 문서와 이미지의 물리 사본을 남기지 않는다.

세션 문서에서 공용 맵을 설명할 때에는 `map_uuid`와 지역 문맥을 사용한다. 세션 폴더에서 공용 카탈로그의 물리 경로를 직접 링크하지 않는다.

## 6. 이관 경계와 검증 기준

- 이관 전후 이미지 7개의 SHA-256은 동일해야 한다.
- 기존 4개 세션 맵의 `map_uuid`는 기존 장면 01~07의 `사용 맵` 참조와 일치해야 한다.
- 신규 공용 맵 2개에는 이 문서의 UUID를 사용한다.
- 세션의 `맵 목록`은 4개 공용 맵 UUID만 참조하며, 개별 맵 문서·이미지의 잔여 사본은 없다.
- 활성 세션 문서에 이전 세션 맵 폴더를 가리키는 물리 경로가 남지 않는다. 설계·계획·검증 보고서의 과거 경로는 역사 기록이므로 수정하지 않는다.
- `11. 맵 이미지`는 이관 검증이 끝난 뒤에만 비어 있는 기존 폴더 처리 여부를 결정한다. 검증 전에는 어떤 원본도 삭제하지 않는다.

## 7. 후속 실행 경계

실제 이관은 별도 실행 계획에서 파일별 원본·대상·SHA-256, 문서별 정보 분리 위치, 참조 변경, 검증 순서를 확정한 뒤 진행한다. 이 설계 문서 자체는 파일 이동이나 세션 문서 변경을 실행하지 않는다.
