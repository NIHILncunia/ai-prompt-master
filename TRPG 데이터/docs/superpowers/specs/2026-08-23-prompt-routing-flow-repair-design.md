# 프롬프트 라우팅 흐름 정비 설계

## 목적

활성 1~8 기능 체계를 기준으로 루트부터 하위 기능까지의 읽기 순서와 기능 간 연결을 단일 경로로 정렬한다. 재번호 이전 참조, 중복 이미지 승인 정본, 존재하지 않는 상대 경로 때문에 잘못된 기능으로 이동하거나 필수 규칙을 건너뛰는 문제를 제거한다.

## 정본 구조

```text
TRPG 데이터/AGENTS.md
  → 1. 프롬프트/AGENTS.md
    → 활성 기능 1~8의 AGENTS.md
      → 각 기능의 0. 마스터 프롬프트
        → 필수 실행 지침·라이브러리·템플릿
```

이미지 생성은 아래 보조 경로를 유일하게 사용한다.

```text
1. 이미지 생성 모듈/공통/1. 이미지 생성 공통 승인 절차.md
  → 내부 기능의 AGENTS.md와 마스터
  → 요구사항 확인서와 최종 영어 프롬프트
  → 명시적 승인
  → 생성
```

## 변경 원칙

- 이미지 승인 절차의 단일 정본은 `1. 이미지 생성 모듈/공통/1. 이미지 생성 공통 승인 절차.md`로 확정한다.
- 현행 번호를 외부 연결의 유일한 기준으로 사용한다.
  - 2번: 로그 하이라이트 추출
  - 3번: 로그 분석
  - 6번: FVTT
  - 최종 세션 하이라이트 이미지: 1번 이미지 생성 모듈 내부 4번
- 기능을 참조할 때에는 숫자만 쓰지 않고 현재 폴더명 또는 내부 기능 경로를 병기한다.
- 이미지 모듈 내부 1~8은 직접 열어도 상위 모듈의 공통 정책과 마스터를 먼저 확인한다.
- 기존 `1. 프롬프트/공통`의 승인 문서는 삭제하지 않는다. 활성 정본이 아님을 명시하고 이미지 모듈 공통 문서로 연결한다.
- 이번 범위는 라우팅과 읽기 순서만 다룬다. 각 기능의 산출물 규격·세계관 내용·이미지 스타일의 세부 표현은 바꾸지 않는다.

## 변경 범위

### 이미지 승인 경로

- `1. 프롬프트/AGENTS.md`의 이미지 승인 절차 참조를 이미지 모듈 공통 경로로 통일한다.
- `1. 프롬프트/공통/AGENTS.md`와 기존 승인 문서에는 활성 정본 위치를 명시한다.
- 이미지 모듈 내부 1~8 AGENTS에 상위 모듈 AGENTS·마스터 확인 단계를 추가한다.

### 로그 흐름 재번호

다음 표현을 현재 경로명으로 정리한다.

- `6번 분석본` → `3. 로그 분석 프롬프트의 분석본`
- `4번 하이라이트 추출` → `2. 로그 하이라이트 추출 프롬프트`
- `5번 이미지 생성` → `1번 이미지 생성 모듈 내부 4번 세션 하이라이트 이미지 생성`

대상은 로그 하이라이트의 AGENTS·마스터·지침서, 로그 분석의 AGENTS·마스터·지침서, 통합 마스터다.

### 잘못된 상대 경로

창작 지원의 특성·능력·클래스 제작기 AGENTS에서 상위 프롬프트 루트 문서를 가리키는 경로를 `../../` 기준으로 복구한다.

### 범위 표현과 공통 자료 경로

- 룰북·설정·FVTT 마스터의 `1~5번 이미지 관련 기능` 표현을 1번 이미지 생성 모듈 내부 1~8 전체가 드러나는 표현으로 바꾼다.
- `1. 프롬프트/공통/AGENTS.md`의 종족 자료 경로를 실제 `종족 데이터/`로 고친다.

## 비변경 범위

- 최상위 `TRPG 데이터/AGENTS.md`의 기능 번호·파일 정책·이미지 결과 저장 정책
- 이미지 모듈의 공통 붓터치 마감 규칙과 각 기능의 개별 화풍·화면비·산출물 계약
- 설정 정본, 룰북 데이터, 세션 제작 본문, 창작 지원 데이터의 내용

## 검증 기준

- 프롬프트 루트와 이미지 내부 1~8 기능이 같은 승인 정본 경로를 가리킨다.
- 활성 지침에서 `6번 분석본`, `4번 하이라이트 추출`, `5번 이미지 생성`, `1~5번 이미지 관련 기능`이 남지 않는다.
- 특성·능력·클래스 제작기에서 선언한 상위 문서 경로가 실제로 존재한다.
- 이미지 내부 1~8 기능의 직접 읽기 순서에 상위 이미지 모듈 지침이 포함된다.
- 활성 최상위 1~8 폴더와 이미지 내부 1~8 폴더의 개수·번호가 유지된다.
