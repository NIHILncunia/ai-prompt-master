# Superpowers 작업 생명주기 관리 체계 설계

## 목적

`TRPG 데이터/docs/superpowers`를 Superpowers 기반 작업의 설계·실행·검증·완료 이력을 영구 추적하는 운영 체계로 확장한다.

기존 `specs`, `plans`, `reports` 구조는 유지하며, 모든 작업의 공식 상태를 단일 레지스트리에서 관리한다. 완료·중단·폐기된 작업도 삭제하지 않는다.

## 운영 원칙

1. 프로젝트의 모든 실질적인 작업은 적용 가능한 Superpowers 스킬을 우선 확인한다.
2. 설계·개편·신규 기능·구조 변경은 `brainstorming`을 선행한다.
3. 승인된 다단계 작업은 `writing-plans`로 실행 계획을 작성한다.
4. Superpowers 문서는 ZIP으로 제공하지 않고 Drive의 `docs/superpowers`에 직접 생성·갱신한다.
5. 공식 상태 판정은 `SUPERPOWERS WORK REGISTRY.md`가 담당한다.
6. 계획서 체크박스는 보조 진행 기록이며 공식 완료 판정 기준이 아니다.
7. 완료·중단·폐기 이력도 영구 보존한다.
8. 프로젝트 고유 기능 지침은 Superpowers에 의해 대체되지 않으며 함께 적용한다.

## 문서 구조

```text
TRPG 데이터/docs/superpowers/
├─ SUPERPOWERS WORK REGISTRY.md
├─ specs/
│  └─ YYYY-MM-DD-<작업>-design.md
├─ plans/
│  └─ YYYY-MM-DD-<작업>.md
└─ reports/
   ├─ YYYY-MM-DD-<작업>-analysis.md
   ├─ YYYY-MM-DD-<작업>-verification.md
   └─ YYYY-MM-DD-<작업>-completion-report.md
```

## 문서 역할

### specs

무엇을 만들거나 변경할 것인지에 대한 확정 설계를 보존한다. 설계가 승인된 뒤 작성한다.

### plans

확정 설계를 실제로 적용하기 위한 작업 순서와 변경 대상을 기록한다. 실행 결과와 관계없이 당시 계획을 보존한다.

### reports

분석·검증·이관 결과·완료 보고 등 실행 과정에서 나온 증거성 문서를 기록한다. 모든 작업에 강제하지 않는다.

### SUPERPOWERS WORK REGISTRY.md

모든 Superpowers 작업의 공식 상태와 연결 문서를 기록하는 단일 정본이다. 상세 내용을 복제하지 않고 각 문서를 연결한다.

## 작업 식별자

별도 UUID를 만들지 않는다. 기본 작업 ID는 날짜와 slug를 결합한 basename을 사용한다.

예:

```text
2026-08-02-creative-support-module-migration
2026-08-08-image-generation-module-reorganization
```

하나의 작업에 spec·plan·report가 여러 개 존재할 경우 동일 basename을 공통 접두어로 사용한다.

## 상태 값

- `설계 중`
- `설계 완료`
- `실행 계획 완료`
- `진행 중`
- `검증 중`
- `완료`
- `중단`
- `폐기`

`완료`와 `폐기`는 종료 상태다. `중단`은 재개 가능한 상태다.

## 상태 전이

```text
신규 작업
→ 설계 중
→ 설계 완료
→ 실행 계획 완료
→ 진행 중
→ 검증 중 (필요한 경우)
→ 완료
```

예외 전이:

```text
설계 중 / 설계 완료 / 실행 계획 완료 / 진행 중
→ 중단
→ 이전 진행 단계로 재개

어느 단계에서든
→ 폐기
```

작업이 단순하여 별도 검증 보고서가 필요하지 않은 경우 `진행 중 → 완료`를 허용한다.

## 완료 판정

완료 여부는 레지스트리의 `상태: 완료`를 유일한 공식 판정으로 사용한다.

계획 문서에 미완료 체크박스가 남아 있거나 완료 보고서가 존재하지 않아도, 실제 반영이 확인되고 레지스트리가 `완료`로 확정하면 완료된 작업으로 취급한다.

반대로 계획 체크박스가 전부 완료되어도 레지스트리가 `진행 중`이면 공식적으로 완료되지 않은 작업이다.

## 레지스트리 필드

각 작업은 최소 다음 정보를 가진다.

- 작업 ID
- 작업명
- 상태
- 작업 유형
- 시작일
- 완료일 또는 종료일
- 설계 문서
- 실행 계획
- 보고서
- 결과 요약
- 후속 작업
- 대체 작업
- 비고

해당하지 않는 필드는 생략할 수 있다.

## 기존 작업 이관

기존 `specs`, `plans`, `reports`를 전수 조사하여 작업 단위로 묶고 레지스트리에 등록한다.

실행 여부가 문서만으로 확인되지 않는 작업은 추측하지 않고 `상태 확인 필요` 비고를 남긴다. 사용자가 완료를 확정했거나 현행 구조로 완료가 검증된 작업은 `완료`로 등록한다.

`2026-08-02-creative-support-module-migration`은 사용자 확정에 따라 완료 작업으로 우선 등록한다.

## 메인 지침 동기화

다음 네 진입점에 Superpowers 우선 활용 원칙을 동기화한다.

- `TRPG 데이터/AGENTS.md`
- `TRPG 데이터/1. 프롬프트/AGENTS.md`
- `TRPG 데이터/1. 프롬프트/00. TRPG 세션 매니저 프로젝트 기본 지침.md`
- `TRPG 데이터/1. 프롬프트/0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md`

내용은 세부 스킬 설명을 복제하지 않고 다음만 명시한다.

- 모든 작업에서 적용 가능한 Superpowers 스킬을 우선 판별
- 설계성 작업은 brainstorming 선행
- 승인된 다단계 작업은 writing-plans 사용
- Superpowers 문서는 Drive 직접 관리
- 작업 레지스트리를 공식 상태 정본으로 사용

## 성공 기준

- 새 작업의 상태를 하나의 문서에서 판별할 수 있다.
- 완료된 과거 계획이 미완료처럼 보이는 문제를 제거한다.
- spec·plan·report의 원래 역할과 이력을 보존한다.
- Superpowers 문서가 ZIP 전달 없이 Drive에서 직접 관리된다.
- 메인 지침 어디에서 진입하더라도 Superpowers 우선 활용 규칙이 동일하게 적용된다.
