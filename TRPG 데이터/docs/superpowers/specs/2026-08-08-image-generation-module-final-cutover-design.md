# 이미지 생성 모듈 최종 전환 및 프롬프트 1~8 재번호 설계

## 1. 목적

이미지 생성 기능 8개를 최상위 `1. 이미지 생성 모듈` 아래로 완전히 통합하고, 이관 전 이미지 기능 폴더와 전환기 번호 해석을 제거한다. 남는 활성 비이미지 기능은 2번부터 8번까지 연속 번호로 재배치한다.

이 설계의 완료 상태에서는 사용자가 번호만 말해도 과거 체계와의 비교 없이 하나의 기능을 결정할 수 있어야 한다.

## 2. 최종 정본 구조

```text
1. 프롬프트/
├─ 1. 이미지 생성 모듈/
│  ├─ 공통/
│  ├─ 라이브러리/
│  └─ 1~8 내부 이미지 기능/
├─ 2. 로그 하이라이트 추출 프롬프트/
├─ 3. 로그 분석 프롬프트/
├─ 4. 룰북 관련 요청 프롬프트/
├─ 5. 설정 관련 요청 프롬프트/
├─ 6. FVTT 관련 요청 프롬프트/
├─ 7. 창작 지원 프롬프트/
├─ 8. 세션 제작 프롬프트/
├─ 공통/
└─ 보관/
```

`공통`과 `보관`은 번호 기능이 아니다. `보관`은 활성 라우팅, 준비 명령의 기능 목록, 재번호 대상에서 모두 제외한다.

## 4. 제거 대상과 보존 경계

다음 폴더는 신규 이미지 모듈로 이관이 검증된 후 최종 전환에서 제거한다.

- `1. 포트레이트 생성 프롬프트`
- `2. 배틀맵 생성 프롬프트`
- `3. 캐릭터 레퍼런스 시트 생성 프롬프트`
- `5. 세션 하이라이트 이미지 생성 프롬프트`
- `10. 토큰 프레임 생성 프롬프트`
- `12. 풍경 일러스트 생성 프롬프트`
- `13. 게임 아이콘 생성 프롬프트`
- `14. 월드 지도 생성 프롬프트`

삭제 전에는 각 폴더의 이관 판정, 신규 파일 존재, 삭제 대상 목록, 백업 위치를 하나의 검증 기록으로 확정한다. 과거 Superpowers 설계·계획·감사·인계 문서 속 구 번호와 구 경로는 역사 기록이므로 변경하거나 삭제하지 않는다.

## 5. 전환 전 정본 완결 게이트

삭제와 재번호보다 먼저 다음을 완료한다.

1. 상위 기본 지침과 통합 마스터의 중첩된 공통 승인 경로를 실제 신규 경로로 통일한다.
2. 포트레이트 계약을 `전신 9:16 → 전신 확정 → 동일 개체 흉상 9:16`으로 통일하고, 각 이미지 호출만 별도 승인으로 처리한다.
3. 신규 내부 5~8번 AGENTS에 `0번 마스터 → 공통 승인 절차 → 기능 실행 문서 → 필요한 라이브러리` 읽기 순서를 명시한다.
4. 최상위 AGENTS와 하위 기본 지침의 Codex 로컬 Markdown 접근 규칙을 하나로 통일한다.
5. 신규 이미지 모듈 경로를 가리키는 현재 운영 참조가 모두 실존 경로인지 검증한다.

이 게이트가 닫히기 전에는 구 이미지 폴더 삭제나 비이미지 기능 재번호를 시작하지 않는다.

## 6. 일괄 전환 방식

전환은 호환 별칭이나 이중 번호 기간을 두지 않는 단일 절차로 수행한다.

1. 최종 전환 대상 파일과 폴더의 읽기 전용 인벤토리·해시·백업을 만든다.
2. 구 이미지 폴더 8개를 제거한다.
3. 비이미지 7개 폴더를 최종 번호로 이름 변경한다.
4. 새 번호가 반영된 각 기능의 AGENTS, README, 0번 마스터, 실행 문서, 라이브러리, 템플릿의 `repository_path`·`drive_path`·본문 참조를 갱신한다.
5. 최상위 4개 운영 문서와 기능 간 상호 참조를 새 번호로 동기화한다.
6. 전환기 매핑표, “구 번호”, “현재/구 번호”, “Phase G 전까지” 같은 운영 문구를 현행 문서에서 제거한다.
7. 새 1~8번 구조, 준비 명령, 경로 참조, 삭제 잔재를 전수 검증한다.

단계 2~6은 하나의 전환 배치다. 단계 중간 상태를 정본으로 기록하지 않으며, 실패 시 백업으로 되돌릴 수 있어야 한다.

| 문서 | 최종 책임 |

| `1. 프롬프트/AGENTS.md` | 번호 요청의 라우팅, 기능별 실제 진입 경로 |

## 8. 검증 계약

최종 전환은 아래 조건을 모두 만족할 때만 완료다.

- 프롬프트 루트의 활성 번호 폴더가 정확히 1~8번이다.
- 구 이미지 기능 폴더 8개가 없다.
- 활성 운영 문서에서 구 이미지 폴더명, 구 비이미지 번호, 전환기 번호 해석이 0건이다.
- `준비`는 최종 1~8번만 나열하고, `준비 ?번`은 최종 번호만 해석한다.
- 1번 이미지 모듈 내부 1~8번이 모두 실제 파일과 올바른 공통 승인 절차를 가리킨다.
- 각 활성 기능의 AGENTS·README·0번 마스터가 실제 폴더명과 기능 번호를 일치시킨다.
- 역사 기록 문서는 보존되고, 현행 운영 문서와 구분된다.
- 삭제 전 백업과 삭제 후 인벤토리 검증 기록이 남는다.

## 9. 범위와 비범위

이 작업은 라우팅·폴더명·경로·운영 문구의 최종 전환이다. 이미지 기능의 세부 화풍, 배틀맵의 기본 비율, 아이콘 스타일 목록처럼 최종 전환과 무관한 기능 설계는 변경하지 않는다.

구 폴더 삭제와 이름 변경은 되돌리기 어려운 작업이므로, 실행 계획에서 백업 검증과 삭제 대상을 별도 승인 게이트로 둔다.
