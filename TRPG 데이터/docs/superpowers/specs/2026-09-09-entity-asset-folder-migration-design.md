# 엔터티 자산 폴더 전환 설계

## 목적

기존 이미지 전용 루트와 공용 레퍼런스·생성 결과·컨셉 자산을 대상별 폴더로 재구성한다. 각 대상은 자산과 자산 인덱스 문서를 함께 가지며, 설정 폴더의 서술형 설정 문서는 이관하거나 복제하지 않는다.

## 확정 구조

```text
5. 신격/<만신전>/<신격>/
6. NPC/<대상>/
7. PC/<대상>/
8. 국가/<대상>/
9. 단체/<대상>/
10. 몬스터/<유형>/<대상>/
11. 맵/<환경>/
12. 종족/<대상>/
13. 지역/<대상>/
14. 용종/<유형>/<대상>/
15. 장소/<대상>/
16. 미분류/<원천>/<대상 또는 원본명>/
18. 아이템/<대상>/
```

- 숫자 접두는 기존 작업 폴더의 고정 순서를 보존한다.
- `3. 캐릭터 레퍼런스 이미지`와 `15. 이미지 생성 결과`는 독립 정본 루트로 유지하지 않는다.
- `16. 컨셉 이미지`는 `16. 미분류`로 전환한다. 현재 4개 자산은 아이템으로 분류한다.
- `15. 장소`는 장소·구조물·비공정 등 독립 장소 자산을 보관한다.
- `11. 맵`은 이미 확정한 공용 맵 카탈로그 계약을 유지하며 이 작업에서 다시 이동하지 않는다.

## 대상 폴더 계약

각 대상 폴더는 `<대상명>.md` 자산 인덱스를 가진다. 인덱스는 설정 본문을 복제하지 않고 아래만 기록한다.

```yaml
document_type: 자산 인덱스
<분류>_uuid: <UUID v4>
name: <대상명>
category: <분류>
```

- UUID 필드명은 `npc_uuid`, `pc_uuid`, `monster_uuid`, `deity_uuid`, `country_uuid`, `group_uuid`, `race_uuid`, `region_uuid`, `place_uuid`, `item_uuid`, `dragon_type_uuid`처럼 `<분류>_uuid`를 사용한다.
- 인덱스 본문은 현재 보관 자산과 원본 이관 경로만 적는다. 설정 사실·세션 결과·플레이 기록은 넣지 않는다.
- 세션 전용 중요 아이템·NPC 문서는 `17. 세션 설계` 패키지 안에 계속 두며, 공용 인덱스와 중복하지 않는다.

## 파일 컨벤션

- NPC·PC·몬스터·신격의 신규 정본 설정화는 `설정화.webp` 9:16, `초상화.webp` 9:16, `토큰.webp` 1:1을 사용한다.
- 지역·장소·아이템·기타의 신규 정본 설정화는 `설정화.webp` 16:9을 사용한다.
- 아이템은 추가로 `아이콘.webp` 1:1을 사용한다.
- 국가·단체·종족은 추가로 `엠블럼.webp` 1:1과 `배너.webp` 16:9을 사용한다.
- 캐릭터 레퍼런스는 `<대상명> 레퍼런스 시트 V1.webp`, 이후판은 `V2`, `V3` 순으로 쓴다.
- 기존 자산은 새 이미지를 만들거나 비율을 강제하지 않는다. 역할이 확정되지 않은 기존 자산·시안은 대상 폴더의 `시안/` 또는 `16. 미분류/`에 원본 파일명을 보존한다.

## 분류와 보존 원칙

- 현재 용도에 따라 NPC·PC·몬스터·신격을 결정한다. 외형과 종족만으로 NPC/몬스터를 바꾸지 않는다.
- 용종은 별도 루트 `14. 용종`으로 보관하되, 대상 폴더·자산 인덱스·이미지 규칙은 몬스터와 동일하다.
- 원래 위치·SHA-256·대상 위치의 매핑을 먼저 고정하고, 이동 뒤 해시와 활성 Markdown 참조를 검증한다.
- 원본명만으로 분류할 수 없는 생성 결과는 추정하지 않고 `16. 미분류/이미지 생성 결과/`에 보존한다.
- 동일 내용의 충돌 파일은 SHA-256이 같은 경우에만 한 정본으로 통합한다. 다른 경우에는 덮어쓰지 않고 `시안/`에 모두 보존한다.

## 저장 규칙 전환

신규 생성은 공용 결과 폴더에 임시 보관하지 않는다. 대상이 확정되면 처음부터 해당 대상 폴더에 저장한다. 대상이 확정되지 않은 생성 결과만 `16. 미분류/이미지 생성 결과/`에 저장하고, 분류 시 원본 자산을 이동한다.
