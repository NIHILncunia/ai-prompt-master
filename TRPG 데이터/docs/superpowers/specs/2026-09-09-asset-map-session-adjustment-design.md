# TRPG 자산·맵 카탈로그 및 상편 2 재설계

## 상태

- 설계 결정 정리 완료
- 물리적 자산 이관·이름 변경: 미실행
- 기존 세션 장면·맵 문서 조정: 설계 정본 검토 뒤 진행

## 1. 범위와 정본 경계

- `설정 폴더`는 세계관 정본 문서만 둔다. 현재 데이터베이스 이관 점검 중이므로 작업 폴더 자산이나 세션 결과를 자동 동기화하지 않는다.
- `작업 폴더`는 실제 플레이에 쓰는 개체 문서, 이미지, 토큰, 아이템, 맵과 세션 이력을 소유한다.
- 플레이로 새로 밝혀지거나 변한 인물 정보는 로그 분석뿐 아니라 해당 인물·외형 자산 문서에도 반영한다.
- 이 설계는 현재 자산의 이동·삭제·이름 변경을 승인하지 않는다. 실제 이관은 별도 실행 계획과 대상 검증 뒤에 수행한다.

## 2. 자산 분류와 대상 폴더

### 2.1 분류

작업 폴더의 개체 자산은 NPC, PC, 국가, 단체(가문 포함), 몬스터, 신격, 종족, 용종, 지역, 장소, 아이템, 맵, 미분류로 관리한다.

- `용종`은 설정 폴더와 이미지 자산 모두에서 이미 독립 분류이므로 유지한다.
- `16. 컨셉 이미지`는 `16. 미분류`로 전환한다.
- `미분류`는 대상이나 소유 분류가 아직 정해지지 않은 임시 수납함이다. 활성 세션이나 문서는 미분류 자산을 직접 참조하지 않는다.
- 현재 컨셉 이미지의 검은 사수의 석궁, 왼팔, 오른팔, 혼탁함을 먹는 돌은 최종적으로 아이템 자산으로 분류한다.

### 2.2 대상 단위와 시안

- 분류가 확정된 대상은 대상별 폴더 안에 문서와 최종 이미지 세트를 함께 둔다.
- 채택한 최종 자산은 대상 폴더 최상단에 둔다.
- 같은 대상의 미채택·보류 이미지 시안은 해당 대상의 `시안` 하위 폴더에 둔다.
- 대상 자체가 정해지지 않은 자료만 `미분류`에 남긴다.

### 2.3 플레이 용도 우선 분류

외형이 여러 개인 존재는 본질이나 종족이 아니라, 그 외형이 실제 플레이에서 수행하는 용도로 분류한다.

예를 들어 칼 드라크의 인간형은 정체가 드러나기 전 NPC로 쓰이므로 NPC 자산이며, 드러난 진체는 전투 몬스터로 쓰이므로 몬스터 자산이다. 두 자산은 같은 존재임을 상호 참조할 수 있으나, 하나의 폴더나 하나의 문서로 강제 통합하지 않는다.

## 3. 이미지 파일 컨벤션

### 3.1 인물 계열

NPC, PC, 몬스터, 신격의 설정화는 9:16 세로형을 사용한다. 인물용 최종 세트는 전신 설정화, 초상화, 1:1 토큰으로 관리한다.

```text
<대상명>.webp
<대상명> 초상화.webp
<대상명> 토큰.webp
```

### 3.2 비인물 개체

지역, 장소, 아이템과 그 밖의 비인물 개체 설정화는 16:9 가로형을 사용한다.

- 아이템은 16:9 설정화 외에 1:1 `<대상명> 아이콘.webp`를 둔다.
- 국가, 단체, 종족은 1:1 `<대상명> 엠블렘.webp`와 16:9 `<대상명> 배너.webp`를 둔다.

## 4. 단일 맵 카탈로그

### 4.1 보관 원칙

모든 맵은 재사용 가능성이나 세션 전용 여부와 관계없이 하나의 루트 맵 카탈로그에 둔다. 세션 폴더는 물리 맵 사본을 소유하지 않고 설계 맵을 참조한다.

```text
맵/
└─ grassland/
   ├─ M_GRASSLAND_001_안개 낀 초원 길.md
   ├─ M_GRASSLAND_001_안개 낀 초원 길_풍경.webp
   ├─ M_GRASSLAND_001_안개 낀 초원 길_맵.webp
   └─ ...
```

- 풍경과 전술 맵을 별도 폴더로 나누지 않는다.
- 환경 폴더 아래에 해당 환경의 맵 문서·풍경·맵 이미지를 평면으로 둔다.
- 그리드 이미지는 만들지 않는다. 논리 그리드 값은 맵 Markdown에만 기록한다.
- 논리 그리드의 가로·세로 수는 각각 5의 배수다. 맵의 비율·방향·넓이는 용도에 따라 정한다.

### 4.2 식별자와 파일명

- `map_uuid`는 소문자 표준 UUID 형식의 영구 참조값이며 생성 뒤 바꾸지 않는다.
- `map_code`는 `M_환경영문명_순번` 형식의 사람용 코드다. 환경 분류·이름·파일명 변경에 맞춰 바꿀 수 있다.
- 장면, 로그 분석, 하이라이트는 `map_uuid`만 참조한다.
- 파일명·폴더 정리와 사람이 읽는 맵 표기는 현재 `map_code`를 사용한다.

## 5. 섬에서 전해진 바람 상편 2 재설계 기준

### 5.1 네 맵의 필수 국면

```text
03. 아그니르 도시 외곽 진입로
  도시 진입과 1차 전투
↓
01. 아그니르 도시 전투 구역
  베르카스가 지휘하는 2차 도시 방어전
↓
04. 성소 외곽 회랑 및 격리 구역
  수상한 마법사 인계, 격리 조사, 혼탁함을 먹는 돌 회수, 실타래 추적
↓
02. 검은 사수의 왼팔 성소
  왼팔 공개와 실타래 최종 갈등
```

맵 03과 04는 보조·선택 공간이 아니다. 각 맵은 다음 공간으로 이동하기 전에 반드시 해결해야 하는 독립 플레이 문제를 담당한다.

### 5.2 혼탁함을 먹는 돌

```text
아이템명: 혼탁함을 먹는 돌
본질: 악마의 씨앗
기능: 혼탁하고 사특한 기운을 흡수해 외부 감지를 피하게 한다.
현재 사용: 수상한 마법사가 확보했고, 실타래의 명령으로 실타래의 기운을 숨기는 데 쓰였다.
장기 위험: 흡수량이 한계에 도달하면 악마가 태어난다.
이번 세션: 악마는 태어나지 않는다.
```

맵 04에서 돌을 회수하는 일은 실타래의 은폐 구조를 무너뜨리는 물리적 단서이자, 악마의 씨앗이라는 장기 위험을 일행이 확보하는 사건이다. 수상한 마법사의 잔류 조종 실과 은폐 술식을 끊는 플레이는 유지하며, 돌 회수와 결합해 실타래를 특정·추적하는 근거를 만든다.

### 5.3 장면 문서 조정 원칙

- 장면 01은 맵 03에서 자코를 처리하는 도시 진입 1차 전투다. 단순 강하·이동 장면으로 두지 않는다.
- 장면 02는 맵 01에서 베르카스를 격파하는 2차 전투다. 맵 03을 보조 전장으로 쓰지 않는다.
- 장면 03의 가족 재회는 맵 01의 전투 후 상태를 재사용한다.
- 베르카스 격파 뒤 워락들이 수상한 마법사를 인계하며, 이는 맵 04에 들어가기 전 발생한다.
- 장면 04와 05는 맵 04에서 수상한 마법사의 격리 조사, 혼탁함을 먹는 돌의 추적·회수, 잔류 조종 실 절단과 실타래 폭로를 담당한다.
- 장면 06은 맵 02에서 왼팔 공개와 보호진 최종전을 담당한다. 맵 04는 최종전의 보조 전장이 아니다.
- 장면 07은 맵 02의 전투 종료 상태를 재사용하고, 장면 08은 별도 전술 맵을 사용하지 않는다.

## 6. 다음 실행 전 검토 대상

1. 현재 더티 워크트리의 세션 장면·맵 문서 변경을 보존한 채, 실제 차이와 소유 범위를 확인한다.
2. `02. 장면 목록`, `01. 시나리오`, 장면 01·02·04·05·06, 맵 목록과 맵 01~04의 참조를 위 설계 기준으로 동기화한다.
3. 장면 9개에 `scene_uuid`, 맵 4개에 `map_uuid`를 부여하고 모든 `사용 맵`을 구조화된 직접 참조로 승격한다.
4. 단일 맵 카탈로그 이관은 세션 패키지 승격과 분리하여 실행 계획을 만든다.
