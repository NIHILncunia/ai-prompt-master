# `준비.` 응답 레이아웃 및 SESSION PROGRESS 운영 설계

- 상태: 마스터 승인 후 구현 대기
- 대상: `TRPG 데이터/1. 프롬프트`의 전역 라우터와 `준비.` 응답 규칙

## 목표

`준비.`가 단순 번호·명칭 목록이 아니라, 마스터가 각 기능의 목적과 대략적인 처리 흐름을 즉시 파악할 수 있는 안내 응답을 출력한다. 또한 모든 실질 응답에서 현재 대화의 실제 진행 상태를 `SESSION PROGRESS`로 일관되게 보고한다.

## 출력 계약

1. 활성 최상위 기능 1~8번을 번호 순서로 표시한다.
2. 각 기능에는 처리 대상과 대표 산출물 또는 연결 관계를 설명하는 1~2문장을 둔다.
3. 내부 기능을 가진 1번 이미지 생성 모듈은 내부 1~8번을 줄바꿈 불릿으로 나열한다.
4. 이미지 생성 모듈 설명 끝에는 다음 공통 절차를 고정으로 표시한다.
   - 요구사항 확인서와 최종 영어 프롬프트를 먼저 공개한다.
   - 마스터의 명시적 승인 후에만 이미지 생성 또는 수정을 실행한다.
5. 이미지 외 기능에는 이미지 승인 절차를 표시하지 않는다. 대신 선행·후속 기능이 필요한 경우에만 짧게 연결 관계를 설명한다.
6. `준비 ?번`의 기존 원칙은 유지한다. 해당 기능의 처리 프로세스만 표시하며 생성·수정·외부 실행은 시작하지 않는다.

## 문서 반영 범위

- 정본 출력 규칙: `TRPG 데이터/1. 프롬프트/AGENTS.md`
- 상위 동기화: `00. TRPG 세션 매니저 프로젝트 기본 지침.md`
- 상위 동기화: `0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md`
- 전역 호출 조건은 `TRPG 데이터/AGENTS.md`에 이미 있으므로, 기능 목록 레이아웃은 중복하지 않는다.

## SESSION PROGRESS 운영 계약

1. 진행 상태가 있는 모든 실질 응답의 본문 뒤, 최하단에 `SESSION PROGRESS`를 표시한다.
2. 활성 작업은 `작업`, `현재`, `단계`, `완료`, `미결`, `다음` 필드를 사용한다.
3. 미완료 작업을 두고 다른 주제로 전환하면 중단 지점과 재개 지점을 보존한다.
4. 진행 중인 작업이 없으면 대기형으로 축약한다.
5. 완료·미결·다음은 실제 대화 진척만 기록하며, 예정 작업을 완료처럼 표시하지 않는다.
6. 사용자가 표시하지 말라고 명시하면 해당 지시를 우선한다.
7. 이 규칙은 이미지 생성 승인 절차와 별개다. 이미지 승인 절차는 이미지 모듈에만, SESSION PROGRESS는 모든 실질 응답에 적용한다.

## SESSION PROGRESS 반영 범위

- 전역 정본: `TRPG 데이터/AGENTS.md`
- 프롬프트 루트 라우터: `TRPG 데이터/1. 프롬프트/AGENTS.md`
- 프로젝트 기본 지침: `00. TRPG 세션 매니저 프로젝트 기본 지침.md`
- 통합 마스터: `0. TRPG 데이터 프롬프트 통합 마스터 프롬프트.md`
- 운영 원전: `TRPG 데이터/SESSION PROGRESS 운영 지침.md`
- Codex 메모리 확장 노트: `C:/Users/nihil/.codex/memories/extensions/ad_hoc/notes/`

## 검증 기준

- `준비.` 응답이 1~8번을 모두 설명한다.
- 이미지 모듈 내부 1~8번이 불릿의 개별 줄로 표시된다.
- 이미지 모듈에만 승인 절차가 표시된다.
- 이미지 외 기능에는 불필요한 승인 절차가 없다.
- `준비 ?번`이 작업 실행 없이 프로세스 안내만 한다.
- 활성형·중단형·대기형의 SESSION PROGRESS가 지침에 정의되어 있고, 사용자 표시 금지 지시를 우선한다.
