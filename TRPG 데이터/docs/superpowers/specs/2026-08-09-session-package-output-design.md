# 세션 제작 패키지형 산출물 및 저장 구조 설계

- 상태: 마스터 승인 완료, 실행 계획 작성 대기
- 대상: `TRPG 데이터/2. 로그/세션 설계`와 `1. 프롬프트/8. 세션 제작 프롬프트`

## 목표

8번 세션 제작의 산출물을 단일 Markdown 파일이 아닌 역할별 Markdown 파일 묶음으로 만든다. Codex는 로컬 동기화 경로에 이 구조를 저장하며, 웹 GPT는 동일한 적용 경로를 보존한 ZIP만 제공한다.

## 저장 구조

```text
TRPG 데이터/
└─ 2. 로그/
   └─ 세션 설계/
      └─ [스토리명]/
         ├─ 00. 세션 아크 개요.md                 # 연속 세션일 때만
         ├─ 01. [세션 제목]/
         │  ├─ 01. 01 [세션 제목] 시나리오.md
         │  ├─ 02. 01 [세션 제목] 장면 모음.md
         │  ├─ 03. 01 [세션 제목] 등장인물 및 몬스터.md
         │  └─ 04. 01 [세션 제목] 조우 설계.md
         └─ 02. [세션 제목]/
```

- `[스토리명]`은 캠페인 또는 시나리오 묶음의 경계다.
- 세션 폴더의 번호는 해당 스토리 안의 회차 순서다.
- 내부 `01~04` 번호는 문서 역할 순서이며, 모든 세션 패키지에서 고정한다.
- 아크 개요와 세션별 파일은 빈 상태로 미리 만들지 않는다.

## 산출물 계약

### 01. 시나리오

세션 개요, 사건의 진실, 현재 상황, 사건의 발단, 전체 진행 흐름, 장면 목록, 결말 가능성, 이후 변화, GM 운영 참고, 추가 제작 자료, 설정 및 로그 참조를 담는다. 장면의 상세 묘사와 인물·조우의 세부 운용표는 담지 않는다.

### 02. 장면 모음

모든 장면의 설계 설명과 실제 진행 묘사를 담는다. 각 장면에는 관련 인물·몬스터와 조우 문서의 항목명을 적어 연결한다. 인물의 전체 프로필 및 조우의 결과표를 중복하지 않는다.

### 03. 등장인물 및 몬스터

NPC와 몬스터의 역할, 목적, 태도, 말투, 외형, 행동 기준, 장면별 등장 관계, 필요한 룰 데이터 또는 참조를 담는다. 장면의 실제 진행 묘사와 조우의 전체 절차는 담지 않는다.

### 04. 조우 설계

모든 조우의 시작 조건, 목적, 참여자, 환경, 가능한 접근, 상황 변화, 성공·부분 성공·실패 결과, 종료 조건, 난이도 조절을 담는다. 조우가 없는 세션에도 이 파일은 기본 산출물로 작성하며, `조우 없음`과 그 이유를 기록한다.

## 실행 환경 정책

- Codex: `G:\내 드라이브\TRPG 데이터\2. 로그\세션 설계\`에 실제 세션 패키지를 저장할 수 있다.
- 웹 GPT: 같은 상대 경로와 파일 구성을 보존한 ZIP만 제공한다. Drive에 직접 생성·수정·업로드하지 않는다.
- 기존 단일 파일 세션은 자동 이전하지 않는다. 새 세션과 마스터가 재구성을 요청한 세션에만 적용한다.

## 함께 정정할 결함

`0. 세션 제작 마스터 프롬프트.md`와 `AGENTS.md`에 남은 로그 분석의 구 번호 `6번`을 현행 `3번`으로 정정한다. FVTT 관련 요청의 현행 번호 `6번`은 변경하지 않는다.

## 검증 기준

1. `2. 로그/세션 설계/` 폴더가 존재한다.
2. 세션 제작 지침이 세션 패키지와 4개 고정 문서를 정의한다.
3. 각 템플릿의 섹션이 파일별 책임 경계와 일치한다.
4. Codex 로컬 저장과 웹 GPT ZIP 제공의 차이가 명시된다.
5. 단일 파일·NPC와 조우 분리 금지의 활성 규칙이 남아 있지 않다.
6. 출력 경로와 ZIP 내부 경로가 일치하는지 검수 항목으로 확인한다.
