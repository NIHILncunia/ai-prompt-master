# 룰북 주분류·분리 테이블 전환 설계

## 목적

보유 룰북을 주된 사용 목적에 따라 데이터북·시나리오북·설정북으로 한 번만 분류하고, 같은 정본 파일 안의 독립 표로 관리한다. 시나리오북과 설정북은 전 페이지 원본 검증을 수행하되 장르·핵심 주제·확인된 데이터 유형만 남기며, 데이터북만 룰북별 상세 위치 인덱스를 가진다.

## 확정 분류 원칙

1. 연속된 모험 진행이 중심이면 시나리오북이다.
2. 세계·지역·세력·문화 설명이 중심이면 설정북이다.
3. 재사용 가능한 규칙·옵션·스탯블록·목록 제공이 중심이면 데이터북이다.
4. 경계가 비슷하면 서문에 명시된 목적과 목차의 주된 장 구성을 우선하고, 여전히 모호할 때만 해당 장의 페이지 비중을 보조 기준으로 사용한다.
5. 한 룰북은 한 주분류에만 속한다. 복합형 구역이나 중복 행을 만들지 않는다.
6. 부수적으로 포함된 데이터는 주분류를 바꾸지 않고 확인된 데이터 유형으로 보존한다.

## 소유 목록 구조

`9999. D&D 룰북 소유 리스트.md` 한 파일 안에 다음 독립 표를 둔다.

- 데이터북: 룰북 이름, 주요 데이터 범위, 확인된 데이터 유형, 실제 파일명, D&D Beyond, 원본 확인, 상세 인덱스
- 시나리오북: 룰북 이름, 장르, 핵심 주제, 확인된 데이터 유형, 실제 파일명, D&D Beyond, 원본 확인
- 설정북: 룰북 이름, 배경 세계·장르, 핵심 주제, 확인된 데이터 유형, 실제 파일명, D&D Beyond, 원본 확인
- Beyond 비교 전용: 기존 비교 목적과 14개 항목을 유지한다.

소유 목록은 논리 룰북 단위다. 여러 실제 파일로 구성된 룰북은 한 행의 실제 파일명 셀에 순서대로 기록한다. 원본 확인은 대응 실제 파일 행이 모두 Y일 때만 Y다.

## 검증 현황 구조

`FVTT 룰북 검증 및 갱신 현황.md` 한 파일 안에서 다음 표를 서로 분리한다.

1. 데이터북 원본 검증: 실제 파일별 행
2. 데이터북 상세 인덱스: 논리 룰북별 행
3. 시나리오북 원본 검증: 실제 파일별 행
4. 설정북 원본 검증: 실제 파일별 행
5. Beyond 비교 전용: 실제 파일 또는 파일 없음 행

각 주분류는 전체·완료·미검증 수와 현재·다음 대상을 독립적으로 관리한다. 이관 시점에는 기존 실제 파일 검증 151행, Y 12행, N 139행, 실제 파일 없음 13행을 보존한다.

## 상세 인덱스와 아카이브

- 데이터북만 활성 상세 인덱스 파일을 가진다.
- 기존 비데이터북 상세 인덱스는 요약 정보를 소유 목록과 검증 현황에 반영한 뒤 `작업 정비/정비 아카이브/룰북 인덱싱 및 FVTT 컴펜디움 이관 체계/룰북별 데이터 위치 인덱스/`로 이동한다.
- 아카이브는 원본 파일명을 유지한다. 같은 이름이 있으면 이동 파일에 `yyyy-MM-dd-HHmm_` 접두를 붙인다.
- 활성 데이터북 인덱스는 1번부터 다시 부여한다. Volo's Guide to Monsters가 1번, One Grung Above가 2번, Xanathar's Guide to Everything이 다음 3번이다.

## 원본 검증

- 데이터북은 기존 상세 인덱스 정책에 따라 개별 항목과 PDF 뷰어 페이지를 기록한다.
- 시나리오북과 설정북은 전 페이지를 조사하지만 장르·핵심 주제·데이터 유형만 기록한다.
- 검증하지 않은 장르·핵심 주제는 `-`와 N을 사용한다. 기존 목록의 데이터 유형 정보는 `기존 목록 기준 —` 접두로 보존하여 전 페이지 검증 결과와 구분한다.
- 확인된 독립 데이터가 없으면 `독립 데이터 없음`으로 기록한다.
- Drive 스트리밍 파일이 읽기 오류를 반환하거나 OCR이 필요한 원본이면 N을 유지하고 부분 검증이나 부분 상세 인덱스를 만들지 않는다.

## 독립 진행 지점

- 데이터북: Xanathar's Guide to Everything
- 시나리오북: Tomb of Annihilation
- 설정북: Guildmasters’ Guide to Ravnica

## 범위 경계

- 원본 PDF·Markdown과 FVTT Pack·모듈 저장소는 변경하지 않는다.
- 웹검색과 Google Drive 커넥터를 사용하지 않는다.
- PDF 임시 자료는 Drive 밖 `%LOCALAPPDATA%\Temp\codex-pdf-*`에서 처리한다.
- 아카이브는 현행 검색·집계·후속 인덱싱 입력에서 제외한다.
