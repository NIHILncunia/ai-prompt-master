# 스토리 정리 공통 지침 설계

## 1. 작업 목적

`TRPG 데이터/2. 로그/스토리 정리/`에 작성되는 장기 스토리 정리 문서의 작성·검증 기준을 독립 지침으로 확립한다.

현재 `3. 로그 분석 프롬프트`는 정보흐름분석, 세션 단위 기승전결 요약, 연속성 기록을 정의하지만 여러 세션을 하나의 장기 이야기로 재구성하는 `스토리 정리` 문서 유형은 별도 실행 규칙이 없다.

이 때문에 기존 `1. 로그 분석 지침서.md`의 비순차 목록 강제 규칙이 장기 스토리 정리에도 오인 적용될 수 있고, 문체·문단 품질을 보완하려면 별도 저장소인 `프로젝트 위그드라실`의 설정 문서 점검 지침을 매번 참조해야 하는 구조적 문제가 생긴다.

이번 작업은 설정 폴더의 지침을 실행 의존성으로 연결하지 않는다. 설정 점검 지침에서 일반화 가능한 문체·의미 보존 원리만 추출하여, 로그 분석 기능이 직접 소유하는 `스토리 정리` 전용 정본 지침으로 재정의한다.

## 2. 설계 원칙

### 2.1 실행 독립성

스토리 정리 작업을 수행할 때 `프로젝트 위그드라실`의 설정 점검 지침을 필수로 읽지 않아도 되어야 한다.

스토리 정리 작성 규칙은 다음 파일이 직접 소유한다.

`TRPG 데이터/1. 프롬프트/3. 로그 분석 프롬프트/2. 스토리 정리 작성 지침.md`

설정 점검 지침은 신규 지침을 설계할 때 참고한 원천이며, 실제 실행 정본은 아니다.

### 2.2 책임 분리

- `1. 로그 분석 지침서.md`
  - 세션 단위 정보흐름분석
  - 정보흐름분석 내부 기승전결 요약
  - 단독 세션 기승전결 요약
- `2. 스토리 정리 작성 지침.md`
  - 여러 세션을 하나의 장기 이야기로 통합
  - 완료 또는 진행 중인 스토리라인 전체 정리
  - 기존 장기 스토리 정리 문서의 재작성·보완
- `2. 로그 하이라이트 추출 프롬프트`
  - 이미지화 가능한 장면 후보 추출
- `8. 세션 제작`
  - 실제 세션 시나리오 제작

각 기능은 서로의 정본 규칙을 복제하지 않는다.

### 2.3 설정 점검 지침과의 관계

설정 점검 지침에서 가져오는 것은 형식이 아니라 다음 품질 원칙이다.

- 사실·인과·주장 강도 보존
- 단문 일변도와 정보 파편화 방지
- 반복 접속사와 동일 종결어미 억제
- 추상 주어와 만능 동사 남발 억제
- 영어식 대명사 반복 억제
- AI식 의미 선언과 예고편식 마감 반복 억제
- 기계적인 동일 문단 길이·동일 전개 구조 금지
- 문단이 충분한 맥락과 인과를 품도록 작성
- 원문에 없는 사실·동기·평가를 윤문 과정에서 추가하지 않음

반대로 다음 설정 전용 규칙은 가져오지 않는다.

- 설정 정본 폴더 탐색 규칙
- 공개 설정·비밀 설정 분류
- `docType`, 설정 YAML 메타데이터
- 설정 템플릿 적용 규칙
- 300토큰·2문단 정량 기준
- 설정 인덱스·역참조 검증
- 이미지 경로 검증
- 설정 정비 이력 관리

## 3. 신규 문서 정의

### 3.1 문서명

`2. 스토리 정리 작성 지침.md`

### 3.2 저장 위치

`TRPG 데이터/1. 프롬프트/3. 로그 분석 프롬프트/`

### 3.3 적용 대상

다음 요청은 신규 지침을 적용한다.

- 특정 스토리 전체 정리
- 여러 세션을 하나의 이야기로 통합
- 장기 스토리 요약
- 완료된 스토리 정리
- 진행 중인 장기 스토리의 누적 정리
- `TRPG 데이터/2. 로그/스토리 정리/` 문서 작성
- 기존 스토리 정리 문서 재작성·보완·윤문

한 세션의 정보흐름분석과 한 세션의 기승전결 요약은 기존 `1. 로그 분석 지침서.md`가 담당한다.

## 4. 자료 우선순위

스토리 정리의 자료 우선순위는 다음과 같다.

1. 대상 스토리의 원본 로그
2. 대상 스토리의 정보흐름분석 문서
3. 같은 스토리의 기존 스토리 정리 문서
4. 세계 연속성 확인에 필요한 다른 스토리의 원본 로그·분석 문서

### 4.1 원본 로그

최종 사실 판정의 우선 근거다.

분석 문서와 원본 로그가 충돌하면 원본 로그를 따른다.

### 4.2 정보흐름분석 문서

전체 세션의 사건, 떡밥, 관계 변화, 미확정 사항을 빠르게 파악하는 색인·해석 보조 자료로 사용한다.

분석 문서의 추론이 원본보다 강한 인과나 감정을 부여했다면 그대로 채택하지 않는다.

### 4.3 기존 스토리 정리

문체와 이전 문서와의 연결성을 참고하는 보조 자료다.

기존 문서의 오류가 원본·분석보다 우선하지 않는다.

### 4.4 다른 스토리 자료

세계 전체의 연속성을 확인할 때만 사용한다.

후대 또는 다른 스토리에서 공개된 정보를 과거 인물이 이미 알고 있던 것처럼 소급 서술하지 않는다.

## 5. 작성 전 전체 구조 분석

본문 작성 전 대상 스토리에 속하는 전체 세션 범위를 먼저 확정한다.

다음 요소를 내부적으로 정리한 뒤 서사 국면을 나눈다.

- 시작 상태
- 최초 갈등
- 주요 전환점
- 주요 인물 또는 세력의 선택
- 갈등 확대
- 최고조
- 결말
- 종료 후 남은 영향

이 단계에서는 세션 번호를 그대로 목차로 변환하지 않는다.

## 6. 세션 경계와 서사 국면

스토리 정리의 소제목과 문단은 세션 번호가 아니라 사건의 변화와 서사적 기능을 기준으로 나눈다.

연속된 여러 세션이 같은 갈등과 사건을 다루면 하나의 서사 국면으로 묶을 수 있다.

한 세션 안에서도 목적·장소·갈등·주체가 크게 바뀌면 여러 국면으로 나눌 수 있다.

섹션 수는 고정하지 않는다.

소제목은 `도입`, `전개`, `결론` 같은 기능명보다 실제 사건이나 변화가 드러나는 제목을 사용한다.

## 7. 문단 구성 원칙

### 7.1 인과 단위

문장 수가 아니라 하나의 인과 단위를 기준으로 문단을 구성한다.

서로 직접 연결되는 다음 요소는 같은 문단에 함께 둘 수 있다.

- 사건의 원인
- 사건의 발생
- 인물의 선택
- 직접적인 결과
- 다음 사건을 열게 된 변화

### 7.2 문단 전환

다음 요소가 실질적으로 바뀌면 새 문단을 고려한다.

- 장소
- 시간
- 사건 주체
- 주요 갈등
- 정보 공개 단계
- 장면의 목적

### 7.3 금지

- 한 문장짜리 문단의 반복
- 사건 하나를 의미 강조를 위해 여러 단문으로 쪼개기
- 모든 문단을 같은 문장 수로 맞추기
- 모든 섹션을 같은 전개 공식으로 작성하기

## 8. 사실 보존 하드 게이트

문체 개선을 이유로 다음 정보를 변경하지 않는다.

- 인명·지명·세력명·사건명·물품명
- 사건 순서
- 행위자와 피해자
- 원인과 결과
- 인물의 실제 선택
- 확정과 추정의 차이
- 당시 공개된 정보의 범위
- 대사와 행동이 가진 주장 강도
- 성공·실패·사망·생존·투항 결과

다음 행위를 금지한다.

- 원본에 없는 인과관계를 새로 연결
- 행동만 확인된 인물의 내면 동기를 확정
- 가능성이나 의심을 확정 사실로 승격
- 후대에 밝혀진 진실을 당시부터 알려진 정보처럼 소급
- 서사를 매끄럽게 만들기 위해 사건 순서를 변경

## 9. 문체 기본값

기본 문체는 `담백한 서사 기록체`로 한다.

소설처럼 장면을 새로 창작하지 않는다.

분석 보고서처럼 매 문단의 의미를 해설하지 않는다.

사건과 선택, 결과가 자연스럽게 이어져 하나의 이야기로 읽히는 수준의 서술성을 목표로 한다.

## 10. 한국어 문체 및 AI 패턴 점검

### 10.1 단문 일변도

짧은 문장이 연속되어 정보가 파편화되면 원인·조건·대비가 이어지는 문장으로 결합한다.

반대로 한 문장에 독립 사건이 과도하게 몰리면 나눈다.

### 10.2 동일 종결어미

같은 종결어미가 연속되면 문장 구조와 시제를 점검한다.

문서 전체의 격식 수준은 유지한다.

### 10.3 접속사 반복

`그리고`, `하지만`, `그러나`, `결국`, `따라서`, `또한`, `즉`, `나아가`, `아울러`, `게다가`, `더욱이`를 기계적으로 반복하지 않는다.

논리 관계가 문장 자체에서 드러나면 접속사를 생략한다.

### 10.4 추상 주어와 만능 동사

다음 형태를 반복하지 않는다.

- `이 사건은 변화를 가져왔다`
- `이 기록은 진실을 보여준다`
- `이 장면은 의미를 제공한다`

가능하면 실제 변화와 결과를 직접 서술한다.

### 10.5 영어식 대명사

한 문단에서 `그`, `그녀`, `그들`, `그의`, `그녀의`가 반복되면 이름·호칭으로 바꾸거나 주어를 자연스럽게 생략한다.

### 10.6 피동과 명사 나열

행위자가 명확하면 불필요한 피동을 줄인다.

조사 없는 명사 나열이 이어지면 주어·목적어·서술어를 복원한다.

## 11. AI식 의미 선언 제한

사건 자체와 다음 결과가 의미를 충분히 보여준다면 별도의 해설 문장을 추가하지 않는다.

다음 형태를 반복하지 않는다.

- `이것은 중요한 전환점이었다.`
- `이 사건은 진실을 보여주었다.`
- `이 장면은 ~을 증명했다.`
- `모든 것은 이 순간 바뀌었다.`
- `그 질문에는 아직 답이 없었다.`
- `전쟁은 새로운 국면으로 접어들었다.`

필요한 경우 한 번 사용할 수 있으나, 모든 문단과 소제목의 마지막을 예고편처럼 마감하지 않는다.

## 12. 인물 감정과 관계 반영

정보흐름분석에 기록된 모든 관계 변화를 스토리 정리에 넣지 않는다.

전체 이야기의 방향을 실제로 바꾼 관계와 감정만 본문에 편입한다.

반영 우선 대상은 다음과 같다.

- 주요 선택을 발생시킨 관계
- 동맹·배신·투항·희생에 영향을 준 관계
- 장기 갈등의 원인이 된 관계
- 결말 또는 후유증으로 이어진 관계

농담, 단발성 언쟁, 장기 서사에 영향을 주지 않은 관계 변화는 생략할 수 있다.

## 13. 전투 서술

전투는 라운드·수치 중심으로 재현하지 않는다.

다음 정보만 우선 보존한다.

- 전투 원인
- 상대와 목적
- 전투 중 공개된 핵심 정보
- 특별한 선택·설득·희생
- 패배·사망·생존·투항 결과
- 전투 뒤 가능해진 다음 행동

HP, 판정 수치, 반복 공격, 세부 라운드는 장기 이야기의 흐름을 바꾸지 않았다면 생략한다.

## 14. 생략 기준

다음 정보는 장기 스토리에 영향을 주지 않았다면 원칙적으로 생략한다.

- 주사위 수치
- HP
- 전투 라운드
- 플레이어 잡담
- 메타 농담
- 반복 확인 대사
- 아이템의 세부 수치
- 장기 서사에 영향을 주지 않는 짧은 전투
- 단순 출석·부재 정보

## 15. 결말 작성

결말에서 같은 주제를 여러 표현으로 반복하지 않는다.

다음 세 요소를 우선 확인한다.

1. 주요 갈등이 어떻게 끝났는가
2. 주요 인물·세력에 무엇이 남았는가
3. 다른 스토리로 넘겨야 할 중요한 후유증이 있는가

후유증이 없으면 억지로 떡밥이나 다음 이야기를 만들지 않는다.

## 16. 기존 스토리 정리 수정

기존 문서를 보완·재작성할 때에는 원본 파일명을 유지한다.

기존 내용 중 원본과 일치하는 사건·인과는 보존한다.

문체 문제만 고치는 경우 원문에 없는 새 사건이나 해석을 추가하지 않는다.

구조 개편이 필요한 경우 세션별 나열을 서사 국면으로 재배치할 수 있으나 사건 순서는 바꾸지 않는다.

## 17. 최종 품질 게이트

작성 후 다음을 검사한다.

1. 원본 로그에 없는 사건을 추가하지 않았는가
2. 분석 문서의 추정을 확정으로 바꾸지 않았는가
3. 세션 번호를 따라 기계적으로 섹션을 나누지 않았는가
4. 한 문장짜리 문단이 반복되지 않는가
5. 같은 의미를 여러 번 다른 표현으로 반복하지 않는가
6. 문단마다 의미·교훈을 해설하지 않는가
7. 접속사와 같은 종결어미가 반복되지 않는가
8. 중요하지 않은 전투·농담·수치가 남지 않았는가
9. 중요한 인물의 선택이 누락되지 않았는가
10. 앞 사건의 결과가 다음 사건의 원인 또는 조건으로 자연스럽게 연결되는가
11. 원본의 사실 강도와 공개 시점이 보존되었는가
12. 소제목이 세션 번호가 아니라 실제 서사 국면을 드러내는가

하나라도 중대한 결함이 남으면 완료로 처리하지 않는다.

## 18. 설정 점검 지침과의 유지보수 관계

스토리 정리 실행 시 설정 폴더의 점검 지침을 필수 참조하지 않는다.

다만 설정 기능의 공통 한국어 윤문·AI 문체 제거 원칙이 대폭 변경되면 `2. 스토리 정리 작성 지침.md`도 비교 점검한다.

이 유지보수 관계는 실행 의존성이 아니다.

설정 기능 번호나 설정 폴더의 세부 구조를 이 문서에 고정하지 않는다.

## 19. 연동 변경 대상

실제 적용 시 다음 파일을 함께 갱신한다.

### 신규

`TRPG 데이터/1. 프롬프트/3. 로그 분석 프롬프트/2. 스토리 정리 작성 지침.md`

### 수정

`TRPG 데이터/1. 프롬프트/3. 로그 분석 프롬프트/AGENTS.md`

- 역할에 `장기 스토리 정리` 추가
- 스토리 정리 요청 시 신규 지침을 읽도록 라우팅
- 필수 읽기 목록에서 모든 작업에 신규 지침을 강제하지 않고 조건부 읽기로 둔다

`TRPG 데이터/1. 프롬프트/3. 로그 분석 프롬프트/0. 로그 분석 마스터 프롬프트.md`

- 적용 조건에 장기 스토리 정리 추가
- 산출물 종류에 장기 스토리 정리 문서 추가
- 기본 처리 순서에 스토리 정리 분기 추가
- 프롬프트 파일 구조에 신규 지침 추가

`TRPG 데이터/1. 프롬프트/3. 로그 분석 프롬프트/1. 로그 분석 지침서.md`

- 비순차 목록 강제 규칙이 `스토리 정리`에는 적용되지 않음을 명시
- 스토리 정리는 `2. 스토리 정리 작성 지침.md`가 소유한다고 경계 정의

## 20. 검증 조건

적용 후 다음을 검증한다.

- 스토리 정리 요청이 3번 로그 분석 기능으로 라우팅되는가
- 정보흐름분석 요청에서는 신규 지침을 불필요하게 읽지 않는가
- 스토리 정리 요청에서는 `2. 스토리 정리 작성 지침.md`가 조건부 필수로 읽히는가
- `1. 로그 분석 지침서.md`의 목록 강제 규칙과 충돌하지 않는가
- `AGENTS.md`와 마스터의 파일 구조·읽기 순서가 일치하는가
- 설정 폴더를 실행 필수 의존성으로 만들지 않았는가
- 기존 `프롤로그.md`, `마키나즈.md` 같은 스토리 정리 문서가 신규 규칙으로 처리 가능한가
- 신규 규칙이 특정 스토리명이나 룩스테라에 종속되지 않는가
