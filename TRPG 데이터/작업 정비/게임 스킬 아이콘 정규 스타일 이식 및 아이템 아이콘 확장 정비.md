## 4. 현재 확정된 게임 스킬 아이콘 계약

### 다중 패키징

- 기본 단위: 3×3 슬롯 시트
- 실제 아이콘: 좌상단부터 행 우선(row-major) 배치
- 빈 슬롯: 순수 검정
- 실제 아이콘 슬롯: 검정·차콜 기본 배경 금지, 속성·주색과 조화되는 유색 비투명 추상 배경
- 9개 초과: 같은 생성 배치에서 3×3 시트를 추가
- 생성 시트 픽셀 규격: 생성 도구의 원본을 보존하며 512×512 슬롯 / 1536×1536 시트를 강제하지 않음
- 자동 분할·재합성: 사용하지 않음
- 낱개 저장: 자동 수행하지 않으며 별도 요청 시에만 파생 작업으로 처리

### 생성 후 검수·저장

`3×3 시트 생성 → 구조/수량/행 우선 순서/경계 침범 검수 → 64/128 상당 축소 판독성 검수 → 원본 시트 그대로 22번 배치 저장소에 저장 → 동명 MD 갱신`

구조가 정상인 시트는 픽셀 크기가 예상과 달라도 후처리 정규화하지 않는다. 구조적·시각적 실패는 재생성 권고로 판정하며, 이미지 재생성은 새 요구사항 확인서와 최종 프롬프트, 새 승인 없이는 실행하지 않는다.

정식 저장 루트는 `TRPG 데이터/22. 아이콘 생성`이다. `스킬 아이콘`, `아이템 아이콘` 아래에 `<YYYY MMDD> <상위 폴더명> <NN>` 배치 폴더를 만들고 동명 `.md`와 시트 원본을 함께 저장한다. 시트가 여러 장이면 `-1`, `-2` 접미사를 사용한다.

## 5. 현재 확정된 시각 문법

- 고채도·고대비 판타지 RPG 스킬 아이콘
- 한 슬롯 하나의 핵심 개념
- 굵고 빠르게 읽히는 실루엣
- 64×64 / 128×128 판독성 유지
- 중심 피사체가 슬롯에서 시각적으로 우세해야 함
- 피사체의 속성·주색·명도·발광과 조화되는 유색 추상 배경
- 선택적인 림라이트와 에너지 글로우
- 페인터리와 그래픽 렌더링의 중간 밀도
- 과도한 전역 bloom, 과도한 미세 텍스처, 배경 이펙트가 주피사체를 압도하는 구성 금지
- 신성/광휘 계열은 백색 과노출로 핵심 형태가 무너지지 않도록 내부 형태선 유지
- 화염·물·바람·암흑처럼 배경과 피사체가 같은 계열로 섞이는 경우 명도/채도/림라이트로 중심 형태를 분리

- 6×6 고밀도 테스트: 대량 한 장 생성의 원시 셀 해상도 한계를 확인하고 3×3 고정 슬롯 방식으로 정책 전환.

문서, 재료, 소비 아이템, 음식, 연금 재료, 보석, 도구, 무기, 장비, 장신구 등 폭넓은 아이템군을 64×64에서도 즉시 분류할 수 있는 아이콘 스타일을 만든다. 무기와 장비는 이 상위 스타일의 하위 분기 또는 확장 검증 범위로 포함한다.

### 유지할 모체 규칙

- 3×3 원본 시트 배치 저장 계약
- 실제 슬롯 전체를 채우는 비투명 배경

- 생성 원본 시트 비분할 보존
- 작은 크기 판독성
- 공통 광원·재질·렌더링 밀도 문법

### 별도 검증할 항목

- 무기 종류별 실루엣 차이
- 장축 무기의 방향성과 프레이밍
- 금속·목재·가죽·마석 등 재질 판독

- 동일 무기 종류 안에서 일반/희귀/전설급 표현 차이를 어떻게 둘지
- 양손/한손/쌍수 등 기능 차이가 필요한지

### 게임 아이템 아이콘 스타일 — 무기 검증 축 진행 중

- 개발 정본 `TRPG 데이터/20. 그림 스타일 분석/게임 아이템 아이콘 스타일/`과 내부 개발 폴더 구조를 생성했다.
- 1차 무기 다양성 3×3 2장 테스트를 수행했다.
- 1차 결과는 무기 종류 다양성은 확보했지만 대부분의 아이콘이 과도한 원소 효과·발광·유색 에너지 배경을 사용해 일반 무기와 속성·마법 무기의 의미 구분이 무너졌다고 판정했다.
- 새 기본값은 `속성·마법 효과 미지정 → 일반 무기`다.
- 일반 무기는 회색·청회색·갈회색 등 저채도 중성 배경과 실제 구조·재질을 우선한다.
- 속성·마법 무기는 명시된 경우에만 유색 배경·룬·보석·국소 발광을 사용하며 효과가 본체를 가리면 실패다.
- 별도 정식 `무기 아이콘 스타일`을 병렬 생성하지 않고 상위 `게임 아이템 아이콘 스타일` 내부의 무기 검증 축으로 다룬다.
