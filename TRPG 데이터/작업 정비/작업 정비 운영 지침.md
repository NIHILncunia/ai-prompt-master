# 작업 정비 운영 지침

## 1. 목적

`작업 정비`는 `TRPG 데이터` 작업 폴더에서 수행되는 장기·다단계 작업의 분석, 진행, 확정, 미결, 중단, 재개, 완료 이력을 지속적으로 추적하는 공통 운영 체계다. 설정 정본의 정비는 설정 폴더의 `설정 정비`가 담당하고, 작업 폴더 내부의 프롬프트 개선·룰북 분석·데이터 정비·구조 개편·이관·장기 제작은 `작업 정비`가 담당한다.

## 2. 기본 구조

```text
TRPG 데이터/작업 정비/
├─ 작업 정비 운영 지침.md
├─ 작업 정비 현황.md
├─ <작업명> 정비.md
├─ <작업명>/
│  └─ 분석·중간 결과·확정 산출물
├─ 정비 중간 보고/
│  └─ 교차 점검·중간 검증·상태 스냅샷
└─ 정비 아카이브/
   └─ 완료된 패치 ZIP·백업 ZIP·정비 산출물 ZIP
```

## 3. 등록 대상

다음 중 하나라도 해당하면 자동 등록한다.

- 여러 단계에 걸쳐 이어지는 분석·설계·개편·이관·검증 작업
- 여러 파일·기능·룰북·데이터를 순차적으로 검토하는 작업
- 중단 후 재개 지점을 보존해야 하는 작업
- 결과가 확정되기 전 후보·미결·이관 사항을 추적해야 하는 작업
- 프롬프트나 프로젝트 운영 체계를 개선하는 작업

단순 조회·단발성 사실 확인처럼 추적 필요가 없는 작업은 등록하지 않을 수 있다.

## 4. 자동 생성 및 갱신

작업 정비 대상이 시작되면 사용자의 별도 요청 없이 다음을 수행한다.

1. `작업 정비 현황.md`에 작업 등록
2. `<작업명> 정비.md` 생성 또는 기존 문서 재사용
3. 필요한 경우 `<작업명>/` 세부 폴더 생성
4. 분석·확정·보류·이관·미결·다음 단계를 작업 진행과 동시에 갱신
5. 중단 시 정확한 중단 지점과 재개 지점 기록
6. 완료 시 완료 범위와 최종 산출물, 남은 후속 작업 여부 기록

## 5. Superpowers 연동

작업 정비와 Superpowers는 병행 체계다.

- `docs/superpowers/specs/`: 설계 정본
- `docs/superpowers/plans/`: 실행 계획 정본
- `docs/superpowers/reports/`: 분석·검증·완료·인계 보고서
- `docs/superpowers/SUPERPOWERS WORK REGISTRY.md`: 공식 작업 상태
- `작업 정비/`: 실제 작업 대상의 진행 맥락과 분석 결과 추적

Superpowers 적용 작업은 작업 정비만 기록하거나 Superpowers 문서만 기록해서는 안 된다. 장기 작업이면 양쪽의 필요한 기록을 자동으로 유지한다.

## 6. 상태 관리

권장 상태는 `준비`, `분석 중`, `설계 중`, `실행 중`, `검증 중`, `검토 대기`, `일시 중단`, `완료`다. 실제 상태와 다른 값을 기록하지 않는다.

완료·중단 이력은 삭제하지 않는다. 동일 작업을 재개하면 기존 작업 기록을 이어서 갱신한다.

## 7. 기록 원칙

- 실제로 수행한 내용만 완료로 기록한다.
- 후보와 확정 사항을 구분한다.
- 이관·보류·폐기된 항목도 이유와 이동 지점을 남긴다.
- 장기 작업의 세부 결과는 작업별 폴더에 누적하고, 정비 문서는 전체 흐름과 상태를 요약한다.
- 작업 정비의 상태와 `SESSION PROGRESS`, Superpowers 레지스트리가 충돌하면 실제 작업 상태를 재검증하고 세 기록을 동기화한다.

## 8. 작업 아카이브

`정비 아카이브/`는 완료된 작업의 재현 근거와 복구용 보관본을 위한 경로다. 활성 작업 파일이나 실행 경로를 대체하지 않는다.

- 대상: 적용·검증이 끝난 패치 ZIP, 검증된 백업 ZIP, 완료된 정비 산출물 ZIP.
- 이동 전 검증: 적용 대상 경로와 파일 수를 확인하고, 내용 교체가 있었다면 원본 ZIP과 적용본의 SHA-256 또는 동등한 무결성 검증을 수행한다.
- 제외: 아직 적용·검증되지 않은 패치, 활성 작업의 원본, 자동으로 다시 풀거나 실행할 자료.
- 보관명: 원본 파일명을 유지한다. 같은 이름이 이미 있으면 기존 파일을 보존하고, 새 파일명 앞에 `yyyy-MM-dd-HHmm_`를 붙인다.
- 접근 규칙: 아카이브 파일은 자동 탐색·자동 추출·자동 재적용 대상이 아니다. 재적용은 마스터의 명시 지시와 대상 검증 뒤에만 수행한다.
- 정리 규칙: 삭제·교체·이동은 마스터가 명시적으로 지시한 경우에만 수행하며, 대상 경로를 먼저 확인한다.
