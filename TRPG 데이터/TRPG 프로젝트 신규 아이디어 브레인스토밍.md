# TRPG 프로젝트 신규 아이디어 브레인스토밍

- 작성 기준일: 2026-09-11
- 목적: 현재 TRPG 세션 매니저 프로젝트에 축적된 세계관·엔터티·세션 설계·로그·룰북/FVTT·집필·이미지 스타일 데이터를 서로 연결해 만들 수 있는 신규 기능 후보를 정리한다.

## 1. 방향성

현재 프로젝트는 단일 생성기 집합을 넘어, 세계관·엔터티·세션 설계·로그 분석·하이라이트·룰북/FVTT·집필 데이터·이미지 스타일 분석이 각각 독립적인 데이터 축으로 발전했다.

따라서 다음 단계의 핵심은 새로운 개별 생성기를 하나 더 추가하는 것보다, 기존 데이터 축들이 서로 반응하도록 만드는 교차 기능과 공통 데이터 계층을 구축하는 데 있다.

최종적으로는 다음 순환 구조를 지향한다.

```text
설정/룰북/자산
    ↓
세션 설계
    ↓
실제 플레이
    ↓
로그 분석
    ↓
사건 및 상태 변화
    ↓
다음 세션 설계
```

---

## 2. 신규 아이디어 목록

### 2.1 Campaign Event Ledger — 캠페인 이벤트 원장

캠페인에서 실제로 벌어진 일을 구조화된 사건 단위로 영구 기록하는 공통 사건 원장이다.

설정 문서는 "세계가 원래 어떠한가", 세션 설계는 "무슨 일이 일어날 예정인가", 이벤트 원장은 "실제로 무슨 일이 일어났는가"를 담당한다.

대표 데이터:

- event_id
- session_id
- scene_id
- event_type
- actors
- targets
- location
- facts
- inferences
- effects
- result
- source_log
- importance
- world_time
- real_time

핵심 원칙:

- 사실과 해석을 분리한다.
- 원본 로그 근거를 남긴다.
- 사건은 가능한 한 append-only 방식으로 보존한다.
- 다른 후속 시스템이 로그 원문을 매번 다시 해석하지 않고 이벤트 원장을 공통 입력으로 사용하도록 한다.

이 아이디어는 전체 시스템의 공통 척추 후보다.

---

### 2.2 World State Engine — 세계 상태 엔진

이벤트 원장에서 발생한 사건을 바탕으로 현재 캠페인의 상태를 관리한다.

예:

- NPC 생존/사망/부상
- 아이템 소유권
- 장소 파괴/봉쇄/변질
- 국가·단체 관계 변화
- 퀘스트 상태
- 정치적 권력 공백
- 특정 지역의 위험도

설정 원본과 캠페인 현재 상태를 분리하는 것이 핵심이다.

```text
Canonical Setting
→ Event Ledger
→ Current Campaign State
```

이를 통해 동일 세계관을 여러 캠페인에서 독립적으로 사용할 수 있다.

---

### 2.3 Knowledge Graph — 정보 인지 그래프

"세계의 진실"과 "누가 무엇을 알고 있는가"를 분리해 관리한다.

예:

- 실제 진실: 왕은 이미 죽었다.
- PC A: 모름.
- PC B: 실종으로 알고 있음.
- NPC C: 암살 사실을 알고 있음.
- 시민: 병환 중이라는 공식 발표만 알고 있음.

활용:

- 플레이어별 스포일러 방지
- NPC가 알 수 없는 정보를 말하는 오류 검출
- PC별 요약 생성
- 비밀·오해·거짓 정보 관리

---

### 2.4 NPC Memory Engine — NPC 기억 엔진

NPC가 세션 중 발생한 사건을 기억하고 후속 행동에 반영하도록 한다.

예:

- 도움받음
- 거짓말을 들음
- 생명을 구원받음
- 친구가 살해당함
- 빚이 생김
- 의심 중
- 공포/존경/신뢰 변화
- 마지막 만남
- 마지막 대화 주제

장기 캠페인에서 NPC의 일관성과 재등장 품질을 크게 높일 수 있다.

---

### 2.5 Story Thread Tracker — 이야기 실마리 추적기

떡밥, 복선, 단서, 약속, 개인 목표, 미해결 사건, 예언 등을 Thread 객체로 관리한다.

대표 데이터:

- thread_id
- type
- origin_session
- related_entities
- related_location
- status
- player_awareness
- resolved_at
- last_touched_session

활용:

- 오래 방치된 복선 자동 탐지
- 미회수 단서 확인
- 다음 세션에서 회수할 후보 추천

---

### 2.6 Session Compiler — 세션 컴파일러

캠페인의 현재 데이터를 읽어 다음 세션에 필요한 자료를 자동 조립한다.

입력 후보:

- 현재 세계 상태
- 직전 세션 이벤트
- 미회수 Story Thread
- 참여 PC
- 관련 NPC
- 지역/장소
- 룰북 데이터
- 몬스터/아이템/주문
- 맵/이미지 자산

출력 후보:

- 이번 세션에서 처리할 이야기 후보
- 필요한 NPC
- 필요한 전투 데이터
- 필요한 맵
- 부족한 이미지
- 관련 룰북 근거
- 세션 준비 체크리스트

---

### 2.7 Continuity Auditor — 연속성 감사기

설정, 세션 설계, 이벤트 원장, 현재 상태 사이의 모순을 탐지한다.

예:

- 이미 사망한 NPC가 이후 세션에 정상 등장
- 한 아이템이 동시에 두 사람 소유
- 파괴된 장소가 정상 상태로 사용됨
- 이동 시간과 세계 시간이 맞지 않음
- 설정상 존재할 수 없는 관계 발생

장기 캠페인에서 데이터 정합성을 유지하는 기능이다.

---

### 2.8 Rule Memory — 판정 기억

실제 테이블에서 어떤 룰 문제를 어떻게 처리했는지 기록한다.

대표 데이터:

- 질문
- 적용 룰
- 룰북 근거
- 당시 마스터 판정
- 하우스룰 여부
- 관련 세션

같은 상황이 다시 발생할 때 과거 판정과 근거를 재사용해 룰 일관성을 유지할 수 있다.

---

### 2.9 Homebrew Balance Lab — 홈브루 밸런스 랩

자작 아이템·특성·능력·클래스의 설계 성능과 실제 플레이 성능을 비교한다.

비교 축:

```text
공식 룰 기준
↔ 설계 예상 성능
↔ 실제 플레이 성능
```

활용 데이터:

- 사용 횟수
- 명중률
- 피해량
- 자원 소비
- 선택률
- 전투 기여도
- 유사 공식 데이터

---

### 2.10 Player Perspective Recap — 플레이어 관점 요약

Knowledge Graph를 이용해 각 PC가 실제로 알고 있는 정보만으로 세션 요약을 생성한다.

GM 전용 진실과 플레이어 인지 정보를 분리해 스포일러 없는 회고를 제공할 수 있다.

---

### 2.11 Visual QA Engine — 이미지 품질/스타일 검수 엔진

현재의 그림 스타일 분석, 견본 레퍼런스, 시안 레퍼런스, 시안 판정 이력을 이용해 신규 생성 이미지가 스타일 기준에 맞는지 자동 검수한다.

검수 후보:

- 라인 일치도
- 명암 방식
- 배경 표현
- 얼굴 연령
- 비율
- 재질
- 색 밀도
- 기존 스타일과의 거리

판정:

- 사용 권고
- 수정 권고
- 재생성 권고

---

### 2.12 Asset Completeness Engine — 자산 완성도 검사기

NPC, PC, 장소, 국가, 단체, 아이템 등 각 엔터티에 필요한 자산이 갖춰졌는지 검사한다.

예:

- NPC 설정 문서 있음 / 초상화 없음
- PC 전신 있음 / 토큰 없음
- 장소 설정 있음 / 풍경 없음
- 아이템 설명 있음 / 아이콘 없음
- 국가 설정 있음 / 엠블럼·배너 없음

누락된 자산을 자동으로 작업 후보에 올릴 수 있다.

---

### 2.13 GM Narration Adapter — GM 서술 어댑터

집필 데이터의 문체 프로필을 TRPG 세션 출력에 맞게 변환한다.

분기 예:

- 소설 문체 → 장면 서술
- 대화 문체 → NPC 대사
- 압축 문체 → 세션 중 즉석 묘사
- 극적 문체 → 컷신
- 문서체 → 편지·일지·공문·신문 등 핸드아웃

세계관 설정 + 세션 상황 + 마스터 문체 프로필을 결합해 일관된 서술을 지원한다.

---

### 2.14 World Reaction Simulator — 세계 반응 시뮬레이터

중요 사건 이후 국가·단체·NPC·지역이 어떤 반응을 보일지 후보를 계산한다.

예:

```text
왕 암살
→ 수도 봉쇄
→ 귀족 파벌 이동
→ 군부 비상대응
→ 주변 국가 외교 반응
→ 시민 루머 확산
```

자동 확정이 아니라 영향 후보 생성과 검토 보조 역할로 사용하는 것이 적절하다.

---

### 2.15 Campaign Cockpit — 캠페인 운영 대시보드

캠페인 전체 상태를 한 화면에서 확인하는 최종 관리 인터페이스다.

표시 후보:

- 현재 세션
- 직전 주요 사건
- 미회수 이야기
- 주요 NPC 상태 변화
- 플레이어별 목표
- 필요한 맵
- 필요한 이미지
- 부족한 FVTT 데이터
- 관련 룰북
- 준비도

단, 기초 데이터 계층이 안정된 뒤 구축하는 것이 적절하다.

---

## 3. 우선순위 제안

### 1순위 — Campaign Event Ledger

다른 시스템이 공통으로 사용할 "실제 발생 사실" 계층을 만든다.

### 2순위 — World State Engine / NPC Memory Engine / Knowledge Graph

Event Ledger의 사건을 현재 상태·기억·인지 정보로 파생한다.

### 3순위 — Story Thread Tracker / Session Compiler

축적된 상태를 다시 다음 세션 설계로 환류시킨다.

### 이후 후보

- Rule Memory
- Continuity Auditor
- Homebrew Balance Lab
- Player Perspective Recap
- Visual QA Engine
- Asset Completeness Engine
- GM Narration Adapter
- World Reaction Simulator
- Campaign Cockpit

---

## 4. 핵심 구조 제안

```text
세션 설계
    ↓
실제 플레이
    ↓
로그
    ↓
로그 분석
    ↓
Campaign Event Ledger
    ↓
────────────────────────────────
↓              ↓              ↓
World State    NPC Memory     Knowledge Graph
↓              ↓              ↓
Story Thread Tracker
    ↓
Session Compiler
    ↓
다음 세션 설계
```

이 순환 구조가 완성되면 프로젝트는 자료 생성기에서 캠페인 상태를 기억하고 변화시키는 운영 시스템으로 발전할 수 있다.

---

## 5. 결론

현재 프로젝트에 가장 필요한 신규 발전 방향은 개별 생성 기능의 추가보다 기존 데이터 축 간의 연결이다.

특히 Campaign Event Ledger를 중심으로 실제 플레이 결과를 구조화하면, 이후 세계 상태·NPC 기억·정보 인지·복선 추적·다음 세션 자동 조립이 모두 동일한 사실 계층을 공유할 수 있다.

장기적으로는 다음 폐쇄 루프를 목표로 한다.

```text
설정 → 세션 설계 → 플레이 → 사건 → 상태 변화 → 다음 세션 설계
```
